# テンプレート: 方針決め / 4_構造の決定

方針決めの段 4「構造の決定」の記録の書式。
あるべき姿の構造を、責務の境界からテストまで順に決め、理由と採らなかった案を残す。

`## 調べたこと` と `## 回答` は、テンプレート『方針決め/共通』に従う。

## セクション一覧

| セクション | 必須or条件 |
| --- | --- |
| `## 決定` | 必須 |
| `## 調べたこと` | 必須 |
| `## 回答` | 必須（段の確認事項が決着したとき） |

## `## 決定`

### 記述例

```markdown
## 決定

| 決めること | 決定 | 理由 | 採らなかった案 | 補足 |
| --- | --- | --- | --- | --- |
| 責務とサービスの境界 | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
| リポジトリとプロセス | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
| モジュール構成（ルート直下を含む） | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
| 設定とデータの置き場所 | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
| 依存の見直しと新しい技術 | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
| 横断の方針 | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
| 画面 | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
| テスト | {決定} | {理由} | {案と採らなかった理由} | {応える品質シナリオ・機能の扱い} |
```

### 補足

**決めること列:**
- 記述例の順のまま置き、前の行の決定を後の行の前提にする
- 対象が無い行（画面を持たない 等）は、決定列に `対象なし` と理由を書く

**決定列:**
- たたき台のときは推奨の決定を書き、ユーザーの回答で確定した内容へ書き換える

**理由列・採らなかった案列:**
- 決定ごとに、理由と、検討して採らなかった案とその理由を残す（案が無い決定は `なし`）

**補足列:**
- 段 2 の品質シナリオと段 3 の機能の扱いのうち、その決定が応えるものを書く

**決めること別の判断基準:**

<!-- table: data -->

| 決めること | 判断基準 |
| --- | --- |
| 責務とサービスの境界 | 分ける単位は変更の理由が異なる責務にし、分割は必要が出てからにする（単一の構成から始める） |
| リポジトリとプロセス | 同時に変更され同時に配布されるものは同じリポジトリ・同じプロセスに置く |
| モジュール構成（ルート直下を含む） | 責務の境界と依存の向きが読み取れる並びにし、ルート直下に置くファイルを決める |
| 設定とデータの置き場所 | 環境ごとに変わる値を設定に出し、置き場所は実行環境の慣習（環境変数・ユーザー設定のフォルダ）に従う |
| 依存の見直しと新しい技術 | 技術ごとに採用 / 試す / 様子見 / 採らないを決め、採用は段 2 の品質シナリオに効く根拠を添える |
| 横断の方針 | ログ・エラー処理・認証・設定の読み方など全体に効く方針を、モジュール構成に反映できる粒度で決める |
| 画面 | 段 3 で残す・作り直す画面の構成と、デザインの方向を決める |
| テスト | 旧システムの振る舞いを守る特性テストと、構造の決定を守る検査（fitness function）を決める |
