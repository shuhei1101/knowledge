# 文章の追記

文章を足す前に、既存の行を直す・消すことで足りないかを確かめ、足りるなら足さない。

ドキュメント・PR 本文・フェーズ手順に文章を足したら、書き終えた直後に次を確認して当てはまる行を消す。
足した分は以降の全ターンの起動プロンプトに載り続けるため、消さないとノイズだけが増える。

<!-- table: data -->

| 確認 | 当てはまったら消す理由 | 出典 |
| --- | --- | --- |
| 手順に無い操作を禁じていないか | 書いていない操作は実行されない | |
| そう書く理由・背景・経緯を説明していないか | 読み手の判断が変わらないなら要らない | |
| 参照先（共通ルール / 規約 / テンプレート / フェーズ索引）に同じ内容が無いか | 参照を 1 行残せば足りる | |
| 直前の正の指示の裏返しになっていないか | 「〜する」の後の「〜しない」は情報量が無い | |
| 手順本文にあることを冒頭リードや概要で言い直していないか | 冒頭リードは 1〜2 行 | |
| 冒頭リード・概要に後から情報を足していないか | 対象そのものが変わったときだけ書き換える | |
| 後から増えうるものの個数を書いていないか | 増減のたびに数だけを直す差分が出る。数を消しても文は成立する | |
| 1 つの説明が 3 行を超えていないか | 決めきれていないと言葉で埋めたくなる。内容を確定させれば短くなる | |
| 消しても読み手の動きが変わらない行を残していないか | 変わらない行は、他の指示を埋もれさせる | C |
| モデルが既に知っている一般の知識（言語の仕様・ライブラリの使い方）を説明していないか | 書くのは、このプロジェクトで決めたことだけ | A / C |
| 実装のコード例を載せていないか | 文で足りる。例は古い書き方に引っ張る。書式を示す例は、文より短く伝わるときだけ残す | `Claude共通.md` / A |
| 版・価格・閾値・モデル名など、時期で古くなる値を書いていないか | 古くなっても直されないまま注入され続ける。公式の参照先を書く | A / C |
| 同じものを別の言葉で呼んでいないか | 別のものと読まれる。既出の呼び名に揃える | A / GT |
| 選択肢を並べたまま、既定を決めていないか | 読み手が選べない。既定を 1 つ書き、例外だけ添える | A |
| 強調（必ず・絶対・重要・太字）を足していないか | 今のモデルは強調に過剰に反応する。重ねると、どれも目立たなくなる | P / C |
| 推量やぼかし（〜と思われる・〜かもしれない）で書いていないか | 手順として実行できない。決めて書く | T |
| 冗長な言い回し（することができる・を行う）を使っていないか | 省いても意味が変わらない | T |
| 同じファイルの中で同じ説明を繰り返していないか（概要・まとめの節を含む） | 最も適切な 1 か所に置く | `Claude共通.md` |

<!-- /table -->

残してよい否定は、実行しうる操作を止めるものだけ。
分岐の `（以降の手順は実行しない）` や、実行できてしまう操作への `（スレッドは Resolve しない）` がこれにあたる。

既存の文章を変えないことは規約『既存文章の維持』が定める。
