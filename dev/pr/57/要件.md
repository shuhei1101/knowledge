[dev/コーディング規約/claude/mcp.md](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/claude/mcp.md) を中心に、次のとおり修正する。
変更するセクション以外の文言は一字一句そのまま残す（規約『既存文章の維持』）。

### 読み取りのツール（`mcp.md` の `## 読み取りのツール`）

- 読み取りのツールに共通の `format`（`markdown` / `json`、既定 `markdown`）を持たせる。`json` のときは structuredContent と text に同じ JSON を入れ、`markdown` のときは structuredContent を返さない（D-62）
- 今の 75〜77 行目（同じ会話で既に返した概要文・関連は省く）を、次の 2 つに書き換える
  - 会話キーは `session_id` と `agent_id` の別々の 2 つの引数で受け、PreToolUse フックが入れる。エージェントには書かせない（D-28）
  - 1 つのセッションで同じ内容は 1 回だけ渡す（D-65）。対象は関連に結合した相手の名前・概要文、1 件を取るツールの末尾の用語の一覧、同じバージョンの文書の本文。2 回目は返し済みのマーカーだけを返し、`repeat_seen` で再取得できる。`/clear`・圧縮の後はフックで記録を捨てる。会話キーが無いときは省かない。検索結果の各行の概要文は省かない
- 1 セッション 1 回の決まりは、MCP のツールに限らず、フック・mod で文脈を追加するときにも当てる。入力に用語の文脈を追加するときは、そのセッションで初めて出た語だけ、語・ID・説明・関連する文書（ID と名前）を 1 回だけ追加する（D-64・D-70）
- 用語・エイリアスの照合に使う語の一覧（語・正規化した語・ID・種類・概要・関連する文書）を返すツールを置く。指定したバージョンから変わっていなければ、変わっていないことだけを返す（D-64）

### 差分のツール（`mcp.md` の `## 差分のツール`）

- 区間（`from`・`to`）で追加・変更・削除された文書の一覧を返すツールを置く。`include_diff` で文書ごとの差分も返す（D-63）
- `from`・`to` は git の commit・日時・ブランチ・タグのどれでも受け、サーバーが commit に解決する。日時はその時点の最後の commit にする。解決した commit と日時を結果の先頭に返す（D-66）
- 1 件を取るツールに差分モード（`diff_from`・`diff_to`・`context_lines`、既定 3）を持たせ、git と同じ `+`・`-` の行で返す。`rev` だけの変化は出さず、参照の ID には名前を添える。`format: json` のときは、変わったキーごとの変更前後の値と、本文の変わった行の配列を返す（D-63）
- 既存の `changes_since_read` の行はそのまま残し、区間を自分で指すときは区間のツールを使う、と使い分けを書く

### 登録（`mcp.md` の `## 登録`）

- 開発ドキュメントサーバーにつなぐ MCP は、リポジトリ直下の `.mcp.json` では配らない。各リポジトリを Claude Code のマーケットプレイスにし、プラグインで配る。利用者は、どのプロジェクトでも使うならユーザースコープ、特定のプロジェクトだけならプロジェクトスコープで入れる（D-82）
- 文書の MCP のプラグインは、文書を持つリポジトリごとに 1 つにし、ほかのプラグインと分ける（D-83）
- 今の「プロジェクト用: ルートの `.mcp.json`」の行に、開発ドキュメントサーバーにつなぐ MCP は対象外であることを書く

### プラグインの分け方（`claudeプラグイン.md`）

- [dev/コーディング規約/claude/claudeプラグイン.md](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/claude/claude%E3%83%97%E3%83%A9%E3%82%B0%E3%82%A4%E3%83%B3.md) に、プラグインは機能ごとに単独にする（利用者が個別にオンオフできる）決まりを書く（D-83）
- 文書の MCP のプラグインの決まりは `mcp.md` の `## 登録` に置き、`claudeプラグイン.md` からは参照だけにする

### 決まりを読ませる場所

- [dev/コーディング規約/claude/フック.md](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/claude/%E3%83%95%E3%83%83%E3%82%AF.md) の `additionalContext` の行に、文脈を注入するときは `mcp.md` の 1 セッション 1 回の決まりに従う、と参照を 1 行追加する。フックを書くときに当たるのは `フック.md` で、`mcp.md` は当たらない（`rules.yaml`）
- [rules.yaml](https://github.com/shuhei1101/knowledge/blob/develop/rules.yaml) の `claudeプラグイン.md` の `paths` に `**/.claude-plugin/**` を追加する。マーケットプレイスの定義（`.claude-plugin/marketplace.json`）とリポジトリ直下のプラグインの定義を書くときに、プラグインの分け方が当たるようにする
