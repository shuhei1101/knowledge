# 要件

## 要望

移した規約を分野ごとに世の中のベストプラクティスと突き合わせ、直す点と書かなくてよい内容を洗い出して直す。
共通の規約へ寄せられる内容は寄せ、重なる記述を消す。

- 分野ごとに、サブエージェントで ai-monitor のプラグインの調査のスキル（`ai-monitor:tech-research`）を使ってベストプラクティスを調べる
  - 分野は `dev/コーディング規約/` の直下のフォルダ（claude・dev・html・markdown・next・prompt・python・ui）と、汎用の規約（`dev/規約/`）・判定フローチャート（`dev/判定フローチャート/`）
- 調べた結果と今の規約を比べ、分野ごとに次を洗い出して直す
  - 直す点: ベストプラクティスと食い違う記述・古くなった記述
  - 書かなくてよい内容: 規約『文章の追記』の確認に当たる記述（モデルが既に知っている一般の知識・実装のコード例・時期で古くなる値など）
  - 共通の規約へ寄せる内容: 複数の分野で重なる記述
- 各言語の環境変数・設定・定数の規約（next/shared『環境変数』・python/shared『シークレットと環境変数』『設定』『定数』）の置き場所の判断を判定フローチャート『設定値の置き場所』へ寄せ、各言語の規約には言語固有の読み方だけを残す
- ページを消す・まとめたときは、各フォルダの `README.md` の目次・直下の `rules.yaml` の行・ページ間のリンクを合わせる
- 分野ごとに、調べた出典と、直した点・直さなかった点の採否を完了報告に添える

## 影響するユースケース

なし（コードを持たず、ユースケースを持たない）。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| YAML の決まりを 1 つの規約へ集める・スキーマの書き方と検査・MCP からの書き込みの決まり | 同じ内容の open の Issue がある。本 PR では YAML の決まりを寄せずに残す | [#15](https://github.com/shuhei1101/knowledge/issues/15) |
| テンプレート（`dev/テンプレート/`）の見直し | テンプレートは設計書・ドキュメントの書式を定めるもので、要望の「移した規約」に当たらないと判断した（レビューで確定する） | 予定なし |
| 公開ドキュメント（`docs/`）の見直し | 規約ではなく、このリポジトリの使い方のページ | 予定なし |
| ai-monitor に残る同じ規約を直す | ai-monitor の文書は ai-monitor の Issue で扱う（[#3](https://github.com/shuhei1101/knowledge/issues/3) の扱いと同じ） | 予定なし |
| 規約を使う各プロジェクトのコードを直した規約へ合わせる | 別のリポジトリの作業 | 予定なし |
