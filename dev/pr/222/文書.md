## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 規約『表し方の優先順位』 | 「キーの表」のグループに、列・オブジェクト・見本の 3 項目を 1 項目 1 文で追加する。既存の項目は変えない | 見本は文より短く伝わる範囲で 1 つだけ記載する |
| 注入の条件の確認 | rule-inject の `args` の `re:` が組み込みの Write・Edit の `content`・`new_string` にヒットするか、alias-inject の `inject_when` が書き込みの中身にヒットするかを、各リポジトリの設計書で確認する | `未確定`（要件.md の `## 要望` の案 A・B） |
| キーの表の注入 | 列見出しに「キー」と「型」を含む Markdown の表の書き込みを条件に、規約『表し方の優先順位』を適用する | 条件の記載の仕方は採った案のキー |
| 種類の資料の注入 | シナリオ・インターフェース定義など、`schemas/design/` に種類のある資料の書き込みを、その種類の名前を条件にテンプレートへ適用する | 適用する種類は、手で記載する資料で必須の項目が漏れる種類に限る |
| 起票 | 今のキーで条件を記載できなければ、そのリポジトリへ条件の追加を起票し、`要件.md` の `## スコープ外` の対応予定を番号へ書き換える | - |
| 確認 | 追加した後に全ての文書の検査を実行し、違反が増えないことを確認する | - |
