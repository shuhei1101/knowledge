# 要件

## 要望

validator `knowledge-checks`（`scripts/knowledge_checks.py`）の文書の検査に、1 つの文書の中の `aliases` の検査を追加する。

- 検査する文書の `aliases[n]` が、同じ文書の前の要素 `aliases[m]`（m < n）と一致したら、`aliases[n]` の違反 1 件を返却する
- 検査する文書の `aliases[n]` が、自分の `name` と一致したら、`aliases[n]` の違反 1 件を返却する
- 照合の前に、判定表『エイリアスを登録しない条件』の ※6 と同じ正規化（NFKC・英字の大文字小文字・前後の空白）を両方の値に適用する。正規化は PR #212 の `normalize_name` を使用する
- 違反の `rule` に一致した相手（`aliases[m]` か `name`）を記載し、`fix` に判定表の ※6 の補足（片方だけ登録する）を記載する
- 名前の索引（`dev-docs.yaml`）を使用せず、検査する文書だけで判定する。`dev-docs.yaml` が無い・読めない場合も、この検査は適用する
- 全ての文書の検査（`check_all.py`）も同じ検査を適用する
- develop の文書に、この検査の違反が 0 件である（11-06 の develop の時点で、`aliases` を持つ 70 件の文書のうち、`aliases` の重複と自分の `name` と一致する `aliases` を持つ文書は 0 件）

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 判定表『エイリアスを登録しない条件』の 4 行目の削除 | 判定表は人がエイリアスを登録する前に参照するもので、検査は登録した後の違反を見つけるだけ。判定表は `rules.yaml` に載らず、規約『ルール索引への登録』の強制注入の基準 2 の「本文から削除する」の対象外（PR #212 の 5 行目と同じ扱い） | 予定なし |
| `aliases` の重複をスキーマの `uniqueItems` で検査する | `uniqueItems` は正規化をせず、正規化して同じになる表記ゆれを見つけられない。この検査が完全に一致する重複も見つける | 予定なし |
