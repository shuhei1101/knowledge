# 要件

## 要望

YAML を扱う決まりを新しい規約 `dev/コーディング規約/dev/YAML.md` に集め、今の規約で重なっている記述を消すか、新しい規約への参照に置き換える。
新しい規約には、今の規約から寄せる決まりに加えて次を決める。

| 決まり | 決める内容 |
| --- | --- |
| スキーマの書き方 | JSON Schema 2020-12 で書く・ファイル名は `{種類}.schema.yaml`・各項目に `title` / `description` を付ける・種類をまたぐ型は `共通.schema.yaml` の `$defs` に置いて `$ref` で指す・ブロック形式で書く |
| 検査 | 読み込むとき（起動の事前確認など）に全ての YAML を検査し、違反は `{ファイル}: {キーのパス}: {理由}` の行で全て並べる。ファイルを書き換えずに違反を並べる検査だけのツールを置く |
| MCP からの書き込み | MCP の口があるプロジェクトでは YAML を直接編集しない。変更を当てた後の中身を検査し、違反が 1 件でもあれば何も書き換えずにエラーを返す。一時ファイルに書いてから置き換え、複数のファイルを書く途中で失敗したら置き換えた分を元に戻す。読み込み・検査・書き込みは排他ロックの中で行う。書き込むツールの説明はスキーマの `title` / `description` / 必須から組み立てる |
| MCP からの読み取り | タグの一覧（名前と説明）を YAML に登録して登録外のタグを書き込みで弾く・タグの一覧のツール（数が 0 のタグも返す）・登録外のタグで検索したら近い候補を添えたエラーにする・読み取りのツールの説明もスキーマから組み立てる |

YAML に限らない MCP の読み取りのツールの作り方（種類ごとの `list_*` を作らず絞り込みつきの `search` 1 つにまとめる・既定の `limit` と `total`・`next_cursor` を返す・`response_format` で返す量を選ぶ・切り詰めたときに絞り込める引数を案内する）は、[dev/コーディング規約/claude/mcp.md](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/claude/mcp.md) に置き、新しい規約からは参照する。
