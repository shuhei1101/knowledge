# 要件

## 要望

規約『文章の書き方』の語の選び方の原則と代表的な語の対応を、knowledge のプラグインの SessionStart フックでセッションの開始時に注入する（ui、ドキュメントの文章ベストプラクティスの D-11・T-7）。
注入はチャットの返答やコードのコメントなど、rule-inject で規約が当たらない文章にも効かせるためのもの。
注入が入った後に、ユーザーの CLAUDE.md の NG 用語の表を削除する（反映作業）。

### 注入する中身

- `docs/rule/convention-writing-style.yaml` の `## 語の選び方` を正本にし、注入する文を別に書き起こさない。規約を書き換えたら、次のセッションの注入も変わる
- 注入するのは次の 2 つと、詳しくは規約『文章の書き方』を読む旨の 1 行
  - 原則表（`word-choice-principle-02`）の原則と、悪い例 → 良い例
  - ドキュメントの語の対応表（`word-choice-table-02`）の避ける語 → 使う語
- 原則の理由の列は注入しない
- 注入の文字数は、規約『フック作成ガイド』の `additionalContext` の上限（公式の hooks リファレンス）に収める
- 規約のファイルが読めないときは何も注入せず、セッションの開始を止めない
- SessionStart の `source` が `startup` / `clear` / `compact` のときだけ注入し、`resume` / `fork` では注入しない

### プラグインの構成

- フックは `hooks/hooks.json` と `hooks/session-start/` のスクリプトで置く（規約『Claude プラグインルール』の `## フックフォルダの定義`）
- マーケットプレイスは #98 で `.claude-plugin/marketplace.json` が置かれているので、新しく作らない

`未確定`: フックを載せるプラグイン（決める段: 要件のレビュー）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 既存のプラグイン `knowledge`（リポジトリの直下。#98）に `hooks/` を追加する | フックが `${CLAUDE_PLUGIN_ROOT}/docs/rule/` の規約のファイルを読め、規約を正本にできる。利用者が入れるプラグインは 1 つのまま | スキル（`/knowledge:text-review`）と注入を個別にオンオフできない |
| B | フック用のプラグインを `plugins/{名前}/` に別に置き、マーケットプレイスに行を追加する | 規約『Claude プラグインルール』の「プラグインは機能ごとに単独」に沿い、個別にオンオフできる | マーケットプレイスから入れたプラグインはプラグインのフォルダだけがキャッシュへコピーされるため、規約のファイルを読めない。注入する文をプラグインの中に複製し、規約と二重になる |

推奨: A

注入の目的は規約と二重に持たないこと（D-11 で CLAUDE.md の表を消す理由）で、B はプラグインの中に二重を作り直す。
スキルと注入はどちらも knowledge の文章の規約を効かせる同じ機能のまとまりとして扱える。

### 確かめ方

knowledge はテストの仕組みを持たないため、テストは書かない。
実装した後に次を確かめる。

- フックのスクリプトを流し、出力の `additionalContext` に原則表と対応表の全ての行が入り、上限の文字数に収まっている
- 規約のファイルを読めない状態で流すと、何も注入せずに正常終了する
- `source` が `resume` の入力で流すと、何も出力しない
- プラグインを入れたセッションを開始すると、注入した文が文脈に入っている

| 文書の MCP（dev-docs）の SessionStart での配信元の一覧の注入 | dev-docs のプラグインが持つ（D-131） | #76 |
