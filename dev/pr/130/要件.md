# 要件

## 要望

[Issue #128](https://github.com/shuhei1101/knowledge/issues/128) の `## 決まったこと`（D-190〜D-200）に沿って、プロンプトの YAML の規約とスキーマを次のとおりにする。
キーの一覧と部品の説明は、Issue の `## 必読` の A-42 の「キーの定義」「部品（parts）とは」を正とする。

- `schemas/prompt.schema.yaml` を新設し、A-42 の「キーの定義」の全キーと、`kind` ごとの必須（`parts[].role` は `kind: llm` のとき必須、`output` は `kind: llm` だけ）を持たせる
  - 変数の定義は `type`・`description`・`enum`・`default`・`items`・`properties` と `required`（変数ごとの真偽値）・`example`・`source` を持ち、`items`・`properties` の下に同じキーで何段でも入れ子にできる
  - 知らないキーは検査で落とし、`x-` で始まるキーはどの階層でも許す
- `docs/rule/prompt-file.yaml` を次のとおりに修正する
  - 対象を LLM の呼び出しに加え、フックの注入文・MCP の instructions・ツールの description に広げる。置き場所はリポジトリ直下の `content/prompts/`、プラグインのフックが読む文はプラグインのルートの `content/prompts/` で、コードは読んで描画するだけにする（D-190・D-191）
  - 構造のキー表・部品のキー表・例を A-42 のキーに置き換える（`node` → `name`、`text.en`・`text.ja` → `parts[].texts[]`、`kind`・`lang`・`description`・`examples` の追加、変数の定義の入れ子）
  - 本文の決まり（実行時は `text.en`・`text.ja` の同期）を、トップレベルの `lang` の本文を注入し、言語の間で使う変数をそろえ同じ変更でほかの言語も修正する決まりにする（D-192・D-197）
  - 検査の項目に、トップレベルの `lang` の本文がどの部品にもあること・同じ部品で言語が重ならないこと・`example` が `type` に合うことを追加する
  - スキーマは各プロジェクトで書かず、1 行目のモードライン `# yaml-language-server: $schema=https://raw.githubusercontent.com/shuhei1101/knowledge/{タグ}/schemas/prompt.schema.yaml` で knowledge のスキーマを指し、変えたいプロジェクトだけコピーする（D-194・D-200）
- `docs/rule/claude-mcp.yaml` の `tool-schema-01` の「description | 関数の docstring（1 行）」を、`content/prompts/` の YAML（`kind: tool`）から登録のときに読む形に修正する（D-191）
- 変えたキーを前提にしている他の規約を、変えたキーに合わせる（`## 更新ドキュメント` の `python-llm-prompt-loader.yaml`・`claude-hook.yaml`）
- `rules.yaml` の `prompt-file` の paths（`**/prompts/**`・`**/prompt/**`）が、リポジトリ直下とプラグインのルートの `content/prompts/` に当たることを確かめる（書き換えは要らない見込み）

終わりの条件:

- `schemas/prompt.schema.yaml` で、A-42 の例 1（`kind: hook`）・例 2（`kind: llm`）が JSON Schema の検査を通る
- `prompt-file.yaml` と `claude-mcp.yaml` が D-190〜D-200 と食い違わない
