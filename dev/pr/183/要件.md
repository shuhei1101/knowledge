### 規約『資源の値の決め方』（移行）

`docs/rule/dev-resource-values.yaml` に作る。
移す元の [資源の値の決め方](https://github.com/shuhei1101/ai-monitor/blob/develop/dev/%E3%82%A8%E3%83%BC%E3%82%B8%E3%82%A7%E3%83%B3%E3%83%88%E9%81%8B%E7%94%A8/%E8%A6%8F%E7%B4%84/%E8%B3%87%E6%BA%90%E3%81%AE%E5%80%A4%E3%81%AE%E6%B1%BA%E3%82%81%E6%96%B9.md) の導き方・既定値・出典は値を変えずに移し、出典は `sources` に持つ。
「下流を待つタイムアウト」の行を、D-23 の待ちの種類で分ける。

| 待ちの種類 | 決め方 |
| --- | --- |
| 利用者・上流が応答を待つ要求（画面からの API・外部 API・MCP のツールの応答） | 実測の p99.9 + 50%。実測が 1,000 回に満たなければ公開仕様の値を使い、計測の作業を残す |
| 自分の処理の完了を待つだけの処理（反映作業のスクリプト・管理の操作・バッチ・CLI・テスト） | ハングの検知だけが役目。実測の 10 倍か外側の作業の上限。進み具合の出力があれば無出力の時間で止まったことを見る |
| 待つ相手がいない常駐の処理（ワーカーの待ち受け・キューの受信） | タイムアウトを置かない |

判定の手順は判定フローチャート『タイムアウトの決め方』へ置き、規約からは参照する。

### 判定フローチャート『タイムアウトの決め方』『フォールバックを置くか』（新規）

`docs/flowchart/flowchart-timeout.yaml`・`docs/flowchart/flowchart-fallback.yaml` に作る。
原稿 A-20 の判定と注記を、テンプレート『判定フローチャート』の書式に合わせる。

- ノードの `kind` を `script` → `start`、`dm` → `question`、`data` → `result` に置き換える
- 注記の表を `- **※N 用語名**: 定義` の項目に分ける
- 注記の中の『設定値の置き場所』・`fallback-01` は `id:` のリンクにする

### fallback-01 からの参照

コーディング全般の `fallback-01` に、判定フローチャート『フォールバックを置くか』へのリンクを追加する。
既存の 2 行の文言は変えない。

### 規約『VS Code 拡張機能の配布』（新規）

`docs/rule/dev-vscode-extension-distribution.yaml` に作る。

| 項目 | 決まり |
| --- | --- |
| バージョン | 拡張機能のコード（`package.json` の `contributes` を含む）を変えた PR で、`package.json` の `version` を上げる |
| .vsix | タグ（`vscode-v{X}.{Y}.{Z}`）で CI が .vsix を作り、そのタグの GitHub Release に添える |
| 公開 | Marketplace・Open VSX へ公開する。自動にできる公開先は CI で、できない公開先は手動 |
| 入れ替えの依頼 | 公開が自動でない間は、反映作業で .vsix を作り、利用者に `code --install-extension` での入れ替えを依頼する |
| ID | 公開した後に `publisher.name` を変えない |

対象が VS Code 拡張機能だけで、Claude プラグインは規約『Claude プラグインルール』の `no-version-01`（manifest に version を置かない）に従うことを概要に記載する。

### rules.yaml の行

`未確定`: 規約『資源の値の決め方』と判定フローチャート『タイムアウトの決め方』を当てる glob（決める段: ドキュメント修正）

rule-inject の索引は本文の照合を持たないため、値を書く場面はファイルのパスで当てる。
`.py` の編集で当たる規約は今 12KB あり（コーディング全般・設計原則・Python のコメント）、規約『ルール索引への登録』の 1 ファイル 10KB を既に超えている。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 値を置くファイルに絞る（設定ファイル・`shared/constants.py`・`shared/settings.py`・`integrations/` の下・反映作業のスクリプト・CI のワークフロー） | glob が狭く、合計の量の基準に収まる | 絞った外のファイルに書いた値には案内が出ない |
| B | コードの拡張子全体（`**/*.{py,ts,tsx,js,jsx,mjs}`） | 値を書く全てのファイルに出る | 1 ファイルの編集で当たる量の基準を超える |
| C | 載せず、タグと `aliases` で案内する | 注入の量が増えない | D-24 の「rules.yaml の索引で案内する」に反する |

推奨: A

ai-monitor#3151 の 120 秒は反映作業のスクリプトの定数で、A の当て先に入る。B は強制注入の基準を満たさない。

判定フローチャート『フォールバックを置くか』は `fallback-01` から参照し、コーディング全般の行（コードの拡張子全体）で案内されるため、行を追加しない。

`未確定`: 規約『VS Code 拡張機能の配布』の行の要否と glob（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 拡張機能に固有のファイルに当てる（`**/.vscodeignore`・`**/vscode/package.json`・`**/.github/workflows/vscode-*.yml`） | バージョンを上げ忘れる場面（拡張機能の編集）で案内が出る | 拡張機能を直下に置くリポジトリの `package.json` には当たらない |
| B | 載せず、タグと `aliases`（`VS Code 拡張機能`・`vsix`）で案内する | 注入の量が増えない | コードだけを変えた PR で案内が出ず、今回の上げ忘れが残る |

推奨: A

上げ忘れは読まずに編集すると後から直す手間が掛かり、強制注入の基準の 1 つ目に当たるため。

### 共通

- 新しい文書のタグは判定フローチャート『タグの付与』で付け、`rev` は 1、`last_reviewed` は作った日にする
- 改めた `dev-coding-general` の `rev` を 1 つ上げ、`last_reviewed` を変えた日にする
- 変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）
