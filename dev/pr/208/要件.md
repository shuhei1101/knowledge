### #189: React の設定ファイルへの案内

`rules.yaml` に次の行を追加する。

| 規約 | 適用するファイル |
| --- | --- |
| 『Tailwind』（`react-core-tailwind`） | `**/frontend/src/shared/styles/*.css` |
| 『ビルド構成』（`react-core-build`） | `package.json`・`tsconfig.json`（適用の方法は下の `未確定`） |
| 『ESLint・Prettier・tsconfig』（`react-devtools-lint-format`） | `**/eslint.config.js`・`tsconfig.json`（適用の方法は下の `未確定`） |

- PR #204 は 3 件を強制注入の 4 つの基準を「満たさない」と判定し、`name`・`inject_when` で案内している。規約『ルール索引への登録』の 4 つの基準で判定し直し、基準ごとの判定を `文書.md` に記載する
- 追加した後、rule-inject の MCP の索引のチェックで、読めないエントリ・実在しない `rule`・ヒットしない `paths` が 0 件であることを確認する

`未確定`: リポジトリの直下に配置する `package.json`・`tsconfig.json` の適用の方法（決める段: ドキュメント修正）

規約『ビルド構成』の `root-01` は `package.json` と各ツールの設定をリポジトリの直下に配置すると定めるため、`frontend/` のフォルダで絞れない。
rule-inject の索引は、ファイルの中身やリポジトリの構成で絞るキーを持たない（`paths`・`exclude`・`tools`・`args`・`on`・`read_by`）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `**/package.json`・`**/tsconfig.json` に適用し、`exclude` で `**/node_modules/**` を除外する | React のプロジェクトの直下の設定を編集するときに案内される | React でない Node のプロジェクト（VS Code の拡張など）でも案内される |
| B | 適用せず、今の `inject_when`（React・tsx・jsx・Vite）の案内のままにする | React でないプロジェクトに適用されない | 設定ファイルの編集で案内されず、#189 の事象が残る |

推奨: A

規約 2 件は 2〜3KB で、1 ファイルの編集で適用される合計 10KB に収まる。React でないプロジェクトに適用されても参照する量が小さく、案内されない不具合のほうが手戻りが大きい。

### #199: 画面の状態の保持先とスクロール位置

話し合いの調査 R-7（`/mnt/c/Users/shuhe/repo/tmp/何でも会話/.mindstella/docs/R-7.md`）の案を元に、出典を確認してから記載する。

| 対象 | 変更 |
| --- | --- |
| 判定フローチャート『画面の状態の保持先』（新規） | スタックによらない保持先の判定。共有・ブックマーク → パス／クエリ、端末をまたぐ → サーバー、端末ごとの好み → localStorage（最初の描画で要るなら Cookie）、そのタブで離れて戻ったとき → 履歴の項目ごとならルーターの機能か history.state、そうでなければ sessionStorage、再読み込みを越える → sessionStorage、それ以外 → メモリ。機密は URL と Web Storage に配置しない |
| 規約『入力と文言』の `state-retention-01` | スクロール位置の行を、ページ全体（ルーターの機能・履歴の項目ごと）とページの中のスクロール領域（領域ごとのキー）に分ける。別の画面から入り直したときに戻したいもの（最後のタブ・絞り込み）の行を追加し、URL に値があれば URL を優先し、sessionStorage の値を使ったときは URL に `replace` で書き戻す。機密の行を追加する |
| スクロール位置とタブの切り替えの決まり（新規の項目） | ページ全体はルーターの機能、ページの中の領域はキーを付けて復元し、中身が変わる領域はキーに項目の ID とタブを含める。保存は移動の前・タブを切り替える前・`pagehide`、復元はデータを描画した後。`history.scrollRestoration` を自分で変更しない・`unload` を使わない・スクロール位置を URL に出さない・中身が大きく変わった一覧は戻さない |
| 規約『URL の状態』の `overview` | 「戻る / 進む・リロードでの復元」は同じ履歴の項目に戻ったときだけと記載する。スクロール位置は URL に配置せず、TanStack Router の `scrollRestoration` と `data-scroll-restoration-id` を使用する |
| 判定フローチャート『React の状態の置き場所』の `q2`・`q8`・※1 | `q2` を共有・ブックマークで同じ表示にしたい値かの判定にし、戻ってきたときの復元を判定フローチャート『画面の状態の保持先』へ分ける。`q8` の「リロード後も保持する」に、sessionStorage と localStorage を選ぶ分岐を追加する。※1 にスクロール位置を URL に出さないことを追加する |

- タブ・絞り込み・並べ替えは、戻る・進むで 1 つずつ戻るため URL に持つのを続ける（R-7 の利用者の考えへの所見）
- 出典は Issue の `## 参考資料` を確認し、確認できたものを文書の `sources` に記載する

`未確定`: スクロール位置とタブの切り替えの決まりの配置先（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 規約『入力と文言』の `状態の保持` のグループに項目を追加する | 保持先の表とスクロール位置の決まりを同じ所で参照できる。`overview` が既に「画面の状態をどこに保持するか」を対象にしている | 『入力と文言』が長くなる |
| B | 新しい規約（例: `ui-scroll-restoration`）を作る | 規約の名前から見つけやすい | 状態の保持の決まりが 2 つの規約に分かれる |

推奨: A

同じ保持先の判断の一部で、分けると保持先の表とスクロール位置の決まりが食い違ったときに気づけない。
