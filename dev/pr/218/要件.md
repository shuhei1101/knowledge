# 要件

## 要望

`schemas/meta.schema.yaml` の最上位の `x-rules` に、ツールの引数の制約を持たせるキーの値を JSON Schema の一部で記載させる決まりを追加する。
メタスキーマは全てのスキーマに当たるため、どのスキーマでツールの引数の制約を持たせても同じ記法になる。

| 場合 | 記法 |
| --- | --- |
| 引数は自由 | キーを省く |
| 引数の一部が必須 | `required: [character_id]` |
| 引数の一部が任意 | `properties` に記載し、`required` に入れない |
| 引数の値を決める | `kind: {const: comment}` |
| 引数の値を候補から選ばせる | `kind: {enum: [comment, note]}` |
| 引数の値の書式だけ決める | `segment_id: {pattern: "^seg-"}` |
| 記載しない引数を指定させない | `additionalProperties: false` |

記載しない引数は、JSON Schema の既定と同じく任意にする。
共通の型（`$defs`）は追加しない。
今のこのリポジトリのスキーマに、ツールの引数の制約を持つキーが無く、型を参照する先が無いため。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `schemas/design/common.schema.yaml` の `$defs` への、引数の制約の共通の型の追加 | 今のこのリポジトリのスキーマに、ツールの引数の制約を持つキーが無い。キーを追加する作業が、そのキーの値の型として作る（判断はレビューで確定する） | 予定なし |
| `rules.yaml` の `tools`・`args`（規約『ルール索引への登録』） | rule-inject の索引の書式で、knowledge のスキーマが決めない | 予定なし |
| aituber の手順のページの `tools[].args` の書き換え | このリポジトリの外の作業で、aituber 側が取り込む | 予定なし |
