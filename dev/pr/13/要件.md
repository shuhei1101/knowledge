# 要件

## 要望

プロンプトのファイル（`**/prompts/**`・`**/prompt/**`）を触るときに当たる規約を、1 ノード 1 枚の YAML の形で新しく作り、今の『プロンプト執筆』『プロンプトローダー』をこの形に合わせる。

- 新しい規約のページを `dev/コーディング規約/prompt/` に置き、直下の `rules.yaml` に `paths` を `**/prompts/**`・`**/prompt/**` にした行を載せる
- 規約に書く決まり
  - 1 ノード（LLM の呼び出し 1 種類）に YAML 1 枚。`prompts/{id}.yaml` を平らに並べ、サブフォルダを作らない
  - 1 枚の中に、メタデータ（`id`・`node`・`tags`・`vars`〔変数の型と必須〕・出力の形）と部品の配列 `parts` を持つ。部品は `id`・`role`・`when`（使う条件）・`text.en`（英語の本体）・`text.jp`（日本語のミラー）を持つ
  - 本文は YAML のブロックスカラーに Jinja2 で書き、未定義の変数はエラーにする（StrictUndefined）
  - 実行時に読むのは `en` だけで、`jp` は人が読むためのミラー。`en` を直したら同じ変更で `jp` も直す
  - 形はスキーマの YAML（例 `prompts/_schema.yaml`）で定義し、`vars` に無い変数を本文で使っていないか・`en` と `jp` がそろっているかを検査する。規約にはキーと検査の内容だけを書き、`_schema.yaml` は各プロジェクトが書く（Knowledge にスキーマの雛形を置かない）
  - 字数・件数などの値はプロンプトに書かず、変数で渡す
  - 日本語でしか書けない中身（キャラクターの語尾・話し方）は入力の値として渡す
  - 更新の MCP の口があるプロジェクトでは、YAML を直接編集せず MCP から更新する
  - Markdown を残して YAML でメタデータを外付けする形と、全部を 1 枚の YAML にする形は採らない
- 『プロンプト執筆』（部品ごとの `.j2`・`.md`、`.jp.*` のミラー、`index.yaml` の `parts`・`mirror_of` で組み立てる形）は新しい規約に置き換えて消す
- 『プロンプトローダー』は、`prompts/{id}.yaml` を読み、`when` に当たる部品の `text.en` を Jinja2 で組み立てる形に書き直す
- 今の形（`.j2`・`.md` の部品・`content/prompts/index.yaml`）を前提にした記述と索引の行を、新しい形に合わせる

## 影響するユースケース

なし（コードを持たず、ユースケースを持たない）。
