# 要件

## 要望

規約『文章の追記』の確認の表の出典列から、読み手が元の資料を辿れるようにする。

- 確認の表の前に、出典の略号の定義を 1 行で置く。書き方はコーディング規約 `ui/` の各ページ（例: [操作とアクセシビリティ](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/ui/%E6%93%8D%E4%BD%9C%E3%81%A8%E3%82%A2%E3%82%AF%E3%82%BB%E3%82%B7%E3%83%93%E3%83%AA%E3%83%86%E3%82%A3.md)）の「出典の略号は … （リンクは `## 出典`）。」に揃える
- ページの末尾に `## 出典` の節を置き、略号ごとに資料へのリンクを並べる
- 略号と資料は、行を足した [shuhei1101/ai-monitor#1713](https://github.com/shuhei1101/ai-monitor/issues/1713) の本文の定義と `## 出典` のとおりにする

  | 略号 | 資料 |
  | --- | --- |
  | A | [Anthropic: Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) |
  | C | [Claude Code: Best practices](https://code.claude.com/docs/en/best-practices)（Write an effective CLAUDE.md） |
  | P | [Anthropic: Prompting best practices](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) |
  | GT | [Google Technical Writing One](https://developers.google.com/tech-writing/one) |
  | T | [textlint-rule-preset-ja-technical-writing](https://github.com/textlint-ja/textlint-rule-preset-ja-technical-writing) |

- 出典列の `Claude共通.md`（2 行）を外す
  - このリポジトリに `Claude共通.md` は無く、ai-monitor の `dev/コーディング規約/claude/Claude共通.md` からも該当の記述は規約『文章の追記』へ移っていて、辿れる先が無い
  - 外した後の出典列は、「実装のコード例」の行が `A`、「同じファイルの中で同じ説明を繰り返していないか」の行が空欄になる（出典の無い他の行と同じ）

出典の略号を持つ他のページ（`dev/コーディング規約/ui/` の 5 件）は、どれも略号の定義と `## 出典` を持ち、同じ型の逸脱は無い。

## 影響するユースケース

なし（コードを持たず、ユースケースを持たない）。
