# React の規約・設計原則を新設して next/ を索引から外し、MCP・YAML の規約に書き込みの作業ツリー・常駐サーバー・設定の決まりを追加する

## 概要

フロントエンドを React で書く人が、ビルド・フォルダ構成・状態の置き場所・採用するライブラリ・キーボード操作の実装を規約から読めるようになり、Next.js 前提の規約が React のリポジトリへ注入されなくなる。
コードを書く人が、言語共通の設計原則とデザインパターンを規約から読めるようになる。
MCP サーバーと設定の YAML を作る人が、書き込む作業ツリー・常駐サーバーの起動と管理・MCP に届かないときの扱い・設定の形と置き場所・共有するスキーマの正本・設定の移し替えを規約から読めるようになる。

## 背景

[Issue #88](https://github.com/shuhei1101/knowledge/issues/88) の要望で、子の [#79](https://github.com/shuhei1101/knowledge/issues/79) と [#74](https://github.com/shuhei1101/knowledge/issues/74) を 1 つの作業 PR で対応する。

- #79: 各リポジトリのフロントエンドをバニラ TS から React へ移す（各リポジトリの移行の Issue は後続）。knowledge には React の規約が無く、Next.js 前提の `next/`（86 件）とバニラ TS 前提の `html/` しか無い。`next/` の 86 件のうち 74 件は当たるファイルが 0 件で、残りは mdmark・alias-inject のテスト・Dockerfile・stories に誤爆している。言語共通の設計原則も無く、Python の文書どうしで YAGNI の扱いが逆になっている。knowledge のワークスペース `tmp/react移行計画` で決めた
- #74: MCP と YAML の前半の決定は [#71](https://github.com/shuhei1101/knowledge/pull/71) までに規約へ入った。後半に dev-docs の設計として決めたうち、どのプロジェクトの MCP・YAML にも当てはまる決まり（書き込みの作業ツリー・常駐サーバー・設定の形と置き場所・スキーマの正本・設定のバージョン）が規約に無い。knowledge のワークスペース `tmp/mcpベストプラクティス検討` で決めた

対象の規約は [#64](https://github.com/shuhei1101/knowledge/pull/64)（[#44](https://github.com/shuhei1101/knowledge/issues/44)）で `docs/rule/*.yaml` へ移っている。
