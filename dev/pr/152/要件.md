# 要件

## 要望

`rev` は書き込む側（エージェント・人）が 1 つ上げる、と規約『ドキュメント管理』と共通のスキーマに記載する。
dev-docs の `write_docs` に `rev` を増やす機能を求める Issue は起票しない。

- dev-docs は配信元を問わず使う汎用のツールで、`rev` を持たない。`write_docs` の `expected_version` は文書の中身から作るバージョン（`search_docs` の `version` 列の値）で、`rev` とは別
- `rev` は knowledge のスキーマが定めるキーで、これまでの作業 PR（[#110](https://github.com/shuhei1101/knowledge/pull/110)・[#112](https://github.com/shuhei1101/knowledge/pull/112)・[#114](https://github.com/shuhei1101/knowledge/pull/114)）も書き込む側が上げてきた

変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）。

- 規約『ドキュメント管理』（`docs/rule/dev-document-management.yaml`）の `metadata-01` の `rev` の行の「書き込みのツールが付ける」を「書き込む側が 1 つ上げる」に修正する
- 共通のスキーマ（`schemas/common.schema.yaml`）の `rev` の `description` の「書き込みのツールが付ける。」を、同じ内容に修正する
- 規約『ドキュメント管理』の `rev` を 1 つ上げ、`last_reviewed` を変えた日にする

終わりの条件:

- `docs/`・`schemas/` に、`rev` を書き込みのツールが付けるとする記述が無い
- 全ての文書の検査（`scripts/check_all.py`）が通る

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| dev-docs の `write_docs` が `rev` を増やすようにすること | dev-docs は配信元を問わない汎用のツールで、knowledge のスキーマのキーを持たない。規約の記述を挙動に合わせる | 予定なし |
| 規約『YAML』（`docs/rule/dev-yaml.yaml`）の `mcp-write-04` の「`expected_version`（`rev`）」 | dev-docs の `expected_version` は文書の中身から作るバージョンで `rev` ではない。`mcp-write-04` は書き込みの照合の単位（項目ごと）を定める決まりで、今回の要望（`rev` を誰が上げるか）とは目的が違う | [#153](https://github.com/shuhei1101/knowledge/issues/153) |
