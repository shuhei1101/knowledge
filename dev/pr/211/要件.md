# 要件

## 要望

`schemas/` のスキーマのフロー形式（`[...]`・`{...}`）を全ての文書の検査の違反にし、既存のスキーマの違反をブロック形式へ書き直す。

| 項目 | 要件 |
| --- | --- |
| 既存の違反の書き直し | `schemas/design/common.schema.yaml`（24 件）・`schemas/design/component.schema.yaml`（2 件）・`schemas/word-list.schema.yaml`（2 件）のフロー形式をブロック形式へ書き直す。値の意味は変えず、`scripts/build_templates.py` が生成する `docs/template/` のテンプレートとの一致を保つ |
| 検査の対象 | `scripts/check_all.py` の yamllint の対象に `schemas/` の全てのスキーマ（`schemas/*.schema.yaml`・`schemas/design/*.schema.yaml`）を追加する |
| 検査のルール | `schemas/` のスキーマに、yamllint の `brackets`・`braces` の `forbid: non-empty` を適用する。`docs/` の文書・`dev-docs.yaml`・`rules.yaml` に適用するルールは変えない |
| 文の決まりの削除 | 検査を追加したら、`schemas/meta.schema.yaml` の最上位の `x-rules` からブロック形式の決まり（`フロー形式（{type: string, ...}）を使わず、ブロック形式で書く。`）を削除する（規約『ルール索引への登録』の `index-decision-01` の 2 つ目の基準） |
| 設計書 | インターフェース定義『全ての文書の検査.py』の yamllint の対象と設定の `constraint` を、追加した対象とルールに合わせて修正する |
| テスト | `schemas/` のスキーマのフロー形式が違反になり、`docs/` の文書のフロー形式は違反にならないことを検査のテストで確認する |

### `schemas/` に適用する yamllint の設定

`scripts/lint/` に `schemas/` 用の設定 `.yamllint-schemas.yaml` を追加し、`brackets`・`braces` の `forbid: non-empty` だけを持たせる（`default` を継がない）。
`.yamllint.yaml`（`extends: default`）をそのまま `schemas/` に適用すると、`indentation` の違反が `schemas/design/` の 16 ファイルで 295 件出て、Issue の要望の範囲を超えるため。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| `schemas/design/` の `indentation` の違反（16 ファイル・295 件） | スキーマの決まりに無い書き方で、Issue の要望に含まれない。`schemas/` には `.yamllint-schemas.yaml` を適用し、`indentation` を検査しない | 予定なし |
| `docs/` の文書のフロー形式（164 件） | ブロック形式の決まりはスキーマのファイルの決まりで、文書には無い | 予定なし |
| `dev/テンプレート/` のスキーマのフロー形式（`共通.schema.yaml`・`部品設計.schema.yaml`・`フェーズ.schema.yaml` の 28 件） | AI Monitor のテンプレートのコピーで、コピー元と同じ内容に保つ。全ての文書の検査は `dev/テンプレート/` を検査しない | 予定なし |
