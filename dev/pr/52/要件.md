### 語の選び方（『文章の書き方』）

『文章の書き方』に `## 語の選び方` を追加し、次を載せる。
各決まりには、すべきことと理由を書き、悪い例と良い例の組を付ける。

- 基準: 文章でない所（UI ラベル・見出し・表の列名・項目名・論理名）は、IT の分野で定着した語（漢語でもカタカナ語でもよい）で書く。文章は自然な文でよいが、冗長な言い回しと話し言葉を避ける
- 定着の判断の拠り所: Microsoft の用語集・Android の日本語文字列・その技術の公式ドキュメントで使われている語
- 原則（理由つき）
  - 訓読みの動詞・一字の語をラベルに使わない（送る→送信、足す→追加、題→タイトル）
  - 比喩で呼ばない（口→インターフェース、形→スキーマ、段→レイヤー）
  - 定着したカタカナ語を和語に訳さない（コピー→写し、マーカー→印 の向きにしない）
  - 新しい呼び名を作る前に、辞書の語と既存の製品・方法論での呼び名を探す。和語を名詞にした造語（〜事・〜もの・〜さ）を作らない（決め事→検討事項、確からしさ→確度）
  - 値を 1 文字だけで、何の値かを添えずに出さない（「大」ではなく「影響度 大」）
- ドキュメントの語の対応表（避ける語 → 使う語。版→バージョン・節→セクション・題→タイトル・印→マーカー・口→インターフェース・形→スキーマ・段→レイヤー・写し→コピー・足す→追加・送る→送信・消す→削除・直す→修正・問い / 答え→質問 / 回答 など）
- 判定フローチャート『語の選び方』へのリンク

既存の確認の表の行（「同じものを別の言葉で呼んでいないか」「冗長な言い回し（することができる・を行う）を使っていないか」）と同じ内容は、`## 語の選び方` に繰り返さない。

`rules.yaml` で『文章の書き方』を当てる範囲は、今の範囲（`**/*.md` と、コメント・本文を書く MCP ツール）のまま改名する。
確認の表の大半は Markdown の文章向けで、コードに当てても読み手の動きが変わらない行が多い。

### 識別子の言語（『コーディング全般』）

`dev/コーディング規約/dev/コーディング全般.md` に、コードの識別子・Enum の値・定数を英語で書く決まりを、悪い例と良い例つきで追加する。
識別子を書くのはコードのファイルで、『文章の書き方』の当たる範囲の外にあるため、コードのファイルに当たる『コーディング全般』に置く。

### 判定フローチャート『語の選び方』

- `dev/判定フローチャート/語の選び方.md` を新設し、評価の資料 A-2 の判定フローチャート（識別子か → 文章の中か → 対応表にあるか → 用語集・公式ドキュメントにあるか → 訓読みの動詞・一字の語・比喩か）を、規約『判定フローチャート』とテンプレート『判定フローチャート』の書式で書く
- `dev/判定フローチャート/README.md` の目次に行を追加する
- `rules.yaml` には載せず、『文章の書き方』からリンクする（『文章の書き方』と同じ範囲に当てると、毎回 2 ページが注入される）

### 画面に固有の型（『入力と文言』）

`dev/コーディング規約/ui/入力と文言.md` の `## 文言` に次を追加する。
既存の行（「ボタンは起きることを動詞で書く」「同じ概念は最後まで同じ言葉で呼ぶ」）と同じ内容は繰り返さない。

- UI の操作の語の対応表（R-4 の英語の操作語と推奨の語・避ける語。Submit→送信、Add→追加、Delete→削除、Edit→編集、Cancel→キャンセル、Retry→再試行 など）
- 一般の Web アプリと同じ形式的な語にする（やわらかさを狙った言い換えをしない。直す→修正、消す→削除。長い文言を短くする）
- 品詞の型: タブ・列名・見出し・状態は名詞、ボタンは操作語、説明文は敬体で述語まで書く
- ボタンの書式: 漢語は「する」を省き、目的語は「を」でつなぐ（追加・権限を追加）。画面タイトルは名詞（権限の追加）
- 状態名の型（未〇〇 / 〇〇中 / 〇〇待ち / 〇〇済み / 完了 / 要〇〇）
- 空の表示の型（一覧は「〇〇はありません。」、検索の 0 件は「該当する〇〇はありません。別の条件を試してください。」、値の欄は「なし」か「—」）
- トグルは、ラベルを変えないチェックボックスかスイッチにする
- メッセージの定型（エラーは「〜できませんでした」、意思の確認は「〜しますか?」）
- 長音は語末の -er / -or / -ar / -y に付ける（ユーザー・サーバー・メモリー）
- `## 出典` に追加した出典（Microsoft Japanese Localization Style Guide・SmartHR Design System・公用文作成の考え方・WAI-ARIA APG 等）を載せる
