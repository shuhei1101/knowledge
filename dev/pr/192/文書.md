## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| `description` の分割 | 17 件の `description` のうち、「何を書くか」を `description` に残し、決まりを `x-rules` へ 1 件 1 文で、良い例を `examples` へ、悪い例を `x-bad-examples` へ、機械で判定できる決まりを制約へ移す | キーの `title`・`$ref`・`x-` の表示用のキーと既存の `examples` の値は変えない |
| 機械で判定できる決まり | 制約を狭めたスキーマごとに、ai-monitor と knowledge の `dev/設計書/` の設計書へ当てる 1 回限りのコマンドを流し、ログを `テスト結果/` に置く | 既存の設計書が通らなくなるキーは文の決まりのまま `x-rules` に残す。ai-monitor の結果はログを取った時点のもので、CI の検査は変えない |
| スキーマの書き方 | 要件.md の `## 要望` のキーごとの書き方を、拡張したメタスキーマの各キーの `description`・`x-rules`・`x-bad-examples` に持たせる | 置き場所は `schemas/meta.schema.yaml` |
| テンプレートの文書の書式 | `template-template` の内容を `schemas/template.schema.yaml` の `description`・`x-rules` へ移し、`docs/template/template-template.yaml` を `delete_docs` で削除する | セクション一覧・記述例・補足の決まりは `items` のキーの `x-rules` に持たせる |
| `rules.yaml` | `template-template` の行の `rule` を `schemas/template.schema.yaml` にし、`**/schemas/**/*.schema.yaml` へ `schemas/meta.schema.yaml` を案内する行を追加する | 規約『ルール索引への登録』の基準に沿う |
| タグ | release が master へ入った後に、`design-schemas/v*` のタグがこの PR の変更を含むようにする | 反映作業『設計書のスキーマのタグの更新』 |
