# 要件

## 要望

`schemas/design/` の設計書のスキーマ（[#182](https://github.com/shuhei1101/knowledge/pull/182) で移した 17 件）で、キーごとの書き方の決まりと悪い例を 1 件ずつ持てるようにする。

| 項目 | 要件 |
| --- | --- |
| キーの役割 | `description` は「何を書くか」の 1〜2 文、`examples` は良い例、`x-bad-examples` は悪い例とその理由、`x-rules` は書き方の決まりの配列（1 件 1 文）、`pattern`・`enum`・`maxLength` などは機械で判定できる決まりを持つ（D-34） |
| キーの形の検査 | `x-rules`・`x-bad-examples` の形を CI の全ての文書の検査で確かめ、形が違うと違反として失敗させる |
| `description` の分割 | 17 件の `description` を上の役割に分ける。分けた後の `description` は全て 2 文以内になる |
| 意味の維持 | 分ける前の `description` の決まりは、`description`・`x-rules`・`x-bad-examples`・機械で判定できる制約のどれかに残す |
| 機械で判定できる決まり | 文の決まりのうち機械で判定できるものを制約へ移す。knowledge の `dev/設計書/` の全ての設計書が検査を通ったままにする |
| テンプレート『テンプレート』 | YAML のスキーマの書き方（各キーの `title`・`description`・`examples`・`x-rules`・`x-bad-examples`・`x-` の表示用のキー）を定める文書に書き直す |

`未確定`: 今の書式（セクション一覧・記述例・補足）の扱い（決める段: ドキュメント修正）

スキーマから生成しないテンプレート（チェックシート・プロジェクト README 等）は、#163 の後も今の書式で残る。

| 案 | 内容 |
| --- | --- |
| A | テンプレート『テンプレート』に、YAML のスキーマの書き方と、スキーマを持たないテンプレートの書式の両方を持たせる |
| B | テンプレート『テンプレート』は YAML のスキーマの書き方だけにし、スキーマを持たないテンプレートの書式は別のテンプレートへ移す |

推奨: A

テンプレートを記載する人が読む文書が 1 つのままになり、`rules.yaml` の案内も増えないため。
