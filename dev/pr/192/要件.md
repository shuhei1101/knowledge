# 要件

## 要望

`schemas/design/` の設計書のスキーマ（[#182](https://github.com/shuhei1101/knowledge/pull/182) で移した 17 件）で、キーごとの書き方の決まりと悪い例を 1 件ずつ持てるようにする。

| 項目 | 要件 |
| --- | --- |
| キーの役割 | `description` は「何を書くか」の 1〜2 文、`examples` は良い例、`x-bad-examples` は悪い例とその理由、`x-rules` は書き方の決まりの配列（1 件 1 文）、`pattern`・`enum`・`maxLength` などは機械で判定できる決まりを持つ（D-34） |
| キーの形の検査 | `x-rules`・`x-bad-examples` の形を CI の全ての文書の検査で確かめ、形が違うと違反として失敗させる |
| `description` の分割 | 17 件の `description` を上の役割に分ける。分けた後の `description` は全て 2 文以内になる |
| 意味の維持 | 分ける前の `description` の決まりと例は、`description`・`x-rules`・`examples`・`x-bad-examples`・機械で判定できる制約のどれかに残す |
| 機械で判定できる決まり | 文の決まりのうち機械で判定できるものを制約へ移す。制約を狭めたスキーマに、ai-monitor と knowledge の `dev/設計書/` の設計書が通ることをログで示す |
| 書き方の正本 | YAML のスキーマの書き方（各キーの `title`・`description`・`examples`・`x-rules`・`x-bad-examples`・`x-` の表示用のキー）は、形を検査する拡張したメタスキーマの各キーに持たせる。テンプレートの文書の書式（セクション一覧・記述例・補足）は `schemas/template.schema.yaml` の `description`・`x-rules` に持たせる。`docs/template/template-template.yaml` は削除する（[確認ログ](./確認ログ.md)。Issue のやりたいことの 3 の成果物を変えた） |
