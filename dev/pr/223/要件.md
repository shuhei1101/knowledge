ai-monitor 側の削除と参照の付け替えは [shuhei1101/ai-monitor#3195](https://github.com/shuhei1101/ai-monitor/issues/3195) が受け持つ。

### 判定の基準と D-30

knowledge の [ドキュメント管理](https://github.com/shuhei1101/knowledge/blob/develop/docs/rule/dev-document-management.yaml) に次を記載する。

- 判定の基準: AI Monitor のエージェント・MCP のツール・ラベル・PR ドキュメントを前提にせず、手元のセッションやほかの開発でもそのまま使える決まりは knowledge に置く
- テンプレート（D-30）: プロジェクトが独自のテンプレートを持つのは、knowledge に無い固有の設計書の種類が要るときだけにする。knowledge の既存の種類を拡張したいときは、プロジェクトで持たずに knowledge へ追加する

### チェックシートの種類

knowledge にはチェックシートを配置する種類が無い。
[テンプレート: チェックシート](https://github.com/shuhei1101/knowledge/blob/develop/docs/template/template-checksheet.yaml) は置き場所を `docs/checksheet/checksheet-{対象}.yaml` と定め、`rules.yaml` にも `**/docs/checksheet/*.yaml` の `paths` があるため、#174 の判定表と同じ形で種類 `checksheet` を追加する（`schemas/checksheet.schema.yaml`・`dev-docs.yaml` の `documents[]` と `nav` のタブ・`description`・`instructions`・`CLAUDE.md`・アーキテクチャ図のサブシステム「文書」の役割）。

### 共通

- 新しい文書の ID は、種類のフォルダの既存の接頭辞（`dev-`・`convention-`・`flowchart-`・`decision-table-`・`checksheet-`）に揃える
- 新しい文書にタグ・`description` を付け、別の名前で呼ばれる文書には `aliases` を登録する（規約『タグと用語の登録』）
- 値を記載する場面・作業の場面で案内する文書は、`rules.yaml` に行を追加する（D-29。載せるかと `paths` は規約『ルール索引への登録』の強制注入の基準で決める）
- 改めた既存の文書の `rev` を 1 つ上げ、`last_reviewed` を持つ文書は変えた日にする
- 変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）
- 移した文書から AI Monitor の固有の単語（planner・tester・reviewer・task-planner・MCP のツール名・`確認:*` などのラベル・`dev/pr/`）を残さない

本文と A-21 で統合と決めており、knowledge の Storybook の規約は今は React だけが使用する。React 以外で Storybook を使用するプロジェクトが出たときに分ければ足りる。

終わりの条件:

- 「移す文書と移行先」の各行が、移行先の文書に移す範囲どおりに入っている
- 新しい文書と、統合した既存の文書に、AI Monitor の固有の単語が残っていない
- 『データフロー作成判定』『PoC要否』が判定表、『設計変更影響調査』が種類 `checksheet` の文書になっている
- 『ドキュメント管理』に判定の基準と D-30 が記載されている
