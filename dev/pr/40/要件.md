# 要件

## 要望

`rules.yaml` に、当てる範囲から一部を外すために広いパターンを細かく分けて列挙したエントリを残さない。
該当するエントリは、広いパターンを `paths` に、外す範囲を同じエントリの `exclude` に書く形へ書き直し、当たるファイルの範囲は変えない。

`origin/develop` の全エントリを突き合わせた結果、該当の候補は次の 1 つだけだった。

| 規約 | 今の `paths` | 列挙で外れている範囲 |
| --- | --- | --- |
| [ui/ドキュメントの部品.md](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/ui/%E3%83%89%E3%82%AD%E3%83%A5%E3%83%A1%E3%83%B3%E3%83%88%E3%81%AE%E9%83%A8%E5%93%81.md) | `**/dev/**/*.md`・`**/docs/README.md`・`**/docs/{はじめに,使い方,リファレンス}/**/*.md` | `docs/` の直下の `index.md`（サイトトップハブ）と、タブでないフォルダ（`_theme/`・`assets/` 等）の Markdown |

`未確定`: `ui/ドキュメントの部品.md` の `docs/` の列挙を `exclude` で書き直すか（決める段: ドキュメント修正の前の reviewer のレビュー）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `**/docs/**/*.md` を `paths` に、`**/docs/index.md`・`**/docs/_*/**`・`**/docs/assets/**` を `exclude` に書く | プロジェクトが `docs/index.yaml` の目次に足したタブのフォルダにも当たる | 外す範囲に挙げていないタブでないフォルダの Markdown にも当たる |
| B | 列挙のまま残す | ai-monitor の規約『ドキュメント管理』の対象（タブのフォルダと `README.md`）と同じ範囲を保つ | タブのフォルダ名を足すたびに列挙を直す |

推奨: A

ai-monitor の規約『ドキュメント管理』は、`docs/index.yaml` の目次に載るフォルダをタブとし、タブの名前を 3 つに限っていない。
部品はドキュメントサイトが描画する Markdown 全てで使えるため、外す側（サイトトップハブとテーマ・素材のフォルダ）を書くほうが規約の対象と合う。

規約『ルール索引への登録』の `## 載せるときの書き方` は `exclude` の書き方と例を既に持ち、揃える記述は無い。

## 影響するユースケース

なし（コードを持たず、ユースケースを持たない）。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 『ビルドレス原則』・『naming/ファイル名』等の、`frontend/` の中を拡張子ごとに並べたエントリ | 当てる拡張子を選ぶ列挙で、範囲から外すための分割ではない。拡張子をまとめるだけの書き換えは要望に含まれない | 予定なし |
| 『テンプレート/はじめに』・『テンプレート/リファレンス』・『事前確認』等の、ファイルを名指しで並べたエントリ | テンプレートの対象のページを選ぶ列挙で、範囲から外すための分割ではない | 予定なし |
| `ui/` の 8 規約で、同じ `rule` を 2 つのエントリに分けたもの | `**/*.md` を外す `exclude` を、画面設計の設計書のエントリに及ぼさないための分割（[#39](https://github.com/shuhei1101/knowledge/pull/39)）で、規約『ルール索引への登録』の書き方どおり | 予定なし |
| 広いパターンと、その内側のパターンを同じエントリに並べたもの（例: 『型ヒント』の `**/*.py*` と `**/shared/types.py*`） | 当たる範囲は変わらず、規約『ルール索引への登録』が重なりを許している | 予定なし |
| ai-monitor の `rules.yaml` の『ドキュメント管理』・`index.schema.yaml` の同じ `docs/` の列挙 | 別のリポジトリの索引。書き直すかは `未確定` の決着で決まる | 判断: `未確定` が案 A に決まったら起票する。レビューで確定する |
