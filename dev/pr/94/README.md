# 用語の登録と関連の張り方の判定フローチャートを追加し、規約『タグと用語の登録』『ドキュメント管理』から参照する

## 概要

文書を書く AI が、用語を登録するか・knowledge 共通かリポジトリ固有か・既存の用語と重なるかと、関連（`related`）を張るか・どの `type` か・片側か両側かを、判定フローチャートを順に当てて決められるようになる。

## 背景

[Issue #86](https://github.com/shuhei1101/knowledge/issues/86) の要望。
規約『タグと用語の登録』の用語の条件と、規約『ドキュメント管理』の関連の決まりは条件の一覧で、文書 1 つに向かって順に当てる形になっていない。
用語を knowledge 共通に置くかリポジトリ固有に置くかの判定は、規約に無い。
react移行計画の D-110 で、判定フローチャートは判定の対象を持つリポジトリに置き、dev-docs でタグを付けて配信し、rule-inject では注入しないと決めた。
エイリアスの判定フローチャートは [alias-inject#30](https://github.com/shuhei1101/alias-inject/issues/30)（[alias-inject#32](https://github.com/shuhei1101/alias-inject/pull/32)）で alias-inject に入っており、knowledge の規約からはこの PR で参照する。
タグのマスター（語彙）を持たないと決め直した（mcpベストプラクティス検討の D-169）ため、react移行計画の D-104 を前提にしない。
