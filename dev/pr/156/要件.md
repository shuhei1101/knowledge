# 要件

## 要望

判定フローチャートを 2 枚追加し、claude の規約 3 枚の該当箇所をその判定に合わせる。
2 つの判定は決める対象が違う（MCP・フックの渡し方と、エージェントに渡す文・処理の置き場所）ため、別の判定フローチャートにする。
図は[テンプレート『判定フローチャート』](https://github.com/shuhei1101/knowledge/blob/develop/docs/template/template-flowchart.yaml)のノード（`start`・`question`・`action`・`result`）で描き、A-11 の mdmark v0.9.0 のノード（`script`・`dm`・`data`）は使わない。

### MCP・フックの渡し方 判定フローチャート（`docs/flowchart/flowchart-mcp-hook-delivery.yaml`）

MCP・フックをセッションへ渡すとき、次の順で判定する（A-11）。

1. 起動する場所が決まらないセッション（手元の任意のフォルダ・プロジェクトを問わない全エージェント）でも使うか → YES: プラグインにして配る（例: dev-docs・rule-inject）
2. 起動する側のプログラム（AI Monitor・aituber のサーバーなど）が起動のコマンドを組み立てるか → YES: 起動の引数で渡す。MCP は `--mcp-config`（ほかを読ませないときは `--strict-mcp-config` も）、フック・許可・ツールの絞り込みは `--settings` のファイル
3. NO（人がリポジトリの中で起動する）→ リポジトリに `.mcp.json` と `.claude/settings.json`（`enabledMcpjsonServers` で承認）を置く

- A-11 の表「渡すものごとの置き場所」（MCP の接続先・フック・使い方の説明・起動時の処理・ツールの絞り込み・更新の反映を、プラグイン・起動の引数・リポジトリのファイルごとに並べた表）を項目に含める
- A-11 の「規約との関係」の表は、改めた後の規約が持つため含めない

### エージェントに渡す文・処理の置き場所 判定フローチャート（`docs/flowchart/flowchart-session-context-placement.yaml`）

エージェントに渡す文・処理を、SessionStart のフック・MCP の instructions・ツールでの取得のどれに置くかを、次の順で判定する（Issue のコメントの判定の順の案）。

1. 処理を実行するか（常駐のサーバーの起動・環境変数の設定・記録の後片付け）→ YES: SessionStart のフック
2. セッションごとに変わる事実か（使える配信元など）→ YES: ツールで取得させる（SessionStart で注入しない）
3. そのプラグインが MCP を持つか → YES: MCP の instructions
4. NO（MCP を持たないプラグインの常に守る決まり。例: rule-inject の新しいファイルの作り方）→ SessionStart で注入する

### 前提の訂正（R-6）

SessionStart の文脈の注入を instructions へ移すのは dev-docs（shuhei1101/dev-docs#92）と mdmark（shuhei1101/mdmark#293）だけで、この PR はそれらのプラグインを変えない。
rule-inject（MCP を rule-inject#36 で廃止）と knowledge（単語の選び方）の SessionStart の注入は残る前提で、判定フローチャートの 4 の結果（SessionStart で注入する）に当たる。

終わりの条件:

- `docs/flowchart/` に上の 2 枚の判定フローチャートがあり、テンプレート『判定フローチャート』のノードで描かれている
- `docs/rule/` に「常駐の MCP サーバーは、プラグインで配る」と、SessionStart の `additionalContext` に変わる事実を書くとする記述が無い
- `claude-mcp`・`claude-context-placement` から、それぞれの判定フローチャートを参照している
- 全ての文書の検査（`scripts/check_all.py`）が通る
