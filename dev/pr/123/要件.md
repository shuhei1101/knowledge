# 要件

## 要望

テンプレート『はじめに』『リファレンス』『チェックシート』の配置先・ファイル名・見出し・書式の記述を、規約『ドキュメント管理』（`docs/rule/dev-document-management.yaml`）の `置き方`（文書の正本は YAML）・`フォルダ`（`docs/` の下は種類だけのフォルダ、ファイル名は ID、参照は ID）に合わせる。
変更する記述以外の文言と、各テンプレートの項目の `id` は変えない（規約『既存文章の維持』）。

### テンプレート『はじめに』（`docs/template/template-getting-started.yaml`）

- `overview`: 対象ページ `はじめに/概要.md`・`はじめに/クイックスタート.md`、配置先 `docs/はじめに/概要.md`・`docs/はじめに/クイックスタート.md`、`docs/はじめに/index.yaml` への行の追加と README の再生成の記述を、決めた配置先（`docs/{種類}/{ID}.yaml`）に合わせる
- `section-list-01` と各セクションの項目: `## できること`・`## 前提`・`## 手順` などの H2 見出しと、`../使い方/...md`・`./クイックスタート.md` の相対リンクを前提にした記述例を、`items` の項目（`group`・`name`・`body`）と ID での参照（`[表示](id:{ID})`）に合わせる

### テンプレート『リファレンス』（`docs/template/template-reference.yaml`）

- `overview`: 対象ページ `リファレンス/API.md`・`リファレンス/コマンド.md`、配置先 `docs/リファレンス/API.md`・`docs/リファレンス/コマンド.md`、`docs/リファレンス/index.yaml` への行の追加と README の再生成の記述を、決めた配置先に合わせる
- `section-list-01`・`list-01`・`detail-name-01`: `## 一覧`・`## {名前}` の H2 見出しと、その下の `### 使い方` などを前提にした記述例を、`items` の項目に合わせる

### テンプレート『チェックシート』（`docs/template/template-checksheet.yaml`）

- `overview`: 置いたフォルダの `README.md` の目次へ 1 行追加する記述を、決めた配置先に合わせる
- `section-list-01`・`lead-01`・`check-items-01`: 1 行目の見出し `# {対象作業} チェックシート` と `## チェック項目` の H2 見出しを前提にした記述例を、メタデータ `name`・`description` と `items` の項目に合わせる

### rules.yaml

3 つのテンプレートの md の glob（`**/docs/はじめに/*.md`・`**/docs/リファレンス/*.md`・`**/dev/**/チェックシート/**/*.md`）を、決めた配置先に合わせる。

`未確定`: 3 つのテンプレートが定める文書の配置先（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 既存の種類 `guide` に置き、はじめに・リファレンス・チェックシートはタグ（`topic:`）で分ける | スキーマを増やさない。分類をメタデータで持つ `folder-02` に合う | `docs/guide/*.yaml` の glob が『セットアップ手順』と重なり、rules.yaml の glob をファイル名の接頭辞で分ける必要がある |
| B | 種類を新設し（`docs/reference/`・`docs/checksheet/` など）、`schemas/` にスキーマを追加する | rules.yaml の glob を種類のフォルダで分けられる | スキーマと種類が増え、今回の Issue の範囲を超える |

推奨: A

今回の Issue は記述を規約に合わせる範囲で、種類の新設はスキーマの設計を伴うため。
