# 要件

## 要望

ai-monitor の `dev/テンプレート/*.schema.yaml` のうち設計書の種別の 15 件を、1 スキーマ 1 ページの Markdown のテンプレートに組み立てて `dev/テンプレート/` に置く。

- 対象は ER図・アーキテクチャ図・インターフェース定義・シナリオ・テスト実行方法・データフロー・モジュール構成・外部API・外部ライブラリ・状態遷移・画面設計・設定・非機能要件・部品設計・開発コマンドの 15 件にする
- 写す元は ai-monitor の `origin/develop` の今の版にする
- 置き場所は `dev/テンプレート/{種別}.md`（`{種別}` はスキーマのファイル名から `.schema.yaml` を落とした名前）にする
- 各ページは、スキーマの項目の `title`・`description`・`examples` から組み立てる
  - ページの構成は `schema_page.py` の出力と同じにする（冒頭にスキーマの `description`、項目の表〔名前・title・型・必須・選択肢・制約・description・examples〕、最上位の `examples` の YAML）
  - 項目の表の description の列には、`description` の全文を `<br>` でつないで入れる
  - `$ref`（`共通.schema.yaml` の型）は解決して、指した先の項目をページの中に展開する
  - 組み立て方は ai-monitor の `src/ai_monitor/features/design_docs/schema_page.py`（項目の表）と `schemas.py` の `resolve_schema`（`$ref` の解決）に倣う
- ai-monitor 固有の記述を落とす
  - エージェント名（`planner`・`tester` など）と「エージェント」を主語にした記述（`モジュール構成`・`外部ライブラリ`・`開発コマンド`・`非機能要件` に当たる）は、主語を外した一般の書き方にする
  - このリポジトリに無い規約・判定フローチャートを名前で指す記述（規約『V字モデル』『不具合の報告』『資源の値の決め方』『開発時の従量課金APIの実行』、判定フローチャート『コマンドの書き先』『非機能要件のレイヤー』）は、名前の参照だけを外す。参照を外すと、このリポジトリに無い仕組みを指す文になるものは文ごと落とす
  - 書くツール（`write_design_doc_*`）・生成した Markdown（`dev/generated/`）・開発ドキュメントサーバー・定数の埋め込み（`!{名前}`）など、ai-monitor の仕組みを前提にした記述は落とす。その仕組みのためだけにある項目（テスト実行方法の `layers[].carry_over`）は項目ごと落とす
- `dev/テンプレート/README.md` の目次に 15 件の行を足す。直下の `rules.yaml` には載せない
- 組み立てた 15 件に、エージェント名・`inject-rules`・「監視対象」・「AI Monitor」・ai-monitor の Issue / PR へのリンクが残っていない

## 影響するユースケース

なし（コードを持たず、ユースケースを持たない）。
