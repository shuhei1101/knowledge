# ルール索引への登録の規約に MCP の引数・タグ・既読の当て方を追加し、MCP・YAML・タグの規約の範囲と例を追加する

## 概要

ルールの索引を書く人が、MCP ツールの引数・タグ・文書の種類・正規表現でルールを当てる書き方と、MCP の呼び出しで既読にする書き方を規約から読めるようになる。
MCP サーバーを作る人が、文書以外の状態の取得・業務のデータの追記、DB への追記、置き場所が分かれるタグの語彙、採否の前の候補のタグをどう扱うかを規約から読めるようになる。

## 背景

[Issue #70](https://github.com/shuhei1101/knowledge/issues/70) の要望で、子の [#45](https://github.com/shuhei1101/knowledge/issues/45) と [#68](https://github.com/shuhei1101/knowledge/issues/68) を 1 つの作業 PR で対応する。

- #45: rule-inject の [#31](https://github.com/shuhei1101/rule-inject/issues/31)（[#34](https://github.com/shuhei1101/rule-inject/pull/34)）で引数・タグ・文書の種類での照合と正規表現が、[#32](https://github.com/shuhei1101/rule-inject/issues/32)（[#38](https://github.com/shuhei1101/rule-inject/pull/38)）で MCP の呼び出しでの既読（`read_by`）が入った。規約『ルール索引への登録』には `paths` と `tools`（ツール名の glob）の書き方しか無い。knowledge のワークスペース `tmp/mcpベストプラクティス検討` の D-20・D-33・D-34 で決めた。
- #68: aituber の設計に規約『MCP サーバー作成ルール』『YAML』『タグと用語の登録』を当てたところ、範囲が読み取りにくい所と、正本の置き場所が分かれるプロジェクトでは守れない所が見つかった。aituber のワークスペースの D-372・D-374・D-376 で決めた。

対象の規約は [#64](https://github.com/shuhei1101/knowledge/pull/64)（[#44](https://github.com/shuhei1101/knowledge/issues/44)）で `docs/rule/*.yaml` へ移っている。
