### #45: ルール索引への登録（`docs/rule/dev-rule-index-registration.yaml`）

書き方の正は rule-inject の [索引の書式](https://github.com/shuhei1101/rule-inject/blob/develop/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/%E7%B4%A2%E5%BC%95%E3%81%AE%E6%9B%B8%E5%BC%8F.md) で、規約には索引を書く人の判断に要ることだけを書く。

- `overview`: 注入の条件に、`tools` に当たった MCP ツールの引数（`args`）を加える
- `載せるときの書き方` に次の項目を追加する
  - `args`: `tools` に当たった MCP ツールの引数の値で絞る。キーは引数の名前（子はドットで結ぶ）。タグ・文書の種類を引数で受けるツールも `args` で当てる。書いた全てのキーが当たるときだけ当たる（D-20・D-34）
  - 正規表現: `paths`・`exclude`・`tools`・`args`・`read_by` のパターンは `re:` で始めると正規表現（部分一致）になる。glob で書けないときだけ使う（D-34）
  - `read_by`: 文書を MCP ツールで読む運用では、そのルールを読む MCP ツールと引数を `read_by` に書き、呼び出しで既読にする。`tools`・`args` に当たっただけでは既読にならない（D-33）
- `載せるかの判断` か `載せるときの書き方` に、MCP で読み書きする文書の規約を、パスではなくツールと引数で当てるときの判断を書く
  - 文書を MCP ツールでだけ読み書きするプロジェクトでは、ファイルのパスに操作が来ないので `paths` は当たらない。読み書きのツールを `tools` に、文書の種類・タグを `args` に書く
  - ファイルを直接編集する経路も残るときは、`paths` も並べて書く

### #68 の 1: MCP サーバー作成ルール（`docs/rule/claude-mcp.yaml` の `サーバーとツールの単位`）

- `server-tool-unit-04`（操作の意味が種類に固有のものは別のツールにする）に、例を 2 つ追加する（D-372）
  - 記録を探すのではなく、ID などから今の状態を計算して返す取得（例: キャラクターの今の状態）
  - 種類ごとに中身と検査が違う、業務のデータの追記（例: ノードが書く行動の選択肢）
- 記録を探して引くツール（コメント・ログ・ノウハウなど）は、文書でなくても `search` と ID で取るツールにまとめる、と書く（D-372）

### #68 の 2: YAML（`docs/rule/dev-yaml.yaml` の `MCP からの書き込み`）

- `mcp-write-04`（`expected_version` の必須化）は YAML の正本の項目を書き換えるときの決まりで、DB への追記には当てない、と範囲を書く

### #68 の 3・4: タグと用語の登録（`docs/rule/dev-tag-term-registration.yaml` の `タグの語彙`）

- `tag-vocabulary-01`: 「タグの語彙は正本の置き場所（Git の YAML・DB など）ごとに 1 つにし、その中をグループで分ける」とする（D-374）
- `tag-vocabulary-04`: 未登録の候補は、採否が決まる前から検索・照合に使ってよい。外すと決めた候補は `deprecated` で振り替え先を指し、付いている項目を振り替える（D-374）
