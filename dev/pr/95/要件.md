### html の規約の仕分け

A-16 の `### html/` の表の判定どおりに仕分ける（D-30・D-31）。

タグ・絞り込み・保存ビューの規約は次のとおりに書く。
A-13 のタグのデータ設計（項目から id で参照・`a/b` の階層・語彙の登録）は書かない。

- タグは平らな文字列で、正規化（NFKC・大文字小文字）だけ行う。分類は `scope:` などの接頭辞の命名で表し、排他のグループ（1 つしか付けられない）は select のプロパティにする。`a/b` のパスは必要なアプリだけに許す（D-72・D-169）
- タグのマスター（説明・group・aliases・deprecated・未登録の検出）は持たない。D-73 は取り下げ（D-169）
- 絞り込みの入れ子はルートを含めて 3 階層・条件は合計 50 個まで、1 グループの結合子は 1 つ。簡単な絞り込みを既定の入口に残し、条件ビルダーへ移せるようにする（D-74）
- 保存ビューは、個人ビューは自動で保存し、共有ビューは明示的に保存する。未保存は点のマーカーで示す（D-75）。`ui-business-screen-elements` の「保存ビュー」の行と食い違わないようにする
- URL にはビューの id と保存ビューとの差分だけを載せ、2,000 文字を超えたらサーバーに一時保存して短い id にする。一時保存の置き場所が無い YAML のアプリは木を JSON のまま載せ、長いときは保存ビューにするよう案内する（D-76）
- テキストの検索構文は持たず、条件ビルダーと全文のキーワード検索の入力欄だけにする（D-77）
- 否定の演算子（is_not・has_none）は空の項目を含め、UI に「空の項目も含みます」と表示する。空を除くときは `is_not_empty` と組み合わせる（D-78）
- 条件ビルダーは react-querybuilder の shadcn registry を Base UI 版のプロジェクトで確かめ、合わなければ shadcn（Base UI 版）の部品で自作する。スキーマは RQB と相互に変換できる形にする（D-79）
- タグの文字列を文書の外に保存する所（画面のプリセット・保存ビューの条件）は、点検で 0 件になった条件を警告する（D-169）

### ui の既存の規約の整理

- 同じ規約に 2 本ずつあるエントリを 1 本にまとめ、A-16 の `### ui/` の表の判定どおりに glob を直す（`screen-design-principles`・`screen-division` は `**/設計書/画面設計/**`、`business-screen-elements`・`information-hierarchy`・`display-stability`・`document-parts` は任意、`operation-accessibility`・`supported-browser` は検査へ、`input-wording` は検査へ + 任意）
- 「検査へ」の規約は、jsx-a11y・`addon-a11y`・axe・browserslist・textlint の prh へ任せる旨を書いて rules.yaml から外し、文章は任意で読む規約として残す（検査の設定は各リポジトリの移行の Issue で入れる）
- プロジェクト固有の行（Issue 起票ボタン・claude-balancer の commit を出典にした行・`debug-fab` など。A-8）を ui・html の規約から削除する（D-39）
- OBS のブラウザソース（`ui-obs-browser-source`）とドキュメントの部品（`ui-document-parts`）を ui の外へ移し、参照元（`ui-supported-browser` など）の参照を直す（D-39）
- 移した・新設した ui の規約の名前で、`react-core-tailwind`・`react-keyboard-shortcut`・`react-keyboard-component` の「ui の規約に従う」の参照をリンクにする

`未確定`: OBS のブラウザソースとドキュメントの部品の移し先（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `docs/rule/` の中で接頭辞を変える（例: `obs-browser-source`・`doc-parts`）。メインのタグも ui から変える | 今のフラットな `docs/rule/` の置き方のまま、ui の規約の一覧から外れる | 接頭辞の種類が増える |
| B | 接頭辞は `ui-` のまま、メインのタグだけを変える | ファイル名と参照を変えずに済む | ファイル名で ui の規約に見え、D-39 の「別のフォルダへ」にならない |

推奨: A

D-39 は ui の規約と分けることが目的で、ファイル名の接頭辞が今の分類の単位になっている。
