# 要件

## 要望

道具が markdown を前提にするファイルを除き、knowledge の文書を YAML の正本へ移す。
従う規約は [ドキュメント管理](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/dev/%E3%83%89%E3%82%AD%E3%83%A5%E3%83%A1%E3%83%B3%E3%83%88%E7%AE%A1%E7%90%86.md)・[YAML ファイルの単位](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E5%88%A4%E5%AE%9A%E3%83%95%E3%83%AD%E3%83%BC%E3%83%81%E3%83%A3%E3%83%BC%E3%83%88/YAML%20%E3%83%95%E3%82%A1%E3%82%A4%E3%83%AB%E3%81%AE%E5%8D%98%E4%BD%8D.md)・[タグと用語の登録](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/dev/%E3%82%BF%E3%82%B0%E3%81%A8%E7%94%A8%E8%AA%9E%E3%81%AE%E7%99%BB%E9%8C%B2.md)・[YAML](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/dev/YAML.md) の `## スキーマ`。
移すのは形式・置き場所・メタデータだけで、規約・テンプレートの中身（決まりの文言）は変えない（規約『既存文章の維持』）。

### 置き場所

- 文書は直下の `docs/` 1 つに置き、その下は種類だけをフォルダにする（`docs/rule/`・`docs/template/`・`docs/flowchart/`・`docs/guide/`）。種類のフォルダの中はフラットにする
- 種類ごとに 1 ファイルで足りる種類（`changelog`）と、タグの語彙・用語集は `docs/` の直下に `{種類}.yaml` で置く（`docs/changelog.yaml`・`docs/tags.yaml`・`docs/terms.yaml`）
- スキーマは直下の `schemas/{種類}.schema.yaml` に置き、種類をまたぐ型（メタデータ・関連・項目）は `schemas/common.schema.yaml` の `$defs` に置く
- 移した後の `dev/` には `pr/` だけが残る

### ファイルの単位と小分け

- 今の md 1 つ（1 トピック）を YAML 1 ファイルにする（判定フローチャート『YAML ファイルの単位』の R5）
- ファイルの中は、今の md のセクション・サブセクションをそのまま 1 項目にせず、必要な部分だけを取得・注入できる単位の項目に小分けにする（[ユーザーの指示](https://github.com/shuhei1101/knowledge/issues/44#issuecomment-6381804904)）
- 各項目は `id`（ファイルの中で一意な英小文字のケバブケース）・`name`・`body`（markdown の本文）を持ち、まとまりは `group` で表す。見出しの並びは `group` と項目の並びで再現する
- 長い自由記述・表・コードブロック・mermaid の図は、項目の `body` に markdown のまま入れる

<!-- table: data -->

| 種類 | 項目の単位 |
| --- | --- |
| `rule`・`guide` | 最上位の箇条書き 1 つ（入れ子の子を含む）か、箇条書きの無いセクションの段落のまとまり 1 つ。直後の表・コードブロックは、それが説明する直前の項目の `body` に含める。行ごとに決まりを並べた表は表 1 つで 1 項目にする |
| `template` | テンプレートのセクション 1 つ（`### 記述例`・`### 補足` を含む） |
| `flowchart` | mermaid の図 1 つで 1 項目、図の下の脚注（`※n`）1 つで 1 項目。図は判定ごとに分けない |
| `changelog` | リリースの行 1 つ |

<!-- /table -->

- `group` は見出しの経路（最上位から親の見出しまで）を ` > ` でつないだ文言、`name` は項目の中身を表す 15 字程度の見出し語を書き起こす（元の文言は `body` にそのまま残す）
- `id` は `{group を英小文字のケバブケースにしたもの}-{2 桁の連番}`（例 `unit-test-01`）にする
- `# タイトル` の直後の見出しの無いリードは、先頭の項目（`id: overview`・`name: 概要`）の `body` にそのまま入れる。`description` はリードとは別に 1〜2 文で書く

### メタデータ

- 各ファイルは [ドキュメント管理](https://github.com/shuhei1101/knowledge/blob/develop/dev/%E3%82%B3%E3%83%BC%E3%83%87%E3%82%A3%E3%83%B3%E3%82%B0%E8%A6%8F%E7%B4%84/dev/%E3%83%89%E3%82%AD%E3%83%A5%E3%83%A1%E3%83%B3%E3%83%88%E7%AE%A1%E7%90%86.md) の `## メタデータ` の必須のキー（`id`・`kind`・`name`・`description`・`tags`・`status`・`visibility`・`rev`）を持つ
- `id` はファイル名と同じ英小文字のケバブケースのスラッグ（例 `python-testing-strategy`）にし、`name` に今の md の見出しを入れる
- `description` は今の md の冒頭のリードから 1〜2 文で書く。リードが無い文書は本文から書き起こす
- `visibility` は今 `docs/` にある文書を `public`、`dev/` にある文書を `internal` にする
- `rev` は全ファイル `1` から始める。`status` は全ファイル `current` にする
- 規約（`rule`）と手順（`guide`）は `last_reviewed` を持ち、移した日を入れる
- 今のフォルダの分類は、第 1 階層（`python`・`next`・`html` など）を `scope:{名前}`、第 2 階層（`testing`・`core` など）を `topic:{名前}` のタグで持ち、主題のタグに `main: true` を付ける。タグは `docs/tags.yaml` に登録し、`description` は「含める / 含めない / 例」で書く

### 参照

- 文書どうしの参照は ID で書き、パスで書かない
- 本文の中の他の文書へのリンクは `[{名前}](id:{文書の ID})` か、項目まで指すときは `[{名前}](id:{文書の ID}#{項目の ID})` にする
- 今の md のリンクのうち、従う必要がある文書への参照は `related` にも `when` つきで持たせる（関連の書き方は『ドキュメント管理』の `## 関連`）

### ルールの索引と参照元

- `rules.yaml` の `rule` を移した後の YAML のパスへ書き換える。`paths`・`tools`・`exclude`・`on` は変えない
- `rules.yaml` の `paths` のうち、knowledge 自体の文書に当てているもの（`**/dev/判定フローチャート/**/*.md` など）は、移した後の種類のフォルダ（`**/docs/flowchart/*.yaml` など）に当たるよう足す
- 直下の `CLAUDE.md`・`README.md` のリンクを移した後の置き場所に合わせる
- テンプレート『判定フローチャート』の、存在しない `index.yaml` の `summary` を参照する記述を、移した後の `description` を参照する記述に直す（展開の計画 A-13 の T-5）

### 確かめ方

- 全ての YAML がそれぞれの種類のスキーマに通る（`check-jsonschema --schemafile schemas/{種類}.schema.yaml docs/{種類}/*.yaml` が違反 0 件）
- `id:` で書いた参照と `related` の `to` が、全て実在の文書・項目の ID を指す
- 移す前の md の本文の文言が、移した後の YAML の `name`・`body` に全て残っている（見出し・表・コードブロックを含む）
- `rules.yaml` の全ての `rule` が実在のファイルを指す
