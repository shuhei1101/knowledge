# MCP の規約に、文書の MCP のプラグインの名前と、mdmark と YAML の正本・MCP の役割の分担を追加する

## 概要

文書の MCP のプラグインを作る人が、プラグインの名前の付け方と、mdmark と YAML の正本・MCP・開発ドキュメントサーバーのどれが何を受け持つかを、規約から読めるようになる。

## 背景

[Issue #59](https://github.com/shuhei1101/knowledge/issues/59) の要望。
knowledge のワークスペース `tmp/mcpベストプラクティス検討` の話し合いで決めた D-84（文書の MCP のプラグインの名前）と D-85（mdmark と YAML の正本・MCP の役割の分け方）が、規約に無い。
[#56](https://github.com/shuhei1101/knowledge/issues/56)（[#57](https://github.com/shuhei1101/knowledge/pull/57)）で `mcp.md` の `## 登録` にプラグインで配ること（D-82）とリポジトリごとに 1 つにすること（D-83）を入れたが、名前は決めずスコープ外にしていた。
mdmark の記述はポートの台帳の行だけで、YAML の正本・MCP との役割の分担は無い。
