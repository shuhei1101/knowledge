# 要件

## 要望

規約『YAML』（`docs/rule/dev-yaml.yaml`）の `## スキーマ`（`schema-01`〜`schema-09`）を別の文書へ切り出すかを判断し、切り出す場合は移して参照を修正する。

| 項目 | 要件 |
| --- | --- |
| 判断の基準 | 移し先が規約『ルール索引への登録』の強制注入の 4 つの基準（`index-decision-01`）を満たすかで判断する。満たさない文書へ移す場合は、`rules.yaml` に記載せずタグと `aliases` で案内する |
| 書き方の正本との分担 | [PR #192](https://github.com/shuhei1101/knowledge/pull/192) で YAML のスキーマの書き方の正本になった `schemas/meta.schema.yaml`・`schemas/template.schema.yaml` と、同じ決まりを 2 か所に記載しない |
| 機械で判定できる決まり | 移す決まりのうち、メタスキーマ・yamllint で判定できるものは検査へ移し、本文から削除する（`index-decision-01` の 2 つ目の基準） |
| 意味の維持 | `schema-01`〜`schema-09` の決まりは、移し先・規約『YAML』・検査のどれかに残す |
| 参照の修正 | `## スキーマ` を指す参照（`dev-yaml.yaml` の `inspection-01`、規約『プロンプトファイル』の `prompt-file.yaml` の `スキーマと検査の参照先`）を、移した後の配置先へ向ける |
| 切り出す場合に決めること | 移し先の文書の ID・名前、`rules.yaml` の当て先（glob）、規約『YAML』に残す参照 |

`未確定`: 切り出すか、切り出す場合の移し先（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 切り出さず、規約『YAML』に残す | 変更が無い | `schema-04` がメタスキーマを指すだけで、スキーマを書くときに規約『YAML』全体（約 20KB）を参照することになる。`rules.yaml` に記載が無いため、スキーマを書くときに案内されない |
| B | 新しい規約（ID・名前はドキュメント修正で決める）へ `schema-01`〜`schema-09` を移し、`rules.yaml` に `**/*.schema.yaml` で記載する | スキーマのファイルを書くときに必ず案内される | `schema-04` の書き方の決まりがメタスキーマと 2 か所に分かれる。`**/schemas/**/*.schema.yaml` には既にメタスキーマが案内されている |
| C | スキーマのファイルの書き方（`schema-02`〜`schema-06`）は、検査で判定できるものを検査へ移し、残りを `schemas/meta.schema.yaml` の `description`・`x-rules` へ移す。当てる範囲（`schema-01`）とリポジトリをまたぐ正本の決まり（`schema-07`〜`schema-09`）は規約『YAML』に残す | 書き方の正本が 1 か所になり、`rules.yaml` の既存の案内（`**/schemas/**/*.schema.yaml`）で案内される | `schemas/` の外に配置したスキーマのファイル（各プロジェクトの `dev/テンプレート/*.schema.yaml` など）には案内されない |

推奨: C

`schema-04` は既に `schemas/meta.schema.yaml` を指しており、書き方の決まりの正本をメタスキーマへ統一した [PR #192](https://github.com/shuhei1101/knowledge/pull/192) の方針と合う。
`schema-02`（JSON Schema 2020-12）はメタスキーマの検査で判定でき、移し先に文として記載する決まりは少ない。
