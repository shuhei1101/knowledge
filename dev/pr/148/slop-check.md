# slop-check

## 現状

なし（新設のサブシステム。アーキテクチャ図のサブシステムに slop-check を追加する）

## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| プラグインの定義 | マーケットプレイスの `plugins[]` に `slop-check` を追加し、PostToolUse のフックを 1 つ登録する | `plugins/slop-check/` に置く（要件.md） |
| フックの契機 | `matcher` を `Write\|Edit\|NotebookEdit\|mcp__.*` にし、対象の MCP ツールの判定はフックが持つ。登録するコマンドは `hooks/post-tool-use/` に置く | 対象の MCP ツールはインターフェース定義『書き込んだ中身の照合』の制約「対象のツール」 |
| 中身の取り出し | Write は `tool_input.content`、Edit は `tool_input.file_path` の修正後のファイル全体、NotebookEdit は `tool_input.new_source`、MCP ツールは識別子のキーを除いた全ての文字列の値 | Edit で修正後のファイルを読めないときは `new_string` を調べる |
| 照合しない書き込む先 | 対応表の正本とコピーへの書き込みは照合しない | 対応表の行を追加するたびに全ての行が通知されるのを防ぐ |
| 照合 | 対応表の各行を、`pattern` があればその正規表現、無ければ `ng` の文字列で中身に当てる。ヒットした位置を含む文字列が `allow` に当たるときは除く | 1 回の書き込みで同じ行が複数ヒットしても、表には 1 行だけ出す |
| 通知 | ヒットした行があれば、要件.md の要望 3 の通知の文を `hookSpecificOutput.additionalContext` で返す。書き込みは止めない（`decision` を返さない） | 表の行は対応表の並びの順 |
| ヒットしないとき | 何も出力せずに終了コード 0 で終わる | |
| 異常 | 対応表が読めない・中身が取り出せない・入力の JSON が読めないときは、何も出力せずに終了コード 0 で終わり、理由を標準エラーに出す | 書き込みの結果を変えない |
| 実行の方式 | Python の標準ライブラリだけで書き、`python3`（端末の 3.12 を下限）で起動する。対応表は JSON のコピーを読む | インターフェース定義設計で確定（『書き込んだ中身の照合』の制約「対応表のコピー」）。書き込むたびに起動するため、uv の依存の解決を起動の時間に入れない |
| テスト | 単体: 照合・中身の取り出し・通知の文の組み立て。結合: フックに PostToolUse の入力の JSON を標準入力で与え、出力の JSON を確認する。E2E: 新規の単一 UC のシナリオ | |
