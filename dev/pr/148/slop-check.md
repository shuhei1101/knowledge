## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| プラグインの定義 | マーケットプレイスの `plugins[]` に `slop-check` を追加し、PostToolUse のフックを 1 つ登録する | 置き場所は要件.md の `未確定`（インターフェース定義設計） |
| フックの契機 | `matcher` を Write・Edit・NotebookEdit と、書き込む MCP ツールにする | 対象の MCP ツールは要件.md の `未確定`（インターフェース定義設計） |
| 中身の取り出し | Write は `tool_input.content`、Edit は `tool_input.file_path` の修正後のファイル全体、NotebookEdit は修正後のノートブックのセルの文、MCP ツールはツールごとに決めた引数の文字列 | Edit で修正後のファイルを読めないときは `new_string` を調べる |
| 照合 | 対応表の各行を、`pattern` があればその正規表現、無ければ `ng` の文字列で中身に当てる。ヒットした位置を含む文字列が `allow` に当たるときは除く | 1 回の書き込みで同じ行が複数ヒットしても、表には 1 行だけ出す |
| 通知 | ヒットした行があれば、要件.md の要望 3 の通知の文を `hookSpecificOutput.additionalContext` で返す。書き込みは止めない（`decision` を返さない） | 表の行は対応表の並びの順 |
| ヒットしないとき | 何も出力せずに終了コード 0 で終わる | |
| 異常 | 対応表が読めない・中身が取り出せない・入力の JSON が読めないときは、何も出力せずに終了コード 0 で終わり、理由を標準エラーに出す | 書き込みの結果を変えない |
| 実行の方式 | 書き込むたびに起動するため、起動の時間を書き込みの待ちに入れない方式にする。Python を `uv run --script` で起動するか、依存の無い Python の標準ライブラリだけで書くかは、モジュール構成設計で決める | `未確定` |
| テスト | 単体: 照合・中身の取り出し・通知の文の組み立て。結合: フックに PostToolUse の入力の JSON を標準入力で与え、出力の JSON を確認する。E2E: 新規の単一 UC のシナリオ | |

`未確定`: 実行の方式（決める段: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | Python の標準ライブラリだけで書き、`python3` で起動する。対応表の YAML は JSON にしたコピーを読む | 依存の解決が無く、起動が速い | YAML を JSON にする工程が増える |
| B | `uv run --script` で起動し、`ruamel.yaml` で対応表の YAML を直接読む | 対応表を変換せずに読める | 書き込むたびに uv の依存の解決が走り、待ちが増える |

推奨: A

フックは書き込むたびに走るため、起動の時間が全ての書き込みの待ちに加わる。対応表のコピーを作る工程は、置き場所の案 A でも同じ工程で済む。
