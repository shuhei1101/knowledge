# 要件

## 要望

1. 対応表: 単語の対応表の新しい種類 `word-list` を追加し、`docs/word-list/word-list-ai-slop.yaml` とスキーマ `schemas/word-list.schema.yaml` を作成する（構造・キー・スキーマの抜粋は話し合いの A-47）
   - 1 行に `id`・`ng`・`ok`（配列、1 件以上）・`pattern`（Python の `re`）・`allow`・`note`・`examples.hit`・`examples.pass` を持つ
   - `ng` が漢字 1 文字の単語は、前後に漢字が続かないときだけヒットさせる（`(?<![㐀-鿿々])形(?![㐀-鿿々])`）。動詞は語幹の後ろに活用語尾を並べる
   - `ng` が漢字 1 文字の行と、`pattern` を持つ行は、スキーマで `pattern`・`examples` を必須にする
   - 正規表現の記載の決まりは、対応表の `description` とスキーマの `pattern` の `description` に記載する（規約にはしない）
   - 対応表の `description` に、NG の 2 種類（和語を使う・定着した外来語を和語に訳す）と、良くない一番の理由（AI が記載した文章だと一目で分かる）を記載する
   - 初回の行は A-48 の「初回に入れる単語」の 44 件に、「箱 → ノード」「推す → 推奨」の 2 件を加えた 46 件
   - `dev-docs.yaml` の `documents[]` に `word-list` の行を追加し、dev-docs の画面と文書の MCP から参照できるようにする
2. 対応表のテスト: knowledge の検査（`knowledge-checks` と `check_all.py`）で、`word-list` の文書の各行の `examples.hit` が全件ヒットし、`examples.pass` が 1 件もヒットしないことを確認する。通らない行は違反として返し、`write_docs` の書き込みと CI を止める
3. プラグイン slop-check: knowledge のマーケットプレイスに、今の `knowledge` プラグインとは別のプラグイン `slop-check` を追加する
   - PostToolUse で、書き込むツール（Write・Edit・NotebookEdit・書き込む MCP ツール）の中身を対応表で調べる。Edit は修正後のファイル全体を調べ、前からある単語も通知する
   - ヒットしたら書き込みを止めずに、次の通知を `additionalContext` で注入する。ヒットするたびに出す
   - 表にはヒットした単語の行だけを出し、OK は「・」でつなぎ、`note` があれば括弧で添える。列名は NG と OK
   - ヒットした位置を含む文字列が `allow` の文字列に当たるときは通知しない
   - 対応表が読めないとき・中身が取り出せないときは、何も注入せずに書き込みの結果を変えない

   ```text
   AI がよく使う単語（AI slop）が入っています。OK の単語に置き換えてください。
   NG の単語でないと意味が通らない理由があるときだけ、そのままにしてかまいません。

   | NG | OK |
   | --- | --- |
   | 直す | 修正 |

   まだ読んでいなければ、用途に合う規約を読んでください。
   - 文書・コメント: 規約『文章の書き方』
     mcp__plugin_dev-docs_dev-docs__search_docs（source: "knowledge", filter: {"field": "id", "op": "eq", "values": ["convention-writing-style"]}, view: "full"）
   - 画面の文言: 規約『入力と文言』
     mcp__plugin_dev-docs_dev-docs__search_docs（source: "knowledge", filter: {"field": "id", "op": "eq", "values": ["ui-input-wording"]}, view: "full"）
   ```

   - knowledge は dev-docs の配信元になっている（#51 は完了）ため、通知には MCP の行を出す
4. 今の注入の廃止: `knowledge` プラグインの SessionStart の注入（`hooks/session-start/inject-word-choice.sh`・`hooks/hooks.json` の行・`hooks/files.yaml` の行）を削除し、`knowledge` プラグインの description から注入の記述を削除する
5. 規約の修正

   - 『入力と文言』の概要から「語の対応表は textlint の prh に任せ、この規約の対応表は任意で読む。」の一文を削除する

   - 規約『文章の書き方』: `description`・`sources[].note` の `## 語の選び方`・概要・`group`（`語の選び方`・`語の選び方 > 原則`・`語の選び方 > ドキュメントの語の対応表`）・項目名（`文章でない所の語の選び方`・`語の選び方の原則表`・`ドキュメントの語の対応表`）・本文の判定フローチャートへのリンクの表示名
   - 判定フローチャート『語の選び方』（`flowchart-word-choice`）: `name`・`group`・フローの `title`・`※1 対応表` の `## 語の選び方` と「ドキュメントの語の対応表」

   - 使い方『プラグインの導入』: 注入の記述（注入の廃止で記述ごと修正する）
