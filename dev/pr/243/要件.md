### #228: AI slop の対応表とボタンの文言

エージェントが次の単語を記載したとき、プラグイン slop-check が置き換え先を通知する。
置き換え先は [shuhei1101/mdmark#394 の確認事項](https://github.com/shuhei1101/mdmark/pull/394#discussion_r4505603696) で決着済み。

| NG | OK | 対象の意味 | 例 |
| --- | --- | --- | --- |
| 閲覧者 | 読者 | - | 閲覧者に見せる → 読者に見せる |
| アクセシブルネーム | スクリーンリーダー向けの名前 | - | ボタンのアクセシブルネーム → ボタンのスクリーンリーダー向けの名前 |
| 〜の枠 | 〜ブロック | UI のまとまった表示。枠線の意味の「枠」は除く | 通知の枠 → 通知ブロック、読み込み中の枠 → 読み込み中のブロック |
| 〜を表示・〜を追加 | 〜表示・〜追加 | ボタンの文言 | 変更を表示 → 変更表示、コメントを追加 → コメント追加 |

- 対応表に上の 4 種の行を追加する。`pattern` は対応表の `pattern-rules-01` の記載方法に従う
- 各行の `examples` の `hit` にヒットすべき文を、`pass` に誤検出させない文（枠線の「枠」、文の中の「〜を表示する」）を記載し、`check_all.py` の検査に合格させる
- ボタンの行は、ボタンの文言として 1 単語で記載された値のときだけヒットさせる（`pattern-rules-01` の「表のセル・ラベル・分類の値のときだけ NG にする動詞」と同じ考え方）
- 対応表のコピー `plugins/slop-check/hooks/post-tool-use/word-list-ai-slop.json` を `scripts/build_word_list.py` で再生成する
- 規約『入力と文言』の `wording-term-format-02` のボタンの書式を、漢語の「する」と目的語の「を」を省く決まりへ修正し、例を「権限追加」にする。同じ規約のボタンの例（`wording-01` の「Issue を作成」、`wording-term-format-02` の「選択 n 件をコピー」）も「を」を省いた文言にする
- 追加する行にヒットする既存の記述（`docs/`・`schemas/` で、ui の規約の「〜の枠」と `next-backend-cache.yaml` の「次の閲覧者」）は、全てこの PR で修正する。ボタンの行にヒットする既存の記述は無い

対応表の行のキーは追加せず、スキーマ・`build_word_list.py`・`slop_check.py` は変更しない。

### #233: シンプルだけど凡庸でない見た目の決まり

画面の見た目を「シンプルだけど凡庸でない」ものにする決まりを、ui の規約とテンプレート『デザイン方針』に追加する。
特定の色や形状は決め打ちしない。
決まりの候補と出典は [shuhei1101/ai-monitor#2351](https://github.com/shuhei1101/ai-monitor/issues/2351) の本文の一案で、言い回し・数値は既存の規約と重複・矛盾しないように決める。

| 置き場所 | 追加する決まり・欄 |
| --- | --- |
| ui の規約（どのシステムにも適用する） | ワンポイントは 1 サイト 1 題材で、題材はそのシステム固有の物から取る。強い色は 1 つをワンポイントに決め、ほかは文字色と線で階層を作る。状態色は状態の表示だけに使用する。見出しと本文の大きさの対比を大きく取り、文字の大きさの段階は大・本文・小の 3 つまで。遊びはトップ・404・まれな操作にだけ配置する。自動で動く図は画面に入った時の 1 回だけで、止まった最後の状態だけで意味が通るようにする。図の向き・順序を示す動きは例外として認め、画面外とタブ非表示で止める・5 秒を超えて動くものに停止ボタンを付ける・動きを減らす設定では止まった図にする |
| テンプレート『デザイン方針』（システムごとに割り当てる） | サイトのワンポイントの題材・色・配置する場所。形状の味付け（角丸の大きさ・ボタンの形状・表の見た目・コールアウトの形状など、機能を変えずに見た目だけ変えられる部分）。色相に加えて明度・彩度の組み合わせを持ち、明暗の両方でコントラストを満たす色の候補 |

- 既存の規約と次のように突き合わせる
  | 既存の規約 | 突き合わせ |
  | --- | --- |
  | [情報の階層と見た目](https://github.com/shuhei1101/knowledge/blob/f82d8ad36e1bec0dd2176332d24f4da390c08bb0/docs/rule/ui-information-hierarchy.yaml) | 「強い色は操作・選択・状態にだけ使う」と「強い色は 1 つをワンポイントに」が食い違うため、どちらかの言い回しを修正して 1 つの決まりにする。「文字の階層は大きさ・太さ・濃さを組み合わせる」と「見出しと本文の対比」は重ねて記載せず、新しい規約から参照する。「使用しない型」（光る影・文字のグラデーション 等）は新しい規約で繰り返さず参照する |
  | [表示の安定](https://github.com/shuhei1101/knowledge/blob/f82d8ad36e1bec0dd2176332d24f4da390c08bb0/docs/rule/ui-display-stability.yaml) | 「動きは状態の変化と操作への反応にだけ使う」の例外として、図の向き・順序を示す動きを認める旨を参照で結ぶ |
  | [操作とアクセシビリティ](https://github.com/shuhei1101/knowledge/blob/f82d8ad36e1bec0dd2176332d24f4da390c08bb0/docs/rule/ui-operation-accessibility.yaml) | コントラストの基準（本文 4.5:1 等）と「動きを減らす設定に従う」は重ねて記載せず参照する |
  | [デザインスタイル規約](https://github.com/shuhei1101/knowledge/blob/f82d8ad36e1bec0dd2176332d24f4da390c08bb0/docs/rule/convention-design-style.yaml) | スタイルの一覧は画面全体の雰囲気の選択で、ワンポイント・形状の味付けはスタイルを決めた後にデザイン方針で選ぶ。変更しない |
  | [画面デザインの原則](https://github.com/shuhei1101/knowledge/blob/f82d8ad36e1bec0dd2176332d24f4da390c08bb0/docs/rule/ui-screen-design-principles.yaml)・[サイトのジャンル](https://github.com/shuhei1101/knowledge/blob/f82d8ad36e1bec0dd2176332d24f4da390c08bb0/docs/rule/ui-site-genre.yaml) | ジャンルの「モチーフ・装飾の例」「UI 要素の味付けの例」は題材の候補の出し分けに使用する例で、新しい規約は 1 サイトに 1 題材へ絞る決まりを持つ。変更しない |
- 追加する本文は対応表の NG の単語を使用しない（「サイトの印」は「ワンポイント」、「形の味付け」は「形状の味付け」、「段」は「段階」と記載する）
- テンプレートの改訂は、レビューの合格後にユーザーへ確認する（規約『ユーザー確認が必須な事項』の「ユーザーが読む・操作するものを作る」）

新しい決まりは、新しい規約 `docs/rule/ui-distinctive-look.yaml`（シンプルで凡庸でない見た目）に配置する。ワンポイント・強い色・文字の大きさの対比・遊びの置き場所は、どれも「凡庸でない見た目を作る」1 つの目的の決まりで、既存の『情報の階層と見た目』『表示の安定』の目的（情報の優先順位、表示の崩れ・揺れの防止）と違う。

テンプレートの欄の追加方法は A に決まった（[確認ログ](./確認ログ.yaml)）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 既存のセクションへ行と補足を追加する（ワンポイントは `## モチーフ・装飾`、形状の味付けは `## 形状と奥行き`、色の候補は `## 色の役割`） | 同じ要素を 2 か所で持たない | 既存の記述例の表の行が増える |
| B | `## サイトのワンポイント` と `## 形状の味付け` を新しいセクションとして追加する | 追加分が見つけやすい | `## モチーフ・装飾`・`## 形状と奥行き` と中身が重なる |

推奨: A

ワンポイントはモチーフの 1 つ、形状の味付けは要素ごとの区切り方の選択で、既存のセクションが同じ要素を扱っている。
