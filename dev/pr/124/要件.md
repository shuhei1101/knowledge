# 要件

## 要望

knowledge の `docs/` 配下の YAML の文書の全件のタグ（`tags`）を、規約『タグと用語の登録』の `tag-scope-01`・`tag-scope-02` に沿って付け直す。

対象は origin/develop（7e5972d）の `docs/` 配下の YAML の文書の全件 252 件（規約 198・テンプレート 42・判定フローチャート 7・手順 3・スキル 1・変更履歴 1）。
7e5972d の時点で、81 件が `scope:` のタグしか持たず、`action:` のタグを持つ文書は 0 件。

終わりの条件:

- 全件で、文書の `name`・`description`、項目の `name`・`group`、本文の見出しに出るドメインの名詞・行為の語が、判定フローチャート『タグの付与』の判定どおりにタグになっている
  - 語は単語まで分け（`tag-split-01`）、一語として定着した複合語は残して構成語も付ける（`tag-split-02`・`tag-name-01`）
  - 行為の語は名詞形の `action:`、道具の公式の名前は `tool:`、それ以外の名詞は `topic:` にする（`tag-name-01`）
  - 見出しの識別子（関数名・ファイル名）は概念の語にしてから付ける（`tag-scope-03`）
  - 規約『タグと用語の登録』の `tag-not-attach-01` に当たる語（見出しによく出る一般語・評価や状態の語・例として名前が出ただけの語）は付けない
- 新しく付けるタグは、付ける前に全件のタグを件数つきで引き、同じ概念の言い方・活用の違いのタグがあればそれに寄せる（`tag-attach-01`・`tag-attach-02`）
- 既存のタグは外さない
- `main: true` は各文書でちょうど 1 つにし（スキーマの `tags` の制約）、最も分量の多い主題のタグに付ける（`tag-attach-01`）
- 書き換えた文書は `rev` を 1 増やし、`last_reviewed` は変えない（#121 の一括の書き換えと同じ扱い）
- `tags` と `rev` 以外のキー・本文は一字一句変えない（規約『既存文章の維持』）

## 影響するユースケース

なし（knowledge はシナリオを持たない。変わるのは文書のメタデータの `tags` だけ）。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 命名規則（`tag-name-01`）に合わない既存のタグの改名（例: 道具の名前の `topic:fastapi` を `tool:fastapi` へ、英語の `topic:frontend` を日本語へ） | 要望は `tag-scope-01`・`tag-scope-02` の範囲の語のタグを揃えることで、既存のタグの改名は含まない。改名はフォルダの位置で引く使い方を変えるため、含めるかは判断が分かれる。今の判断は含めない（既存のタグは外さず、新しく付けるタグを既存のタグに寄せる） | レビューで確定 |
| `skills/text-review/SKILL.md`・`schemas/` 配下・`rules.yaml` | 文書のメタデータの `tags` を持たない | 予定なし |
| 用語集（`terms.yaml`）への用語の登録 | knowledge は用語集を持たない。複合語を残すかは `tag-split-02` の用語集に無いときの基準で決める | 予定なし |
