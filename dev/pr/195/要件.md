# 要件

## 要望

knowledge の文書のスキーマのうち、Markdown の本文を持つ文字列のキーに `contentMediaType: text/markdown` を追加し、`write_docs` の mdmark の点検の対象にする。

| スキーマ | キー | 値の中身 |
| --- | --- | --- |
| `schemas/common.schema.yaml` | `$defs/item.properties.body` | 項目の Markdown の本文。`metadata.items[]` から参照され、rule・template・flowchart・decision-table・guide・changelog・word-list の項目が使う |
| `schemas/skill.schema.yaml` | `properties.flow` | mdmark の `flow` を HTML のコードブロックで書いた Markdown |
| `schemas/skill.schema.yaml` | `properties.sequence` | mdmark の `sequence` を HTML のコードブロックで書いた Markdown |

- `schemas/prompt.schema.yaml` の `texts[].body` は Jinja2 の本文のため対象にしない
- 追加した後、対象のキーを持つ全ての文書の値を `mdmark check --text -` に通し、書き込みを止める警告が出ないことを確かめる。`<!-- embed: ... -->` を持つ `convention-writing-style` の `word-choice-table-02` は `unknown_mark` だけで、書き込みを止めない
- 全ての文書の検査（`scripts/check_all.py`）が違反 0 件のまま通る（`jsonschema` は `contentMediaType` を検査しない）

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 設計書のスキーマ `schemas/design/common.schema.yaml` の `$defs/markdown` | knowledge の配信元の文書は使わず、各プロジェクトが `design-schemas/v*` のタグで指して使う。追加すると各プロジェクトの設計書への `write_docs` の挙動が変わり、タグの更新も要る。判断: 含めない。レビューで確定する | 起票予定 |
| 単一 UC『エージェントが knowledge の文書を書き込む』への、mdmark の点検で書き込みを止める異常シナリオの追加 | 点検は dev-docs#111 が入れる機能で、マージ前の今は E2E で確かめられない。判断: 含めない。レビューで確定する | 起票予定 |
