## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 設計書の本文の型 | `$defs/markdown` の `description` の次に `contentMediaType: text/markdown` を追加する | knowledge の文書のスキーマの `schemas/common.schema.yaml` と同じ記法 |
| 既存の設計書の確認 | `dev-docs.yaml` の設計書の種類が `schemas/design/` を元にしたスキーマのコピーを指すプロジェクト（ai-monitor・claude-balancer など）の設計書で、`$defs/markdown` の型のキーの値を `mdmark check --text -` で点検し、`diagram_invalid`・`syntax_warning` が 0 件であることを確認する | 結果のログを `テスト結果/` に配置する。警告が出たときは、その値と警告を表にして書き込みが止まる設計書を列挙する |
| プロンプトの種類 | `kind` の `enum` と `description` に種類を 1 つ追加する。`allOf` の条件は `kind: llm` だけを `then` にしたまま変えない | 種類の名前は要件.md の `未確定` で決める |
| 規約『プロンプトファイル』 | structure-02 の `kind` の行・structure-04 の `role` の行に追加する種類を記載し、`overview`・`layout-01`・`description` の対象の列挙に追加する。検査のセクションに `system_prompt` の検査を追加する（要件.md の `未確定` で決める） | `rev` を上げ、`last_reviewed` を更新する |
| スキーマの文言 | dev-docs#148 の修正前後の表のとおりに置き換え、knowledge 側だけの `examples` も対応表の `ok` の単語に置き換える | 置き換えた後に dev-docs の develop の `templates/` と照合する |
| 確認 | 全ての文書の検査を実行し、違反が増えないことと、警告の件数が base と同じであることを確認する | ログを `テスト結果/` に配置する |
