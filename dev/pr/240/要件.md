### #197 設計書の本文の型

- `$defs/markdown` に `contentMediaType: text/markdown` を 1 行追加する。`$ref` で `$defs/markdown` を指す全てのキーで有効になる
- 既存の設計書の確認は、`schemas/design/` を元にした設計書のスキーマを持つプロジェクトの設計書を対象に、`$defs/markdown` の型のキーの値を `mdmark check --text -` で点検し、`diagram_invalid`・`syntax_warning` が出ないことを確認する
- `design-schemas/v*` のタグを打つ作業は反映作業に記載する
- `design-schemas/v*` のタグは、この PR を develop へマージした直後に、planner が develop の squash commit へ打つ。タグがまだ無いため、最初のタグ `design-schemas/v1.0.0` にする（[確認ログ](./確認ログ.yaml)）

### #226 エージェントのシステムプロンプトの種類

- 規約『プロンプトファイル』の structure-02（`kind`）と、`schemas/prompt.schema.yaml` の `kind` の `enum`・`description` に、エージェントのシステムプロンプトの種類を追加する
- 追加する種類は `role` を記載しない（`kind: llm` 以外と同じ `else` の条件に該当する）。`output` も記載しない
- 変数は `kind: llm` と同じ `vars` で持つ
- 種類の名前は `agent` にする。部品の `role` の値 `system` と同じ単語を使用せず、他の種類と同じく文の指定先で名前を付けるため
- 起動の構成の `system_prompt` が指すファイルの `kind` が `agent` であることは、規約『プロンプトファイル』の検査のグループに独自の検査として記載する。2 つのファイルにまたがり JSON Schema で見られないため、実装は起動の構成を持つプロジェクトの検査に任せ、[#224](https://github.com/shuhei1101/knowledge/issues/224) の `launch` のスキーマの `system_prompt` から参照する

### #236 スキーマの文言

- dev-docs#148 の `要件.md` の修正前後の表のとおりに置き換える。キー・型・形式・`enum`・`const` の値は変えない
- knowledge 側だけにある `examples` の値（`new-file-guide` など）も、同じ対応表の `ok` の単語に置き換える
- 置き換えた後に、dev-docs の develop の `templates/prompt.schema.yaml`・`templates/common.schema.yaml` と照合し、`examples` 以外の文言が一致することを確認する
