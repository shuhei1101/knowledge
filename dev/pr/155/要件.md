# 要件

## 要望

規約『YAML』の `mcp-write-04` の `expected_version` を、読んだときの文書のバージョン（中身から作る値）とし、照合の単位を文書ごとと記載する。
照合の単位は dev-docs の `write_docs` の実装（文書ごと）へ統一し、dev-docs 側は修正しない。

- dev-docs の `write_docs`・`delete_docs` の `expected_version` は、読んだときの文書の `version`（中身のハッシュの短縮）で、`rev` ではない
- dev-docs は 1 つのファイルが複数の文書を持つ配信元でも文書ごとにバージョンを持つため、「ファイルではなく〜ごとに持つ」の趣旨はそのまま成り立つ
- `rev` は knowledge のスキーマが定めるキーで、書き込む側が 1 つ上げる（[#152](https://github.com/shuhei1101/knowledge/pull/152) で記載済み）。書き込みの照合には使わない

変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）。

- 規約『YAML』（`docs/rule/dev-yaml.yaml`）の `mcp-write-04` の 1 行目の「項目の `expected_version`（`rev`）」を、読んだときの文書のバージョン（中身から作る値）に修正する
- 同じ項目の 2 行目の「バージョンはファイルではなく項目ごとに持つ」を「文書ごとに持つ」に修正する
- 3 行目（YAML の正本の項目を書き換えるときに当て、DB への追記には当てない）は変えない
- 規約『YAML』の `rev` を 1 つ上げ、`last_reviewed` を変えた日にする

終わりの条件:

- `docs/`・`schemas/` に、書き込みの `expected_version` を `rev` とする記述と、照合の単位を項目ごととする記述が無い
- 全ての文書の検査（`scripts/check_all.py`）が通る

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| dev-docs の `write_docs` を項目ごとの照合にすること | 照合の単位は dev-docs の実装（文書ごと）へ統一する。`update` は項目のパスごとのハッシュも受けるが、規約が求めるのは文書ごとの照合までで、項目ごとの照合を必須にする理由が無い | 予定なし |
| dev-docs の `write_docs` の `update` で、変えていない項目の引用符まで書き換わる（`"..."` が `'...'` に、`'2020-12'` が引用符なしに変わる） | 規約『既存文章の維持』から外れる差分になるため、今回は `docs/rule/dev-yaml.yaml` を直接編集して回避した。dev-docs の不具合で今回の要望に含まれない | [shuhei1101/dev-docs#91](https://github.com/shuhei1101/dev-docs/issues/91) |
