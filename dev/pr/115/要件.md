# 要件

## 要望

文書の MCP の読み取りのツールが本文を返すときに、文書ごとの場所と範囲を rule-inject の載せ方で載せる決まりを規約に追加する。
変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）。

規約『MCP サーバー作成ルール』（`docs/rule/claude-mcp.yaml`）:

- `## 読み取りのツール` に、本文を返すときは文書ごとに場所（文書のファイルの絶対パスか URL）と範囲（`full`・`section`・`summary`）を載せる、と追加する
  - markdown は文書ごとに `<document path="..." scope="...">` で包み、json は各項目に `path`・`scope` を持たせる
  - 載せ方の詳細は rule-inject の [MCPの結果の書式](https://github.com/shuhei1101/rule-inject/blob/master/docs/%E3%83%AA%E3%83%95%E3%82%A1%E3%83%AC%E3%83%B3%E3%82%B9/MCP%E3%81%AE%E7%B5%90%E6%9E%9C%E3%81%AE%E6%9B%B8%E5%BC%8F.md) を参照し、knowledge に写さない（参照先は rule-inject の master にある）
  - 既読になるのは `full` で、パスで返した文書だけ（rule-inject の書式）。規約には `full` を全文を返したときだけ付ける、と書き、`section`（セクションを指定した取得）・`summary`（`view` が `brief` など説明だけ）との当て方を `read-tool-03`・`read-tool-10` の取り方と揃える
- `read-tool-11` の「複数なら `<document>` で包む」と、追加する決まりが食い違わないようにする（1 件でも場所と範囲を載せるため）

規約『ルール索引への登録』（`docs/rule/dev-rule-index-registration.yaml`）:

- `index-writing-12` の「文書を MCP ツールで読む運用では、`read_by` に記載する」を、rule-inject の『MCPの結果の書式』に従わない MCP ツールで読む運用に限る、に修正する（D-124 の「従わない MCP は `read_by` を使う」）

変えたページは `rev` を 1 つ上げ、`last_reviewed` を変えた日にする。
