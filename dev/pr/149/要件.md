# 要件

## 要望

[Issue #144](https://github.com/shuhei1101/knowledge/issues/144) の `## 決定` に沿って、次のとおりにする。
判定フローチャートの構造は Issue の `## 必読` の A-7、チェックシートの項目は Issue 本文の表（A-8 と同じ 8 項目）を正とする。

- `docs/flowchart/flowchart-alias-registration.yaml`（`id: flowchart-alias-registration`、判定フローチャート『エイリアスの登録』）を新設する
  - 開始は「文書を作成・改名した」「会話・Issue で別の名前で呼ばれた」にする
  - 候補（略称・英語名・旧名・文書の中で呼んだ名前）を列挙してから判定へ進む
  - 最初の分岐を「その名前が指すのは文書 1 件か、概念か」にし、文書ならエイリアスの判定へ、概念なら判定フローチャート『用語の登録』（`flowchart-term-registration`）へ進む
  - 続く判定は A-7 のとおり、実際にその名前で呼ばれたか・一般語か・1〜2 文字かほかの単語の一部か・正規化で吸収できる表記ゆれか・ほかの文書や用語の `name` か `aliases` に既にあるか、の順にする
  - 図は `template-flowchart` の書き方（mdmark のフロー図の部品と、ノードの `kind` の `start`・`question`・`action`・`result`）で描く
- 規約『タグと用語の登録』（`docs/rule/dev-tag-term-registration.yaml`）の `alias-register-02`・`alias-not-register-01` の判定フローチャートの参照を、alias-inject の GitHub の URL から `id:flowchart-alias-registration` のリンクへ変更する
- 同じ規約の `description の書き方` のグループに、Issue 本文の 8 項目のチェックシート（文の数・文字数 40〜120 字・要素・タイトルの言い直し・検索で当てたい単語・書かないもの・変わる値・用語の選び方）を追加する

終わりの条件:

- 規約『タグと用語の登録』から、エイリアスの判定フローチャートを knowledge の中の `id:` のリンクで参照できる
- 新しい判定フローチャートが A-7 の判定と食い違わず、`template-flowchart` の書き方に沿う
- description のグループのチェックシートが Issue 本文の 8 項目と食い違わない
