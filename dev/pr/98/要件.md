# 要件

## 要望

スキルの設計書のテンプレートと、文章を点検して修正するスキルを追加する（mdmark改善の D-31・A-8・T-2）。
項目・各セクションの説明・サンプルの正本は A-8（`/mnt/c/Users/shuhe/repo/mdmark/tmp/mdmark改善/.mindstella/docs/A-8.md`）。
変更する項目以外の文言は一字一句そのまま残す（規約『既存文章の維持』）。

### スキルの設計書のテンプレートの新設

`docs/template/template-skill.yaml` を、既存のテンプレートと同じ書式（`kind: template`・スキーマ `schemas/template.schema.yaml`・タグ `scope:テンプレート`）で作る。
テンプレートの正本は develop の `schemas/` に揃える（#82 の D-63）。

- 項目は A-8 の表のとおり（`title`・`skill`・`issue`・`primary_actor`・`trigger`・`arguments`・`preconditions`・`externals`・`flow`・`sequence`・`branches`・`refs`）
- `flow`（手順）は mdmark の `flow`、`sequence`（外部とのやり取り）は mdmark の `sequence` で書く
- シナリオのテンプレートにある `test_file`・`setup`（Mock）・`test`・`expected` は持たず、結果は `branches[].result` に書いて突き合わせの観点にする
- モジュール構成とインターフェース定義は書かない
- 各セクションの書くこと・書かないことは A-8 の `## 各セクションの説明` のとおり
- 記載例は A-8 のサンプル（文章を点検して修正する）を使う

`rules.yaml` に、テンプレートをスキルの設計書のパスへ当てる行を追加する。

### 文章を点検して修正するスキルの新設

A-8 のサンプルを設計書にして、スキルを作る。

- 範囲を受ける。ファイルのパス・フォルダのパス（配下をすべて）・Git のコミットか範囲（変わったファイル）のどれでもよい
- 範囲をファイルに展開し、ファイルが無ければ規約を読まずに、渡した範囲と見つからないことを返す
- 文章の規約（『文章の書き方』『既存文章の維持』『論点の提示』『ドキュメントの部品』と、範囲にルールがあるときの『ユーザ配下ルール記載時の規約』）を、dev-docs があれば dev-docs で、無ければ knowledge の規約のファイルで読む
- 先にすべてのファイルを調べて修正する箇所の一覧を作り、その後でまとめて修正する（一覧が空なら修正しない）
- サマリーにファイルごとの修正した箇所・当てた規約・件数を出す。修正する箇所が無ければ「修正する箇所はありませんでした」を出す（[確認ログ](./確認ログ.md)）

スキルは knowledge に置くプラグインとマーケットプレイスで配る（[確認ログ](./確認ログ.md)）。
プラグインはスキルだけを持ち、文書の MCP は持たない（文書の MCP の配り方は #76 の D-82 のとおり dev-docs が持つ）。

### 確かめ方

スキルのテストは書かない。
スキルを実装した後に、設計書（手順のフローチャート・外部とのやり取り・分かれる結末）とスキルの手順を突き合わせて確かめる（D-31）。

### 未確定の論点

`未確定`: プラグインの構成と、スキルの設計書の置き場所・`rules.yaml` でテンプレートを当てるパス（決める工程: ドキュメント修正の依頼の前に reviewer と決める）

プラグインの構成は公式の構成（#82 の D-62）に揃え、マーケットプレイスを `.claude-plugin/marketplace.json`、プラグインを `plugins/knowledge/`（`.claude-plugin/plugin.json`・`skills/text-review/SKILL.md`）に置く。

| 案 | 内容 | メリット | デメリット |

| A | スキルのフォルダの中（`plugins/knowledge/skills/text-review/design.yaml`）に置き、`rules.yaml` は `**/skills/*/design.yaml` に当てる | スキルと設計書を一緒に読め、置き場所がスキルの置き場所に追従する | 文書を `docs/` の外に置く（規約『ドキュメント管理』の「文書は docs/ 1 つに置く」に反する）。設計書がプラグインと一緒に利用者の端末へ配られる |
