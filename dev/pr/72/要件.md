# 要件

## 要望

各端末で、汎用の開発ドキュメントサーバー dev-docs（[shuhei1101/dev-docs](https://github.com/shuhei1101/dev-docs)）を通して knowledge を使えるようにし、使い方のページを書き直す。
knowledge は自分のサーバーと MCP を作らず、dev-docs が読む設定・スキーマ・検査と変換のスクリプト・文書の MCP のプラグイン `knowledge-docs` だけを置く。
利用者の流れは次のとおり。

1. dev-docs をクローンし、dev-docs の管理用のプラグインと `knowledge-docs` をユーザースコープで入れる
2. 端末の設定 `~/.config/dev-docs/settings.yaml` の `projects[]` に knowledge の `dev-docs.yaml` を追加し、dev-docs に読み直させる
3. 画面（`http://127.0.0.1:${DEV_DOCS_PORT:-8781}/knowledge/`）で文書を読み、Claude Code から `knowledge-docs` の MCP で文書を検索・取得・書き込みする

dev-docs の設計は話し合いの A-23（システム定義・フォルダ構成）・A-24（シーケンスと MCP の見え方）・A-25（設定のキー一覧）、決定は D-96〜D-115 に従う。
MCP のツール（A-14）・画面・会話キーごとの返し済みの記録・スキーマの検査・既定の変換は dev-docs が持つ。
規約の側（接続先とポートの台帳・dev-docs での配信の立て方）は #73 が直す。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | ai-monitor の設計書の置き場所（`dev/設計書/`）と Schema に置き、ai-monitor の書くツール（`write_design_doc_*`）で書く | エージェントの設計・照合・レビューの手順と道具がそのまま使える | 『ドキュメント管理』の `folder-01`（文書は `docs/` 1 つに置く）から外れる |
| B | 『ドキュメント管理』に合わせて `docs/` に種類（`design` など）を追加し、`schemas/` に Schema を置いて `dev-docs.yaml` の `documents[]` で配る | knowledge の規約と揃い、dev-docs の画面と MCP で設計書も読み書きできる（A-25 の例も `docs/design/` に置く） | ai-monitor の書くツールと設計書の検証が使えない |

推奨: A

ai-monitor の照合・レビューの手順は `dev/設計書/` と書くツールを前提にしており、dev-docs を ai-monitor が使うようになる（D-101）までは、その前提に合わせる方が手戻りが少ない。

### 確かめ方

- dev-docs の管理の MCP の `check_project` が knowledge の `dev-docs.yaml` とスクリプトに誤りを返さず、`try_convert` で全ての種類の文書が Markdown に変換できる
- `projects[]` に追加して読み直させると、`http://127.0.0.1:8781/knowledge/` で develop の全ての文書が開ける
- `knowledge-docs` を入れた Claude Code の `/mcp` で接続でき、`search_docs` が knowledge の文書を返す
- 書き込みのツールが、検査のスクリプトに通らない内容を書かずに `isError` で返す
- CI が、違反のある YAML を含む PR で失敗する

## 影響するユースケース

既存のユースケースは無く、全て新規。
画面・MCP・起動の振る舞いは dev-docs のユースケースで、knowledge のユースケースはそれを knowledge の設定とスクリプトで使う流れを扱う。

| 種別 | ユースケース | 影響 | 依存 |
| --- | --- | --- | --- |
| 複合ユースケース | 利用者が端末に knowledge を導入して規約を引く | 新規（dev-docs とプラグインの導入・knowledge の登録から、画面と MCP での検索・取得まで） | 利用者が dev-docs に knowledge を登録する, エージェントが knowledge の文書を検索・取得する |
| 単一ユースケース | 利用者が dev-docs に knowledge を登録する | 新規（`projects[]` への追加・`check_project`・`try_convert`・読み直し） | |
| 単一ユースケース | 利用者が画面で knowledge の文書を読む | 新規（`nav` のタブ・サイドバーと、変換した本文） | 利用者が dev-docs に knowledge を登録する |
| 単一ユースケース | エージェントが knowledge の文書を検索・取得する | 新規（`knowledge-docs` の MCP） | 利用者が dev-docs に knowledge を登録する |
| 単一ユースケース | エージェントが knowledge の文書を書き込む | 新規（書き込みのときに検査のスクリプトを通す） | 開発者が文書の違反を検査する |
| 単一ユースケース | 開発者が文書の違反を検査する | 新規（検査のスクリプトと CI） | |
