# 要件

## 要望

各端末で、次の流れで knowledge を使えるようにし、使い方のページを書き直す。

1. knowledge を clone する
2. 開発ドキュメントサーバーを起動する（既定のポート 8781、環境変数 `KNOWLEDGE_PORT` で上書き）
3. このリポジトリのマーケットプレイスから文書の MCP のプラグイン `knowledge-docs` を、ユーザースコープかプロジェクトスコープで入れる。プラグインの MCP は HTTP で開発ドキュメントサーバーにつながり、文書の検索・取得・差分・書き込みのツールが使える

従う規約は [MCP サーバー作成ルール](https://github.com/shuhei1101/knowledge/blob/develop/docs/rule/claude-mcp.yaml)・[YAML](https://github.com/shuhei1101/knowledge/blob/develop/docs/rule/dev-yaml.yaml)・[ドキュメント管理](https://github.com/shuhei1101/knowledge/blob/develop/docs/rule/dev-document-management.yaml)・[Claude プラグインルール](https://github.com/shuhei1101/knowledge/blob/develop/docs/rule/claude-plugin.yaml)。
MCP のツールは Issue 本文の `## インターフェース定義（A-14）` に合わせる。ツール名・引数名は設計で確定させる。

推奨: A

ai-monitor の道具が読む設計書は、道具が前提にする置き場所に置く必要があり、`dev/pr/` を markdown のまま `dev/` に残したのと同じ扱いになる。

### 確かめ方

- 開発ドキュメントサーバーを起動すると、`http://127.0.0.1:8781/` で develop の全ての文書が mdmark の共通スタイルで開ける。`KNOWLEDGE_PORT` を変えると待ち受けのポートが変わる
- `knowledge-docs` を入れた Claude Code の `/mcp` で接続でき、A-14 の全てのツールの定義が出る（`claude-mcp` の `verification-01`）
- 同じ会話で同じ版の文書を 2 回取得すると、2 回目は本文を省いた印が返る。`repeat_seen: true` で本文が返る
- 検査のツールが develop の `docs/` で違反 0 件になり、違反を入れた YAML では違反の行を出して失敗する
- 書き込みのツールが、検査に通らない内容と `expected_version` の合わない内容を書かずに `isError` で返す
- CI が、違反のある YAML を含む PR で失敗する

## 影響するユースケース

既存のユースケースは無く、全て新規。

| 種別 | ユースケース | 影響 | 依存 |
| --- | --- | --- | --- |
| 複合ユースケース | 利用者が端末に knowledge を導入して規約を引く | 新規（clone・サーバーの起動・プラグインの導入から検索・取得まで） | 利用者が開発ドキュメントサーバーを起動する, エージェントが文書を検索・取得する |
| 単一ユースケース | 利用者が開発ドキュメントサーバーを起動する | 新規 | |
| 単一ユースケース | 利用者が開発ドキュメントサーバーで文書を読む | 新規 | 利用者が開発ドキュメントサーバーを起動する |
| 単一ユースケース | エージェントが文書を検索・取得する | 新規（検索・取得・セクションの一覧・タグの語彙・用語の概要・骨組み・関連と影響範囲） | 利用者が開発ドキュメントサーバーを起動する |
| 単一ユースケース | エージェントが文書の変更を確かめる | 新規（前回からの差分・区間の変更・取得の差分モード） | エージェントが文書を検索・取得する |
| 単一ユースケース | エージェントが文書を書き込む・削除する | 新規（スキーマの取得・関連の候補・書き込み・削除） | 開発者が文書の違反を検査する |
| 単一ユースケース | 開発者が文書の違反を検査する | 新規（検査のツールと CI） | |
