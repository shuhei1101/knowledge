# 要件

## 要望

[#111](https://github.com/shuhei1101/knowledge/issues/111) の決定（D-179〜D-182）と `## やること` を、develop の規約『タグと用語の登録』（`docs/rule/dev-tag-term-registration.yaml`）と判定フローチャート『タグの付与』（`docs/flowchart/flowchart-tag-attach.yaml`）へ反映する。
起点 Issue の本文（必読・決まったこと・やること）を正にする。
変更する項目以外の文言は一字一句そのまま残す（規約『既存文章の維持』）。

### 規約『タグと用語の登録』

| 入れる内容 | 出所 |
| --- | --- |
| タイトルを単語まで分け、「A の B」の名詞句のタグは作らない。一語として定着した複合語は残し、構成語のタグも付ける。複合語を残すかの第一の基準は「用語集にあるか」で、次に「分けると意味が変わる・関係ない文書が当たる」 | D-179・やること 4 |
| 命名規則の表（`facet:value`・facet 名は英語の小文字・topic は 1 概念の名詞・定着した複合語は構成語も付ける・action は名詞形・tool は公式の名前を小文字のハイフン区切り・表記ゆれは使われているタグに合わせる） | D-179 の命名規則 |
| 拾う範囲: タイトル・見出し・description・表の行見出し（各行の 1 列目）に出るドメインの名詞・行為の語は機械的に全部タグにする。本文だけに出る語はタグにせず全文検索に任せる | D-180 |
| 付けない一般語の例: 機能・手段・背景・仕組み・案・一覧・リクエスト・レスポンス・例・前提・流れ・要点・補足・決めたこと・残る検討事項・やりたいこと | D-180・やること 4 |
| 見出しの識別子（関数名・ファイル名。`list_changes`・`describe()`・`dev-docs.yaml`）はタグにせず、概念の語にしてから付ける（`dev-docs.yaml` → `topic:設定`） | やること 4 |
| ファイルの種類ごとの書き出す範囲と付けるファセットの表（Markdown・YAML の文書・ソースコード（files.yaml の行）。ソースコードは `topic:`・`tool:` だけで、関数名・クラス名は拾わない） | D-181・D-177 |
| 「既存のタグに寄せる」は、同じ概念の言い方・活用の違い（「強い／強く」など）だけを合わせる意味で書く。意味が近いだけの別の概念は別のタグにしてよい。付ける数・タグの種類の上限は持たない | 起点 Issue のユーザーのコメント（[TH-304](https://github.com/shuhei1101/knowledge/issues/111#issuecomment-6515480450)） |
| タグの節を、他のリポジトリ（dev-docs・MindStella・aituber・AI Monitor）のエージェントがこの規約だけを参照して付けられる書き方にする（knowledge 固有の前提に頼らない） | D-182・やること 3 |

あわせて、既存の例のうち D-179 と食い違うもの（`tag-attach-01` の `topic:索引の点検`・`topic:タグ設計` などの名詞句のタグ）を、単語に分けた例へ修正する。
`tag-not-attach-01` の「使われているタグと同じ意味の語・表記ゆれ」の行は、TH-304 の意味（同じ概念の言い方・活用の違い）に合わせて修正する。

### 判定フローチャート『タグの付与』

A-38 の改訂案にする。

- 書き出し（A2）の範囲を ※1 として規約のファイルの種類ごとの表に合わせる
- Q3「行為の語か?」（YES → 名詞形にして `action:` にする）を入れる
- Q4「分けると意味が変わる、一語として定着した複合語か?」（YES → 複合語のまま `topic:` にし、構成語も書き出しに加える／NO → 単語に分け、分けた語ごとに Q1 から判定する）を入れる。※2 の定義の第一の基準を「用語集にあるか」にする（やること 4）
- 見出しの識別子を概念の語にしてから判定する分岐か注記を入れる（やること 4）
- 使われているタグを使い回すかの判定（今の Q3、A-38 の Q5）の「同じ意味か近い意味のもの」は、TH-304 に合わせて「同じ概念の言い方・活用の違い」にする
