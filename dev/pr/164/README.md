# フィルター・照合条件の AND・OR・NOT の共通の構造を規約にし、判定フローチャート『エイリアスの登録』に照合条件を付ける分岐を追加する

## 概要

フィルター・照合条件を設計・実装する人が AND・OR・NOT の共通の構造を規約で参照でき、エイリアスを登録する人が、特定の文脈でだけ文書を指す名前に照合条件を付けるかを判定フローチャート『エイリアスの登録』で決められるようにする。

## 背景

[Issue #157](https://github.com/shuhei1101/knowledge/issues/157) の要望。
条件を AND・OR・NOT の入れ子で記載する考え方が規約に無く、ツールごとに条件の書き方が決まっている（dev-docs の `filter`・rule-inject の `paths`・`exclude`・`tools`・`args`）。
判定フローチャート『エイリアスの登録』（`flowchart-alias-registration`）は一般語の名前を「登録しない」へ進め、React の規約『フォルダ構成』のように特定の文脈でだけその文書を指す名前の扱いが無い。
alias-inject は [shuhei1101/alias-inject#57](https://github.com/shuhei1101/alias-inject/issues/57)（作業 PR [shuhei1101/alias-inject#58](https://github.com/shuhei1101/alias-inject/pull/58)、マージ済み）で文書ごとの照合条件 `inject_when` を持った。
同じ要望の [shuhei1101/alias-inject#59](https://github.com/shuhei1101/alias-inject/issues/59) は、Issue #157 へ一本化して閉じられている。
