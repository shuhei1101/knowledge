### #93: Retry-After の値の決め方

`retry_after` 属性を持たない例外（`LlmServerError`）を 503 で返すときの Retry-After の値の決め方を、`python-fastapi-auth-error` の `exception-handler-01` の表の下に記載する。
D-53 で自作の `with_retry`（`base_delay`・`max_delay`）を stamina に置き換えるため、導出の元の値は stamina に置き換えた後の `python-llm-exception-retry` の記述から取る。

値の出所は、`python-llm-exception-retry` の `LlmServerError` へのリトライの待ち（stamina のバックオフの上限）から導く。
規約『資源の値の決め方』は値を導出の元の値から導くとしており、上流の 5xx からの回復を待つ間隔として、同じ例外へのリトライの待ちが元の値になる。
導出の元の値があるため、ユーザーの意向でしか決まらない値には当たらない。

見送った案:

| 案 | 内容 | 見送った理由 |
| --- | --- | --- |
| A | 固定値を規約に書く | 根拠の無い値になり、規約『資源の値の決め方』の「導出の元の値と並べて書く」を満たせない |
| B | 設定（`Settings`）に持たせ、既定値を明示する | 既定値の決め方が別に要り、結局リトライの待ちから導くことになる |

### #85: 規約『タグと用語の登録』の改訂

- `dev-tag-term-registration` を R-8 の付け方と D-169 に改める
  - 付ける前に、使われているタグを検索の集計（dev-docs の `group_by: tags`）で件数つきで引き、同じ意味のタグがあれば使い回す
  - 判定は「その語で探した人に、この文書が出てほしいか」。当てはまるものは全部付け、上位の広いタグも一緒に付ける
  - 数の上限・目安は持たない（D-106）。最も分量の多い主題に `main` を付ける
  - タグは自由な文字列で、比較の前に正規化（NFKC・大文字小文字）する。分類は `scope:` などの接頭辞の命名で表す
  - `tag-vocabulary-01`〜`04` と、`tag-attach-01` の「新しいタグを候補として登録し、説明を記載する」を削除する
  - 「別の言い方は既存のタグの `aliases` に入れる」を「使われているタグを引いて同じ語を使う」に修正する。同じ意味のタグを新設しない決まりは残す
  - 「タグを付ける条件」「タグを付けない条件」の表を例として書き直す（「分量の 2 割以上」と「本文で触れているだけ」の行を削除する）
  - エイリアス・用語の条件は変えない
- タグを付けるかの判定フローチャートを `docs/flowchart/` に新設して正にする（D-108。R-8 の図を元にする）
- MCP・YAML の規約（[#42](https://github.com/shuhei1101/knowledge/issues/42)・[#68](https://github.com/shuhei1101/knowledge/issues/68)・[#70](https://github.com/shuhei1101/knowledge/issues/70) でマージ済み）から、タグの語彙のツール（`list_tags`）・未登録のタグの候補・`warnings` の候補の記述を削除する
- `docs/tags.yaml`・`schemas/tags.schema.yaml` を削除し、参照している `rules.yaml`・`schemas/common.schema.yaml`・規約を修正する（develop の 60281a4 では、目次（`README.md`）から両ファイルを参照している箇所は無い）
- 完了後、#85 の `## 依存・後続` の後続（shuhei1101/mindstella#333・shuhei1101/mindstella#335・shuhei1101/ai-monitor#2975・shuhei1101/ai-monitor#2984・shuhei1101/ai-monitor#3068・shuhei1101/mdmark#175・shuhei1101/aituber-legacy#2112）へ着手できる旨をコメントし、shuhei1101/mindstella#358 の [スレッド](https://github.com/shuhei1101/mindstella/pull/358#discussion_r4398520071) へ規約の改訂が入った commit / PR へのリンクを添えて返信する（計画の行の概要のとおり task-planner が #85 の close 時に行う）
