# Python の規約を機械検査へ寄せて推奨ライブラリを更新し、Retry-After の値の決め方を記載して、規約『タグと用語の登録』をタグのマスターを持たない付け方に改める

## 概要

Python のリポジトリで作業する AI が、機械検査で判定できない判断の規則だけを、使う側のファイルを編集するときに読み、今の推奨ライブラリ（pyright・stamina・httpx2・SQLAlchemy 2.1 など）で書けるようになる。
文書にタグを付ける AI が、使われているタグを引いて使い回し、探した人に出てほしい文書へ漏れなくタグを付けられるようになる。

## 背景

[Issue #99](https://github.com/shuhei1101/knowledge/issues/99) の要望で、次の 3 つの子 Issue を束ねる。

- [#81](https://github.com/shuhei1101/knowledge/issues/81): `python/` の 42 件の多くが `**/*.py*` に当たり、`integrations/llm/**` を 1 つ編集すると 18 件・75.8KB が当たる。ruff・mypy で判定できる規則まで文章で注入しており、推奨ライブラリの一部（httpx・自作のリトライ・Instructor）が古い。各リポジトリの React 移行の前提になる
- [#93](https://github.com/shuhei1101/knowledge/issues/93): [PR #90](https://github.com/shuhei1101/knowledge/pull/90) で `LlmServerError` を 503（Retry-After 付き）にしたが、`retry_after` 属性を持たない例外の Retry-After の値の決め方がどの規約にも無い
- [#85](https://github.com/shuhei1101/knowledge/issues/85): 規約『タグと用語の登録』が付けない方へ倒しており、探したときに文書がヒットしない。あわせて、タグのマスター（語彙）を持たないと決め直した（D-169）ため、マージ済みの規約・`docs/tags.yaml` からマスターの記述を外す

決定の記録はローカルのワークスペース `tmp/react移行計画` と `tmp/mcpベストプラクティス検討` にある。
