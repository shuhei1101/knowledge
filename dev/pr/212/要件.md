# 要件

## 要望

validator `knowledge-checks`（`scripts/knowledge_checks.py`）の文書の検査に、`aliases` の衝突の検査を追加する。

- 検査する文書の `aliases[n]` が、配信元の `alias_type` を持つ行（`rule`・`template`・`flowchart`・`decision-table`・`guide`・`skill`）のほかの文書の `name` か `aliases` と一致したら、`aliases[n]` の違反 1 件を返却する
- 照合の前に、判定表『エイリアスを登録しない条件』の ※6 と同じ正規化（NFKC・英字の大文字小文字・前後の空白）を両方の値に適用する
- ほかの文書は、文書の ID が検査する文書と異なる文書とする（書き込みでは、ディスクにある書き込み前の自分を照合の相手にしない）
- 違反の `rule` に衝突の相手の文書の ID と、相手の `name`・`aliases` のどちらと衝突したかを記載し、`fix` に判定表の 5 行目の補足（指す文書を 1 件に決めて片方だけに登録する）を記載する
- 全ての文書の検査（`check_all.py`）も同じ検査を適用する
- develop の文書に、この検査の違反が 0 件である（11-06 の develop の時点で、`aliases` が他の文書の `name`・`aliases` と衝突する文書は 0 件）

照合の相手の名前の索引は、今の ID の索引（文書の ID → 項目の ID）とは別に作り、`check_document` の引数に追加する（全ての文書の検査は 1 度だけ作って指定する）。
参照の検査の入出力を変えずに済み、`check_all.py` の変更が索引を 1 つ追加して指定するだけになる。

## スコープ外

| 項目 | 理由 | 対応予定 |
| --- | --- | --- |
| 文書の `name` どうしの衝突（11-06 の develop では `next-shared-env-var` と `react-shared-env-var` の「環境変数と設定」） | 要望は `aliases` の衝突だけ。スタック別の規約は同じタイトルを持ち、照合条件 `inject_when` でヒットする場面を分けている。今の判断はスコープ外で、レビューで確定する | 予定なし |
| 文書の中での `aliases` の重複と、自分の `name` と正規化で同じになる `aliases`（判定表の 4 行目） | 要望は、ほかの文書との衝突だけ。自分の中の重複も機械検査で判定できるため、含めるかの判断が分かれる。今の判断はスコープ外で、レビューで確定する | 起票予定 |
| 判定表『エイリアスを登録しない条件』の 5 行目の削除 | 5 行目の補足（指す文書を 1 件に決める）は人の判断で、検査は衝突を見つけるだけ。判定表は `rules.yaml` に載らず、強制注入の基準 2 の「本文から削除する」の対象外 | 予定なし |
