# 要件

## 要望

knowledge の `rules.yaml` をどのリポジトリのセッションからも参照されるようにし、エントリを強制注入の 4 つの基準で絞る。
tmux でのサーバーの立て方の規約を新設し、Markdown・YAML の検査ツールを CI に追加し、claude・dev・テンプレートの規約の矛盾と古い記述を修正する。

### 強制注入の 4 つの基準

`on: [write]` で登録するのは、次の 4 つをすべて満たすルールだけにする。
満たさないルール（任意で読むルール）は `rules.yaml` から完全に除外する（D-92）。

| 基準 | 判定の目安 |
| --- | --- |
| 読まずに編集すると、後から修正するのに手間が掛かる | 書式（テンプレート）、AI の既定と逆の独自の決まり、安全 |
| 機械検査で判定できない | lint・スキーマ・型検査で判定できる部分は検査へ移し、本文から削除する |
| glob が狭い | 特定のファイル名・フォルダで当てる。拡張子だけの glob は全言語共通の規約 1〜2 件に限る |
| 短い | 1 ルール 4KB 以内、1 ファイルの編集で当たる合計 10KB 以内。テンプレートは例外 |

`dev-rule-index-registration` の本文を、この基準で書き換える。

### rule-inject の索引への登録

knowledge の `rules.yaml` を、利用者の全ての Claude Code の設定から参照される rule-inject の索引に登録する（反映作業）。
登録の仕方は shuhei1101/ai-monitor#3040 の設定ファイル（`RULE_INJECT_CONFIG` が指す YAML の `global.indexes`）に合わせ、使い方『規約の索引を当てる』の手順も同じ書き方へ改める。

端末の 10 個の設定に入っている rule-inject は 0.2.3 で、設定ファイルを読まず、環境変数 `RULE_INJECT_INDEXES_USER` のカンマ区切りの索引を読む（`INDEX_SEPARATOR`）。
このため、反映作業では各設定の `RULE_INJECT_INDEXES_USER` に knowledge の索引をカンマ区切りで追加し、使い方『規約の索引を当てる』には設定ファイルの書き方と、設定ファイルを読まないバージョン（0.2.3 まで）の環境変数の書き方を記載する（案 A。設定ファイルは shuhei1101/rule-inject#52 の develop にある）。

### tmux でのサーバーの立て方の規約（新規）

A-14 の下書きを規約にする（`docs/rule/dev-local-server.yaml`。名前は『ローカルサーバーの立て方』）。

| 項目 | 決まり |
| --- | --- |
| セッション名 | `{リポジトリ}-{worktree}-{役割}`。メインリポジトリでは `{worktree}` を省く。ai-monitor が自動で起動するものは今の方式のまま例外にする（D-80） |
| ポート | worktree の dev サーバーは OS が選ぶ空きポートを `.dev/{役割}.port` に記録する。固定ポートはメインリポジトリのサーバーと常駐サーバーだけ（D-81） |
| ログ・ポートの置き場所 | worktree の直下の `.dev/`（gitignore する）（D-84） |
| 常駐サーバー | 必ず動いていてほしい常駐サーバー（MCP・gateway など）は systemd --user、dev サーバーは tmux。#74 の SessionStart のフックは落ちていたときの補助（D-82） |
| 落ちたとき | プロセスが終わったらセッションも閉じる（tmux の既定）。ログは `tee` でファイルに残す（D-83） |

テンプレート『セットアップ手順』の `has-session`・`kill-session` に `=` を付け、`ss -tanH` を `ss -ltnH` に修正する。

### 検査ツール

markdownlint・textlint・yamllint を追加し、CI の文書の検査のワークフローで動かす。
JSON Schema の検査は、全ての文書の検査（`scripts/check_all.py`）が既に行っている（D-57）。

markdownlint・textlint は、文書の YAML の Markdown の項目を 1 項目ずつ当て、違反の行を元の文書の YAML の行で出す（PoC 検証で成立。CI.md の `## PoC 結果`）。
`.md` のファイルにはそのまま当てる。

既存の文書に違反があるルール（`one-sentence-per-line`・`no-inline-strong`・MD031・MD032・MD040・`preset-ja-technical-writing`）は警告にし、違反をログに出してもジョブを失敗させない（[確認ログ](./確認ログ.md)）。
#145 の移行で違反を修正した後に、失敗させる設定へ切り替える。

### 共通

- 改めた文書の `rev` を 1 つ上げ、`last_reviewed` を変えた日にする
- 変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）

終わりの条件:

- 利用者の Claude Code のセッションで、knowledge の外のリポジトリのファイルを編集したときに knowledge のルールが案内される
- `rules.yaml` のエントリが上の表のとおりで、末尾の `*` を持つ glob が無い
- `docs/rule/` に『ローカルサーバーの立て方』があり、テンプレート『セットアップ手順』の `-t` に `=` が付いている
- CI で markdownlint・textlint・yamllint が動き、違反でジョブが失敗する（警告にしたルールを除く）
