# 要件

## 要望

Markdown・ソースコードを管理用の YAML（`files.yaml`）に載せる判定と各列に入れる値、`description` の書き方、設計書と 1 対 1 のコードの `implements` を規約に記載する（mcpベストプラクティス検討の D-171・D-173〜D-177）。
変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）。

規約『ドキュメント管理』（`docs/rule/dev-document-management.yaml`）:

- `## 配信` の `delivery-08`（YAML でない文書の files.yaml）の後に、files.yaml の行の決まりを記載する
- 載せるファイルの判定を判定フローチャートで記載する（Issue 本文のフローチャートを規約『判定フローチャート』の書き方に合わせる）
  - 除外の条件は、生成物・ロック・バイナリ・ベンダーのコード・再エクスポートや空の `__init__` だけのファイル
  - 除外の条件に当たらなければ全て載せ、1 行 1 ファイルにする
  - テストは載せて `related` の `tests` で対象のコードを指す。対応する設計書があるコードは `related` の `implements` でその設計書を指す
  - 除外の条件の見分け方（フォルダ名・ファイル名の末尾・NUL バイト 等）は dev-docs の [文書のメタデータ](https://github.com/shuhei1101/dev-docs/blob/develop/docs/%E3%81%AF%E3%81%98%E3%82%81%E3%81%AB/%E3%82%B3%E3%82%A2%E3%82%B3%E3%83%B3%E3%82%BB%E3%83%97%E3%83%88/%E6%96%87%E6%9B%B8%E3%81%AE%E3%83%A1%E3%82%BF%E3%83%87%E3%83%BC%E3%82%BF.md) の「載せるファイルの判定」を参照し、knowledge に写さない
- 各列に入れる値を表で記載する

  | 列 | 入れる値 | 入れないもの |
  | --- | --- | --- |
  | `path` | files.yaml のフォルダからの相対パス。1 行 1 ファイル | glob |
  | `name` | 何のファイルかを表す日本語の名詞句（例 `タスクのリポジトリ`） | クラス名・ファイル名の繰り返し |
  | `description` | 規約『タグと用語の登録』の description の書き方 | 関数の一覧・実装の手順 |
  | `tags` | 規約『タグと用語の登録』の `tag-scope-02` のソースコードの行（`topic:`・`tool:`） | `kind:`・`scope:`・状態・評価の語 |
  | `related` | `implements`・`tests`・`see_also` | import で分かる依存 |
  | `status` | `deprecated` など検索で外したい状態だけ | - |

- 設計書と 1 対 1 のコードは、コード側の files.yaml の行に必ず `implements` を記載し、設計書には逆向き（設計書 → コード）を記載しない、と記載する。逆向きは被参照で引く（dev-docs の `trace_related`）
- files.yaml の行の `related` の `type` は `implements`・`tests`・`see_also` で、`## 関連` の `related-02` の `type`（`requires`・`references`・`replaces`・`part_of`・`change_together`）は YAML の文書に使う、と書き分ける。`related-02` の文言は変えない
- `metadata-01` の表の `description` の行（`本文を読まずに中身が分かる 1〜2 文`）を、規約『タグと用語の登録』の description の書き方を参照する 1 文に合わせる

規約『タグと用語の登録』（`docs/rule/dev-tag-term-registration.yaml`）:

- description の書き方を記載する
  - 種類を問わず 1 文で、「何を受け持つか／何について書いてあるか」＋「どんなときに読むか」
  - 例: `タスクの保存と取得を受け持つ。保存先や検索の条件を変えるときに読む`
  - 関数の一覧・実装の手順は書かない
  - 既存の文書を YAML にするときも同じ書き方にする
- `tag-scope-02` の書き出す範囲（description から語を書き出す）・判定フローチャート『タグの付与』『用語の登録』と食い違わないことを確かめる。ソースコードのタグの観点（`topic:`・`tool:` だけ）は #111 で `tag-scope-02` に入っており、この PR では書き足さない

共通のスキーマ（`schemas/common.schema.yaml`）:

- メタデータの `description` の `description`（`本文を読まずに中身が分かる 1〜2 文。`）を、規約の 1 文の書き方に合わせる

変えた規約 2 ページは `rev` を 1 つ上げ、`last_reviewed` を変えた日にする。
