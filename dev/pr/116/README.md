# 規約に、files.yaml に載せるファイルの判定・各列に入れる値・description の観点・設計書との implements を記載する

## 概要

Markdown・ソースコードを管理用の YAML（`files.yaml`）に載せる判定と各列に入れる値、`description` の書き方、設計書と 1 対 1 のコードの `implements` を規約に記載する。

## 背景

[Issue #91](https://github.com/shuhei1101/knowledge/issues/91) の要望。
D-171 で Markdown・ソースコードのメタデータは files.yaml の行に置くと決まり、その行に何をどう入れるかを mcpベストプラクティス検討の D-173〜D-177 で決めた。
規約『ドキュメント管理』の `delivery-08` は files.yaml に載せることだけを持ち、載せる判定・列の値・`implements` を持たない。
依存の [#73](https://github.com/shuhei1101/knowledge/issues/73)・[#85](https://github.com/shuhei1101/knowledge/issues/85)・[#86](https://github.com/shuhei1101/knowledge/issues/86)・[#111](https://github.com/shuhei1101/knowledge/issues/111)・[shuhei1101/dev-docs#34](https://github.com/shuhei1101/dev-docs/issues/34) は close 済み。
