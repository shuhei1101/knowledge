# ドキュメント管理

AI エージェントが読み書きする文書の置き方・メタデータ・関連・配信の決まり。

## 置き方

- 文書の正本は YAML にする
  markdown にするのは、道具が markdown を前提にするファイル（README・CLAUDE.md・AGENTS.md・SKILL.md・PR の本文など）だけ
- 大きな文書は項目ごとに分け、長い自由記述は項目の本文のキーに入れる
- YAML ファイルを分ける単位は [YAML ファイルの単位](../../判定フローチャート/YAML ファイルの単位.md) で決める
- 道具がフロントマターを要求するファイル（SKILL.md など）のほかは、フロントマターを使わない

## フォルダ

- 文書は `docs/` 1 つに置き、その下は種類だけをフォルダにする
  種類のフォルダの中はフラットにする
- 公開範囲・分類・トピック・言語はメタデータで持ち、フォルダにしない
- ファイル名は ID か変わりにくいスラッグにする
- 文書どうしの参照は ID で記載し、パスで記載しない
- 種類ごとのスキーマは `schemas/{種類}.schema.yaml` に置く

```text
repo/
├── README.md
├── CLAUDE.md
├── schemas/
└── docs/
    ├── scenario/
    │   └── SC-12.yaml
    ├── rule/
    │   └── python-testing.yaml
    └── terms.yaml
```

## メタデータ

<!-- table: data -->

| キー | 中身 | 必須 |
| --- | --- | --- |
| `id` | 変わらない ID | 必須 |
| `kind` | 文書の種類（英語の定数） | 必須 |
| `name` | タイトル | 必須 |
| `description` | 本文を読まずに中身が分かる 1〜2 文 | 必須 |
| `tags` | タグ（[タグと用語の登録](./タグと用語の登録.md)）。各要素は `name` と、主題なら `main: true` | 必須 |
| `status` | 状態（英語の定数） | 必須 |
| `visibility` | 公開範囲（`public` / `internal`） | 必須 |
| `rev` | 変更ごとに増えるバージョン。書き込みのツールが付ける | 必須 |
| `aliases` | 本文や会話でこの文書を呼ぶ別の名前 | 任意 |
| `related` | 関連（`## 関連`） | 任意 |
| `code_refs` | 対応するコードのパスとシンボル | 任意 |
| `interfaces` | 定義している公開インターフェース | 任意 |
| `last_reviewed` | 最後に内容を確かめた日 | 手順書・規約など鮮度を見たい種類だけ。種類のスキーマで決める |

<!-- /table -->

- 作成日時・更新日時は持たない
  要るときは git から取る
- 紐付けに使えるメタデータは多めに持たせ、返す量は読み取りのツールで絞る（[MCP サーバー作成ルール](../claude/mcp.md)）

## 関連

- 各要素に `to`（相手の ID）・`type`（関係の種類）・`when`（いつ読むか、1 文）を持たせる
  機械で判定できるときだけ `paths`（glob）を併記する
- `type` は `requires`・`references`・`replaces`・`part_of`・`change_together` から選ぶ
- 片側だけ記載し、逆向きはツールで出す
  `change_together` だけは両側に記載し、直し忘れの検査に使う
- `when` を記載できない関連は張らない
  本文でリンクしている相手は重ねない
  件数の上限は種類のスキーマで決める
- 規約・手順のように従う必要がある文書への参照が切れたら、CI で止める

## 配信

- 開発ドキュメントサーバーは develop ブランチの全件を配信する
- GitHub Pages は、master へのマージで動く GitHub Actions のワークフローで、`visibility: public` の文書だけを HTML にして配信する
  YAML の原本は成果物に入れない
- ブランチのフォルダをそのまま配信する Pages の方式は使わない
