# タグと用語の登録

文書にタグ・用語・エイリアスを付けるときと、タグの語彙・用語集に登録するときの決まり。

## タグの語彙

- タグの語彙は 1 つにし、グループ（`topic`・`kind`・`scope`・`tool` など）で分ける
  同じ名前のタグをグループごとに別に定義しない
- 各タグは `name`・`group`・`description`・`aliases`・`deprecated`（振り替え先）を持つ
  `description` は「含める / 含めない / 例」の 3 点で記載する
- 種類ごとのスキーマで、使ってよいグループと必須の数を決める
- 語彙に無いタグは拒否せず、未登録の候補として受け付ける
  検査で警告し、人か AI が採否を決める

## タグを付ける条件

<!-- table: data -->

| 条件 | 例 |
| --- | --- |
| 文書の主題（分量の 2 割以上）には、その主題のタグを `main: true` で付ける | 「索引の点検」が中心の設計書に `topic:索引の点検` |
| 文書の種類・触る範囲のグループは、スキーマが必須とする数だけ付ける | 手順書に `kind:how-to` |
| 語彙に合うタグが無い主題は、新しいタグを候補として登録し、説明を「含める / 含めない / 例」で記載する | 「やめた言い方の点検」がどのタグにも含まれないので新設 |
| 2 つ以上の文書で同じ主題が出て一緒に引きたいときは、既存の文書にもさかのぼって付ける | `topic:タグ設計` を新設したら過去の調査 2 件にも付ける |

<!-- /table -->

## タグを付けない条件

<!-- table: data -->

| 条件 | 例 |
| --- | --- |
| 本文で触れているだけで主題になっていない | 1 段落だけ言及した「Mermaid」 |
| そのタグ 1 つでは何の話か決まらない評価・状態の語 | 「重要」「初心者向け」「ベストプラクティス」 |
| 状態・フェーズなど別のキーで表せるもの | 「決定済み」は `status` で表す |
| 既存タグの同義語・表記ゆれ。新設せず既存タグの `aliases` に入れる | `topic:用語集` があるのに `topic:glossary` を作らない |

<!-- /table -->

## 用語を登録する条件

<!-- table: data -->

| 条件 | 例 |
| --- | --- |
| プロジェクト固有の呼び名（システム名・製品の固有の語・話し合いで決めた呼び名） | 「ワークスペース」 |
| 一般的な語でも、このプロジェクトで一般と違う・狭い意味で使う語 | 「フェーズ」= エージェントが 1 ターンで実行する手順のまとまり |
| 外部ライブラリ・外部サービスを調べたときのその名前（調べた資料へのエイリアスでもよい） | 「sqlite-vec」 |
| 同じものに 2 つ以上の言い方が出たとき。正式な語を用語に、残りを `aliases` か `avoid` に入れる | 「移し替え」と「マイグレーション」 |

<!-- /table -->

## 用語を登録しない条件

<!-- table: data -->

| 条件 | 例 |
| --- | --- |
| 一般的な意味のまま使っている技術用語 | 「JSON」「正規表現」 |
| 1 文書の中だけで使い他の文書に出ない語 | ある PR の一時的な作業名 |

<!-- /table -->

## エイリアスを登録する条件

エイリアスは、文書そのものを特定の語に紐付ける文字列。
利用者にはその語にツールチップで文書を出し、エージェントはタグと並んで検索に使う。

<!-- table: data -->

| 条件 | 例 |
| --- | --- |
| 本文や会話で、その文書をタイトル以外の名前で呼んでいる | 「索引と用語集を書く」を「索引の手順」と呼ぶ |
| 略称・英語名・旧名で参照される | `api.md` に「公開関数」 |

<!-- /table -->

## エイリアスを登録しない条件

<!-- table: data -->

| 条件 | 例 |
| --- | --- |
| 複数の文書や用語に当てはまる一般語（ツールチップが誤った紐付けになる） | 「設定」「手順」 |
| 1〜2 文字の語や、ほかの語の一部としてよく出る語 | 「印」（「印刷」に当たる） |
| 正規化で吸収できる表記ゆれ | 「ＡＰＩ」と「API」の両方は登録しない |

<!-- /table -->

## 一致のさせ方

- 一致の前に NFKC・英字の大文字小文字・前後の空白を正規化し、残る揺れは `aliases` に列挙する
- 正規表現は、やめた言い方（`avoid`）の点検だけに使い、from / to のテストを付ける
  自動の紐付け（ツールチップ・検索）には使わない
