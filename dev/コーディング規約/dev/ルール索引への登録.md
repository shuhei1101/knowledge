# ルール索引への登録

`docs/` 配下のドキュメントを新規作成・移動・リネームしたときは、プロジェクトの直下の `rules.yaml`（rule-inject の索引）に載せるかどうかを判断する。
索引に載せたドキュメントは、`paths` の glob に一致するファイルを扱うとき、または `tools` の glob に一致する MCP ツールを呼ぶときに本文が自動で注入される。
既存ドキュメントを編集したときも、索引に載っているかと `paths` / `tools` が今の内容と合っているかを確認する。

## 載せるかの判断

- 特定のファイル種別・ディレクトリを扱うときに毎回従ってほしい規約・書式 → 載せる
- 特定の MCP ツールを呼ぶときに毎回従ってほしい規約・書式 → 載せる
- 必要になったときに取りに行く参照資料（調査メモ・一覧・議事録）→ 載せない
- 検査のコードで判定できる決まり → 載せずに検査に記載する

## 載せるときの書き方

- 索引に `rule`（索引ファイルからの相対パス）と `paths` / `tools` の 1 エントリを追加する
- `paths` には「そのドキュメントに従ってほしい対象ファイル」の glob を書く
  - 対象が実装言語なら拡張子で引く（例: `**/*.py*`）
  - 対象がドキュメント種別ならそのフォルダで引く（例: `**/dev/設計書/シナリオ/**`）
  - 照合は絶対パスに当てるため、`**/` か `*` で始め、`~` を使わない
  - 波括弧は候補を 2 つ以上並べるときだけ使う（例: `**/*.{ts,tsx}`）
- `paths` の範囲から外したいファイル・フォルダは、同じエントリの `exclude` に `paths` と同じ書き方の glob で書く（例: `paths: ["**/*.html*"]` に `exclude: ["**/docs/_layouts/**"]`）
  - 外れるのはそのエントリだけで、同じ `rule` の別のエントリが当たればそのルールは案内される
- `tools` には「そのドキュメントに従ってほしい MCP ツール」の完全名に当てる glob を書く（サーバー名は `*` で受ける。例: `mcp__*__create_review_comment`）
- `on` には「そのルールへの追従が必須になる操作種別」（`read` / `write` / `mcp` の組み合わせ）を書く。省略時は索引の `default_on`（無ければ `["read", "write", "mcp"]`）に従う
- MCP のツールで書き込む文書の規約は、書き込みのツールを `tools` に記載し、`on` に `mcp` を含める
  止めずに案内すると、案内はツールの実行後に読まれる
- `paths` と `tools` は別々に照合され、書かなかった方は当たらない
- 既存エントリの `paths` と対象が重なってよい（一致したルールはすべて注入される）
  - 同じ `rule` のエントリが複数当たったときは 1 つにまとめて案内し、どれかの `on` に含まれる操作種別を必須とする（範囲ごとに `on` を変えたいときは、同じ `rule` を `paths` を分けて複数のエントリに書く）
- 索引が複数ある場合は、そのドキュメントを置いたリポジトリの索引に載せる
