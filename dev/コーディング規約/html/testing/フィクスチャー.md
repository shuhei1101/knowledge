## Factory-as-Fixture パターン（DB リソース準備の推奨形）

シナリオテストで「複数インスタンス作りたい」「引数付きでリソース作りたい」ケースは、**fixture が関数を返す** 形にする。
値を返す fixture で名前をハードコードする（`userA` 等）のは避ける。

- **1 fixture = 1 責務**（`createUser` / `createProfile` / `createTask` を分けて `tests/e2e/fixtures.ts` に並置）
- **依存はテスト本体で引数として明示**（`createProfile(userA)` の形）
- **cleanup は fixture 内で自動追跡** → `use()` の後で作成順の **逆順 delete** を回す
- **Playwright は要求された fixture だけ初期化** するので、テストは必要な factory だけ引数で受ける

```typescript
// tests/e2e/fixtures.ts
import { test as base } from "@playwright/test";

export const test = base.extend<{
  createUser: (name: string, role?: "user" | "admin") => Promise<User>;
  createProfile: (user: User, opts?: { visible?: boolean }) => Promise<Profile>;
  createTask: (user: User, title: string) => Promise<Task>;
}>({
  createUser: async ({}, use) => {
    const created: User[] = [];
    await use(async (name, role = "user") => {
      const u = await api.createUser({ name, role });
      created.push(u);
      return u;
    });
    for (const u of created.reverse()) await api.deleteUser(u.id);
  },

  createProfile: async ({}, use) => {
    const created: Profile[] = [];
    await use(async (user, opts = { visible: true }) => {
      const p = await api.createProfile(user.id, opts);
      created.push(p);
      return p;
    });
    for (const p of created.reverse()) await api.deleteProfile(p.id);
  },

  createTask: async ({}, use) => {
    const created: Task[] = [];
    await use(async (user, title) => {
      const t = await api.createTask(user.id, title);
      created.push(t);
      return t;
    });
    for (const t of created.reverse()) await api.deleteTask(t.id);
  },
});
```

テスト側は必要な factory だけ引数で要求:

```typescript
import { test } from "./fixtures";

test("ユーザーだけ", async ({ page, createUser }) => {
  const a = await createUser("A");
});

test("プロフィール編集", async ({ page, createUser, createProfile }) => {
  const a = await createUser("A");
  const p = await createProfile(a, { visible: true });
});

test("全部使う", async ({ page, createUser, createProfile, createTask }) => {
  const a = await createUser("A");
  const p = await createProfile(a);
  const t = await createTask(a, "既存タスク");
  // 終了時に t, p, a の順（LIFO）で自動 delete
});
```

- **アンチパターン**: `setupAllScenarioX()` のような god setup で全リソース作らない（単一責務を保つ）
- **アンチパターン**: fixture 内で名前ハードコード（`userA: async ({}, use) => { const u = await api.createUser({ name: "A" }); ... }`）→ 常に factory を返す形にする
- **アンチパターン**: `try/finally` で手動 cleanup を書く → fixture の `use()` 後に任せる（漏れ防止）
- **配置**: `frontend/tests/e2e/fixtures.ts` に factory-as-fixture を集約、各 spec は `import { test } from "./fixtures"`
