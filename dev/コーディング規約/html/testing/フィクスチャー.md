# Factory-as-Fixture パターン（DB リソース準備の推奨形）

シナリオテストで「複数インスタンス作りたい」「引数付きでリソース作りたい」ケースは、fixture が関数（factory）を返す形にする。

- 1 fixture = 1 責務（`createUser` / `createProfile` / `createTask` を分けて `tests/e2e/fixtures.ts` に並置）
- 依存はテスト本体で引数として明示する（`createProfile(userA)` の形）
- cleanup は fixture 内で作成したものを追跡し、`use()` の後で作成順の逆順に delete する
- テストは必要な factory だけを引数で受ける（Playwright は要求された fixture だけ初期化する）
- アンチパターン: `setupAllScenarioX()` のような god setup で全リソースを作る
- アンチパターン: fixture 内で名前をハードコードした値を返す（`userA` 等）。常に factory を返す
- アンチパターン: `try/finally` で手動 cleanup を書く。fixture の `use()` 後に任せる
- 配置: `frontend/tests/e2e/fixtures.ts` に集約し、各 spec は `import { test } from "./fixtures"`
