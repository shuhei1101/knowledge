# 型システム（汎用 TypeScript）

- TypeScript を使う全プロジェクト共通の型の書き方。`any` を避け、不明なら `unknown` で受けて絞る。
  - 公開 API（export する関数・型）には必ず型を付ける。局所変数は推論に任せてよい。
- 型エイリアスは `type` を使う。
  - `interface` はライブラリ拡張・declaration merging が必要なときだけ。
- 状態や種別は union リテラルで表し、文字列のべた書きを型で縛る。
- コールバック・依存の契約は関数型エイリアスにして名前を付ける。
  - 引数の型に使うと意図が読みやすい
- 汎用ユーティリティだけ generics を使う。
  - 制約（`extends`）を付けて緩すぎる型を避ける。
- 内部関数の戻り値を別の場所で使うときは手書きせず導出する。
  - シグネチャ変更に型が追従する。
- 型だけの import は必ず `import type`。
  - ランタイム import と混ぜない。
- グローバルな `types.d.ts` に集約しない。
  - 型はそれを所有するコードの近くに置く。
  - 狭い範囲なら同じファイル内（export 不要）、複数で使うなら一段上の共有層で export する
  - 範囲の判断は各スタックの配置ルールに従う。
