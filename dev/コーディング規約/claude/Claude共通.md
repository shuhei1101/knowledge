# Claude 成果物の共通ルール

## 簡潔に書く
- SKILL.md・ルール・CLAUDE.md を新規作成・編集するときは規約『文章の追記』の確認表に従う。

## 文の書き方
いい例: 箇条書きのインデントで表現
```md
- ブラウザに出す依存を増やさない。
  - フレームワーク（React/Vue）・状態管理ライブラリ・UI ライブラリは使わない
  - 外部依存がどうしても必要なときだけ vendoring する（`html/shared/vendor.md`）
  - dev ツール（tsc / eslint / vitest 等）は別（`html/tooling/tsc運用.md`）
```
悪い例: 横に長い。
```md
ブラウザに出す依存を増やさない。フレームワーク（React/Vue）・状態管理ライブラリ・UI ライブラリは使わない。外部依存がどうしても必要なときだけ vendoring する（`html/shared/vendor.md`）。dev ツール（tsc / eslint / vitest 等）は別（`html/tooling/tsc運用.md`）。
```

## スクリプトの配置場所
- スクリプトは`{pluginsルート}/scripts/{任意のカテゴリフォルダ}/`配下に配置します。
  - スクリプトは機能ごとにフォルダを分けてください。
- スキルから特定スクリプトを呼ぶときにmcpを仲介すること
  - これにより、スクリプト実行時の説明や引数の説明をスキル側に記載しなくてよいため
  - スキル内でスクリプトを呼ぶ場合は極力stdioのmcpに登録すると良い。

## メインエージェント / スキル / カスタムサブエージェントの関係

Claude Code は学習データにこの区別が入っていないので、明示的に理解して書き分けること。

### メインエージェント
- ユーザーと直接対話する Claude 本体。会話履歴を保持する主コンテキスト。
- スキルを呼び出すが、スキルはメインエージェントの中で読み込まれる。

### スキル（`skills/**/SKILL.md`）
- **メインエージェントと同じコンテキストで読み込まれるただのファイル**（別プロセスではない）。
- 戻り値の概念はない。スキル内で調査 / 収集した情報はメインエージェントのコンテキストに直接残るので、「戻り値」を書く必要はない。
- 入力は `arguments` フロントマターで宣言した位置引数（`$issue_number` 等）のみ。それ以外は「メインエージェントが知っていること」を前提にして良い。
- 書き方の禁止事項:
  - `## 戻り値` / `## 出力` セクションを作らない（同一コンテキストだから不要）
  - 「このスキルは呼び出し元に〜を返す」等の記述は書かない
  - スキル内のステップは「メインエージェントが順番に実行する手順書」として書く

### カスタムサブエージェント（`agents/**/*.md`）
- **別コンテキストで起動する独立プロセス**。呼び出し元の会話履歴・スキル内容・他ファイル情報を **一切持たない**。
- 情報源は **呼び出し時に渡された引数（入力）のみ**。それ以外は知らない前提で書く。
- サブエージェント側は呼び出し元を知らないので、呼び出し元のスキル名やフェーズ名を本文に書かないこと。
