# Security

## セキュリティヘッダ

`next.config.ts` の `headers()` で全レスポンスに付与:
X-Frame-Options (SAMEORIGIN) / X-Content-Type-Options (nosniff) / Referrer-Policy (strict-origin-when-cross-origin) / Strict-Transport-Security / Permissions-Policy。CSP は要件に応じて nonce 方式（proxy.ts で nonce 生成 → ヘッダに付与）。

## CSRF

- Server Actions は同一 origin チェック自動（追加対策不要）
- route.ts の mutation は Origin ヘッダ検証、または SameSite=strict cookie で防御

## XSS

- React の文字列補間は自動エスケープで安全
- `dangerouslySetInnerHTML` は DOMPurify で sanitize したものだけ渡す
- ユーザー入力 URL を `<a href>` に流すときは protocol を http/https に限定

## SQL Injection

- Drizzle の SQL Builder / `sql` テンプレートは parametrized で安全
- `sql.raw` への文字列結合だけが危険なので使わない

## Open Redirect

- `redirect()` に URL クエリ等の外部入力を直接渡さない
- `/` 始まりかつ `//` 始まりでないことを検証してから redirect

## Mass Assignment

- リクエスト body を Zod schema で parse してから DB に渡す（許可フィールドの制限）

## 認証セッション

- httpOnly + Secure + SameSite=strict cookie
- トークンは長いランダム文字列、30 日 + sliding renewal
- ログアウト時にサーバー側 token も無効化

## その他

- 全外部入力（body / action input / URL クエリ）を Zod で parse
- エラーレスポンスに stack / 内部詳細を出さない（ログに記録）
- secret は env / Vercel ダッシュボードのみ。`NEXT_PUBLIC_` を付けない。定期ローテーション
- CI で `pnpm audit --prod`
- 認証 API には厳しい rate limit、フォーム POST には CAPTCHA
- File upload はサイズ制限 + MIME ホワイトリスト + 別ドメイン保存
