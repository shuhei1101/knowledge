# appError.ts — エラークラス階層

- アプリ内のエラーは必ず AppError 派生を投げる（generic `Error` 直 throw しない）
- AppError は `message, statusCode, code, field?` を持つ
- `AppError.fromResponse(data, statusCode)` で API 失敗レスポンスから復元
- 内部詳細（stack・DB クエリ）をクライアントに見せない
- catch して握り潰さない（再 throw か handler に渡す）

## 階層と投げる場所

<!-- table: data -->

| クラス                 | status / code    | 投げる場所                                          |
| ---------------------- | ---------------- | --------------------------------------------------- |
| `ClientValueError`     | 400 / VALUE      | バリデーション失敗（route / action）。`field?` あり |
| `ClientAuthError`      | 401 / AUTH       | 認証・認可失敗（auth-context, service）             |
| `VersionConflictError` | 409 / CONFLICT   | 楽観的ロック衝突（db.ts の updateXxx）              |
| `QueryError`           | 500 / QUERY      | SELECT 失敗（query.ts）                             |
| `DatabaseError`        | 500 / DATABASE   | 書き込み失敗（db.ts, service.ts）                   |
| `RateLimitError`       | 429 / RATE_LIMIT | レート制限（proxy.ts, route.ts）                    |
| `AppError`（generic）  | 任意             | 404 / 403 等の汎用                                  |

<!-- /table -->

## 処理する場所

| 場所              | Handler                          |
| ----------------- | -------------------------------- |
| `route.ts`        | `withRouteErrorHandling`         |
| Server Action     | `handleActionError`              |
| クライアント hook | `handleAppError(error, router)`  |
| ルートバウンダリ  | `error.tsx` / `global-error.tsx` |
