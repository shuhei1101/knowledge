# 環境変数と設定

方針: 環境変数は秘密情報のみ、構造化設定は YAML（Python バックエンドと設定を共有できる）。

## どこに何を置くか

置き場所の判定は [設定値の置き場所](../../../判定フローチャート/設定値の置き場所.md) に従う。

| 値                                         | 置き場所                                                     |
| ------------------------------------------ | ------------------------------------------------------------ |
| DB password / OAuth secret / Stripe secret | `.env.local`（dev）/ Vercel ダッシュボード（prod）           |
| 環境ごとに変わる値（接続先・LLM モデル名） | `~/.config/{project}/settings.yaml`（git 管理しない）        |
| retry・timeout・機能フラグの既定値         | `config/defaults.yaml`（git 管理する）                       |
| その checkout だけの上書き                 | リポジトリ直下の `settings.local.yaml`（git 管理しない）     |
| 環境で変わらない定数（最大長等）           | `app/(shared)/constants.ts`（UPPER_SNAKE_CASE）              |

- `.env.sample` / `settings.sample.yaml` をテンプレとして git 管理（必要変数の正式リスト）

## NEXT_PUBLIC_ プレフィックス

- クライアントで読む値のみ付ける（ブラウザ JS にバンドルされ公開される）
- シークレットには絶対付けない

## ルール

- `serverRuntimeConfig` / `publicRuntimeConfig` は Next.js 16 で廃止 → `process.env.*` を直接使う
- ランタイム評価したい場合は `connection()` でバウンダリを張る
- env は `@t3-oss/env-nextjs` + Zod で型安全に一元化（`env.ts`）。`process.env` を散在的に読まない
- YAML は `app/(shared)/config.ts` の loader で 既定値 → 環境の値 → checkout の上書き の順に重ねて読み、Zod schema で parse、モジュールキャッシュ
- log level 等は env で YAML を上書き可能にする

## クライアントへの config 公開

| 方式                                           | 使いどき                     |
| ---------------------------------------------- | ---------------------------- |
| next.config.ts の `env` でビルド時インライン   | 変更頻度の低い値（推奨）     |
| API ルート + `useQuery`（staleTime: Infinity） | 再デプロイなしで反映したい値 |

## 機能フラグ

- `config/defaults.yaml` の `features:` に boolean（環境の値・checkout の上書きで上書きする）
- `app/(shared)/feature-flags.ts` の `isFeatureEnabled(name)` ラッパー経由で参照（将来 GrowthBook 等への置き換えを容易に）
