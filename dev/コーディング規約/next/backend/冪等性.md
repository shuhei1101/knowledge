# Next.js App Router — Idempotency

> 対象: 課金・通知送信・在庫減少など、二重実行されると致命的な POST。`Idempotency-Key` ヘッダで冪等性を担保する。
クライアントは UUID 等の一意キーを `Idempotency-Key` ヘッダで送る。
サーバーは利用者とキーの組に一意制約を付けて、レスポンスと期限とともに保存する。
同じキーで再来たら前回のレスポンスを返す（処理は走らせない）。

## どこに適用するか

| ケース                | Idempotency 必要?  |
| --------------------- | ------------------ |
| 課金 / 払い戻し       | ✅ 必須            |
| 通知 / メール送信     | ✅ 必須            |
| 在庫減少 / 予約       | ✅ 必須            |
| 一般的なフォーム POST | △ あると安全       |
| GET / PUT / DELETE    | ❌ HTTP 仕様で冪等 |
| PATCH                 | ❌ 楽観的ロックで二重適用を防ぐ |

## クリーンアップ

期限切れキーは Cron で定期的に削除する（期限の列で絞って DELETE する）。

## Stripe との連携

Stripe API は `Idempotency-Key` をネイティブサポートする（SDK では `idempotencyKey` オプション）。Stripe へ渡すキーはクライアントのキーに利用者 ID を含めて作り、利用者をまたいで衝突させない。
