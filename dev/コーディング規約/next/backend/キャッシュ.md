# Caching（Next.js 16）

`cacheComponents: true` を有効化（PPR が標準動作: 静的部分はプリレンダ、`cookies()` / `headers()` / `<Suspense>` 内はリクエスト時レンダ + ストリーム）。

## "use cache" + cacheLife + cacheTag

- データ取得関数の先頭に `"use cache"` を置き、`cacheLife` を併記する
- invalidate の対象にするデータには `cacheTag` を付ける
- `cacheLife` のプロファイルは公式の `cacheLife` を参照する

## invalidate API の使い分け

| API | 挙動 | 用途 |
| --- | --- | --- |
| `revalidateTag(tag, profile)` | stale マーク → 次の閲覧者は古いデータを見つつ背後で再生成 | 遅延 OK な更新（一覧・カタログ）。第 2 引数必須（Next.js 16） |
| `updateTag(tag)` | 即時 expire + 同リクエスト内で再フェッチ（read-your-writes） | フォーム保存・設定変更（Server Action 内のみ） |
| `refresh()` | client router の RSC payload を更新（`router.refresh()` のサーバー版） | mutation 後に画面を最新化 |

`updateTag` が使えない Route Handler・Webhook から即時に消すときは `revalidateTag(tag, { expire: 0 })`。

Server Action での典型: 自分が見る単体は `updateTag(`resource:${id}`)`、他人の一覧は `revalidateTag("resources", "max")`、最後に `refresh()`。

## 決定フロー

```
ユーザーごとに違うデータ? → キャッシュしない
どれくらい古くていい? → 即時=なし / 数分=minutes / 数時間=hours / 1ヶ月+=max
mutation 後に即時反映必要? → Yes: updateTag + refresh / No: revalidateTag(tag, "max")
```

マスター系（カテゴリ・アイコン等）は `cacheLife("max")` + 管理画面更新時に `revalidateTag`。
