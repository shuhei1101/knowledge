# Next.js App Router — Webhook Receiver

> **対象**: Stripe / GitHub / Slack 等の Webhook を受信するパターン。

## 配置

```
app/api/v{N}/webhooks/{provider}/route.ts
```

例: `app/api/v{N}/webhooks/stripe/route.ts`

## 重要ポイント

### 1. 署名検証

Stripe / GitHub / Slack それぞれの公式ライブラリで検証する。

| プロバイダ | 関数                                                      |
| ---------- | --------------------------------------------------------- |
| Stripe     | `stripe.webhooks.constructEvent(body, signature, secret)` |
| GitHub     | HMAC-SHA256 + secret で `X-Hub-Signature-256` 検証        |
| Slack      | HMAC-SHA256 + signing secret で `X-Slack-Signature` 検証  |

自前で検証するときは、署名を定数時間で比較し、タイムスタンプが古いリクエストは拒否する（リプレイ対策）。

### 2. raw body

署名検証には raw body が必要。`await request.text()` で生文字列を取得（`request.json()` だと検証に失敗）。

### 3. Idempotency

同じイベントが複数回届き、到着順も保証されない。`event.id` を `processed_events` テーブルに保存して二重処理を防ぐ（詳細パターンは `冪等性.md`）。順序や処理済みの判断にイベントの `created` を使わない。

### 4. レスポンス時間

Webhook は素早く 2xx を返すべき。重い処理は、短ければ `after()`（`next/server`）で応答後に回し、長ければジョブキューに積んで、即時 200 を返す。

### 5. リトライポリシー

再送の有無はプロバイダごとに違う（Stripe は 2xx 以外で再送、GitHub は自動再送しない）。再送してほしい失敗だけ 5xx を返す。

### 6. その他

- 署名シークレットの置き場所は [設定値の置き場所](../../../判定フローチャート/設定値の置き場所.md) と `shared/環境変数.md` に従う
- ロガーにはイベント ID・type・処理結果を記録
