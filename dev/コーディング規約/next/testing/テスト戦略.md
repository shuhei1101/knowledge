# テスト戦略

Stack: Vitest（Unit / Component）+ Playwright（E2E）+ Testing Library + MSW（任意）。
ピラミッド構造: ユニットで網羅し、E2E はクリティカルパスのみ。
テストの対応関係は設計書（モジュール構成 / 結合 / シナリオ）のテスト表が SoT で、テストは表と 1:1 で実装する。

## テストレベル

| Level       | Tool                     | 対象                                          | 比率 |
| ----------- | ------------------------ | --------------------------------------------- | ---- |
| Unit        | Vitest                   | 純粋関数・schema・util                        | 多   |
| Component   | Vitest + Testing Library | コンポーネント描画・操作                      | 中   |
| Integration | Vitest                   | service / db / API（実 DB or testcontainers） | 中   |
| E2E         | Playwright               | ブラウザでの重要フロー                        | 少   |
| External    | Vitest                   | 外部 API ラッパーの実接続（実際に使うパラメータ値の網羅） | 少   |

- Unit / Component の単位 = 1 ファイル。
  同一ファイル内のヘルパーは実物のまま、ファイル外 / プロセス外の依存は Mock する
- Unit は分岐ごとに 1 テスト以上置き、分岐カバレッジを極力 100% にする
- External は CI では実行しない。
  AI は、副作用が発生するか、見積もりが規約『開発時の従量課金APIの実行』の閾値を超える課金が発生するときは、ユーザーが実行を許可したときだけ実行する

## フォルダ構成

```
tests/
├── unit/                  # 単体テスト
│   ├── schema/
│   ├── service/
│   └── utils/
├── components/            # コンポーネントテスト
├── integration/           # 結合（service / route・1 ユースケース = 1 ファイル）
├── external/              # 外部疎通（実 API）
├── e2e/                   # E2E（画面単位フォルダ + ユースケース別ファイル）
│   ├── resources/
│   │   ├── list.spec.ts
│   │   ├── create.spec.ts
│   │   ├── edit.spec.ts
│   │   └── delete.spec.ts
│   ├── auth/
│   └── usecases/          # 横断ユースケース
├── pages/                 # Page Object Model
├── fixtures/              # テストデータ Factory
└── helpers/
    ├── db.ts              # DB シード・クリーンアップ
    ├── auth.ts            # ログイン済み状態を作る
    └── server.ts          # MSW handlers
```

## テスト関数の書式

- テスト名（`test` / `it` の説明文字列）は `{関数名}_when_{条件}` とし、期待値は名前に入れない（期待値が変わるたびに名前が変わるため）。
  条件分岐のない唯一のケースは `{関数名}` のみ
- 何を確認するか（設計書テスト表の概要 + 正常系 / 異常系）はテスト直前のコメントに書く
- 関数内を `// 準備` → `// 実行` → `// 検証` の順のコメントで区切る。
  例外検証のように実行と検証が一体になる場合は `// 実行・検証` にまとめる

```ts
// 19 歳は未成年と判定する（正常系）
test("is_minor_when_age_19", () => {
  // 準備
  const user = new User({ age: 19 });
  // 実行
  const result = user.isMinor();
  // 検証
  expect(result).toBe(true);
});
```

## カバレッジ

- 結合・E2E はカバレッジ率で縛らない（CUJ・重要ユースケースが通っているかを定性判断）

## CUJ（必ず E2E でカバーするフロー）

- 新規登録 → ログイン
- CRUD 一巡（作成 → 一覧 → 詳細 → 編集 → 削除）
- 検索・フィルタ・ソート
- 権限ガード（権限なしで編集 URL 直アクセス → 弾かれる）
- エラーハンドリング（ネットワーク失敗時の UI）

## 保守性

- セレクタは Page Object に、データ生成は Fixtures に集約
- mock は最小限。mock しすぎて振る舞いを検証できないなら integration に切り替える
- E2E でユニットレベルの検証をしない（unit に降ろす）
