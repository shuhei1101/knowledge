# Test Fixtures（Data Factory）

- 1 リソース = 1 fixture ファイル、`tests/fixtures/index.ts` でまとめて export
- 各 fixture は 4 点セットで提供
  - `build{Resource}(overrides?)` — デフォルト値 + overrides を返す（DB 保存なし）
  - `seed{Resource}(overrides?)` — 1 件 INSERT して row を返す
  - `seed{Resource}s(count)` — n 件 INSERT
  - `clean{Resource}s()` — 全削除
- 関連データは既存 fixture を組み合わせて連鎖生成（`seedResourceWithTags` 等）
- 名前は `nanoid(6)` suffix で一意化（並列実行の衝突防止）
- 固定値は const（`TEST_USER_ID`、`fixedDate`）
- enum 網羅ヘルパー（`ALL_RESOURCE_STATUSES` 等）を `as const` で

## DB cleanup 戦略

| 戦略                   | Pros       | Cons                                 |
| ---------------------- | ---------- | ------------------------------------ |
| 各 test 前に truncate  | 単純・確実 | やや遅い                             |
| transaction rollback   | 高速       | Vitest concurrent と相性悪い場合あり |
| testcontainers で別 DB | 完全分離   | セットアップが重い                   |

truncate は外部キーがあるテーブルから順に delete。`beforeEach` で truncate + 基本 seed。

## E2E 専用 seed API

E2E から DB を直接触れない場合はテスト専用 route を用意。`NODE_ENV === "test"` 以外は 403 で防御。
