# 入力と文言

入力・送信・エラー・通知の振る舞いと、画面に出す言葉。
画面の状態をどこに保持するか。
出典の略号は I = Impeccable、V = Vercel Web Interface Guidelines、GOV = GOV.UK Design System、C = IBM Carbon Design System（リンクは `## 出典`）。

## 入力と送信

| 要素 | 出典 |
| --- | --- |
| ラベルは常に見せる。入力欄の中の例示文をラベルの代わりにしない | V / I |
| 入力し終える前にエラーを出さない（1 文字ごとに検証しない） | GOV |
| 送信中は二重送信を防ぎ、処理中であることを見せる | V / I |
| 押せない理由が画面から読み取れないボタンを無効にしない。理由を近くに書くか、押したときに理由を示す | GOV |
| 取り返しのつかない操作には確認か取り消し猶予を置く。安全に戻せるなら確認より取り消しを選ぶ | V / I |

## エラーと通知

| 要素 | 出典 |
| --- | --- |
| エラーは原因の近くに、何が起きたかと直し方を書く。入力内容は消さない | V / I |
| 検証エラーが出たら、フォームの先頭にエラーの一覧を出し、各項目へのリンクを付けてフォーカスを移す。一覧と各項目の文言を揃える | GOV |
| 対応が要る通知（エラー・警告）は関係する場所に置き、自動で消さない。自動で消える通知は短い完了の知らせに限り、後から見返せる場所を用意する | C |
| 通知に置く操作は 1 つにする | C |

## 文言

| 要素 | 出典 |
| --- | --- |
| ボタンは起きることを動詞で書く（「OK」ではなく「Issue を作成」）。確認のボタンも操作名にする | V / I |
| 同じ概念は最後まで同じ言葉で呼ぶ（「公開」の結果は「公開しました」） | I |
| 内部の用語やエラーコードを主なメッセージにしない | I |
| 見れば分かるものにラベルを付けない（切り替えの部品の前の「ビュー:」等） | - |
| 文言は識別子より意味を先に書く（「v3.0.0（現在）」ではなく「現在（v3.0.0）」） | - |

## 状態の保持

| 保持するもの | 置き場所 | 出典 |
| --- | --- | --- |
| 共有したいもの（タブ・ビュー・絞り込み・並べ替え） | URL | - |
| 端末ごとの好み（列の表示・密度） | localStorage | - |
| 1 回の作業中だけのもの（入力途中の下書き・スクロール位置） | sessionStorage | - |
| 保存ビュー | サーバー（画面が書き込みの経路を持たないときは localStorage） | - |

未保存の入力があるまま画面を離れるときは警告する（V）。
