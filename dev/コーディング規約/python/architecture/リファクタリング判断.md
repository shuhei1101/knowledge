# リファクタ判断基準

## DRY 化 — 何回書いたら共通化するか

| トリガー             | アクション                                         |
| -------------------- | -------------------------------------------------- |
| 1 回目               | そのまま書く                                       |
| 2 回目（コピペ発生） | 共通化を検討開始                                   |
| 3 回目               | 必ず共通化（`_helpers.py` / `shared/utils.py` へ） |
| 4 回目以降に発見     | 共通化漏れ。最優先で潰す                           |

- ロジック 3 行以上で再利用候補なら関数化
- 1〜2 行の同じ式はインライン重複でも OK（共通化コストが上回る）

## 抽象化 — いつ型エイリアス / Protocol を切るか

| 状況                                  | アクション           |
| ------------------------------------- | -------------------- |
| 実装が 1 個                           | 抽象化しない         |
| 2 個目が見えた / テスト用 Mock が要る | 関数の型エイリアス   |
| 3 個以上 or 振る舞いが複雑            | `Protocol`           |
| 拡張ポイントが予定済み                | 最初から型エイリアス |

抽象化のコストは「読む人が辿る型ジャンプの増加」。毎回必要かを問う。

## 設定外出し — いつコードから出すか

| 種別                                       | 配置先                      |
| ------------------------------------------ | --------------------------- |
| 環境ごとに変えたい値（API キー・モデル名） | `.env` / `settings.py`      |
| 複数ファイルで参照する固定値               | `shared/constants.py`       |
| 業務的に固定の選択肢                       | `Literal[...]` or `StrEnum` |
| 長文 / テンプレート                        | `content/prompts/*.md` 等ファイル   |
| 非エンジニアが触る値                       | `settings.yaml`             |

- 「コード変更なしで値を変えたい」→ 設定へ

## 関数の長さ

- 関数が 40 行を超えたら、分けられないかを考える

## ファイル分割

| 状況                        | アクション                                          |
| --------------------------- | --------------------------------------------------- |
| 〜200 行                    | OK                                                  |
| 200〜400 行                 | 役割別（types / service / query / route）分割を検討 |
| 400 行以上                  | 分割推奨                                            |
| セクションマーカー 5 個以上 | 分割サイン                                          |

reference（`*.md`）は 1 ファイル 1 トピック原則（フック注入単位を小さく保つ）。
