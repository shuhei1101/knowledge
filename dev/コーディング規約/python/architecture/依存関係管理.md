# 依存方向のルール

```
features / server
        ↓
   integrations / runtime
        ↓
      shared
```

- `shared/` は誰にも依存しない（最下層）
- `integrations/` / `runtime/` は `shared/` のみに依存
- 同層内（features 同士、integrations 同士）の相互参照は基本禁止

## 同層参照が必要になったときの 3 パターン

| パターン                      | 使いどき                                    |
| ----------------------------- | ------------------------------------------- |
| shared に共通化して引き上げ   | 複数 feature が同じユーティリティを使う     |
| 関数の型エイリアスで DIP      | feature A が feature B のデータを必要とする |
| server でオーケストレーション | 複数 feature を組み合わせる処理             |

### 型エイリアス DIP の要点

- 利用側 feature の `types.py` に「自分視点の最小 DTO」（`UserMinimal` 等）と関数型（`type FindUserForChat = Callable[...]`）を定義
- 相手 feature の DTO 全体は知らない
- adapter（変換 + 配線）は `main.py` で書く

## 依存方向チェック

import 文の grep で検出できる:
- features 内に `from {pkg}.features.` がないか
- shared 内に shared 以外への `from {pkg}.` がないか
- integrations 内に `from {pkg}.features.` がないか

## 例外: 型のみインポート

`TYPE_CHECKING` 配下の型参照は実行時依存でないため緩く扱えるが、基本はそもそも参照しない設計を優先。
