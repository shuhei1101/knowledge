# composition root — 関数の配線

`main.py` で関数依存を組み立てる。クラスベース DI コンテナは使わない。

## 基本パターン

```python
@dataclass(frozen=True, slots=True)
class Handlers:
    """配線済み関数の束。"""
    generate_response: Callable[[str], Awaitable[str]]
    create_user: Callable[[CreateUserInput], User]

def build_handlers(settings: Settings) -> Handlers:
    chat = partial(chat_with_openai, api_key=settings.openai_api_key.get_secret_value())
    return Handlers(
        generate_response=partial(generate_response, chat=chat),
        create_user=partial(create_user, save=save_user, generate_id=generate_uuid_v7),
    )
```

- `Handlers` を dict でなく dataclass にする理由: タイポを静的検出・IDE 補完・配線一覧の明示
- 肥大化したら `_build_llm_handlers(settings)` 等カテゴリ別に分割（必要になってからで OK）

## FastAPI との組み合わせ

- `lifespan` で `app.state.handlers = build_handlers(settings)` をセット
- route からは `request.app.state.handlers` 経由でアクセス
- `build_fastapi(settings) -> FastAPI` で組み立て、`include_router` で集約

## CLI との組み合わせ

`__main__.py` で argparse → `Settings()` → `build_handlers` → 実行 → `sys.exit(main())`。

## テストでの差し替え

`build_test_handlers()` を conftest に作り、mock 関数を partial で注入。build 系は外部依存をすべて引数で受けるテスト前提の設計にする。

## ライブラリ標準クラスはそのまま使う

FastAPI（`APIRouter` / Middleware）、Pydantic（`BaseModel` / `BaseSettings` 継承）、typer / click の Command、asyncio の Task / Queue 等、公式がクラスを推奨するものは無理に関数化しない。
