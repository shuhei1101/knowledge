# パフォーマンスチートシート

最適化に着手する前に計測する。「推測するな、計測せよ」。

## 計測ツール早見表

<!-- table: data -->

| ツール                           | 用途                                         | 備考                    |
| -------------------------------- | -------------------------------------------- | ----------------------- |
| `time.perf_counter()` / `timeit` | 単発 / マイクロベンチ                        | 手書き計測              |
| `cProfile` + `snakeviz`          | 全体プロファイル（開発中）                   | 標準ライブラリ + 可視化 |
| `line_profiler`                  | 行単位（`@profile` + `kernprof -lv`）        | 特定関数を細かく        |
| `py-spy`                         | 本番 attach（`top` / `record -o flame.svg`） | 低オーバーヘッド 1〜3%  |
| `scalene`                        | CPU + メモリ + GPU を行単位                  | HTML レポート           |
| `memray`                         | メモリプロファイル                           | リーク調査              |
| `pytest-benchmark`               | 回帰ベンチ                                   | CI に組み込み可         |

<!-- /table -->

使い分け: どこが遅いか不明 → cProfile（開発）/ py-spy（本番）。特定関数 → line_profiler / scalene。メモリ → memray。cProfile はオーバーヘッドが大きいので本番では使わない。

## ホットパスのチェックリスト（試す順）

1. アルゴリズム改善（O(n²) → O(n log n)、最大効果）
2. 不要処理の除去（ループ内の関数呼び出しを外へ）
3. データ構造（`in` 判定は list → set / dict、連続アクセスは deque）
4. `@functools.cache` / `@cached_property` でメモ化
5. 文字列はループ `+=` でなく `"".join(parts)`
6. `list.extend` > append ループ、comprehension > map > for
7. 数値配列は NumPy / pandas
8. 並列化（`concurrency/並列処理.md`）
9. Cython / numba / Rust 拡張は最終手段

## メモリ最適化

`@dataclass(slots=True)` / `__slots__` / `array.array` / `numpy.ndarray` / ジェネレータ式 / `weakref`（循環参照切り）

## I/O 最適化

ファイル: バッファ調整・mmap。ネットワーク: コネクションプール（`httpx.AsyncClient`）・圧縮。DB: バッチ INSERT・インデックス・`EXPLAIN ANALYZE`。

## 注意

- 早すぎる最適化をしない（可読性 < ナノ秒の節約になっていないか）
- マイクロベンチを過信しない（その改善がシステム全体の何 % かを考える）
