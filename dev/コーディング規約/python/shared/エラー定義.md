# 例外階層

すべてのドメイン例外は `AppError` を継承する単一階層（`shared/errors.py`）。docstring のみのシンプルなクラス定義。

<!-- table: data -->

| クラス                    | 親               | 意味                             |
| ------------------------- | ---------------- | -------------------------------- |
| `AppError`                | Exception        | 基底                             |
| `ValidationError`         | AppError         | 入力検証エラー                   |
| `NotFoundError`           | AppError | 対象が見つからない               |
| `ConflictError`           | AppError | 状態競合（重複・楽観ロック失敗） |
| `ForbiddenError`          | AppError | 権限不足                         |
| `UnauthorizedError`       | AppError | 未認証 / 認証失敗                |
| `IntegrationError`        | AppError | 外部サービス連携                 |
| `IntegrationTimeoutError` | IntegrationError | 外部タイムアウト                 |
| `LlmError`                | IntegrationError | LLM API 由来                     |
| `LlmRateLimitError`       | LlmError         | レート制限                       |
| `LlmServerError`          | LlmError | 5xx                              |
| `LlmBadRequestError`      | LlmError | 4xx                              |
| `LlmAuthError`            | LlmError | 401 / 403                        |
| `LlmContentFilterError`   | LlmError | フィルタ拒否                     |

## 設計原則

- 最上位で `except AppError:` 1 つで全業務例外を捕まえられる
- vendor 例外（openai / anthropic / httpx）は境界でラップして外に流さない
  - features / server は `LlmError` 系だけ知ればよく、vendor 入れ替えで変わらない
  - リトライ判定が型で書ける
- メッセージは日本語 1 行、`raise X from e` で原因連鎖必須
- str を raise しない、広い `except Exception` で握りつぶさない

## 処理する場所

- FastAPI: `register_exception_handlers(app)` で HTTP マップ（`fastapi/認証とエラー.md`）
- CLI: `main()` で `ValidationError` → 2、`AppError` → 1、その他 → 99 のような終了コード分け
- 横断処理は `@catch_and_map` 等のハンドラーデコレータ（`core/デコレーター.md`）
