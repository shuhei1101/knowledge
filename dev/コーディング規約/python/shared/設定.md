# pydantic-settings による設定管理

既定値・環境の値・checkout の上書き・環境変数を `Settings(BaseSettings)` で型安全に読む（`shared/settings.py`）。
置き場所の判断（秘匿値・環境の値・既定値・定数のどこに置くか）は [設定値の置き場所](../../../判定フローチャート/設定値の置き場所.md) に従う。ここは Python での読み方だけを決める。

## 読み込み

- 設定の 3 段（既定値 → 環境の値 → checkout の上書き）は、`settings_customise_sources` で `YamlConfigSettingsSource` に `yaml_file` を並べて読む。後のファイルが勝つ。無いファイルは飛ばされる
- ネストした項目は `deep_merge=True` で重ねる（既定の浅い重ねでは、後のファイルが上位キーの中身ごと置き換える）
- `settings_customise_sources` が返す順が優先順。`init_settings` → `env_settings` → YAML の順にして、環境変数・引数が 3 段より勝つようにする
- 既定値の YAML が無くても飛ばされるので、項目の既定値はコードに持たず YAML だけに置く（欠けたら必須項目の検証エラーで起動時に止まる）
- YAML を読むには `pydantic-settings[yaml]` を入れる
- `~` は `Path.expanduser()` で展開してから渡す
- 秘匿値だけ `~/.config/{project}/secrets/` に分けるときは `secrets_dir` で読む

## 型と検証

- API キーは `SecretStr`（ログに出ない）。外部クライアントに渡す時だけ `get_secret_value()`
- `extra` は既定の `forbid` のままにする（YAML のキーの打ち間違いを検出する）
- 計算済みパス（`project_root` 等）は `default_factory` / `@property` で
- 検証は `@field_validator`（log_level の許可値チェック等）
- ネスト設定は `BaseModel` 入れ子。環境変数は `env_nested_delimiter="__"` で `DB__HOST` → `Settings.db.host`
- 環境変数名は `UPPER_SNAKE_CASE`、外部サービス系は `{SERVICE}_{NAME}`（`OPENAI_API_KEY`）

## 運用

- 秘匿値を持つファイルは、キーとプレースホルダだけを書いたサンプル（`settings.sample.yaml`）を対で置いて git 管理する
- `Settings()` は main.py で 1 度だけインスタンス化し、partial で各関数に埋める（関数内で毎回作らない）
- `os.environ` を直接読まない（型も検証もない）
