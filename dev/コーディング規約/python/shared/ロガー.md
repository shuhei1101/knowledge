# JSON Lines 構造化ログ

`print` ではなく logger。出力は JSON Lines（1 行 1 JSON）で集計・grep・dashboard 連携を見据える。

## 標準実装の要点（`shared/logger.py`）

- `JsonLinesFormatter(logging.Formatter)`: `{ ts, level, name, msg }` + `extra={...}` のフィールドを取り込み（LogRecord 予約キーは除外）、`exc_info` は `exc` に
- `json.dumps(..., ensure_ascii=False, default=str)`
- root logger はプロセスで 1 度だけ設定（フラグで二重登録防止）、stdout へ
- 各モジュールは `logger = get_logger(__name__)`（出力の name でどこから出たか即わかる）
- レベルは `Settings.log_level` から main で反映。本番 WARNING 以上、開発 DEBUG

## レベル運用

| レベル   | 用途                                             |
| -------- | ------------------------------------------------ |
| debug    | 開発時のみ（トレース、引数 dump）                |
| info     | 業務イベント（リクエスト受領、ユースケース完了） |
| warning  | 想定内エラー（retry で吸収、無効入力）           |
| error    | 想定外エラー（人間が対応すべき）                 |
| critical | プロセス継続不能                                 |

## 書き方

- 集計に使うものは構造化引数（`extra={"provider": ..., "tokens": ...}`）、一時的なデバッグは f-string
- 例外は `logger.exception(...)`（traceback が自動で乗る）して再 raise
- 機密情報（password / key）を extra に入れない
- ループ内の大量 debug は本番で INFO 以上に抑制

## 出力先

開発 / Docker / serverless とも stdout のまま。単発スクリプトのファイル保存はランチャー（bat / sh）側で tee。
