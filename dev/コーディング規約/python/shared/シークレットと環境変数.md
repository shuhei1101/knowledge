# シークレット / 環境 / 構造 / アセットの分離

置き場所の判定は [設定値の置き場所](../../../判定フローチャート/設定値の置き場所.md) に従う。
シークレットは git 管理下のファイルにもログにも書かない。

<!-- table: data -->

| 種別                                                 | 保管先                                                                     | git |
| ---------------------------------------------------- | -------------------------------------------------------------------------- | --- |
| シークレット（API キー / DB パスワード）             | `~/.config/{project}/settings.yaml`（本番は secret manager）               | ❌  |
| 環境の値（ローカルパス / ポート / 既定モデル名）     | `~/.config/{project}/settings.yaml`                                        | ❌  |
| その checkout だけの上書き                           | リポジトリ直下の `settings.local.yaml`                                     | ❌  |
| 既定値（項目の一覧と既定値）                         | `config/defaults.yaml`                                                     | ✅  |
| 構造定義（スキーマ / 選択肢 / カテゴリ）             | コード（`constants.py` / `Literal` / `StrEnum`）                           | ✅  |
| アセット定義（プロンプト / カタログ）                | `content/`                                                                 | ✅  |
| ランタイム状態（履歴・キャッシュ）                   | `data/`                                                                    | ❌  |

<!-- /table -->

- 秘匿値を持つファイルには必ずサンプル（`.env.sample` / `settings.sample.yaml`）を対で置き、そちらを git 管理する。
  必要なキーとプレースホルダだけを書き、実値は入れない
- シークレットと環境の値は、ホーム配下の `settings.yaml` 1 ファイルにまとめる。
  分けるほど設定の所在が散るので、git の外なら 1 箇所に集約したほうが扱いやすい
- シークレットだけ分けたいときは `~/.config/{project}/secrets/` に置き、pydantic-settings の `secrets_dir` で読む

## 環境変数の命名

- `UPPER_SNAKE_CASE`、外部サービス系は `{SERVICE}_{NAME}`（`OPENAI_API_KEY`）
- ネストは `env_nested_delimiter="__"` で `DB__HOST` → `Settings.db.host`

SecretStr の扱いは `shared/設定.md`。
