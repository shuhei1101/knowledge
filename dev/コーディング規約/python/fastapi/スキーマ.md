# 入出力 Pydantic スキーマ

- リクエスト / レスポンスは Pydantic、内部 DTO（`@dataclass`）とは分離
- 配置は `features/{feature}/schemas.py`（小規模なら `types.py` にまとめても可）
- 変換メソッドをスキーマ側に持たせて route をワンライナーにする
  - リクエスト側に `to_domain(self) -> DomainXxx`
  - レスポンス側に `@classmethod from_domain(cls, result) -> Self`

## Field

- 固定選択肢は `Literal[...]`（OpenAPI に enum として出る）

## camelCase 対応

フロントが snake_case を受け入れられるならそのままが一番楽。必要なら `ConfigDict(populate_by_name=True, alias_generator=...)` + `Field(alias=...)`。

## response_model

レスポンススキーマは戻り値の型注釈（`-> Response`）で指定する。`from_domain` で明示変換して返すのを基本にし、返す型と宣言したい型が合わないときだけ `response_model=` を使う。
