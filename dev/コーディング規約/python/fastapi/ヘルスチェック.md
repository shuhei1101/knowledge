# ヘルスチェック

- `/healthz` は `{"status": "ok"}` を返すだけ（プロセス生存判定）
- DB / 外部 API への疎通確認を入れない
  - 外部障害でヘルスチェックが落ちる → プロセス kill 連鎖で悪化
  - 重くなりトラフィックを圧迫、偽陽性も増える

## liveness / readiness を分ける場合

| 用途      | エンドポイント | 中身                                         |
| --------- | -------------- | -------------------------------------------- |
| liveness  | `/healthz`     | 200 を返すだけ                               |
| readiness | `/readyz`      | `app.state.ready` フラグ確認、未起動なら 503 |

lifespan の startup 完了時に `app.state.ready = True`。

## 依存先の状態を見たい場合

`/healthz/deep` のような診断用エンドポイントを別に作る。認証必須にし、load balancer の probe には使わない（監視・運用向け）。
