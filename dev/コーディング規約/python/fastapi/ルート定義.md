# ルーター実装パターン

ルーターは薄く。責務は 4 つだけ:
1. 入力パース（Pydantic）
2. 認証（Depends）
3. service 関数呼び出し
4. レスポンス変換

## 配置

- 基本は `features/{feature}/route.py`（feature 単位で完結）
- 複数 feature のオーケストレーションだけ `server/routes/`

## 書き方

- `APIRouter(prefix=, tags=)` を router 側で設定（`include_router` には付けない）
- 引数は `Annotated[T, Path/Query/Header/Depends(...)]` パターン
- 共通ロジック（認証等）は `Depends` を型エイリアス化（`CurrentUser = Annotated[User, Depends(get_current_user)]`）
- レスポンススキーマは戻り値の型注釈で指定（返す型と合わないときだけ `response_model=`。`fastapi/スキーマ.md`）、作成系は `status_code=201` を明示、`responses={...}` で OpenAPI に反映
- ストリーミング（SSE）は `response_class=EventSourceResponse`（`fastapi.sse`）で `ServerSentEvent` を yield し、終端は `ServerSentEvent(raw_data="[DONE]")`
- body を `dict` / `list` で受けない（必ず Pydantic）
- route 内で直接 DB / 外部 API を叩かない（service.py へ）
- 画面の HTML はテンプレートで組み立て、`html/core/サーバー描画.md` に従う
- 件数が増えうる一覧は最初からページに分け、次のページを取る手がかり（URL か cursor）を返す
- 時間のかかる処理は、受け付けた時点で 202 と状態を照会する先を返し、完了まで待たせない

## エラー処理

route 内で `HTTPException` を直接 raise しない。`NotFoundError` 等の AppError 系を raise し、exception_handler に HTTP 変換させる。
