# 認証と例外ハンドラ

## 認証パターン

- Bearer: `server/auth.py` の `verify_token`（Header から検証 → `AuthContext` dataclass を返す）を `Auth = Annotated[AuthContext, Depends(verify_token)]` に型エイリアス化
- API Key: `x-api-key` ヘッダを `settings.api_key.get_secret_value()` と比較
- Scope 検証: `require_scope(scope)` の Depends ファクトリで `ForbiddenError`
- 失敗時は `UnauthorizedError` を raise（HTTPException 直 raise しない）

## SecretStr

- `SecretStr` の扱いは `shared/設定.md`
- 認証失敗のログは warning 程度にする

## 例外ハンドラ

`server/error_handlers.py` の `register_exception_handlers(app)` で例外階層を一括 HTTP マップ:

<!-- table: data -->

| 例外                      | HTTP                          |
| ------------------------- | ----------------------------- |
| `ValidationError`         | 400                           |
| `UnauthorizedError`       | 401                           |
| `ForbiddenError`          | 403                           |
| `NotFoundError`           | 404                           |
| `ConflictError`           | 409                           |
| `LlmRateLimitError`       | 429（retry-after ヘッダ付与） |
| `AppError`                | 500                           |
| `IntegrationError`        | 502                           |
| `IntegrationTimeoutError` | 504                           |

<!-- /table -->

- 500 / 502 系はハンドラ内で `logger.exception`
- レスポンスは [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457.html) の Problem Details（`application/problem+json`。`type` / `title` / `status` / `detail`、拡張メンバーに `code` / `request_id`）に統一する
- Pydantic の `RequestValidationError`（デフォルト 422）もカスタム可
