# プロンプトローダー実装

`content/prompts/index.yaml` を読み、部品ファイル群を Jinja2 でレンダリングして 1 つのプロンプトに組み立てる。書き方は `llm/プロンプト執筆.md`。

## 構成

```
src/{pkg}/integrations/llm/prompts/
├── index_loader.py       # index.yaml の読み込みとキャッシュ
├── builder.py            # 部品結合 + Jinja2 レンダリング
└── types.py              # PromptPart / PromptSpec 等の DTO
```

プロンプト本体はリポジトリ直下の `content/prompts/`、ローダーは `src/` 配下。場所は `shared/constants.py` の `PROJECT_ROOT` から解決。

## index_loader.py

- `@cache` で 1 プロセス 1 回だけ読む（ホットリロードは `cache_clear()`）
- 戻り値は TypedDict（`PromptIndex`: parts / llms / display / legacy_aliases）

## builder.py

- Jinja2 `Environment` は `StrictUndefined`（未定義変数で即例外）+ `auto_reload=True`
- `render_part(rel_path, **vars)`: `.j2` は Jinja2 レンダリング、`.md` は静的読み込み
- `build_prompt(llm_id, **vars)`: `llms[llm_id].includes` を順に積んで `"\n\n".join`
- role 別に分けたいときは `build_bundle` で `PromptBundle(system, user)` を返す
  - Anthropic の `system=` 引数と分離でき、system 全体を 1 つの `cache_control` ブロックに包める
- 言語切替: `lang="jp"` のとき `.jp.{ext}` ミラーが存在すれば差し替え
- グループ化: 同じ category の連続部品を `## {h2ラベル}` で囲む拡張も可（display.categories 参照）

## ルール

- ローダーは pure な変換に限る（外部 API を叩かない）
- 部品パスをハードコードしない（index.yaml の includes が SoT）
- プロンプトをグローバル変数に持たない（vars が変わると不整合）
- 結合テストは実 LLM を呼ばず `build_prompt` の結果文字列だけ検証（未定義変数で例外が出ることも確認）
