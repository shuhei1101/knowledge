# LLM 例外階層とリトライ戦略

リトライ可否を例外の型で判断できるよう `LlmError` ベースで分類する。

<!-- table: data -->

| 例外                      | 意味         | リトライ                                            |
| ------------------------- | ------------ | --------------------------------------------------- |
| `LlmRateLimitError`       | レート制限   | ✅ 指数バックオフ（`retry_after` 属性があれば尊重） |
| `LlmServerError`          | 5xx          | ✅ 短い待ち                                         |
| `IntegrationTimeoutError` | タイムアウト | ✅ ジッタ付き                                       |
| `LlmBadRequestError`      | 4xx          | ❌ プロンプト修正が必要                             |
| `LlmAuthError`            | 401 / 403    | ❌ API キー要修正                                   |
| `LlmContentFilterError`   | フィルタ拒否 | ❌ 同じ入力は同じ結果                               |

<!-- /table -->

## with_retry デコレータ

- `@with_retry(retries=3, on=(...), base_delay=1.0, max_delay=30.0, jitter=0.2)`
- 指数バックオフ（`base_delay * 2^attempt` を max_delay でクランプ）+ ジッタ
- `LlmRateLimitError.retry_after`（Retry-After ヘッダから抽出してコンストラクタに渡す）があれば delay に優先採用
- リトライ時は warning ログ（attempt / max / exception / delay_sec）、最終失敗は error ログ

## タイムアウト

クライアントレベル（`AsyncOpenAI(timeout=30)`）+ デコレータレベル（`@with_timeout(seconds=60)`）の 2 レイヤー。
