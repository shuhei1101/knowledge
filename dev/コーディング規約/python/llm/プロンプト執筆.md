# プロンプトファイルの書き方と組み立て

プロンプトはコードに埋め込まずファイル化し、部品を細かく分割して index.yaml で組み立てる。

## 配置

```
{project_root}/
├── content/prompts/               # src/ の外（コードではない正本）
│   ├── index.yaml                 # 部品メタデータと組み立て定義の SoT
│   ├── characters/                # キャラごとの不変設定
│   ├── shared/                    # 横断部品（履歴・出力スキーマ・few-shot）
│   └── modes/                     # ユースケースごとの部品
└── src/{pkg}/integrations/llm/prompts/   # ローダー実装
```

非エンジニアでも編集でき、パッケージング時の同梱 / 分離も選べる。

## 部品の粒度

- 1 ファイル = 1 つの H3 セクション（先頭は `### {タイトル}`）、数行〜30 行目安
- 使わない情報をコンテキストに入れない（どの LLM がどのブロックを使うか可視化）

## 静的 vs 動的

| 拡張子 | 用途                             | キャッシュ               |
| ------ | -------------------------------- | ------------------------ |
| `*.md` | 静的部品（変数なし）             | プロンプトキャッシュ対象 |
| `*.j2` | Jinja2 テンプレート（{% raw %}`{{var}}`{% endraw %}） | リクエスト毎に変動       |

`modes/{mode}/static/` と `dynamic/` にディレクトリ分けし、組み立ては static → dynamic の順に積む（「固定値は上、動的値は下」をディレクトリで表現）。

## index.yaml

| キー             | 内容                                                                                |
| ---------------- | ----------------------------------------------------------------------------------- |
| `parts[]`        | 全部品の `path` + メタ（`kind` / `role` / `category`、任意で `lang` / `mirror_of`） |
| `llms[]`         | 各 LLM 呼び出しの `includes` リスト（並び順 = 積み順 = キャッシュ境界）             |
| `display`        | UI 表示名・H2 グループラベルの多言語定義（任意）                                    |
| `legacy_aliases` | 旧パス → 新 ID（リネーム後方互換、任意）                                            |

- Python 側にパス一覧（`STATIC_PARTS = [...]` 等）をハードコードしない
- 部品追加は `parts[]` + 対象 `includes[]` への追記だけで済む形を保つ（A/B テストも includes 差し替えで）

## i18n ミラー

日英両方持つ部品は `.jp.j2` / `.jp.md` のファイル名サフィックス。index.yaml に両方載せ `mirror_of` で対を明示、ローダーが `lang` で切り替え。
