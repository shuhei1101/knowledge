# 言語ルール

## 文字種・言語の使い分け

<!-- table: data -->

| 対象 | 言語 |
| --- | --- |
| コメント / docstring | 日本語 |
| 識別子（変数 / 関数 / 型 / モジュール） | 英語 |
| `print()` / `logger` の出力文字列 | 日本語 |
| bat / PowerShell スクリプトの出力 | 英語（エンコーディングでバグるため） |
| 例外 raise 時のメッセージ | 日本語 |
| UI 表示文字列 | 日本語 |

## 文字列フォーマット

- f-string を標準にする（i18n が必要な場合のみ gettext）
- logger は検索性重視なら構造化引数（extra）、開発ログは f-string

## import の並び

ruff の `I` ルールで自動整理。`from __future__ import annotations` → 標準ライブラリ → サードパーティ → 自パッケージの順、グループ間に空行 1 つ。

## 例外

- ドメイン例外は `AppError` 継承（階層は `shared/エラー定義.md`）
- 広い `except Exception:` はハンドラーデコレータ / 最上位ハンドラのみ
- vendor 例外（anthropic / httpx 等）は `IntegrationError` 系にラップ
- `raise X from e` で原因例外を必ず連鎖
- Result 型 / Either は使わない（例外を普通に投げる）
- 横断関心事（ログ・リトライ・例外変換）はハンドラーデコレータで束ねる
- `assert` を実行時の検査に使わない（最適化モードで消える）。前提の確認は例外を投げる。テストの `assert` は可
- `try` に入れるのは失敗しうる行だけにする

## ロギング

- `print` ではなく `logger`
- debug: 開発時のみ / info: 業務イベント / warning: 想定内エラー / error: 想定外 / critical: 継続不能

## エンコーディング

- すべて UTF-8、BOM なし
- Windows でのファイル読み書きは `encoding="utf-8"` を明示
