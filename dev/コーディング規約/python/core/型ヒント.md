# 型ヒント

Python 3.12+ 必須。PEP 695 で書く。

## 基本

- `from __future__ import annotations` を全ファイル冒頭に置く
- 関数 / メソッドの引数と返り値には必ず型注釈。クラス属性 / モジュール変数にも
- `Any` は最終手段（理由をコメントで残す）

## PEP 695

- 型エイリアスは `type X = ...` 文（`TypeAlias` import は使わない）
  - 識別子型: `type UserId = str`
  - 関数型: `type AsyncChatFn = Callable[[ChatMessages], Awaitable[str]]`
- ジェネリクスは `def first[T](xs: list[T]) -> T | None` / `class Pair[K, V]` 形式
- 制約付きは `def parse[T: BaseModel](raw: str, schema: type[T]) -> T`

## NewType vs type 文

| 用途                                   | 推奨                     |
| -------------------------------------- | ------------------------ |
| 読み手のための別名（`str` と区別されない） | `type UserId = str`      |
| 型チェッカーで厳密に分離（明示キャスト必須） | `NewType("UserId", str)` |

プロジェクト内でどちらかに統一する（混在しない）。

## 使うべき typing 機能

| 機能                       | 使いどき                                                 |
| -------------------------- | -------------------------------------------------------- |
| `Self`                     | 自分自身の型を返すメソッド                               |
| `@override`                | スーパークラスのメソッド上書き（タイポ検出）             |
| `Annotated`                | Pydantic Field / FastAPI Depends・Query のメタデータ付与 |
| `TYPE_CHECKING`            | 重いモジュールの型のみ import / 循環 import 回避         |
| `Literal` + `assert_never` | match 文の網羅性チェック（値追加を型エラーで検知）       |

- Pydantic のモデルのフィールドと FastAPI のルートの引数・戻り値が使う型は `TYPE_CHECKING` の中で import しない（実行時に型を解決する）
- DTO 使い分け（Pydantic / dataclass / TypedDict / Protocol）は `architecture/TypeScriptスタイル適用.md`
- デコレータ・`@overload` は `core/デコレーター.md`
