# コメントルール

言語・履歴コメント禁止などの共通原則は `dev/コーディング全般.md`。本ファイルは Python 固有の詳細。

- AI と共同で書く前提なので多めに書く
- コメント量はコードの非自明さに従う。レイヤーで分けない（サービスもヘルパーも同じ濃度）

## 必須 / 推奨マトリクス

<!-- table: data -->

| 対象                               | 要否      | 形式                                           |
| ---------------------------------- | --------- | ---------------------------------------------- |
| export する関数 / 型、public 関数  | ✅ 必須   | 1 行 docstring                                 |
| 内部関数（`_` 始まり）             | ⚠️ 推奨 | 複雑なら必須                                   |
| 設計上重要なフィールド             | ✅ 必須   | `Field(description=...)` or インラインコメント |
| 自明なフィールド                   | ❌ 不要   |                                                |
| 複数ステップを持つ関数の各ステップ | ✅ 必須   | `#` で各ステップの意図                         |
| 条件分岐                           | ✅ 必須   | 分岐ごとに「条件の意味 + 何をするか」          |
| 自明な 1 行・`logger.*` の行       | ❌ 不要   |                                                |

<!-- /table -->

「設計上重要なフィールド」= 外部キー / ステータス enum / 業務フラグ / 楽観ロック / 監査カラム / 業務的に複雑な意味を持つもの。

## docstring

- 1 行で目的だけ書く（型は signature が持つので `@param` / `@returns` は書かない）
- 複数行が必要なら 1 行目に要約、空行、詳細

## 条件分岐の書き方

読み手がコメントだけで判断ツリーを追えるようにする:

```python
# 在庫が残っているか
if stock.remaining > 0:
    # あり: 通常購入フロー
    order = _place_order(stock, qty)
elif stock.restock_eta is not None:
    # 切れているが再入荷予定あり: 予約として受け付ける
    order = _reserve(stock, qty)
else:
    # 完全な在庫切れ: 購入不可エラー
    raise OutOfStockError(stock.id)
```

自明な分岐（`if x is None: return`）だけ省略してよい。
