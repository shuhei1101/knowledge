# プロンプトファイル

プロンプトは 1 ノード 1 枚の YAML に書き、英語の本体と日本語のミラーをキーで持つ。

## 配置

- 1 ノード（LLM の呼び出し 1 種類）に YAML 1 枚を置く
- `prompts/{node}.yaml` を平らに並べ、サブフォルダを作らない
- 置き場所はリポジトリ直下の `content/prompts/`（[コンテンツの置き場所](../dev/コンテンツの置き場所.md)）

## 形

1 枚の中に、メタデータと部品の配列 `parts` を持つ。

| キー | 内容 |
| --- | --- |
| `id` | プロンプトの識別子（ファイル名の `{node}` と同じ） |
| `node` | 人が読むノードの名前 |
| `tags` | 分類のタグ |
| `vars` | 本文で使う変数の型と必須 |
| `output` | 出力の形 |
| `parts` | 部品の配列。並びが積み順になる |

部品は次のキーを持つ。

| キー | 内容 |
| --- | --- |
| `id` | 部品の識別子 |
| `role` | `system` / `user` など、積む先 |
| `when` | 使う条件。`vars` を使う Jinja2 の式で、無い部品は常に使う |
| `text.en` | 英語の本体 |
| `text.jp` | 日本語のミラー |

```yaml
id: reply
node: 返答生成ノード
tags: [chat]
vars:
  max_chars: {type: int, required: true}
parts:
  - id: rules
    role: system
    text:
      en: |
        Reply within {{ max_chars }} characters.
      jp: |
        {{ max_chars }} 文字以内で返答する。
```

## 本文

- 本文は YAML のブロックスカラー（`|`）に Jinja2 で書き、未定義の変数はエラーにする（StrictUndefined）
- 実行時に読むのは `text.en` だけで、`text.jp` は人が読むためのミラー
- `text.en` を直したら同じ変更で `text.jp` も直す
- 字数・件数などの値は本文に書かず、変数で渡す
- 日本語でしか書けない中身（キャラクターの語尾・話し方）は入力の値として渡す
- 変数を含まない部品を上、含む部品を下に並べる（[コストとキャッシュ](../python/llm/コストとキャッシュ.md) のキャッシュ境界）

## 検査

形はスキーマの YAML（例 `prompts/_schema.yaml`）で定義し、各プロジェクトが書く。
スキーマにはこのページのキーを持たせ、次を検査する。

- `vars` に無い変数を本文で使っていない
- `text.en` と `text.jp` がそろっている

## 更新

更新の MCP の口があるプロジェクトでは、YAML を直接編集せず MCP から更新する。

## 採らない形

- Markdown を残して YAML でメタデータを外付けする形
- 全部を 1 枚の YAML にする形
