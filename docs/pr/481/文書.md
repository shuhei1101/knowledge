## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 記録の参照 | 記録 R-33・A-71 と R-3 の B・C の技法の行ごとに中身を確認し、技法を 1 文書の単位に切り分ける | 似た技法は、記録をまたいでも 1 文書にまとめる |
| 配置先の判定 | 技法ごとに、ノウハウ・規約・knowledge に配置しないもののどれかを `knowhow-01`・`knowhow-02` で判定し、判定の一覧をこの計画書に記載してレビューで確定する | 既存の規約・ノウハウと同じ内容なら登録せず既存の文書を指す。A-71 のノードが毎回従う原稿は登録せず、元の技法だけを登録する |
| ノウハウの文書 | `write_docs` で `kind: knowhow` の文書を作る。ID は `knowhow-script-{topic}`、`visibility` は `internal`、`last_reviewed` は登録した日 | `necessity`・`scenes`・`cases`・`evidence`・`confidence` はスキーマの `x-rules` で決める |
| 既存の文書への追記 | #478 の技法のうち既存の文書に追加するものは、`write_docs` の `update` でその文書の記述と `sources` に追加する | 既存の記述は変えない |
| タグ | 付ける前に `search_docs` の `group_by: tags` で使用中のタグを確認し、同じ意味のタグを再利用する | `topic:ノウハウ` は全ての文書に付ける |
| 出典 | 記録の出典名から URL を引き直して `sources` に記載する | URL を引けなかった技法は登録せず、調べた出典と引けなかった旨をこの計画書の判定の一覧に記載し、`要件.yaml` のスコープ外に挙げる。後続の扱いはユーザーへの確認事項で確定する |
| 更新ドキュメントの表 | 登録した文書を `要件.yaml` の `docs` に追加する | 新規作成する文書の ID は技法の切り分けで決定する |

## 技法ごとの判定

出典の URL はスキーマの `sources[].url` で必須のため、URL を引けて該当箇所を本文か見出しで確認した出典だけで文書を作った。
`confidence` は登録した `evidence` からスキーマの `x-rules` で決めた（記録の確度とは別に決め直した）。
URL を引けなかった技法は登録していない。
