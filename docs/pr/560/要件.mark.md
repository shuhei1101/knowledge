# 要件

## 要望

アプリが実行中に書き換えるデータを、リポジトリに配置するか Git の管理外に配置するかを、規約で判定できるようにする（起点 Issue の決定。D-867 の案 A・D-872）。

| データ | 配置先 | 書き込みの残し方 |
| --- | --- | --- |
| 端末に依存する設定（接続先・パス・秘匿値） | Git の管理外（今のとおり。判定フローチャート『設定値の置き場所』） | - |
| 利用者と AI が育てるデータ（定義・メタデータ・一覧） | 実行中に書き換わっても、リポジトリの `content/` | 書き込みのたびに稼働しているブランチへ直コミット（project-index の `write_docs` の `commit`）か、通常のコミット |
| 実行の記録（履歴・キャッシュ・ジョブの結果・会話の記録）と大きいファイル（音声・画像・動画） | Git の管理外のデータのフォルダ（`data/`） | - |

- 規約『コンテンツの置き場所』の「配置するもの」に、アプリが実行中に書き換える定義・メタデータ・一覧を追加する
- 同規約の「配置しないもの」の「ランタイムの状態」を、実行の記録と大きいファイルに言い換える
- メタデータの YAML だけを `content/` に配置し、ファイルの本体（画像・音声）を `data/` に配置するアセットの例を同規約に記載する
- 判定フローチャート『設定値の置き場所』の概要の対象外の案内に、実行中に書き換わる定義・メタデータ・一覧も『コンテンツの置き場所』に従う旨を追加し、q3（実行中に書き換わる状態か）が実行の記録を指すと分かる記載にする
