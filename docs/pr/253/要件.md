# 要件

## 要望

knowledge の `dev/` を廃止し、文書を `docs/` 1 つにまとめる。
置き場所は [ai-monitor#3307 の `### 種類のフォルダ`・`### 置き場所の規則`](https://github.com/shuhei1101/ai-monitor/blob/cc97586e6/dev/pr/3307/%E3%83%A2%E3%83%8B%E3%82%BF%E3%83%BC.md) に従う。
1 回の PR で移し、レビューを通した後はこのプロジェクトでマージする。

### 移す順番

1. `dev/` の置き場所のまま、ai-monitor の [f135cff63](https://github.com/shuhei1101/ai-monitor/commit/f135cff63c1f6b4089f3db4bfdc1b2cb5bcdcb71)（ai-monitor#3307 のマージの直前の commit）の `dev/テンプレート/変換/v0.4.0.py` で、設計書の参照をパスから ID へ書き換える
2. 下の表のとおりに移す
3. `dev/` を指すパスを、移した後の置き場所に合わせる

### 置き場所

### 公開範囲

- `dev/` から移す文書に `visibility: internal` を付け、`dev-docs.yaml` の `documents[]` へ行を追加する
- 今の `docs/` の文書の `visibility` は変えない
- Pages は `scripts/build_pages.py` の `visibility` の絞り込みで `internal` を出さない（ai-monitor#3307 の `docs/_config.yml` の `exclude` など Jekyll 前提の項目は読み替える）

### パスの追随

`dev/` を指す次のパスを、移した後の置き場所に合わせる。

- `rules.yaml` の `**/dev/設計書/**`・`**/dev/pr/**` などの `paths`
- `.gitignore` の `dev/generated/`
- `schemas/design/*.schema.yaml` の `x-folder`
- `dev-docs.yaml`（`documents[]` の行の追加）
- `CLAUDE.md`・`README.md`（`dev/` を指す記述があれば）
- `ai-monitor-version.ini`（v0.4.0 の変換を掛けた後の版）

`未確定`: AI Monitor の設計書のスキーマのコピーと knowledge の文書のスキーマの名前の重なり（決める工程: インターフェース定義設計）

AI Monitor は設計書のスキーマを `schemas/{kind}.schema.yaml` から参照する（`TEMPLATES_DIR = "schemas"`）。
knowledge の `schemas/` には knowledge の文書のスキーマの `common.schema.yaml`・`files.schema.yaml` があり、AI Monitor のコピーの `common.schema.yaml`・`files.schema.yaml` と名前が重なる。
両方の `common.schema.yaml` が型の違う `$defs/id` を持つため、1 つのファイルにまとめられない。
`scripts/check_all.py` は `schemas/*.schema.yaml` の全てに knowledge のメタスキーマを適用するため、コピーを配置すると検査の対象が変わる。
決まるまで、`dev/テンプレート/` のスキーマのコピーと変換を残し、`dev-docs.yaml` の `documents[]` に設計書の行を追加しない。

| 案 | 内容 |
| --- | --- |
| A | knowledge の文書のスキーマの 2 件を重ならない名前に変え、`$ref`・`yaml-language-server` の行・`dev-docs.yaml`・スクリプト・テストの参照を合わせる。AI Monitor の develop のコピーを `schemas/{kind}.schema.yaml`、変換を `schemas/conversions/` に配置し、`check_all.py` の knowledge のスキーマの検査から除外する |
| B | AI Monitor に設計書のスキーマのフォルダを設定で変えられるようにする Issue を起票し、それまで AI Monitor のコピーを配置しない |

推奨: A

B は AI Monitor の変更を待つ間、設計書の検証が動かないため。
AI Monitor のバージョンアップの配布も `schemas/` の同じ名前のファイルを書き換えるため、名前を変えない限り knowledge の 2 件が上書きされる。
