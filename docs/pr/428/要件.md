# 要件

## 要望

knowledge の今の書き方のマーカーを mdmark の JSON の記載へ移し、`mdmark check` が `legacy_mark` を出さない状態にする。
範囲は次の 5 つ。

| 範囲 | 内容 |
| --- | --- |
| 変換のスクリプト | `scripts/knowledge_markdown.py`（converters が表を包むマーカー）・`scripts/build_templates.py`（`_TABLE_OPEN`）を JSON の記載で出す形へ修正し、設計書と `tests/unit/scripts/`・`tests/integration/scripts/` の期待値（`test_knowledge_markdown.py`・`test_build_templates.py`・`test_check_all.py`）を追随させる |
| `docs/` の YAML の本文 | `docs/pr/` を除く YAML の本文の行だけの `<!-- table: data -->` を JSON の記載にする（`mdmark upgrade` は YAML の本文を書き換えないため） |
| `docs/pr/` の PR ドキュメント | Markdown へ `mdmark upgrade` を適用し、移行の報告に挙がる記載（拡張・`libraries` のマーカー、書き出さない記載）を記載し直す |
| `docs/template/` | 生成元のスキーマを持つテンプレートは `scripts/build_templates.py` で生成し直す |
| `docs/*/README.md` | 手で直さず、AI Monitor の `python -m ai_monitor.design_docs publish` で生成し直す |

終わりの条件:

- 作業ブランチで `mdmark check` が `legacy_mark` を出さない（`docs/pr/{番号}/テスト結果/` の `.log` は対象外）
- 全ての文書の検査（`scripts/check_all.py`）が通る
- マージした後に [shuhei1101/mdmark#478](https://github.com/shuhei1101/mdmark/issues/478) へ完了をコメントする

`<!-- embed: {文書の ID} -->` は knowledge の変換のスクリプトが mdmark に渡す前に展開する独自のマーカーで、mdmark の記法に無いため、今の書き方のまま残す。
