# 要件

## 要望

シナリオの `scenarios[].flow` を mdmark の map（`<!-- map -->`〜`<!-- /map -->` の中に mermaid のブロックと補足を置く図。D-51・D-52・D-56）で記載し、テンプレート『シナリオ』と `docs/scenario/` の設計書に map の外の Mermaid の図が残らない。

### スキーマ

- `schemas/design/scenario.schema.yaml` の `flow` を、`common.schema.yaml#/$defs/mermaid` の参照から map で記載する型の参照にする
- `flow` の `description`・`x-rules`・`x-used-by` を map の書き方に合わせる（単一ユースケースは `sequenceDiagram`、複合ユースケースは単一ユースケースをノードにした `flowchart`。1 図 = 結末 1 本の一本道）
- 記載例（`examples`）の図を map で記載し直す
- `common.schema.yaml` の `$defs/mermaid` は、インターフェース定義の `flow` とモジュール構成の `diagrams[].diagram` が参照するので残す
- map の型は `common.schema.yaml` に `$defs/map` を追加し、`flow` から参照する（[#251](https://github.com/shuhei1101/knowledge/issues/251) がインターフェース定義の `flow` とモジュール構成の図を map にしたときも同じ型を参照する）
- 複合ユースケースのノードから `click` で単一ユースケースへリンクする決まりは削除する（map は `click` の行を読み捨てる）。指す先は `scenarios[].uses` が持つ

### 設計書

- `docs/scenario/` の全ての設計書の `scenarios[].flow` を map で記載し直す。図の中身（登場するもの・やり取りの順番・ノード）は変えない

### テンプレート

- `scripts/build_templates.py` で `docs/template/template-scenario.yaml` を生成し直す

### 確認

- 全ての文書の検査（`scripts/check_all.py`）が通る
- 書き直した map を mdmark の点検に通し、誤りが無い

### 設計書のスキーマのタグ

- 既存のシナリオが新しい記載方法と合わなくなる変更なので、`design-schemas/v*` のメジャーを上げる（今の最新は `design-schemas/v4.0.0`）
- タグは [#252](https://github.com/shuhei1101/knowledge/pull/252)・[#266](https://github.com/shuhei1101/knowledge/pull/266) と同じく、この PR を develop へマージした後に planner が develop の squash commit へ打つ（反映作業）
