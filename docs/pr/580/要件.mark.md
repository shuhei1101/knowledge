# 要件

## 要望

- レビューのチェックシート（`checksheet-review-*`）が、観点を 1 件 = 1 要素の構造で持てるようにする。各要素は ID・観点名・確認すること・補足と、成果物の種類（`target:`）・工程（`process:`）のタグを持つ
- タグの語彙は [shuhei1101/ai-monitor#3826](https://github.com/shuhei1101/ai-monitor/pull/3826) の `docs/checksheet/review-aspects-*.yaml` と同じ書式（`target:{成果物の種類}`・`process:{工程名}`、種類によらない観点は `target:共通`）にし、AI Monitor の観点と同じタグの値で検索できるようにする
- `project-index.yaml` に、観点 1 件を 1 文書として配信する `records` の行を追加し、`nav` に観点の文書のまとまりを追加する
- `checksheet-review-common` の観点（表の 20 行）を、新規の構造の要素へ書き換える。ページの ID `checksheet-review-common` は変えず、ID で取得する利用者は引き続きページを取得できる
- 検査（knowledge-checks）は、観点の ID の重複と、観点の本文の `id:` の参照先の実在を、`items[]` と同じく違反にする
- 変換（knowledge-markdown）は、ページの Markdown に観点を表で出す
- 全ての文書の検査（`scripts/check_all.py`）が、追加した行の文書にもスキーマの検査と文書の違反の検査を適用し、合格する
- `search_docs` を `source: knowledge` と `target:共通` のタグで絞ると、`checksheet-review-common` の観点が 1 件ずつ 20 件返ることを確認する

観点を持つファイルの配置は、チェックシートのスキーマに観点の配列 `aspects` を加え、`checksheet-review-*.yaml` のページの中に観点を持つ。
`project-index.yaml` には、同じファイルを `records: aspects` で指す種類 `review_aspect` の行を、`checksheet` の行の後ろに追加する。
観点の ID は `aspect-{ファイル名から checksheet- を除いた名前}-{2 桁の番号}`（`aspect-review-common-01`）にする。
