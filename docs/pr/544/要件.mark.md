# 要件

## 要望

knowledge の SKILL.md の生成と検査を `project-index skill-md`（project-index の IF-37）へ切り替える。

- 配信元の設定 `project-index.yaml` の `generators[]` に `[project-index, skill-md]`、`validators[]` に `[project-index, skill-md, --check]` を登録し、スキルのエージェントフローの行から呼ぶ
- スキルのエージェントフロー（`docs/skill/*.yaml`。`type: flow` の `meme-research.yaml` を含む）を、`agent_flow` の行の置き場所 `docs/agent-flow/*.yaml` へ中身を変えずに移す
- 移した後に `project-index skill-md` で生成した `skills/*/SKILL.md` が、生成元のコメントのパスのほかは今の SKILL.md と同じ中身になる
- 独自の生成のコマンド（`scripts/build_skills.py`・ロック・単体と結合のテスト・IF-312-1・MOD-312-1・SC-312-1）を削除する
- 全ての文書の検査（IF-72-3 / `scripts/check_all.py`）から、SKILL.md と生成元の比較を外す

`未確定`: 配信元 `knowledge` の種類の ID（決める段: インターフェース定義設計）

| 案 | 内容 |
| --- | --- |
| A | 種類の ID を `skill` から `agent_flow` に改め、`alias_type` も合わせる。`kind: skill` で引いている箇所（`rules.yaml` の `operations.kind` 等）を直す |
| B | 種類の ID は `skill` のまま、`paths` だけを `docs/agent-flow/*.yaml` に改める |

推奨: A

`project-index skill-md` は配信元の設定の `agent_flow` の行を生成の対象にするため、行の ID を `agent_flow` にしないと生成の対象にならない。
ほかのリポジトリの手順・設定から `source: knowledge`・`kind: skill` で引いている箇所は、ホームの `repo/` の下の grep では見つかっていない。設計の工程で他のリポジトリの設計書を引いて確かめ直す。
