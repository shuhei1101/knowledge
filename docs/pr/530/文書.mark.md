## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 配信元の設定 | 新規の配信元の設定のファイルに、作品とネットミームの `documents[]` の 2 行・検査・`direct_commit`（`branch: develop`・`kinds` に 2 つの種類）を記載する。`alias_type` は持たせない | 配置先は直下の `memes/`、配信元の ID は `knowledge-memes` |
| スキーマ | 作品とネットミームのスキーマを `memes/schemas/` に新規作成する。条件があるキーは `if`・`then` にする | キーは MindStella の資料『データ: ネットミーム』のとおり |
| 共通のキーへの対応 | `documents[].metadata` で `name`・`description`・`tags` を対応させ、`related`・`status` には対応させない | ネットミームの `description` は `context` |
| 検索の分離 | 規約の配信元の `documents[]`・`files.yaml` の範囲から、新規の配信元のフォルダを除外する | 規約の検索の結果とタグの集計に混ざらない |
| 使い方 | 新規の配信元を端末の設定の `sources[]` に登録する手順と、`direct_commit.scope` の記載を追加する | - |

## 実装

| 項目 | 内容 |
| --- | --- |
| 共通のキーへの対応の差 | project-index の `documents[].metadata` は 1 つの列だけを対応させるため、ネットミームの `description` は `context` だけに対応させた（要件の「`context` と `use_when` をつないだ文」にはしていない）。`related` は `{to, type}` の要素を持たない `work` の文字列に対応させられないため、対応させていない。ユーザーの回答で差を受け入れ、要件と SC-72-4 の期待値を修正した（確認ログ） |
