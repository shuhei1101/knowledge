# 要件

## 要望

knowledge のリポジトリの中に、規約の配信元（`knowledge`）とは別の配信元を作り、作品とネットミームを 1 件 1 ファイルの YAML の文書として持つ。
終了の条件は次のとおり。

| 項目 | 終了の条件 |
| --- | --- |
| 種類 | 作品とネットミームの 2 つの種類（`documents[]` の行）があり、`search_docs` で種類を絞って検索できる |
| スキーマ | 作品とネットミームのキーを持つ。条件があるキー（作品の `airings` は `type: anime` のとき必須、ネットミームの `type`・`popularity` は `work` なしのとき必須、`styles[].patterns` は `styles[].type: parody` のとき必須）を JSON Schema の `if`・`then` で検査する |
| 共通のキーへの対応 | ネットミームの `name` は `term`、`description` は `context` と `use_when` をつないだ文、`tags` は `tags[].name`、`related` は `work`。作品の `name` は `title`、`description` は `description`。`state` は共通のキー `status` に対応させない |
| 検査 | 書き込みと全ての文書の検査で、`work` が指す作品が実在すること・タグが「タグの語彙」の分類に合うことを検査し、違反を返却する |
| 配信元の分割 | 規約の配信元の検索の結果とタグの集計に、作品とネットミームが混ざらない。`alias_type` を持たせない |
| 直コミット | 新規の配信元の設定の `direct_commit` が、作品とネットミームの種類の直コミットを `develop` へ許可する |
| 使い方 | 新規の配信元を端末の設定に登録し、直コミットを呼べる作業場所を指定する手順が使い方にある |

キーの一覧・型・説明・見本と、タグの語彙は MindStella の資料 [データ: ネットミーム](/home/shuhei2441/repo/tmp/nandemo-kaiwa/.mindstella/docs/A-237.mark.md) を正にする。
