# 要件

## 要望

- 規約『GitHub Actions の workflow のテスト』（`docs/rule/python-testing-workflow.yaml`）を新設し、入口が `trigger` の workflow のインターフェース定義のフロー 1 つを、pytest から `gh` を呼ぶテストの関数 1 つにする書き方を、次の順で定める
  1. フローのセットアップのとおり検証用のブランチを用意して push する
  2. `gh workflow run {ファイル} --ref {ブランチ} -f {入力}` で起動する
  3. `gh run watch {ID} --exit-status` で終わるまで待つ
  4. `gh run view {ID} --json conclusion,jobs` で実行の結論と step ごとの結論を取得する
  5. フローの図の step が通り、図に無い step が `skipped` かと、期待値を確認する
  6. `gh run download {ID} -n {成果物}` で成果物の中身を確認する
  7. 検証用のブランチを削除する
- 検証用のブランチを本物のリポジトリへ push するため、このテストは手元で回す層（判定フローチャート『テストの実行場所』の ※2）であることを記載する
- `gh` の呼び方（起動した実行の ID の取り方・待ち方・結論の取得）は、テンプレート『テスト実行方法』の `run_runner` の記載例と統一する
- 規約『テストの種類と配置』から新しい規約を参照できるようにし、`rules.yaml` で `tests/e2e/workflow/` のテストのファイルに新しい規約を適用する
- 全ての文書の検査（`scripts/check_all.py`）が pass する
