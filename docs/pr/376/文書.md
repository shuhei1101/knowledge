## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 単一ユースケース | SC-72-6 の流れに、map の点検・workflow との突き合わせ・SKILL.md の比較の違反と、SKILL.md の再生成の案内を追加する | - |
| インターフェース定義 | IF-72-3 の `flows`・`constraints` に 3 つの検査を追加する。違反にする map の誤りの種類、突き合わせの 4 つの対応、SKILL.md の不一致の違反と案内の文言を定める | mdmark が無い・起動できないときの扱いは既存の lint の CLI の在りかの確認に合わせる |
| 外部ライブラリ | LIB-137-1 の `version`・`catalogs` に上げる先のタグと `check` のコマンド（`--text`・出力の違反の種類）を追加し、`verification` に上げる先のタグでの検証を記録する | 上げる先のタグは `v0.13.0` |
| モジュール構成 | MOD-72-6 に 3 つの検査の関数、MOD-137-1 に `MDMARK_TAG` の値、MOD-312-1 に check_all.py と共有する組み立ての関数を記載する。map の中の Mermaid の取り出しは 1 か所に配置し、map の点検と突き合わせが使用する | 取り出しの置き場所は `未確定` |
| チェックシート | workflow のファイルとの一致の行を、全ての文書の検査が確認する対応と、レビューで確認する観点（結末ごとのフロー・ジョブの中で重なる `name`）に分ける | 検査が確認する対応だけで足りる行は削除する |
| 開発コマンド・README | 全ての文書の検査が mdmark を npx で呼ぶため Node を前提に加える | - |

`未確定`: map の中の Mermaid の取り出しの置き場所（決める工程: モジュール構成設計）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `scripts/_lint.py` の文書の Markdown の項目の取り出しの横に配置する | 項目の取り出しと同じ場所で、ファイルが増えない | lint の呼び出しの役割に図の取り出しが混ざる |
| B | 新しい `scripts/_mermaid.py`（仮）に配置し、check_all.py から import する | 役割が分かれる | ファイルと設計書が 1 つずつ増える |

推奨: A

map の点検は文書の Markdown の項目を 1 項目ずつ一時の .md に書き出す既存の流れに乗り、取り出しの対象も同じ項目のため。
