## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| map の点検 | 文書の Markdown の項目のうち map を含む項目を mdmark の `check --text` にかけ、返った違反のうち map の誤りの種類だけを、文書のパスと項目の行つきの違反にする。`legacy_mark` は捨てる | mdmark は `npx -y github:shuhei1101/mdmark#{MDMARK_TAG}` で呼び、タグは build_pages.py の `MDMARK_TAG` を共有する |
| workflow との突き合わせ | 入口が `trigger` のインターフェース定義ごとに、対応する `.github/workflows/*.yml` を読み込み、`entry.value`・`request`・`exclusivity`・`overall_flow` と `flows[].flow` の step と分岐を、`on`・`on.workflow_dispatch.inputs`・`concurrency`・step の `name`・`if` と比べる。食い違いを 1 件ずつ違反にする | 設計書から workflow のファイルの対応の取り方（`files.yaml`・関連のキー等）はインターフェース定義設計で決める |
| SKILL.md の比較 | build_skills.py の組み立てを import し、設計書ごとに組み立てた中身と `skill.path` の SKILL.md を比べる。一致しなければ SKILL.md のパスの違反にし、`uv run --frozen --script scripts/build_skills.py` を案内する | 既存の `check_design_templates` と同じ型 |
| MDMARK_TAG | 上げる先のタグへ書き換え、Pages の成果物の作成を手元で実行して出力を確認する | - |
| テスト | 単体は 3 つの検査の関数ごとに、一致・不一致・対象なしを確認する。結合は一時フォルダのリポジトリで全ての文書の検査を実行し、違反の行と終了コードを確認する | map の点検の結合テストは npx で mdmark を起動する |
