### #343: map の点検

- 文書の Markdown の項目にある map（`<!-- map -->`〜`<!-- /map -->` の中の Mermaid）を、mdmark の点検（`check --text`）にかける
- 違反にするのは map の誤り（`map_invalid` など）だけで、前の書き方のマーカーへの `legacy_mark` は違反にしない
- `MDMARK_TAG` と外部ライブラリ『mdmark』（LIB-137-1）の採用バージョンを、map の点検を持ち、前の書き方のマーカーも読み込むタグへ上げる。Pages の成果物が上げた後も作れることを確認する

`未確定`: 上げる先のタグ（決める工程: インターフェース定義設計。外部ライブラリの設計書の検証で確認する）

| 案 | 内容 |

| B | `v0.13.0`（今の最新） |

推奨: B

前の書き方のマーカーを読み込み、map の点検を持つなら、新しいタグのほうが #316・#173 で上げ直す差が小さい。前の書き方のマーカーを読み込まなくなっていれば A にする。

### #369: インターフェース定義と workflow のファイルの突き合わせ

入口が `trigger` の GitHub Actions の workflow のインターフェース定義（`docs/interface/` の YAML）と、workflow のファイル（`.github/workflows/*.yml`）を突き合わせる。

| 設計書 | workflow のファイル |
| --- | --- |
| `entry.value`（起動の条件） | `on` のイベントと起動を絞る条件 |
| `request` | `on.workflow_dispatch.inputs` |
| `exclusivity` | `concurrency` の `group`・`cancel-in-progress` |
| `overall_flow`・`flows[].flow` の step と分岐 | step の `name`・`if` |

- map の中の Mermaid の取り出しは、#343 の取り出しと同じ処理を使用する

### #371: SKILL.md と生成元の比較

- `docs/skill/` の `type: skill` の設計書ごとに、`build_skills.py` と同じ組み立てで作った中身と、`skill.path` の SKILL.md を比べる
- 一致しなければ違反にし、再生成のコマンド（`uv run --frozen --script scripts/build_skills.py`）を案内する
