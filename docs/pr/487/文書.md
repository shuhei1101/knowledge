## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 検索の対象 | `project-index files` に `**/*` を渡し、種類の行・`docs/pr/**`・`skills/**`・`scripts/**` を `--exclude-path`、Git が無視するファイルを `git ls-files --others --ignored --exclude-standard` で除いた残りを管理用の YAML の行にする | `docs/pr/` を入れない判断は要件.yaml のスコープ外 |
| 管理用の YAML | 置くフォルダごとに `files.yaml` を作り、`project-index.yaml` の `documents[]` に `records: files`・`body_file: path`・`schema: schemas/knowledge-files.schema.yaml` の行を加える。`docs/` を範囲に持つ行の `exclude` に `docs/pr/**`、直下の行の `exclude` に `.gitignore`・`tmp/.gitignore` で無視するパス（`tmp/**`・`docs/generated/**`・`_site/**`・`.pytest_cache/**`・`.ruff_cache/**`）を書く | 置くフォルダの分け方は要件.md の `## 要望` |
| メタデータ | setup の手順 4 の段階で `name`・`description`・`tags` を付け、`project-index skew` の `similar_descriptions`・`singleton_tags`・`dominant_tags` を見直す | タグは `search_docs` の `group_by: tags` の既存のタグから選ぶ |
| 関連 | `project-index links` の出力と、テストのファイルの `tests` の候補を付ける | 設計書 → コードの向きの関連は付けない |
| 確認の時点 | 管理用の YAML ごとに `project-index checkpoint` で記録する | |
| 確認 | `check_project` の索引の同期の件数 0 と違反 0（作業 PR の worktree と、Git が無視するファイルを持つメインのクローンの両方）、`scripts/check_all.py` の合格 | 全ての文書の検査が新しい行で落ちたら、単体テスト作成を `todo` へ戻してスクリプトの修正を計画する |
| ナビゲーション | 加えた `documents[]` の行を、規約『開発ドキュメントのナビゲーション』の並びで `nav` に加える | |
