# 要件

## 要望

配信元 knowledge のフォルダで `/project-index:setup` の 2 回目以降の手順を流し、検索の対象を project-index の setup の推奨の範囲に合わせ、管理用の YAML の行とメタデータを今の付け方で見直す。

- 検索の対象は、Git 管理のファイルのうち `docs/pr/` を除く全てにする（Git が無視するファイルは除く）
- 種類の行（`docs/` の YAML の文書・`records: files` の行）が持たないファイルは、フォルダごとに置く管理用の YAML の行にし、`project-index.yaml` の `documents[]` に `records: files`・`body_file: path` の行を加える
- 管理用の YAML の行のメタデータ（`name`・`description`・`tags`）は、setup の手順 4 の段階（目次のページ → `project-index outline` → 見出しの直下の段落 → 本文）で付け、`project-index skew` で偏りを見直す
- 既存の `skills/files.yaml`・`scripts/files.yaml` の行は、`project-index changed` で確認の時点の後に中身が変わったファイルだけメタデータを見直す
- 見直した後に、管理の MCP の `check_project` の索引の同期の件数（管理用の YAML に無いファイル・ファイルが無い行・`metadata` の列が無い文書）が 0 で、違反が無いことを確かめる
- 全ての文書の検査（`scripts/check_all.py`）が合格することを確かめる

管理用の YAML は、直下・`docs/`・`schemas/`・`tests/`・`plugins/slop-check/` など、ファイルを持つ上位のフォルダごとに置き、`docs/{種類}/README.md` は `docs/` の管理用の YAML が持つ。
