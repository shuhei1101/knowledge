# 要件

## 要望

| Issue | 終わりの条件 |
| --- | --- |
| [#370](https://github.com/shuhei1101/knowledge/issues/370) | `TP-72-1.yaml` の lint 層（TL-1）の全件実行に actionlint が入り、`.github/workflows/` の workflow のファイルを検査する |
| [#409](https://github.com/shuhei1101/knowledge/issues/409) | `tests/e2e/workflow/test_test_yml.py`（IF-352-1 の 4 フロー）を実行して全 pass を確認し、`tests/e2e/workflow/` を回す `TP-72-1.yaml` の層（`location: local`）が確定している |

- TL-1 の全件実行は、ruff・pyright・actionlint のどれかが失敗しても全てを最後まで回し、1 つでも失敗したら失敗で終える 1 コマンドにする（テンプレート『テスト実行方法』の `layers`）
- actionlint は、他の道具と同じくバージョンを固定して起動する。入れ方を TL-1 の `prerequisites` に記載する
- `tests/e2e/workflow/` を回す層は、規約『GitHub Actions の workflow のテスト』の `placement-02` のとおり `location: local` にし、`run_all`・`run_one` を記載する
- 結合テストを実行して失敗した場合は、原因（workflow・テスト）を直してから全 pass を確認する

`確定`: `tests/e2e/workflow/` を回す層（決めた工程: モジュール構成設計。案 A で TP-72-1 の TL-6 に記載）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | TL-6（E2E テスト）の `run_all` を `tests/e2e/workflow/` を回すコマンドで確定させる | 層を増やさない | TL-6 はシナリオの E2E（`tests/e2e/単一ユースケース/` 等）も回す層で、シナリオの E2E を作ったときに `run_all` と `location` を書き直す |
| B | `tests/e2e/workflow/` だけを回す層を `TL-7` として追加し、TL-6 は `未確定` のまま残す | インターフェース定義の結合テストを、シナリオの E2E と分けて回せる | 層が 1 つ増える |

推奨: A

スキーマ（`schemas/design/test_procedure.schema.yaml`）の `layers[].name` は種別の列挙で、テスト実行方法の中で一意（`x-unique-in-kind`）のため、案 B の層を足せない。
`結合テスト（バック）` は TL-3 が持ち `location: runner` のため、`tests/e2e/workflow/` を回す `local` の層は TL-6 になる。

`確定`: actionlint の入れ方（決めた工程: モジュール構成設計。案 A で TP-72-1 の TL-1 に記載）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | PyPI の `actionlint-py` を `uvx --from actionlint-py=={版} actionlint` で起動する | ruff と同じく uv だけで版を固定して起動でき、環境構築の手順が増えない | 配布元が actionlint 本体ではなく、本体の版への追従が配布元に依存する |
| B | 公式のリリースのバイナリを入れる手順を開発コマンドの環境構築に追加し、PATH の `actionlint` を起動する | 本体の配布物をそのまま使用する | 環境構築の手順が増え、手元の版をコマンドで固定できない |

推奨: A

TL-1 の他の道具が全て uv で版を固定して起動しており、前提に uv だけを求める形を保てるため。
