# 要件

## 要望

用語集のスキーマ（`schemas/terms.schema.yaml`）の用語（`$defs.term`）に、その用語を説明するページを指す任意のキーを追加し、マージの後に `design-schemas/v*` のタグを上げる。

- キーの値は、ページの表示名とリンク先の組の並び（0 件以上）にする
- リンク先は、用語集の YAML のあるフォルダからの相対パスか URL で、見出しのアンカー付きを含む
- キーを省いた今の用語集（knowledge の `docs/terms.yaml`・mdmark の `docs/guide/用語集.yaml`）は、そのまま検査を通る
- mdmark は、このキーを alias-inject の行の `metadata` で列として指してエイリアスに取り込み、用語集の表の `詳細` の列のリンクに描く

`未確定`: キーの名前と値の構造（決める段: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | キー `details` を追加し、要素を `name`（表示名）と `href`（相対パスか URL）の組にする | mdmark の公開のガイドのように、文書の ID を持たないページや見出しのアンカーへも張れる | alias-inject の `related` とは別の列になる |
| B | alias-inject の `related` に合わせ、要素を `to`（文書の ID）の並びにする | alias-inject が既に解釈する列で、文書の関連として `trace_related` でもたどれる | ID を持たないページ・見出しのアンカーを指せず、表示名とリンク先を ID から引き直す仕組みが利用側に要る |

推奨: A

要望の入出力が表示名とリンク先（相対パスか URL・アンカー付き）の組で、文書の ID では表せないため。
