# 要件

## 要望

`docs/template/` の設計書の種類のテンプレート 15 件の本文を、`schemas/design/` の対応するスキーマから生成し、手で書く本文とスキーマの二重管理を無くす。

| 項目 | 要件 |
| --- | --- |
| 対象 | `schemas/design/` の種類のスキーマと 1 対 1 に対応するテンプレート（`template-architecture`・`template-component`・`template-config`・`template-dataflow`・`template-dev-command`・`template-er`・`template-external-api`・`template-external-library`・`template-interface`・`template-module`・`template-nonfunctional`・`template-scenario`・`template-screen-design`・`template-state-transition`・`template-test-procedure`） |
| 生成元 | スキーマのキーごとの `title`・`description`・`examples` と、[#192](https://github.com/shuhei1101/knowledge/pull/192) で追加した `x-rules`・`x-bad-examples`。`$ref` で指す共通の型（`common.schema.yaml`）も解決して出す |
| 決まりと悪い例 | `x-rules` を「決まり」、`x-bad-examples` を「悪い例」（値と理由）としてテンプレートに出す |
| 生成しない部分 | `id`・`kind`・`name`・`description`・`tags`・`status`・`visibility`・`rev` などのメタデータは生成で上書きせず、今の値を残す |
| 手で書く部分 | 生成した後に手で記載する本文が残らないようにする。今のテンプレートにだけある記述は、スキーマの `description`・`x-rules`・`examples`・`x-bad-examples` へ移してから生成する |
| ずれの検出 | スキーマを変えてテンプレートを生成し直さなかったとき、CI の全ての文書の検査で失敗させる |
| `x-hidden` | [shuhei1101/ai-monitor#3180](https://github.com/shuhei1101/ai-monitor/issues/3180) の要望（内部向けのキーに `x-hidden: true`）を `schemas/design/` に適用し、生成するテンプレートでも `x-hidden` のキーの扱いを決める |

生成したテンプレートの持ち方: スクリプトで `docs/template/template-*.yaml` の `items` を生成して commit し、CI の全ての文書の検査で、スキーマから組み立て直した `items` と一致するかを検査する。
既存の `build_word_list.py`（正本の対応表から JSON のコピーを書き出す）と同じ持ち方で、dev-docs・Pages・Read のどれで参照しても同じ本文が出る。

キーごとの決まりと悪い例の表し方: キーの表とは別の項目「キーごとの決まり」に、決まりか悪い例を持つキーだけを表で出す（[確認ログ](./確認ログ.md)）。

ai-monitor#3180 の扱い: `x-hidden` を knowledge の正本に適用し、元の Issue は ai-monitor 側に残る作業（`dev/テンプレート` のコピー）へ書き換えた（[shuhei1101/ai-monitor#3180](https://github.com/shuhei1101/ai-monitor/issues/3180) の `## knowledge の正本への適用`）。
ai-monitor#3104 のスキーマの修正は、この PR からは除外し [#210](https://github.com/shuhei1101/knowledge/issues/210) へ切り出した（[確認ログ](./確認ログ.md)）。
