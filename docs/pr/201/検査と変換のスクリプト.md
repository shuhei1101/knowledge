## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 生成の CLI | `schemas/design/` の種類のスキーマごとに、`x-kind` から対応するテンプレートの文書を決め、`items` を生成して書き出す新しいスクリプトを `scripts/` に配置する | 対応はスキーマの `x-kind` とテンプレートの ID の対応表で持つ。対応するテンプレートが無いスキーマ（`index`）は飛ばす。インターフェースは [設計書のテンプレートの生成](https://github.com/shuhei1101/knowledge/blob/feat/template/generate-from-schema/dev/%E8%A8%AD%E8%A8%88%E6%9B%B8/%E3%82%A4%E3%83%B3%E3%82%BF%E3%83%BC%E3%83%95%E3%82%A7%E3%83%BC%E3%82%B9%E5%AE%9A%E7%BE%A9/scripts/%E8%A8%AD%E8%A8%88%E6%9B%B8%E3%81%AE%E3%83%86%E3%83%B3%E3%83%97%E3%83%AC%E3%83%BC%E3%83%88%E3%81%AE%E7%94%9F%E6%88%90.py.yaml) |
| 生成する本文 | 概要（スキーマの `description`・トップの `x-rules`）・キーの表（`$ref` を解決したキーごとの `title`・型・必須・選択肢・制約・`description`・`examples`）・キーごとの決まりと悪い例（`x-rules`・`x-bad-examples`）・記載例（トップの `examples`）の項目にする | 表し方は規約『表し方の優先順位』に沿う。`x-hidden: true` のキーもキーの表に出す。キーごとの決まりと悪い例は、キーの表とは別の項目の表に出す（確認ログ） |
| 書き出し | テンプレートの文書のメタデータの行は変えず、`items` だけを置き換える。生成した結果が今のファイルと同じなら書き換えない | ruamel.yaml で読み込んで書き出し、コメントとキーの並びを残す |
| ずれの検出 | 全ての文書の検査で、スキーマから生成した `items` と commit されたテンプレートの `items` を比べ、違えば違反として終了コード 1 で終わる | 違反の内容に生成のコマンドを添える |
| CI | ワークフローは変えない（全ての文書の検査がずれを検出する） | - |
| テスト | 単体テストでキーの種類ごと（`$ref`・`enum`・`x-rules`・`x-bad-examples`・入れ子の配列）の生成とメタデータを残すことを確認する。結合テストで、リポジトリの 15 件のテンプレートがスキーマから生成したものと一致することを確認する | - |
