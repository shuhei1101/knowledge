# 要件

## 要望

- 配信の設定（`project-index.yaml`）の `nav` のタブ「設計書」のグループ「シナリオ」を、`auto`（`document: scenario`）から、シナリオの文書の ID を利用者の手順の順に並べた `page` の並びにする
- グループ「シナリオ」には、`docs/scenario/` の全てのシナリオ（目次の `index.yaml` を除く）を並べる
- 修正の後、dev-docs の画面のタブ「設計書」のグループ「シナリオ」をスクリーンショットで撮り、並びが下の表の順であることを確認して reviewer の確認を受ける

並びは、利用者が knowledge を導入して参照する手順 → エージェントが書き込む手順 → 開発者が検査・生成・テストする手順の順にする。

| 順 | シナリオ | 理由 |
| --- | --- | --- |
| 1 | SC-72-1 利用者が端末に knowledge を導入して規約を参照する | 導入から参照までの複合 UC で、2〜4 の起点 |
| 2 | SC-72-2 利用者が project-index に knowledge を登録する | 導入の最初の手順 |
| 3 | SC-72-3 利用者が画面で knowledge の文書を参照する | 登録の後に画面で参照する |
| 4 | SC-72-4 エージェントが knowledge の文書を検索・取得する | 登録の後に MCP で参照する |
| 5 | SC-137-1 利用者が GitHub Pages で knowledge の公開文書を参照する | 端末に導入しない参照の手順 |
| 6 | SC-72-5 エージェントが knowledge の文書を書き込む | 参照の次に行う書き込み |
| 7 | SC-148-1 エージェントが書き込んだ中身の AI slop の単語を通知される | 書き込みの後に起きる |
| 8 | SC-72-6 開発者が文書の違反を検査する | 書き込んだ文書を開発者が検査する |
| 9 | SC-201-1 開発者がスキーマから設計書のテンプレートを生成する | スキーマを変えた後の生成 |
| 10 | SC-312-1 開発者がスキルの設計書から SKILL.md を生成する | 設計書を変えた後の生成 |
| 11 | SC-352-1 開発者がランナーでテストの層の全件を実行する | 変更の最後に行うテストの全件実行 |
