# 要件

## 要望

`rules.yaml` の設計書の Schema（`schemas/design/` の種類ごとの Schema と `glossary.schema.yaml`）を案内する全てのエントリで、案内の `ツール:` の行のとおりにツールを呼べば、エラーにならずに Schema の本文が返り、そのルールが既読になる。
規約『ルール索引への登録』の項目『read_tool の記載』を、`rules.yaml` と同じ記載に統一する。

`未確定`: Schema の本文を返却する呼び方（決める工程: ドキュメント修正のレビュー）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `read_tool` を `search_docs` に替え、`args` を `{"source": "knowledge", "filter": {"field": "id", "op": "eq", "values": ["schemas/design/{種類}.schema.yaml"]}, "view": "full", "outside_scope": true}` にする（knowledge が配信する Schema のファイルの文書を参照する） | knowledge の中で完結する。エントリの `rule`（knowledge の Schema のファイル）と同じものを返却し、他の knowledge の文書を指すエントリと同じ記載になる | 書き込む側のプロジェクトが `design-schemas/v*` のタグで指すバージョンではなく、knowledge の配信しているバージョンを返却する |
| B | `describe` のまま、project-index が `source` を省いた `describe(kind)` に作業場所の配信元を補う | 書き込む側のプロジェクトが指すバージョンの Schema を返却する | project-index の変更が要り、作業場所がどの配信元の中でもないとき（worktree の外など）は補えない |
| C | `describe` のまま、rule-inject の `read_tool` に作業場所ごとに値を差し替える記法を追加して `source` を指定する | 書き込む側のプロジェクトが指すバージョンの Schema を返却する | rule-inject の索引の書式と既読の判定の変更が要る |

推奨: A

エントリの `rule` が knowledge の Schema のファイルを指しており、Read で参照したときに返るものと同じものを返却するため、バージョンの違いは今の案内と変わらない。
knowledge の変更だけで案内どおりに呼べる状態にでき、他のリポジトリの変更を待たない。
