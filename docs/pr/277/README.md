# 判定フローチャート『精度評価をするか』『機能を呼ぶインターフェースの選び方』と、エージェントを Mock にする決まりを追加する

## 概要

規約・設計を記載する人が、LLM のノードに精度評価をするか、機能を呼ぶインターフェースと新しい手順の指定方法をどれにするかを判定フローチャートで決められ、E2E・結合テストでは Claude Code のエージェントを Mock にする決まりに従えるようにする。

## 背景

束の親 Issue [#273](https://github.com/shuhei1101/knowledge/issues/273) の要望で、子 Issue は [#229](https://github.com/shuhei1101/knowledge/issues/229) と [#231](https://github.com/shuhei1101/knowledge/issues/231)。

- #229: 規約『E2E テスト（Playwright）』は外部 I/O（LLM・TTS など）をモックに切り替えると定めているが、Claude Code のエージェント・サブエージェント・スキルの扱いが無い。Python の規約『テストレイヤー』の E2E テストの行は「実環境で確認」のまま。どの LLM のノードに精度評価をするかの基準も無い（話し合いの A-31・A-102・A-103・TH-606）
- #231: 機能を呼ぶインターフェース（フック・スキル・MCP ツール・API・CLI）を決める拠り所が無い（移し元 [shuhei1101/ai-monitor#2109](https://github.com/shuhei1101/ai-monitor/issues/2109)）。あわせて、新しい手順をエージェントフロー・サブエージェント・スキルのどれにするかの判定（A-110・D-273 A）を同じ判定フローチャートで扱う（[ユーザーの追記](https://github.com/shuhei1101/knowledge/issues/231#issuecomment-6772338591) の D-363 A）。規約『注入文の書き分けと書き方』の置き場所の表は「スキル: 複数ステップの作業手順」で、D-273 A と食い違う
