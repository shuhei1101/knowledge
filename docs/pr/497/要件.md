規約『フォルダ構成』のテストの置き場所は変えない（案 B は採らない）。

規約『V字モデル』の対応表の画面設計・部品設計の行のテストの場所に React のフロントエンドは対象の横（規約『フォルダ構成』の `test-01`）を、シナリオの 2 行に React のフロントエンドは `frontend/tests/e2e/{複合ユースケース,単一ユースケース}/`（同 `test-02`）を追加する。
`test_file` の `description`・`x-rules`・`examples` に、React のフロントエンドのファイルを追加する。

`pattern` を写した `docs/template/template-component.yaml`・`template-screen-design.yaml`・`template-scenario.yaml` は `scripts/build_templates.py` で生成し直し、手で編集しない。

develop へマージした後に、`design-schemas/v*` のタグを打つ（`pattern` を広げるだけで今の設計書はそのまま検査を通るため、マイナーを上げる。反映作業）。

ai-monitor の設計書の検証（`src/ai_monitor/features/design_docs/validate.py` の `check_tests`）は `test_file` のパスを `tests/` に限らずに読むため、追従は要らない。

部品設計の `test_file` は、画面設計と同じく `*.test.ts(x)` だけを一致させ、stories のファイル（`*.stories.tsx`）は一致させない。規約『V字モデル』は部品設計の確認を、ストーリーを Playwright で開いて確認するテスト関数と定めており、テストのファイルは stories と別に持つ。

### 完了の条件

- 上の表の値が、変更後の列のとおりに `pattern` に一致する・一致しない
- 規約『V字モデル』の画面設計・部品設計・シナリオの行が、規約『フォルダ構成』の置き場所と食い違わない
- 全ての文書の検査（`scripts/check_all.py`）が通る
- develop へマージした後に `design-schemas/v*` のタグを打っている
