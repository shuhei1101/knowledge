# 要件

## 要望

- テスト実行方法の `run_all` が確定している層（TL-1〜TL-3）に、判定フローチャート『テストの実行場所』で決めた実行場所（`location`）を記載する。lint の層（TL-1）は `local` にする
- `location` が `runner` の層は、その層の全件を回す workflow を `workflow_dispatch` だけで起動するものとして作り、起動・待機・ログの取得を 1 コマンドにした `run_runner` を記載する
- `runner` の層も `run_all`・`run_one` を手元のコマンドのまま残す
- 層の中の一部のテストだけが手元を要る場合は、そのテストにマーカーを付けてランナーの全件実行から除く
- workflow はインターフェース定義の設計書がレビューで合格してから作る
- この作業 PR では workflow が develop に無く `workflow_dispatch` で起動できないため、`runner` の層も手元の全件実行で回し、理由をログに記録する

`確定`: workflow を 1 本にして層を入力で選ぶか、層ごとに分けるか（決めた工程: インターフェース定義設計。案 A で [IF-352-1](../../interface/IF-352-1.yml.yaml) に記載）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 1 本の workflow が入力 `layer` で回す層を選ぶ | 道具の入れ方を 1 か所で持てる | 層ごとに要る道具が違うと step の `if` が増える |
| B | 層ごとに workflow を分ける | 層ごとの step が素直になる | 共通の step が重複する |

推奨: A

テンプレート『インターフェース定義』の例と同じ構造で、TL-2・TL-3 はどちらも uv と Python で回り、違いは TL-3 の npm の道具だけのため。
