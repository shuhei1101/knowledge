# データの設計書を 2 つのレイヤーに分け、オブジェクトの形で記載するテンプレート『データ』を追加し、『ER図』を DB 設計のレイヤーにする

## 概要

利用者が、1 つのユースケースで扱うデータの全体をオブジェクトの構造で記載する設計書『データ』でレビューでき、DB 設計（『ER図』）から上のレイヤーのどのキーを保存するかを辿れるようにする。

## 背景

[#249](https://github.com/shuhei1101/knowledge/issues/249) の要望。
データの構造の設計書のテンプレートは『ER図』（`template-er`）だけで、テーブルごとの表で記載するため、参照する人が頭の中でテーブルを結合しないとデータの全体が見えない（手元の話し合いで「見づらい。オブジェクトの形のほうが読みやすい」と指摘された）。
『ER図』は、利用者と決めること（項目の意味・一意の範囲・状態の遷移・保持と削除）と、実装の直前に決めること（データベースの型・インデックス・削除時の連動）を同じ設計書に持つ。
後続の [shuhei1101/ai-monitor#3361](https://github.com/shuhei1101/ai-monitor/issues/3361) が、このテンプレートを使用する設計の工程を追加する。
