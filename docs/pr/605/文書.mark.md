## 変更方針

<!-- table: {"kind": "data"} -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 画面設計のスキーマ（画面全体の欄） | `screen_type`（`list`・`detail`・`edit`・`settings`・`shell`・`other`）・`leave_guard`（`none`・`unsaved`・`autosave_error`）を必須で追加し、画面全体で保持する状態の `retained_state` を追加する。`screen_type` ごとに要る要素の `kind`（一覧は `table`・`list`・`board`・`tree`、`shell` は `nav`・`sidebar`、`edit`・`settings` は入力の要素、`shell`・`other` 以外は `heading`）を `elements` の `contains` で検査する | Issue の表の 1・12 |
| 保持する状態の構造 | `retained_state[]`（`what`・`store`・`key`・`save_on`・`restore_on`・`precedence`・`reset_when`・`reason`）を `common.schema.yaml` の `$defs` に置き、画面全体・要素・部品設計から参照する。`store` は `url_path`・`url_query`・`session_storage`・`local_storage`・`cookie`・`router`・`server`・`memory`・`none`。URL の search・Web Storage・Cookie には `key`、`none` には `reason` を必須にし、`none` には `key`・契機を禁止する | Issue の表の 1・10 |
| 画面設計のスキーマ（要素の欄） | `icon`・`label_display`・`accessible_name`・`tooltip`・`narrow`・`disabled_reason`・`confirm`・`feedback`・`toggle_state`・`live`・`history`・`resets`・`shortcut`・`pane`・`tabs`・`table`・`close`・`modal`・`initial_focus`・`return_focus`・`retained_state` と、表の列の `sortable`・`filterable`・`pinnable`・`hideable` を `properties` に追加する。ペインは画面全体の `panes[]` ではなく、`sidebar`・`pane` の要素の `pane` に持たせ、幅と開閉の保持は要素の `retained_state` に記載する。ショートカットは要素の `shortcut` に持たせ、画面全体のキーは `kind` が `shortcut` の要素に記載する | Issue の表の 2〜4・6〜11 |
| 画面設計のスキーマ（必須・禁止） | #600 から移した種類ごとの必須・禁止を、#603 の `kind` を判別子にした `allOf` の `if` / `then` に `required` と `{欄: false}` で追加する。`button` は `label_display`・`confirm` を必須（`enabled_when` を持つなら `disabled_reason` も）、`icon_only` は `icon`・`accessible_name`・`tooltip` を必須、`toggle` は `toggle_state`、`tabs` は `tabs`・`retained_state`、`sidebar` は `pane`、`table` は `table`、`table_column` は `sortable`、`dialog`・`popover` は `close`・`initial_focus`・`return_focus`、`shortcut` は `shortcut` を必須にする。規約『入力と文言』の `retention-design-01` の要素（入力・選択・タブ・サイドバー・開閉・一覧と表）は `retained_state` を必須、表示だけの要素は禁止にする。条件は各欄の `x-rules` に記載する | `additionalProperties: false` を保つ |
| 画面設計のスキーマ（文言の量） | 欄を追加せず、`label`・`hint` の `x-rules` から規約を参照する。`hint` は今のとおり入力の種類以外で禁止にする | Issue の表の 5 |
| 既存の欄の置き換え | `table_column` の自由文の `sorting` を削除し、`sortable`・`filterable` と `table.default_sort` に分ける | 同じ事柄を 2 つの欄で持たない（メタスキーマの決まり） |
| 既存の日本語の enum | `io`（`input`・`output`・`input_output`）・`align`（`left`・`center`・`right`）・`initial_state`（`enabled`・`disabled`・`readonly`）を英語にそろえる | 下の `未確定` の論点を推奨の案 A で決めた。`align`・`initial_state` も同じ理由で含めた |
| 部品設計のスキーマ | `persisted_state`（`retained_state` と同じ構造）・`states[].viewport`（`desktop`・`mobile`）を追加し、`accessibility` を `label_display`（部品が持てる形状の配列）・`accessible_name_arg`（`icon_only` を持つなら必須）・`keyboard`・`rules` のオブジェクトにする | - |
| `x-rules` の参照先 | 欄ごとに Issue の表の規約の項目と、#604 で追加した規約（`ui-layout` の `splitter-01`・`ui-input-wording` の `storage-key-01`・`retention-design-01` など）を、規約名と項目の ID で参照する | 既存の `x-rules` の記載方法（規約『レイアウト』の `pitfall-text-code-05`）に合わせた |
| 記載例 | 両スキーマの `examples` を新規の欄と必須・禁止に合わせる | スキーマの検査で `examples` を検査する |
| テンプレート | `scripts/build_templates.py`・`scripts/build_markdown_templates.py` で再生成する | 手で編集しない |
