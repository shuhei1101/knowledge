# 要件

## 要望

`schemas/design/` の設計書のスキーマの `refs`（最上位の `refs` と、項目の中の `refs`）の要素を、参照の文字列（`$defs/ref`）から、規約『ドキュメント管理』の「関連」（`related-01`〜`related-05`）に合わせたオブジェクトへ変え、メジャーを上げた設計書のスキーマのタグを作成する。

| 範囲 | 内容 |
| --- | --- |
| 共通の型 | `schemas/design/common.schema.yaml` に設計書の関連の要素の型を追加する。キーは `schemas/knowledge-common.schema.yaml` の `related_item` と同じ名前にする |
| 種類のスキーマ | `schemas/design/` の全ての種類のスキーマの `refs` の `items` を、追加した関連の要素の型にする。件数の上限は `related` と同じ扱いで種類のスキーマに持たせる（`related-04`） |
| テンプレート | 設計書のテンプレート（`docs/template/`）を `scripts/build_templates.py` で生成し直す |
| knowledge 自身の設計書 | `refs` を持つ設計書（`docs/` の設計書の種類のフォルダと `docs/skill/`）の `refs` を、関連の要素へ書き換え、要素ごとに `type`・`when` を決める |
| タグ | develop へマージした後に、メジャーを上げた `design-schemas/v9.0.0` を作成する |

関連の要素のキー:

| キー | 必須 | 中身 |
| --- | --- | --- |
| `to` | ✓ | 関連先の設計書の ID（`$defs/id` の `pattern`）。項目のパスを含めない |
| `item` | | 関連先の項目のパス（今の参照の `#` より後の記載方法）。設計書全体を指すときは持たない |
| `type` | ✓ | `requires`・`references`・`replaces`・`part_of`・`change_together` のどれか（`related-02`） |
| `when` | ✓ | いつ参照するかの 1 文（空文字は不可） |
| `paths` | | 機械で判定できるときの glob の並び |

`$defs/ref` そのものは変えない。
`refs` 以外で `$defs/ref` を使用する項目（`container`・`callers`・`callees`・`uses`・`component`・`interface` 等）は文字列のまま残す。

完了の条件:

- `schemas/design/` の全ての `refs` の `items` が関連の要素の型を指し、`refs` 以外の `$defs/ref` が変わっていない
- 全ての文書の検査（`scripts/check_all.py`）が通る
- develop へマージした後に `design-schemas/v9.0.0` を作成し、[shuhei1101/ai-monitor#3534](https://github.com/shuhei1101/ai-monitor/pull/3534) へタグを通知する
