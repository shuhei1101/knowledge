## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 関連の要素の型 | `common.schema.yaml` の `$defs` に、`to`（`$defs/id`）・`item`（任意）・`type`（enum 5 値）・`when`（`minLength: 1`）・`paths`（任意。文字列の並び）を持ち、`additionalProperties: false` のオブジェクトの型を追加する。`examples`・`x-used-by`・`x-rules` はメタスキーマ（`schemas/meta.schema.yaml`）の決まりに従って持たせる | キーの名前と `title` は `related_item` に合わせる |
| 関連の並びの型 | `common.schema.yaml` の `$defs` に、要素を関連の要素の型にした配列の型を追加し、件数の上限を `related` と同じ 8 件にする | 今の knowledge の設計書の `refs` の最大は 6 件（CMD-72-1 の `categories`） |
| 種類のスキーマ | 全ての種類のスキーマの `refs`（最上位と項目の中）を、追加した配列の型を指す構造にする。`refs` 以外の `$ref: common.schema.yaml#/$defs/ref` は変えない | `refs` の `description`・`x-used-by` は関連の要素に合わせて修正する |
| テンプレート | `scripts/build_templates.py` で生成し直し、手で編集しない | 生成で関連の要素のキーの表が出ない場合は、スクリプトの修正をタスク一覧へ戻す |
| knowledge 自身の設計書 | 各 `refs` の要素を `to`・`item` に分け、判定フローチャート『関連の張り方』で `type` を選び、`when` を 1 文で記載する。`when` を記載できない要素は削除する（`related-04`） | project-index の `write_docs` で書き込む |
| 設計書のスキーマのタグ | develop へマージした後に `design-schemas/v9.0.0` を作成する（反映作業） | 今の文字列の `refs` は新規のスキーマの検査を通らないため、メジャーを上げる |
