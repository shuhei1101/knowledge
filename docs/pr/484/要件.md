# 要件

## 要望

- aituber の話し合いの記録 R-3（台本の技法）のうち、`## D 演者に合わせる` と `## E レビューの観点`、`## 最初の調べもの（knowledge-intake）から残すもの` のうちネタの選別の基準・当て書きの情報源の 2 行の技法ごとに中身を確認し、テンプレート『ノウハウ』のとおり 1 技法 1 文書で `docs/knowhow/knowhow-script-{topic}.yaml` に登録する。似た技法は 1 文書にまとめる
- 技法ごとに、規約『ドキュメント管理』の規約とノウハウの分け方（`knowhow-01`）と知見の配置先（`knowhow-02`）で、ノウハウ・規約・knowledge に配置しないもののどれにするかを判定する
- 「LLM に渡す情報」「LLM の典型の失敗」「レビューの出し方」は、#466（作業 PR [#475](https://github.com/shuhei1101/knowledge/pull/475)）で登録した `knowhow-eval-*`・`knowhow-prompt-*` と重ならないかを確認し、重なる分は新規に登録せず既存の文書を指す。A の技法で登録済みの `knowhow-script-*` と重なる分も同じく既存の文書を指す
- 記録は出典名だけで URL を持たないため、出典の URL を検索してから `sources` に記載する。公開リポジトリに手元のパスを記載しない（#460 の[確認事項](https://github.com/shuhei1101/knowledge/pull/460#discussion_r4597420523)の決定）
- 判定と書き方は #470 の [docs/pr/470/文書.md](https://github.com/shuhei1101/knowledge/blob/c2a2715/docs/pr/470/%E6%96%87%E6%9B%B8.md) の `## 変更方針` に合わせる
- 登録した文書は、書き込みの検査と全ての文書の検査に通る
