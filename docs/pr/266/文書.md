## 変更方針

<!-- table: data -->

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| メタスキーマ | ルートの `x-rules` に要件の 4 件の決まりを追加し、`properties` に `x-used-by`（`type: array`・`items` は空でない文字列）を `title`・`description`・`x-rules`・`examples` 付きで定義する | 既存の決まりの文言は変えない |
| キーの見直し | `schemas/design/` のスキーマごとに、全てのキーを 4 件の決まりに照らし、下の「見直しの結果」の表に記載してから修正する | 使用先は、`scripts/` の変換・検査・生成がそのキーを参照する箇所か、テンプレート・規約のレビューの観点から調べる |
| 使用先の記載 | 使用先のあるキーに `x-used-by` を記載する | `$defs` の共通の型は型の側に記載し、`$ref` で指す項目は使用先が型と違うときだけ項目の側に記載する |
| 削除・分割 | 使用先の無いキー・二重のキーを削除し、2 つの事柄を持つキーをオブジェクトに分ける。`examples` を合わせる | 全ての文書の検査の `examples` の検査で確認する |
| テンプレート | `scripts/build_templates.py` で `docs/template/` の設計書の種類のテンプレートを生成し直す | 使用先の列は計画書『検査と変換のスクリプト』 |
| 確認 | 全ての文書の検査を実行する | ログを `テスト結果/` に配置する |

## 見直しの結果

全てのキーに `x-used-by` を記載し、共通の型（`$ref`）を指して使用先が型と同じキーは、型の側の `x-used-by` を使用する。
