# 要件

## 要望

設計書のスキーマのどのキーも、実装かレビューのどこで使用するかがスキーマと生成したテンプレートで分かり、使用先の無いキーが無い。

### キーを設ける条件

`schemas/meta.schema.yaml` のルートの `x-rules` に、次の決まりを追加する。

<!-- table: data -->

| 決まり | 該当する例（aituber のテンプレートの案） |
| --- | --- |
| キーは実装かレビューのどこかで使用するときだけ設け、使用先を `x-used-by` に記載する | `limits`・`updated` |
| ほかの設計書・原本のファイルと同じ事柄を持つキーを設けず、参照（`ref`）にする | `mcp_servers`・`tools[].when` |
| 2 つの事柄を持つキーはオブジェクトに分ける | `model`・`prompt_files` |
| `enum` は値が互いに重ならない事柄だけにし、重なりうる事柄は真偽のキーかオブジェクトに分ける | `tools[].type` |

<!-- /table -->

- `x-used-by` は `meta.schema.yaml` の `properties` に、使用先の文の配列として定義する（`x-rules` と同じく 1 件 1 文）
- 使用先は、そのキーの値を参照する実装（変換・検査・生成）か、そのキーで確認するレビューの観点を記載する

### 既存のキーの見直し

- `schemas/design/` の全てのスキーマ（`common.schema.yaml` を含む）のキーを、追加した決まりで見直す
- 使用先のあるキーには `x-used-by` を記載する。使用先の無いキー・ほかの設計書と二重のキーは削除し、2 つの事柄を持つキーはオブジェクトに分ける
- 削除・分割したキーに合わせて `examples` を修正する
- 見直した結果（キーごとの使用先・削除・分割）は計画書『文書』の表に記載し、レビューで確認する

### テンプレート

- `scripts/build_templates.py` は、キーの表に `x-used-by` を持つ使用先の列を出す（規約『表し方の優先順位』のキーの表）
- `docs/template/` の設計書の種類のテンプレートを生成し直す

### 確認

- 全ての文書の検査と `tests/` の単体・結合テストが通る

### 設計書のスキーマのタグ

- 既存の設計書が検査を通らなくなる変更なので、`design-schemas/v*` のメジャーを上げる（今の最新は `design-schemas/v3.0.0`）
- タグは [#252](https://github.com/shuhei1101/knowledge/pull/252)・[#265](https://github.com/shuhei1101/knowledge/pull/265) と同じく、この PR を develop へマージした後に planner が develop の squash commit へ打つ（反映作業）
