# 要件

## 要望

規約『トークン管理とコスト最適化』（`docs/rule/python-llm-cost-cache.yaml`）の「プロンプトキャッシュの設計」を、次の 5 点で今のプロバイダーの仕様に合わせる（[#510](https://github.com/shuhei1101/knowledge/issues/510) の「参考（一案）」の 5 行）。

| No | 対象 | 内容 |
| --- | --- | --- |
| 1 | `prompt-cache-04` の表 | OpenAI の行を、モデルの世代によって書き込みの費用と明示のブレイクポイントがある記載に修正する |
| 2 | 項目の追加 | 毎回変わる末尾を書き込みの対象から除外する（自動の区切りを使用せず、変わらない部分の最後に明示のブレイクポイントを指定する） |
| 3 | 項目の追加（`prompt-cache-05` の近く） | 呼び出しの間隔と保持の時間を比べ、間隔の方が長い用途ではキャッシュを前提にしない |
| 4 | `prompt-cache-06` | 使用量のログのキーに書き込みのトークン（Anthropic の `cache_creation_input_tokens`・OpenAI の書き込みのトークンのキー）を追加する |
| 5 | 項目の追加 | 中身が変わるエイリアスのモデルは、キャッシュの決まりも変わりうるので、使用量で実測する |

- 単価・保持の時間・モデル名は規約に記載せず、公式のドキュメント（メタデータの `sources`）を参照する記載にする（規約『文章の書き方』の「時期で変わる値を記載していないか」）
- キー名・パラメータ名・OpenAI の Chat Completions で明示のブレイクポイントを指定できるかは、ドキュメント修正の前に公式のドキュメントで裏付けを取り、裏付けの取れた記載だけを書く
- 終了の条件: 5 点が規約に記載され、全ての文書の検査（`uv run --frozen --script scripts/check_all.py`）が違反なしで終了コード 0 になること
