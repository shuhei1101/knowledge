# 要件

## 要望

dev-docs の配信の設定（`project-index.yaml` の `nav`）のタブの並びとサイドバーのグループの決まりを、knowledge の規約に記載する。
決まりは Issue #421 の「決まったこと」（TH-1142）に従い、次の 3 つを持つ。

| 項目 | 決まり |
| --- | --- |
| タブの並び | 入口になるもの（はじめに・使い方）と抽象的なものを左に、内部の詳細と参照用の資料（リファレンス・用語集）を右に並べる |
| サイドバー | グループ（`nav.tabs[].items[].group`・`auto.group_by`）でまとめる（機能の単位など） |
| 配信しないもの | フォルダの目次（`kind: index`）を、タブとサイドバーに並べない |

- Issue の参考資料の出典（タブの数の上限・1 つの一覧の件数・入れ子の深さ・順の指定）は、出典を開いて裏付けを取れたものだけを決まりに入れ、規約の `sources` に記載する
- 設計書の種類を 1 つのタブ「設計書」にまとめ、種類をサイドバーのグループにする形は、project-index の `nav` で記載できる（`group` は入れ子にでき、`auto.group_by: kind` で種類ごとのグループになる。project-index の [設定](https://github.com/shuhei1101/project-index/blob/develop/docs/guide/%E8%A8%AD%E5%AE%9A.md) の `### nav`）
- 目次を並べないことは、`auto.filter` の `not`（`kind` が `index`）で記載できる。`auto.group_by: '@folder'` は各フォルダの `index.yaml` を先頭に並べるため、`filter` と組み合わせる
- 既存の規約『表し方の優先順位』の `page-split-01`（1 要素 1 ページにしてサイドバーのグループでまとめる・サイドバーをフォルダでまとめる）は、ページの分け方の決まりで、新しい規約と食い違わない。新しい規約からは参照だけを張る

`未確定`: 規約の配置場所と名前（決める段: ドキュメント修正の前の承認確認）

| 案 | 内容 |
| --- | --- |
| A | 新しい規約 `docs/rule/dev-docs-navigation.yaml`（名前『開発ドキュメントのナビゲーション』）にし、rule-inject の索引（`rules.yaml`）で `project-index.yaml`・`dev-docs.yaml` を触るときに注入する |
| B | 規約『ドキュメント管理』の `group: 配信` に項目を追加する |

推奨: A

『ドキュメント管理』は文書の配置・メタデータ・関連・配信の方式を持ち、文書を作る・移すときに読まれる。タブとサイドバーの決まりは `nav` を記載するときだけ要るので、分けたほうが `nav` を触るときだけ注入できる。

`未確定`: タブの並びの具体的な順（決める段: ドキュメント修正の前の承認確認）

| 案 | 内容 |
| --- | --- |
| A | はじめに・使い方・設計書・規約・コード・リファレンス・用語集（決定の「参照用の資料（リファレンス・用語集）を右に」に合わせる） |
| B | はじめに・使い方・リファレンス・設計書・規約・コード・用語集（Issue の参考の一案） |

推奨: A

Issue の決定は、リファレンスを用語集と同じ「参照用の資料」として右に置く。B はリファレンスを 3 番目に置き、決定と食い違う。
