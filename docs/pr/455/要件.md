# 要件

## 要望

- 配信の設定（`project-index.yaml`）の `nav.tabs[]` を、規約『開発ドキュメントのナビゲーション』の `## タブの並び` の順（はじめに・使い方・設計書・規約・コード・リファレンス・用語集。配信元に無いタブは飛ばす）にし、タブを 7 件以下にする
- 設計書の種類（アーキテクチャ図・非機能要件・シナリオ・インターフェース定義・モジュール構成・外部ライブラリ・テスト実行方法・開発コマンド・フォルダ構成）をタブ「設計書」1 つにまとめ、種類をサイドバーのグループにする
- 規約の種類（規約・テンプレート・判定フローチャート・判定表・チェックシート・単語の対応表）をタブ「規約」にまとめ、種類をサイドバーのグループにする
- フォルダの目次（`kind: index`）と、読む人が参照しない内部のファイルを、タブとサイドバーに並べない
- 修正の後、dev-docs の画面をスクリーンショットで確認し、reviewer の確認を受けてから完了にする。確認する画面は、タブの並びと数・サイドバーのグループ・目次や内部のファイルが出ていないか・文書をスクロールした状態

`未確定`: 種類「ノウハウ」・「スキル」と、変更履歴を置くタブ（決める工程: 実装。規約の `## タブの並び` の表に行が無い）

| 案 | 内容 |
| --- | --- |
| A | ノウハウはタブ「規約」のグループ、スキルはタブ「使い方」のグループ、変更履歴はタブ「はじめに」に置く |
| B | ノウハウ・スキルをそれぞれ独立したタブにし、変更履歴はタブ「使い方」に残す |

推奨: A

規約の表の 7 件に収まり、ノウハウは規約と同じく作業の前に参照する資料、スキルは利用者が起動する手順、変更履歴は規約の表で「はじめに」に入れる文書のため。

`未確定`: タブ「規約」のサイドバーで、規約（`rule`）の文書を種類のグループの下でさらにまとめるか（決める工程: 実装）

| 案 | 内容 |
| --- | --- |
| A | 規約のグループの下を `auto` の `group_by` でタグの分野（`scope:*`）ごとのグループにする（入れ子は 2 階層まで） |
| B | 規約のグループの下は名前の順の一覧のままにする |

推奨: A

規約は 200 件を超え、規約『開発ドキュメントのナビゲーション』の `## グループでまとめる` が機能の単位でグループにすることを求めるため。
`group_by` で分野を引けない場合は B にする。
