# 要件

## 要望

- 配信の設定（`project-index.yaml`）の `nav.tabs[]` を、規約『開発ドキュメントのナビゲーション』の `## タブの並び` の順（はじめに・使い方・設計書・規約・コード・リファレンス・用語集。配信元に無いタブは飛ばす）にし、タブを 7 件以下にする
- 設計書の種類（アーキテクチャ図・非機能要件・シナリオ・インターフェース定義・モジュール構成・外部ライブラリ・テスト実行方法・開発コマンド・フォルダ構成）をタブ「設計書」1 つにまとめ、種類をサイドバーのグループにする
- 規約の種類（規約・テンプレート・判定フローチャート・判定表・チェックシート・単語の対応表）をタブ「規約」にまとめ、種類をサイドバーのグループにする
- フォルダの目次（`kind: index`）と、読む人が参照しない内部のファイルを、タブとサイドバーに並べない
- 修正の後、dev-docs の画面をスクリーンショットで確認し、reviewer の確認を受けてから完了にする。確認する画面は、タブの並びと数・サイドバーのグループ・目次や内部のファイルが出ていないか・文書をスクロールした状態

種類「ノウハウ」・「スキル」と変更履歴は、規約の `## タブの並び` の表に行が無いため、次の置き場にする（実装で決定）。

| 文書 | 置き場 | 理由 |
| --- | --- | --- |
| ノウハウ | タブ「規約」のグループ | 規約と同じく作業の前に参照する資料 |
| スキル | タブ「使い方」のグループ | 利用者が起動する手順 |
| 変更履歴 | タブ「はじめに」 | 規約の表で「はじめに」に入れる文書 |

タブ「規約」の規約（`rule`）の文書は、ID の接頭辞（`dev-`・`react-`・`python-` など）で分野ごとのグループにする（実装で決定）。
規約は 200 件を超え、`scope:*` のタグは付いていない文書があるため、全ての文書が持つ ID の接頭辞で分ける。
