## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| タブの並び | `nav.tabs[]` を、はじめに・使い方・設計書・規約・コード・用語集の順にする（リファレンスに入れる文書は無いので飛ばす） | ノウハウ・スキル・変更履歴の置き場は `未確定`（要件） |
| タブ「設計書」 | アーキテクチャ図・非機能要件・シナリオ・インターフェース定義・モジュール構成・外部ライブラリ・テスト実行方法・開発コマンド・フォルダ構成を、種類ごとの `group` に `auto`（`document`）で並べる。グループの順は、全体（アーキテクチャ図・非機能要件・フォルダ構成）→ 振る舞い（シナリオ・インターフェース定義・モジュール構成）→ 開発（外部ライブラリ・テスト実行方法・開発コマンド）にする | 種類の `documents[]` は目次を含まないので、目次は並ばない |
| タブ「規約」 | 規約・テンプレート・判定フローチャート・判定表・チェックシート・単語の対応表を、種類ごとの `group` にする | 規約の下のまとめ方は `未確定`（要件） |
| タブ「コード」 | 今のタブ「ファイル」の、スキルの本体・検査と変換のスクリプトの 2 グループを移す | - |
| タブ「用語集」 | 今のタブ「使い方」の中の用語集のグループを独立したタブにする | - |
| 目次 | `index` の種類はどのタブにも並べない。`group_by: '@folder'` を使うときは `filter` の `not`（`kind` が `index`）を付ける | - |
| 使い方の文言 | 『knowledge を project-index の配信元に登録する』の「種類のタブ」を「タブ」にする | - |
| 画面の確認 | 修正の後に dev-docs の画面（`http://127.0.0.1:8781/knowledge` の作業ブランチ）をスクリーンショットで撮り、タブの並びと数・サイドバーのグループ・目次や内部のファイルが出ていないか・文書をスクロールした状態を確認して、画像を PR に載せて reviewer の確認を受ける | - |
