# 要件

## 要望

エージェントフローのスキーマの `steps[].calls[].server` の `x-used-by` と、SKILL.md の生成（[IF-312-1](https://github.com/shuhei1101/knowledge/blob/9e62ae1ef1c85feed73de39be07b2aa0e60b5f30/docs/interface/IF-312-1.py.yaml) の「工程のセクション」・[scripts/build_skills.py](https://github.com/shuhei1101/knowledge/blob/9e62ae1ef1c85feed73de39be07b2aa0e60b5f30/scripts/build_skills.py) の `render_call`）が `type: mcp` の行を出す振る舞いを一致させる。
同じ説明を持つテンプレート『エージェントフロー』の `steps[].calls[].server` の行も合わせる。

終わりの条件:

- スキーマ・テンプレートの `calls[].server` の説明と、IF-312-1 の「工程のセクション」の `mcp` の書式が食い違わない
- `build_skills.py` の出力が IF-312-1 の書式どおりで、単体・結合テストが通る

直し方: SKILL.md の生成は `server` を参照のまま出す今の振る舞いを保ち、スキーマ・テンプレートと IF-312-1 にそう定める。スキルから MCP のツールを呼ぶときは、`type: tool` に完全な名前を記載する。

スキルが呼ぶ MCP サーバーは project-index などプラグインが出すもので、定義は knowledge の外のリポジトリにあり、knowledge の中で解決するには定義の写しを持つことになる。
また、プラグインのツールの完全な名前は `mcp__plugin_{プラグイン}_{サーバー}__{tool}` で、『MCP サーバーの定義』の `server` の pattern（`^[a-z0-9]+(-[a-z0-9]+)*$`）では表せない。
