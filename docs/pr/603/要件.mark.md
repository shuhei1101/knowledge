# 要件

## 要望

画面設計（`schemas/design/screen.schema.yaml`）の要素の `kind` を英語の enum にし、`kind` を判別子にした要素の `allOf` の `if` / `then` で、今のスキーマにある欄の種類ごとの必須・禁止を検査で求める。
部品設計（`schemas/design/component.schema.yaml`）も同じ考え方で見直す。

- 要素の `kind` が enum を持ち、enum に無い値（`div`・`h1`・`列` など）を記載すると、全ての文書の検査（`scripts/check_all.py`）が違反を出す
- enum の語彙は、Issue の表の種類（button・toggle・input・select・textarea・tabs・nav・sidebar・pane・table・table_column・dialog・popover・label など）を起点に、各プロジェクトの画面設計書で使用している種類を受けられるように決め、値ごとの意味をスキーマに記載する
- 今のスキーマにある欄（`placeholder`・`hint`・`options`・`range`・`overflow`・`pending_state`・`count_limit`・`align` など）について、種類ごとの必須・禁止を `if` / `then` の `required` と `{欄: false}` で記載し、違反した要素を検査が見つける
- 要素の `items` は `additionalProperties: false` のまま、全ての欄を `properties` に並べ、`if` / `then` では必須・禁止だけを指定する（今の `overflow` の必須と同じ使い方）。分岐は `oneOf` ではなく `allOf` + `if` / `then` で記載する
- 種類ごとの必須・禁止の条件を、スキーマの `kind` と該当する欄の `x-rules` に記載して、テンプレートの決まりの表に出す
- 部品設計のスキーマで、種類（引数の `type` など）で欄の要否が分かれる箇所を同じ仕組みで見直す
- スキーマの `examples` を enum と必須・禁止に合わせ、テンプレート『画面設計』『部品設計』（`docs/template/template-screen-design.yaml`・`template-component.yaml`）と Markdown のテンプレート（`docs/template/markdown/screen-design*.md`・`component*.md`）を再生成する
- 既存の画面設計が検査で落ちるため、マージの後に `design-schemas/v*` のメジャーを上げたタグを作る。配布先は、タグを上げるときに `kind` と欄を直して検査に合格させる
- マージの前に、[Issue #600](https://github.com/shuhei1101/knowledge/issues/600) の「やりたいこと」と修正した内容を突き合わせ、ずれが無いことを確認する
