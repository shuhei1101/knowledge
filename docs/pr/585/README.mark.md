# 画面設計のスキーマに、件数の上限と超えたときの扱い・上限が無い値の区分を追加し、入力を持たない値と固定の領域の値で overflow を必須にする

## 概要

画面を設計・実装・テスト・レビューする人が、並べる値の件数の上限と超えたときの扱い、上限が無い値かどうかを画面設計のキーに記載でき、長い値の扱いの記載が漏れた画面設計を検査で見つけられるようになる。

## 背景

[Issue #584](https://github.com/shuhei1101/knowledge/issues/584) の要望。
[#571](https://github.com/shuhei1101/knowledge/pull/571) で画面設計の要素に長い値の扱い（`overflow` の `type` と `max_length`）を任意のキーとして追加した。
件数の上限と上限が無い値の区分を記載するキーは無く、AI Monitor の手順は要素の `description` への記載で回避している（[shuhei1101/ai-monitor#3829](https://github.com/shuhei1101/ai-monitor/pull/3829)）。
入力を持たない値を表示する要素と固定の領域に配置する要素でも `overflow` は任意のままで、記載が漏れても検査に合格する。
各プロジェクトは設計書のスキーマを `design-schemas/v*` のタグで指すため、必須にする変更はメジャーを上げたタグで配る。
