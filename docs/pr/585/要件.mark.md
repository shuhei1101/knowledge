# 要件

## 要望

画面設計（`schemas/design/screen.schema.yaml`）の要素に、件数の上限・上限を超えたときの扱い・上限が無い値の区分を記載するキーを持たせ、入力を持たない値を表示する要素と固定の領域に配置する要素で `overflow` の記載を検査で求める。

- 要素に、並べる値の件数の上限と、上限を超えたときの扱い（折り返す・件数でまとめる・読み込みを分ける）を記載するキーがある
- `overflow` に、長さの上限が無い値（AI や他の人が記載した文字）を区分するキーがある
- 入力を持たない値（記録から取得する値・AI や他の人が記載した文字）を表示する要素と、固定の領域に配置する要素で `overflow` を省くと、全ての文書の検査（`scripts/check_all.py`）が違反を出す
- 必須にする要素の判定は要素のキーの値で行い、判定の条件をスキーマの `overflow` の `x-rules` に記載して、テンプレートの決まりの表に出す
- テンプレート『画面設計』（`docs/template/template-screen-design.yaml`）と Markdown のテンプレート（`docs/template/markdown/screen-design.md`・`screen-design.example.md`）を再生成して、追加したキーの行が出る
- 折り返すか省略するかの既定は規約『レイアウト』（`ui-layout`）に従い、スキーマには記載しない
- 必須にする変更で既存の画面設計が検査で落ちるため、マージの後に `design-schemas/v*` のメジャーを上げたタグを作る。配布先は、タグを上げるときに `overflow` を記載して検査に合格させる
- マージの前に、[Issue #584](https://github.com/shuhei1101/knowledge/issues/584) の「やりたいこと」の 3 点と修正した内容を突き合わせ、ずれが無いことを確認する

件数の上限のキーの構造と、固定の領域に配置する要素の判定方法は [文書](./文書.mark.md) の表 1・表 2 で決めた。
