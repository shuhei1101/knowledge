## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 画面設計のスキーマ（件数） | 要素に、並べる値の件数の上限と、上限を超えたときの扱い（折り返す・件数でまとめる・読み込みを分ける）を記載する任意のキーを追加する | `未確定`（[要件](./要件.mark.md) の件数の上限のキーの構造） |
| 画面設計のスキーマ（上限が無い値） | `overflow` に、長さの上限が無い値（AI や他の人が記載した文字）を区分するキーを追加し、区分した値は `max_length` を持たない | - |
| 画面設計のスキーマ（必須） | 入力を持たない値を表示する要素（`io` が `表示` で `source` を持つ要素 等）と固定の領域に配置する要素で、`overflow` を `allOf` の `if` / `then` で必須にし、条件を `x-rules` と `condition` に記載する | 固定の領域の判定は `未確定`（[要件](./要件.mark.md) の固定の領域に配置する要素の判定方法） |
| 画面設計のスキーマ（記載例） | `examples` に、件数の上限を持つ要素と上限が無い値の要素を追加し、必須の条件に該当する要素が `overflow` を持つ | スキーマの検査で `examples` を検査する |
| テンプレート『画面設計』・Markdown のテンプレート | `scripts/build_templates.py`・`scripts/build_markdown_templates.py` で再生成する | 手で編集しない |
| 設計書のスキーマのタグ | 必須にする変更で既存の画面設計が検査で落ちるため、マージの後に `design-schemas/v*` のメジャーを上げたタグを作る | 反映作業 |
