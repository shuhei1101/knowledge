# 要件

## 要望

- 種類「ノウハウ」（`knowhow`）を、[schemas/knowhow.schema.yaml](https://github.com/shuhei1101/knowledge/blob/5d4f69b/schemas/knowhow.schema.yaml) のスキーマで配信できるようにする。`docs/knowhow/*.yaml` に配置した文書が、`search_docs`（`kind: knowhow`）で返り、書き込みの検査と全ての文書の検査に通り、画面に表示される
- `docs/knowhow/` はフラットに配置し、ファイル名は `knowhow-{scope}-{topic}.yaml`（`scope` は分野。`script`・`direction`・`video`・`game` など）にする
- 配信の設定（`project-index.yaml`）の説明・`instructions`・`when` に、創作の知見（台本・演出・ゲーム）とノウハウを加える
- 規約『ドキュメント管理』に、規約とノウハウの分け方と、知見の配置先を加える

  | 種類 | 入れるもの |
  | --- | --- |
  | 規約（`docs/rule/`） | 守らないと不具合・不統一になるもの |
  | ノウハウ（`docs/knowhow/`） | 守らなくても成り立つが、知っていると質が上がる知見 |

  | 知見 | 配置先 |
  | --- | --- |
  | 複数のプロジェクトで使用できる技法 | knowledge |
  | 実行時のノードが毎回従う内容（進め方・プロンプト） | そのプロジェクトのリポジトリを原本にし、元になった技法が knowledge にあれば ID で指す |
  | 1 つのプロジェクトだけで使用する知見 | そのプロジェクトのリポジトリ |
  | 調べた結果そのもの（調査・PoC の記録） | 話し合いのワークスペース。ノウハウには結論・出典と確認した記録の要点を持たせる |

- ノウハウの公開の既定は `internal` にし、公開するものだけを 1 件ずつ `public` にする
- ノウハウは注入の索引（`rules.yaml`）に登録せず、進め方の文書・スキルの工程から ID かタグで指す
- `docs/rule/` の全件を、上の分け方で調べ、ノウハウに該当する文書を `docs/knowhow/` へ移す。移した文書を指す knowledge の中の参照（`rules.yaml`・ほかの文書の `id:` のリンク・`related`）を修正する
- 移す文書を決めたら、そのパスを直接参照しているほかのリポジトリの箇所（aituber-support・mindstella の `rules.yaml` など）を調べ、追従の Issue を起票してから移す。そのときに `破壊的変更` を付けるかを判断する
- ほかのリポジトリの `docs/rule/` は変えない
- 完了後、起点 Issue に、後続（ノウハウの一覧の 21 件の登録）へ着手できる旨をコメントする

`未確定`: 移す文書（決める工程: ドキュメント修正。調べた結果の一覧をレビューで確定する）
