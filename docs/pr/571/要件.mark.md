# 要件

## 要望

長さが変わる値（記録から取得する値・利用者が入力する値）を表示する箇所の、長いときの扱いと最大の長さの値での確認の決まりを knowledge の文書に持ち、画面を設計・実装・テスト・レビューする人が参照できるようにする。
固定の文言だけの箇所は対象にしない。

- 画面設計のスキーマ（`schemas/design/screen.schema.yaml`）の要素に、表示する値が長いときの扱い（折り返す・省略する・スクロール）を記載するオブジェクトのキーと、表示する値の最大の長さを記載するキーがあり、テンプレート『画面設計』（`docs/template/template-screen-design.yaml`）を再生成してその行が出る
- キーは任意で、キーを省いた今の画面設計の設計書はそのまま検査を通る
- 規約『レイアウト』に、固定の文言のラベル・ボタンは折り返さず縮めず、長さが変わる値の側で折り返すか省略する決まりがある
- テストの規約（規約『E2E テスト（Playwright）』・規約『Storybook』）に、長さが変わる値を表示する画面・部品は最大の長さの値を入れた場面（テストデータかストーリー）を持ち、スクリーンショットで確認する決まりがある
- チェックシート『実装した画面のレビュー観点』『モック HTML のレビュー観点』の長い値の行が、長さが変わる値を表示する箇所ごとに最大の長さの値を入れた画面のスクリーンショットがあり、ラベル・ボタンの中の折り返し・枠からのはみ出し・後ろの要素との重なりが無いことを確認する行になっている
- マージの後に `design-schemas/v*` のマイナーを上げたタグを作る
- マージの前に、[Issue #570](https://github.com/shuhei1101/knowledge/issues/570) の「やりたいこと」の 3 点と修正した内容を突き合わせ、ずれが無いことを確認する

画面設計のキーの構造は [文書](./文書.mark.md) の変更方針の表 1 で決めた。
