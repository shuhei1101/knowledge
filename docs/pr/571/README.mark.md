# 長さが変わる値の、長いときの扱いと最大の長さの値での確認を、画面設計のスキーマ・UI の規約・レビューの観点に追加する

## 概要

画面を設計・実装・テスト・レビューする人が、長さが変わる値（記録から取得する値・利用者が入力する値）を表示する箇所の、長いときの扱いと最大の長さを画面設計に記載し、最大の長さの値を入れた画面のスクリーンショットで崩れが無いことを確認できるようになる。

## 背景

[Issue #570](https://github.com/shuhei1101/knowledge/issues/570) の要望。
長さが変わる値が長いときに、ラベル・ボタンの中の文字の折り返し・枠からのはみ出し・後ろの要素との重なりが、レビューを通って残っている（直近の例は [shuhei1101/mindstella#690](https://github.com/shuhei1101/mindstella/issues/690)）。
画面設計のスキーマは入力の最大長（`elements[].max_length`）だけを持ち、規約『レイアウト』には固定の文言のラベル・ボタンを縮めない決まりが無く、レビューのチェックシートは「極端なデータ」「長い名前」の一般の観点だけで、対象と確認の方法を持たない。
画面設計のテンプレートはスキーマ（`schemas/design/screen.schema.yaml`）から生成し、各プロジェクトは `design-schemas/v*` のタグで指すため、キーを追加した後にタグを上げる。
