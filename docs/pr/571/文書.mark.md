## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 画面設計のスキーマ | `elements[]` に、表示する値が長いときの扱い（`wrap` / `truncate` / `scroll`）と表示する値の最大の長さを記載する任意のキーを追加し、スキーマの `examples` に例を入れる。固定の文言だけの要素には記載しない | 決定: 表 1 の A（`overflow.type` と `overflow.max_length`） |
| テンプレート『画面設計』 | `scripts/build_templates.py` で再生成する | 手で編集しない |
| 規約『レイアウト』 | 固定の文言のラベル・ボタンを長さが変わる値と同じ行に並べるときは、ラベル・ボタンを折り返さず縮めず（`white-space: nowrap`・`flex-shrink: 0`）、値の側を `min-width: 0` にして折り返すか省略する行を、落とし穴チェックリストのテキスト・コードに追加する | 省略したときの全文の表示は `pitfall-text-code-03` を参照する |
| 規約『E2E テスト（Playwright）』 | 長さが変わる値を表示する画面は、画面設計の最大の長さの値を入れたテストデータの場面を持ち、その画面のスクリーンショットを撮る行をルールに追加する | 固定の文言だけの画面は対象にしない |
| 規約『Storybook』 | 長さが変わる値を表示する共通コンポーネントは、最大の長さの値を入れたストーリーを持つ行を追加する | 画面の部品は E2E で確認する（`storybook-02`） |
| チェックシート『実装した画面のレビュー観点』 | 「極端なデータ」の行を、長さが変わる値を表示する箇所ごとに最大の長さの値を入れた画面のスクリーンショットがあり、ラベル・ボタンの中の折り返し・枠からのはみ出し・後ろの要素との重なりが無いことを確認する行へ具体化する（0 件・大量・絵文字の観点は残す） | 補足の列に規約『レイアウト』『表示の安定』へのリンクと、画面設計の最大の長さを参照する旨を配置する |
| チェックシート『モック HTML のレビュー観点』 | 「長い名前」の行を、同じ内容へ具体化する（空・1 件・大量のデータの観点は残す） | 同上 |
| 設計書のスキーマのタグ | 任意のキーの追加で今の設計書がそのまま検査を通るため、マージの後に `design-schemas/v*` のマイナーを上げたタグを作る | 反映作業 |

表 1: 画面設計のキーの構造

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `overflow` のオブジェクトに、扱いの `type`（`wrap` / `truncate` / `scroll`）と最大の長さの `max_length` を持たせる | 長い値の扱いと長さを 1 か所に記載でき、後から引数（省略したときの全文の出し方 等）を追加できる | 入力の最大長 `elements[].max_length` と同じ名前のキーが入れ子に出る |
| B | `overflow` のオブジェクト（`type`）と、表示する値の最大の長さの `display_max_length` を別のキーにする | 入力の最大長と名前で見分けられる | 長い値の扱いと長さが 2 か所に分かれる |

決定: A

最大の長さは長いときの扱いを決める材料で、扱いと並べて記載するほうが実装とテストで見落としにくいため。
入力を受ける要素で入力の最大長と同じ値なら、入れ子の `max_length` を省く（スキーマの `x-rules`）。
