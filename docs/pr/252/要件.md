- 図の記述から Mermaid の記法（`stateDiagram-v2`・`erDiagram`・`-->` などの記法）を説明する文を削除する。knowledge 側だけにある `x-rules`・`x-bad-examples` も同じ基準で修正する
- 文言は knowledge の原本の記載方法（AI slop の単語の対応表に合わせた単語）で記載し、ai-monitor#3222 の文言をそのまま写さない
- `common.schema.yaml` の `$defs/mermaid` は、シナリオ・インターフェース定義の `flow` とモジュール構成の `diagrams[].diagram` が参照するので残す。この 3 つのキーは変えない

### 既存の設計書とテンプレート

- `dev/設計書/` の設計書を修正したスキーマに合わせる。アーキテクチャ図の `subgraphs` を `frame` に、非機能要件とテスト実行方法の要素に `id` を、外部ライブラリ『maid』の文の中の検討事項の ID を `decisions` に移す
- `docs/template/` の設計書のテンプレートを `scripts/build_templates.py` で生成し直す
- 全ての文書の検査と `tests/integration/scripts/` の既存の結合テストが通る

### 設計書のスキーマのタグ

- 既存の設計書が検査を通らなくなる変更なので、`design-schemas/v*` のメジャーを上げる（`design-schemas/v2.0.0`）
- タグは、[#240](https://github.com/shuhei1101/knowledge/pull/240)・[#245](https://github.com/shuhei1101/knowledge/pull/245) と同じく、この PR を develop へマージした後に planner が develop の squash commit へ打つ（反映作業）
