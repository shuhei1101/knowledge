## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 通知の配列 | `progress` の後に、任意の配列 `turn_notices`（`x-heading`・`x-shape: table`・`x-key: name`）を追加する | 名前の理由は [要件](./要件.mark.md) |
| 要素の `name` | 通知の名前（英小文字とハイフン）。必須。エージェントの中で重ねない | `triggers[].name` と同じ pattern |
| 要素の `when` | 通知する条件の文。必須 | 例: 前の番の後に、遊んでいるゲームが切り替わった |
| 要素の `content` | 通知する内容の文。必須 | 例: 切り替わったことと、切り替えた後のゲームの概要 |
| 要素の `sources` | 内容の元にするデータの設計書への参照の並び。任意 | `common.schema.yaml#/$defs/ref` |
| 要素の `delivery` | 届け方の `via`（`input`: 番の初めの入力の文に入れる / `tool_result`: ツールの結果に添える）と、`tool_result` のときのツール（`server`: 『MCP サーバーの定義』への参照・`tool`: ツールの名前）。必須 | `progress` の `server`・`tool` と同じ持ち方。`tool_result` のときに `server`・`tool` を必須にする |
| スキーマの例 | `examples` の AG-1 に、`input` と `tool_result` の通知を 1 件ずつ追加する | - |
| テンプレート | `scripts/build_templates.py` で `docs/template/template-agent.yaml` を生成し直す | 手で編集しない |
| 設計書のスキーマのタグ | 任意の配列の追加で今の設計書がそのまま検査を通るため、マージの後に `design-schemas/v*` のマイナーを上げたタグを作る | 反映作業 |
