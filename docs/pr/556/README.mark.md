# テンプレート『エージェントの定義』に、番の初めに受け取る通知の内容と条件の配列を追加する

## 概要

エージェントの定義の設計書を記載する人が、エージェントが番の初めに何を・どの条件で・どの経路で受け取るかを、設計書の 1 か所に一覧で記載できるようになる。

## 背景

[Issue #553](https://github.com/shuhei1101/knowledge/issues/553) の要望。
aituber のブレインノードなどのエージェントは、番の初めに状態に応じた通知（遊んでいるゲームが切り替わった・再生中のセリフを止めて残りの文がある・ブレインノードなしのモードで先に出した発話がある）を受け取る。
設計書『エージェントの定義』のスキーマ（`schemas/design/agent.schema.yaml`）の `triggers` は決まったメッセージを送るきっかけで、状態に応じて変わる通知の内容と条件を記載するキーが無い。
そのため通知の一覧が、ツールのインターフェース定義とエージェントフローの工程の文に分かれる。
話し合いの検討事項 D-860 で、エージェントフローではなくエージェントの定義に通知の配列を追加すると決まった（通知はどのエージェントフローの工程にも共通で、エージェントの単位で決まるため）。
aituber は設計書のスキーマを `design-schemas/v*` のタグで指すため、キーを追加した後にタグを上げる。
