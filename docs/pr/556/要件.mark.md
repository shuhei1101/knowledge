# 要件

## 要望

設計書『エージェントの定義』のスキーマ（`schemas/design/agent.schema.yaml`）に、番の初めに受け取る通知の任意の配列を追加し、テンプレート『エージェントの定義』（`docs/template/template-agent.yaml`）を生成し直して、マージの後に `design-schemas/v*` のタグを上げる。

- 配列の 1 要素は、通知 1 件の名前・条件・内容・元にするデータ・届け方を持つ
- 届け方は、番の初めの入力の文に入れるか、ツールの結果に添えるかのどちらかで、ツールの結果に添えるときはどのツールかを指す
- ゲーム実況のブレインノード（発話の取得のツールの結果で通知する）と、配信・個人チャットのブレインノード（番の初めの入力の文で通知する）の通知を、同じ配列に記載できる
- 配列を省いた今のエージェントの定義の設計書は、そのまま検査を通る
- スキーマの `examples` に、通知の配列の例を入れる

配列のキーは `turn_notices` にする。
`triggers`（エージェントを起動し入力を渡すきっかけ）と分けるため、きっかけではなく通知の名前にする。
