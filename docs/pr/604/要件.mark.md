# 要件

## 要望

- スプリッターの決まりを追加する
  - 規約『レイアウト』（`ui-layout`）に、サイドバーと補助のペインは既定でスプリッター（ドラッグとキー操作での幅の変更・最小と最大の幅・変えた幅の保存）と開閉のボタンを持つ項目を追加し、`layout-pattern-01` のサイドバーの行の「左に固定・常に表示」をこの既定に合わせて修正する
  - 規約『共通コンポーネント規約』（`convention-common-components`）の `components-layout-01` のサイドバーの行の観点「開閉可否、幅の固定 / 可変」を、新しい既定に合わせて修正する
  - 規約『キーボード操作』（`ui-keyboard`）の `composite-widget-02` の部品の表に、分割線（APG の Window Splitter）の行を追加する
  - 規約『操作とアクセシビリティ』（`ui-operation-accessibility`）の `wcag22-01` のドラッグの代替の手段の行が、スプリッターにも当たる（キー操作と開閉のボタン）ことを示す
- 上タブ（領域）を移って戻ったときのページを決める
  - 規約『入力と文言』（`ui-input-wording`）の状態の保持に、上タブを押したときは同じブラウザのタブの中でその領域で最後に開いたページを開き、無ければ領域の既定のページを開く決まりを追加する
  - 同じ規約のスクロール位置の決まりに、サイドバー自体のスクロール位置を追加する
- アイコンを使う既定を決める
  - 規約『ボタンのラベル』（`ui-button-label`）の `icon-or-text-01` に、標準の操作（閉じる・コピー・設定へ移る など）は既定でアイコンを付け、狭い幅ではアイコンだけにする決まりを追加する
- Web Storage のキーの付け方を決める
  - 規約『入力と文言』に、キーにアプリの接頭辞・版・画面とタブ（領域）を含める書式と、sessionStorage と localStorage で同じキーを使わない決まりを追加する
  - 判定フローチャート『画面の状態の保持先』（`flowchart-screen-state-retention`）の sessionStorage のキーの結果から、この書式を参照する
- 設計書に保持の欄を記載する基準を決める
  - 規約『入力と文言』に、画面設計で保持する状態（入力・選択・開閉・幅・スクロール位置・タブ）の記載を必須にする要素の基準を追加する

`未確定`: 各決まりの既定の値（スプリッターの最小と最大の幅・キーで動かす量・キーの書式の区切り文字）（決める段: ドキュメント修正）
