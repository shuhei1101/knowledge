## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| JSON のキー | `camelcase-01` に、対象の API は基底クラスに `alias_generator` を配置せず、キーを snake_case のまま返却する例外を追加する | 判定は「判定」の行の箇所を参照する |
| エラーの応答 | `exception-handler-03`・`exception-handler-04` に、対象の API は MCP のツールと同じ構造の JSON（`application/json`）を、プロジェクトの設計書がエラーの種類ごとに決めたステータスコードで返却する例外を追加する | RFC 9457 で返却する場合は、例外の名前を `code`、例外の種類を `category`、メッセージを `detail`、例外ごとの内容を拡張のメンバー `details` に対応させる |
| エラーレスポンスの宣言 | 規約『ルーター実装パターン』の `ProblemDetail` の一括宣言に、対象の API は MCP のツールと同じ構造のモデルを宣言する例外を追加する | - |
| 判定 | 「同じスキーマのデータを MCP のツールでも返却するか」で判定する条件を 1 か所に配置し、上の 3 か所から参照する | 規約『入出力 Pydantic スキーマ』の項目『対象の判定』に、条件と結果の表で配置する（[要件](./要件.mark.md)） |
