# 要件

## 要望

テンプレート『フォルダ構成』（`schemas/design/layout.schema.yaml`）を次のとおり改訂し、テンプレート `docs/template/template-layout.yaml` を生成し直す。

- リポジトリの外を元にする複製の元（パッケージの名前とバージョン、配布元のリポジトリとバージョン 等）を、`entries[].generated_from` のキーで記載できる
- git で管理する生成物・複製を `gitignore` に入れない場合の記載方法が、`x-rules` の生成物・複製・一時ファイルの決まり（`rules-01`）に定まっている
- 規約『フォルダ構成の切り方とレビュー』のレビューの観点『管理しないもの』が、新しい記載方法と食い違わない
- knowledge 自身のフォルダ構成 `docs/layout/LAY-72-1.yaml` が新しい記載方法で記載され、全ての文書の検査に合格する

`未確定`: `generated_from` でリポジトリの外の元を記載するキーの構造（決める段: ドキュメント修正）

| 案 | 内容 |
| --- | --- |
| A | `generated_from` に `source`（外の元の名前とバージョン。例: `npm:yaml@2.6.1`・`shuhei1101/ai-monitor@v1.2.0:docs/_theme/`）を足し、`path` と `source` のどちらか 1 つを必須にする。`command` は任意にする |
| B | `generated_from` とは別に `copied_from`（`package`・`version`・`repository` などを分けて持つオブジェクト）を足す |

推奨: A

元がリポジトリの中か外かの違いだけで、手で書き換えず元から作り直すという `generated_from` の目的は同じため。

`未確定`: git で管理する生成物・複製の記載方法（決める段: ドキュメント修正）

| 案 | 内容 |
| --- | --- |
| A | `generated_from` に `tracked`（git で管理する理由）を足し、`tracked` を持つエントリは `gitignore` に入れない |
| B | `rules-01` に、git で管理する理由をエントリの `contents` に記載すると定めるだけにする |

推奨: A

管理する理由がキーにあれば、レビューの観点『管理しないもの』で `gitignore` の漏れと区別して確認できるため。
