# 要件

## 要望

テンプレート『フォルダ構成』（`schemas/design/layout.schema.yaml`）を次のとおり改訂し、テンプレート `docs/template/template-layout.yaml` を生成し直す。

- リポジトリの外を元にする複製の元（パッケージの名前とバージョン、配布元のリポジトリとバージョン 等）を、`entries[].generated_from` のキーで記載できる
- git で管理する生成物・複製を `gitignore` に入れない場合の記載方法が、`x-rules` の生成物・複製・一時ファイルの決まり（`rules-01`）に定まっている
- 規約『フォルダ構成の切り方とレビュー』のレビューの観点『管理しないもの』が、新しい記載方法と食い違わない
- knowledge 自身のフォルダ構成 `docs/layout/LAY-72-1.yaml` が新しい記載方法で記載され、全ての文書の検査に合格する

`未確定`: `generated_from` でリポジトリの外の元を記載するキーの構造（決める段: ドキュメント修正）

| 案 | 内容 |
| --- | --- |
| A | `generated_from` に `source`（外の元とバージョン）を追加し、`oneOf` を `{required: [path, command]}` と `{required: [source]}` の 2 つの枝にする（`command` は `source` の枝でだけ任意）。`source` の書式は、パッケージなら `{レジストリ}:{パッケージ名}@{バージョン}`（例: `npm:yaml@2.6.1`）、リポジトリなら `{owner}/{name}@{タグ}:{パス}`（例: `shuhei1101/ai-monitor@v1.2.0:docs/_theme/`）と `x-rules` に記載する。`generated_from` の `description`・`x-used-by` に、外の元はバージョンを上げて取り直す使い方を追加する |
| B | `generated_from` とは別に `copied_from`（`package`・`version`・`repository` などを分けて持つオブジェクト）を足す |

推奨: A

元がリポジトリの中か外かの違いだけで、手で書き換えず元から作り直すという `generated_from` の目的は同じため。
`path` を持つエントリは今のとおり `command` を必須にし、再生成のコマンドの記載漏れを検査で検出できるようにする。

`未確定`: git で管理する生成物・複製の記載方法（決める段: ドキュメント修正）

| 案 | 内容 |
| --- | --- |
| A | `generated_from` に `tracked`（git で管理する理由）を足し、`tracked` を持つエントリは `gitignore` に入れない |
| B | `rules-01` に、git で管理する理由をエントリの `contents` に記載すると定めるだけにする |

推奨: A

管理する理由がキーにあれば、レビューの観点『管理しないもの』で `gitignore` の漏れと区別して確認できるため。

案 A のとき、`docs/layout/LAY-72-1.yaml` で `tracked` を記載するエントリは、`.gitignore` に無く `generated_from` を持つ次の全てにする。

- `docs/README.md` と、`docs/{architecture,nonfunctional,scenario,interface,module,library,test-procedure,dev-command,layout}/README.md`
- `docs/template/`
- `scripts/*.py.lock`（`knowledge_checks`・`knowledge_markdown`・`check_all`・`build_pages`・`build_word_list`・`build_templates`・`build_skills`）
- `scripts/lint/package-lock.json`
- `skills/{skill}/SKILL.md`
- 対応表のコピー `word-list-ai-slop.json`
