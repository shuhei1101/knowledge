# レビューの観点に、インターフェースの種類の判定フローチャートとの一致と、ブラウザのスクリプトを .js で手書きしていないことの確認を追加する

## 概要

設計と実装のレビューで、機能を呼ぶインターフェース・手順の指定方法の種類の選び方と、ブラウザのスクリプトの拡張子をチェックシートから確かめられるようにする。

## 背景

[Issue #304](https://github.com/shuhei1101/knowledge/issues/304) の要望で、[#285](https://github.com/shuhei1101/knowledge/issues/285)・[#288](https://github.com/shuhei1101/knowledge/issues/288) を 1 本の作業 PR で行う束。
[#299](https://github.com/shuhei1101/knowledge/pull/299) で ai-monitor の reviewer のチェックシートを `docs/checksheet/` へ成果物の種類ごとに移したが、移す行の文言を変えないため、2 つの観点の追加は #285・#288 に残した。
#285 は [#277](https://github.com/shuhei1101/knowledge/pull/277) で新設した判定フローチャート『機能を呼ぶインターフェースの選び方』の結果との一致を、#288 は [#284](https://github.com/shuhei1101/knowledge/pull/284) で書き換えた規約『ビルドレス原則』の拡張子の決まりを、レビューで確かめる観点にする。
今の『実装・テストコードのレビュー観点』の行は「`tsc` を挟める配信なのに `.js` で記載していないこと」だけで、例外の読み違いを通し、設計の段を確かめる行も無い（shuhei1101/mindmap#21 では設計の段で `.js` に決まったまま合格した）。
