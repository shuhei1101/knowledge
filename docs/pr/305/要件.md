- #285: [インターフェース定義・モジュール構成のレビュー観点](id:checksheet-review-interface-module) に、新しく作った機能を呼ぶインターフェース（フック・MCP ツール・API・CLI）と手順の指定方法（エージェントフロー・サブエージェント・スキル）の種類が、判定フローチャート [機能を呼ぶインターフェースの選び方](id:flowchart-interface-choice) の結果と合っていることの行を追加する
- #288 の設計: モジュール構成の設計書が指すブラウザのスクリプトのファイルが `.ts` で、`.js` を手書きする設計になっていないことの行を [インターフェース定義・モジュール構成のレビュー観点](id:checksheet-review-interface-module) に追加する
- #288 の実装: [実装・テストコードのレビュー観点](id:checksheet-review-code-test) の「`tsc` を挟める配信なのに、ブラウザのスクリプトを `.js` で記載していないこと」の行を、`.ts` で記載し `.js` を手書きしていないことを確かめる行に修正する。補足の例外は [js で記載してよい場合](id:html-core-buildless#script-extension-02)・[HTML に直接記載する script](id:html-core-buildless#script-extension-04) を参照する
- #288 の部品設計: `docs/checksheet/` に部品設計のレビュー観点のチェックシートが無いため、`docs/checksheet/checksheet-review-component.yaml` を新設し、部品設計の `implementation` がブラウザのスクリプトを指すとき `.ts`（`.tsx`）で、`.js` を手書きする設計になっていないことの行を置く
- 文書を書き込んだ後、`uv run --frozen --script scripts/check_all.py` が合格する
