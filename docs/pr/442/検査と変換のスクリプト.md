## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| mdmark の参照 | 既定を `develop` にし、タグか commit の SHA を指定すると固定する | 配置先は `未確定`（[要件](./要件.md) の推奨は `_common.py` の定数） |
| mdmark の設定の `version` | Pages の成果物の作成が一時フォルダに記載する `mdmark.config.yaml` の `version` に、参照が `develop` のときに何を記載するかを決める | `未確定`（決める段: インターフェース定義設計） |
| 既存機能への影響 | 呼ぶ参照の値だけを変え、検査と成果物の作成の流れ・出力は変えない | - |
| 外部ライブラリ | develop の最新は mdmark の develop へ入った変更がすぐ有効になるため、mdmark の develop が壊れたときは固定の設定でタグか commit の SHA に戻す | - |

`未確定`: 参照が `develop` のときに設定の `version` へ記載する値

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `version` を記載しない | mdmark が手元のバージョンを聞く `upgrade` を呼ばないため影響が無い | `build` が `version` を要るかを確認する必要がある |
| B | 最新のタグを記載する | 設定の構造が今と同じ | タグを上げるたびに値の修正が要り、今回の目的と食い違う |

推奨: A

`build` を呼ぶだけの一時の設定で、移行の手順を適用する `upgrade` は呼ばないため。
