# 要件

## 要望

直下の `project-index.yaml` の `direct_commit.kinds[]` に、dev-docs のメタデータの画面から直コミットしてよい knowledge の種類を追加する。

| 要件 | 終了の条件 |
| --- | --- |
| 管理用の YAML の種類 | `files.yaml` を配信する種類（`skills`・`scripts`・`plugin`・`tests`・`schemas`・`docs_folder`・`root`）が `direct_commit.kinds[]` にあり、[shuhei1101/project-index#267](https://github.com/shuhei1101/project-index/issues/267) のキーで行の本文（`@body`）の書き換えを断ってメタデータだけを許可している |
| 規約などの種類 | `rule`・`flowchart`・`decision-table`・`checksheet`・`guide` が `direct_commit.kinds[]` にある |
| テンプレートとスキーマ | `template` と、スキーマの原本（`schemas/`）は直コミットの対象にしない |
| 説明の追随 | 配信元の設定の `instructions`・README・アーキテクチャ図・シナリオの、直コミットできる種類の記載が `direct_commit.kinds[]` と一致する |

管理用の YAML の行が指す本文はスキル・スクリプト・テスト・スキーマ・生成した目次・設定で、どれも直コミットの対象にしないため、メタデータだけを許可する手段（[shuhei1101/project-index#267](https://github.com/shuhei1101/project-index/issues/267)）が入るまで管理用の YAML の種類は追加しない。

規約など、本文を持つ文書の種類（`rule`・`flowchart`・`decision-table`・`checksheet`・`guide`）は直コミットの対象に追加する（[確認ログ](./確認ログ.yaml)）。
許可は種類の単位のため、エージェントの `write_docs` からは本文も直コミットできる。行の追加と文言の修正だけに留めるのは、画面の項目の絞り込みとスキルの手順に頼る。

`skill`・`changelog`・設計書の種類（`scenario`・`interface` など）・目次（`index`）は追加しない。
`skill` はスキルの工程、設計書は AI Monitor の設計を持ち、どちらも作業 PR のレビューで変える。
