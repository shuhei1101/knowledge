## 要望

正は規約『文章の書き方』の `## 語の選び方`・判定フローチャート『語の選び方』・規約『入力と文言』の `## 文言`（[#52](https://github.com/shuhei1101/knowledge/pull/52) で追加）にする。
Issue 本文の要点と手元の資料（`tmp/ui、ドキュメントの文章ベストプラクティス/` の A-2・A-3・R-3・R-4・決定 D-1〜D-14）は、規約に無い語を判断するときの参考にする。
Issue 本文の対応表にある「書く → 記載する」は規約の対応表に無いため、文章の中の「書く」は修正の対象にしない。

### 修正の対象

`## 更新ドキュメント` のページ（`dev/pr/` を除く `dev/`・`docs/`・`README.md`・`CLAUDE.md`・`rules.yaml`）で、次を修正する。

- 文章でない所（見出し・表の列名・項目名・論理名・UI のラベル）の語を、対応表と判定フローチャートで IT の分野で定着した語に修正する（節 → セクション、形 → スキーマ・構造、段 → レイヤー・工程、版 → バージョン、印 → マーカー、口 → インターフェース、題 → タイトル、写し → コピー 等）
- 文章の中の動詞は対応表の語に「する」を付けて使う（足す → 追加する、消す → 削除する、直す → 修正する、送る → 送信する、問い / 答え → 質問 / 回答）
- 文章の冗長な言い回し（することができる・を行う）と話し言葉を修正する
- 同じものを同じ語で呼ぶ（同じファイルの中と、ファイルをまたいで同じ概念を指す語）

次は修正しない。

- 規約『文章の書き方』の対応表の避ける語の列・原則の表の悪い例の列、規約『入力と文言』の対応表の避ける語の列など、避ける語そのものを例として挙げている箇所
- コードの識別子・Enum の値・定数・コードブロックの中のコード
- 引用など、外部の文書から原文のまま載せている箇所
- 置き換えると意味が変わる語（「段落」「形式」「手段」「題材」など前後に漢字が続く熟語。数え方のスクリプトも数えない）

### 見出しとリンクの追随

- 見出しを変えたときは、リポジトリの中でその見出しを指すリンク・アンカー・『{規約名}』の `## {見出し}` の参照も同じ commit で修正する
- テンプレートの見出し（例: テンプレート『デザイン方針』の `## 形と奥行き`、テンプレート『方針決め/1_目的と制約』の `## 問いと答え`）を変えたときは、そのテンプレートの中のセクション一覧・記述例の見出しも揃える
- ファイル名に避ける語を含むファイルは無いため、ファイル名は変えない（`破壊的変更` は付けない）
