# 要件

## 要望

配信元 `knowledge` の 3 つの種類（ノウハウ `knowhow`・単語の対応表 `word-list`・用語集 `terms`）を、knowledge のワークツリーの外部の手元のセッションから、`write_docs`・`delete_docs` の `commit` で develop へ直コミットできるようにする。
規約などのほかの種類は、今までどおり Issue と作業 PR で登録する（直コミットを許可しない）。
終了の条件は次のとおり。

| 項目 | 終了の条件 |
| --- | --- |
| 直コミットの許可 | `project-index.yaml` の `direct_commit` が、`knowhow`・`word-list`・`terms` の直コミットを `develop` へ許可する。ほかの種類に `commit` を指定した呼び出しは断られる |
| 呼べる作業場所 | 端末の設定の `knowledge` の行の `direct_commit.scope` が手元の全ての作業場所（`/home/shuhei2441/**`）で、knowledge のワークツリーの外部（`/home/shuhei2441/repo/tmp/` の話し合いのフォルダ）から 3 つの種類を直コミットできる |
| 対応表のコピー | `word-list` の直コミットで、対応表のコピー `plugins/slop-check/hooks/post-tool-use/word-list-ai-slop.json` も原本と同じ内容に書き直され、同じコミットに入る（CI の全ての文書の検査が原本とコピーの不一致で落ちない） |
| slop-check への反映 | `word-list` を直コミットした直後から、slop-check の照合が登録した行を使用する |
| alias-inject への反映 | `terms` を直コミットした直後から、alias-inject の案内が登録した用語を使用する |
| 使い方 | knowledge の行に `direct_commit.scope` を記載する手順と、直コミットできる種類の確認が使い方にある |

`未確定`: slop-check の照合へ直後に反映する方法（決める段: インターフェース定義設計）

slop-check のフックは、インストールしたプラグインのフォルダ（`${CLAUDE_PLUGIN_ROOT}`）の対応表のコピーを参照する。
プラグインのフォルダはプラグインを更新するまで変わらないため、直コミットしただけでは照合に反映されない。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | 環境変数で knowledge の develop のワークツリーの対応表のコピーを指せるようにし、指したファイルがあればそれを参照する。無ければ今までどおりプラグインのフォルダのコピーを参照する | 直コミットの直後から反映される。プラグインの更新が要らない | フックの読み込み先の分岐と、端末の環境変数の設定（反映作業）が増える |
| B | 読み込み先は変えず、直コミットの後にプラグインを更新して反映する | フックを変えない | 直後には反映されず、更新の操作を忘れると反映されない |

推奨: A

Issue の「登録した直後から反映される」を満たすのは A だけで、alias-inject も develop のワークツリーの原本を参照して直後に反映している。
