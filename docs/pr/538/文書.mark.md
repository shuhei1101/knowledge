## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 直コミットの許可 | `project-index.yaml` に `direct_commit`（`branch: develop`・`kinds: [knowhow, word-list, terms]`）を記載する | ほかの種類は記載しない |
| 対応表のコピーの生成 | `project-index.yaml` の `generators[]` に対応表のコピーの作成を登録し、書き込みの後にコピーを書き直す | 直コミットでは生成物も同じコミットに入る（project-index の『文書のMCP』の直コミットの手順 4〜5） |
| 説明書 | `instructions` に、3 つの種類は許可した作業場所から直コミットで登録できることを記載する | - |
| シナリオ | 直コミットの単一ユースケース `SC-536-1` を新規作成する。正常シナリオ（3 つの種類）と、許可していない種類・範囲の外部の作業場所の異常シナリオを持つ | E2E は SC-514-1 と同じく一時フォルダの bare リポジトリへプッシュする |
| 使い方 | 「knowledge を配信元に登録する」に、knowledge の行の `direct_commit.scope` の記載と、直コミットできる種類の確認を追加する | slop-check の読み込み先を変える場合は、環境変数の設定も追加する |
| 用語集への反映の確認 | alias-inject は develop のワークツリーの `project-index.yaml` から用語集を参照するため、読み込み先は変えない。直コミットの直後に反映されることを単一ユースケース設計で確認する | - |
