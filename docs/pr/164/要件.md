# 要件

## 要望

フィルター・照合条件の AND・OR・NOT の共通の構造を規約として新設し、判定フローチャート『エイリアスの登録』に、一般語の名前でも特定の文脈でだけその文書を指すなら照合条件を付けて登録する分岐を追加する。
規約『タグと用語の登録』の、一般語を登録しない例もこの分岐に合わせる。

### 条件の共通の構造の規約（新規）

フィルター・照合条件を設計・実装するときに読む規約として、dev-docs の `search_docs` の `filter` が持つ構造（Issue の A-12）を記載する。

| 要素 | キー | 意味 |
| --- | --- | --- |
| 条件 | `field`・`op`・`values`・`match` | 1 つの項目を比べる。`values` が複数のときは `match: any`（どれか）か `all`（全て） |
| AND の束 | `and` | 配列の全てに当たる |
| OR の束 | `or` | 配列のどれかに当たる |
| NOT の束 | `not` | 中の条件か束に当たらない |

| 決まり | 内容 |
| --- | --- |
| 否定の書き方 | 1 つの条件の否定は否定の比べ方（`ne`・`not_contains`）、束の否定は `not` |
| 入れ子の深さ | 3 レイヤーまで。超えるなら条件を分けて登録する |
| 値の正規化 | NFKC と大文字小文字を統一して比べる（`case_sensitive` で解除） |
| 空の束 | 記載しない（検査で弾く） |
| 省略形 | 条件を 1 つだけ記載するときは束で包まない |

- 置き場所は分野をまたぐ `dev` の規約 `docs/rule/dev-filter-condition.yaml`（ID `dev-filter-condition`）
- 参考にした仕組み（dev-docs の `filter`・Notion API の `filter`・Elasticsearch の `bool`・MongoDB のクエリ）は `sources` に記載する
- 例は alias-inject の `inject_when`（条件の `field` は照合した本文を指す `text`、`op` は `contains`・`not_contains`）に合わせる
- 画面の条件ビルダーの構造は規約『タグの絞り込みと保存ビュー』（`ui-tag-filter`）に従い、保存するときにこの構造へ変換する。`ui-tag-filter` の `builder-02` から新しい規約を参照する

### 判定フローチャート『エイリアスの登録』の分岐（D-15 の案 A）

`q3`（複数の文書や用語に当てはまる一般語か ※4）が YES のとき、すぐに「登録しない」へ進めず、「特定の文脈でだけその文書を指すか」を判定する分岐を追加する。

- YES: 照合条件を付けて登録する。条件の書き方は新しい規約を参照する
- NO: 今のとおり「登録しない」
- 「特定の文脈」の注記には、alias-inject の照合条件で表せる文脈（照合した本文に出る別の単語）と、例（React の規約『フォルダ構成』を「React」か「tsx」を含み「Python」を含まない本文でだけ案内する）を記載する
- alias-inject の照合条件は文書に 1 つで、その文書の `name`・`aliases` の全てに効く（alias-inject#57 の D-14）。条件を付けると、その文書の他の名前も条件に当たる本文でだけ案内されることを注記に記載する
- 文書のタイトル（`name`）そのものが一般語のときは、タイトルも ※1 の候補にし、照合条件の記載までを判定する（タイトルは aliases に登録しない）。alias-inject は `name` も照合するため

### 規約『タグと用語の登録』（`dev-tag-term-registration`）

`alias-not-register-01` の「複数の文書や用語に当てはまる一般語」の行を、特定の文脈でだけその文書を指すなら照合条件を付けて登録する例外に合わせる。

### ルール索引（`rules.yaml`）

新しい規約の行を追加する。
`paths` は、フィルター・照合条件を実装するファイル名（`**/*{filter,condition}*.{py,ts,tsx}`）にし、`on` は `write` にする。

### 共通

- 改めた規約・判定フローチャートの `rev` を 1 つ上げ、`last_reviewed` を変えた日にする
- 変える項目の外の文言は一字一句そのまま残す（規約『既存文章の維持』）
- 規約『YAML』（`dev-yaml`）の `mcp-read-04`（検索のタグを AND・`any_tags` で OR に絞る引数）は、タグだけを並べる引数で入れ子の条件を記載しないため変えない

終わりの条件:

- `docs/rule/` に、条件・束・否定の書き方・入れ子の深さ・値の正規化・空の束・省略形を定めた規約がある
- 判定フローチャート『エイリアスの登録』で、一般語の名前が「特定の文脈でだけその文書を指す」場合に照合条件を付けて登録する結果へ進み、その結果から新しい規約を参照している
- 規約『タグと用語の登録』の一般語の例が、判定フローチャートの分岐と食い違わない
- 全ての文書の検査（`scripts/check_all.py`）が通る
