# 要件

## 要望

workflow のインターフェース定義のテストの配置を `tests/e2e/workflow/` のまま残し、規約『V字モデル』（`docs/rule/dev-v-model.yaml` の `mapping-01`）の対応表に、入口が `trigger` の GitHub Actions の workflow のインターフェース定義の例外として記載する。
`test_file` の説明（`schemas/design/interface.schema.yaml` と、生成し直すテンプレート『インターフェース定義』）にも同じ例外を記載し、`tests/e2e/workflow/` を記載する規約・例・`rules.yaml` の行と食い違わないようにする。

| 案 | 内容 |
| --- | --- |
| A | `tests/integration/{サブシステム名}/` へ移す |
| B | `tests/e2e/workflow/` に残し、規約『V字モデル』の対応表に例外を記載する |

採用: B

- workflow のテストは検証用のブランチを本物のリポジトリへ push して GitHub Actions を起動する（`python-testing-workflow` の `placement-02`）。
  `uv run pytest` は単体・結合・非機能要件を回し、E2E だけをガードで skip する（`python-testing-layers` の `file-placement-02`）ため、`tests/integration/` へ移すと既定の実行で push と起動が走る
- `rules.yaml` は規約『GitHub Actions の workflow のテスト』をフォルダの glob（`**/tests/e2e/workflow/test_*.py`）で当てている。
  `tests/integration/{サブシステム名}/` へ移すと、workflow のテストと他の結合テストをパスで見分けられない
