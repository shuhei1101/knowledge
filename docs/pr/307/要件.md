### #247 話し合いで決めた文書の決まり 4 件の規約への追加

次の 4 件の決まりを knowledge の規約に追加する。
既存の記載で足りる決まりは追加しない。

| 対象 | 決まり | 追加する規約 | 既存の記載との関係 |
| --- | --- | --- | --- |
| 資料の本文 | 本文には原本だけを記載する（経緯・履歴・旧構成からの変化は記載しない）。参照した資料は末尾の「参照した資料」の表に、絶対パスか URL で記載する | 規約『表し方の優先順位』の `本文に出さないもの` と、新しい group `参照した資料` | 規約『文章の書き方』の確認表の「そう記載する理由・背景・経緯を説明していないか」は、文章を追加した後の確認で、旧構成からの変化・履歴と参照した資料の記載先を定めない。規約『コーディング全般における規約』の「コメントに履歴・経緯・背景は書かず」はコードのコメントが対象 |
| テンプレートと資料 | 資料を作るときにテンプレートが無ければ、先にテンプレートを作る。テンプレートから作る資料は、テンプレートの 1 単位（1 ユースケース・1 エージェントフロー）を 1 ファイルにする。図のテンプレートは、図の要素をメタデータ（表・YAML）に持たせ、図はそこから描く | 規約『表し方の優先順位』の `図`・`ページの分け方` と、新しい group `テンプレート` | テンプレート『シナリオ』とシナリオのスキーマの「1 ファイル = 1 ユースケース」はシナリオだけが対象で、ほかのテンプレートの 1 単位とテンプレートを先に作る決まりは無い |
| 設定の構造 | 設定ファイル・スキーマ・マーカーの引数は、拡張性を最優先に設計する。後から引数が付きうる値は、今は値が 1 つでも文字列にせず、キーを追加できるオブジェクトにする | 規約『YAML』の `設定ファイル` | 規約『設計原則の優先順位』の拡張性は Python のクラス・関数の設計が対象 |
| VS Code 拡張機能の .vsix | 手動でアップロードする .vsix を作るときは、Marketplace に公開済みのバージョンより上のバージョンにする（同じバージョンは上書きできない） | 規約『VS Code 拡張機能の配布』の `.vsix` | `version-01` はバージョンを上げる契機だけを定める |

追加先の規約が、該当する文書・設定・.vsix を作るエージェントに注入されるかを `rules.yaml` で確かめ、当たらない場合は `paths`・`tools`・`args` を追加する。

終わりの条件:

- 資料の本文・テンプレートと資料・設定の構造・VS Code 拡張機能の .vsix の 4 件の決まりが knowledge の規約にあり（既存の記載で足りるものは追加しない）、該当する文書・設定を作るエージェントに注入される
