# 要件

## 要望

判定フローチャート『リポジトリの置き場所』（`docs/flowchart/flowchart-repo-location.yaml`）を新規作成する。
WSL で開発するリポジトリ 1 つについて、Windows のドライブ（`/mnt/c`）に配置するか Linux 側（ext4）に配置するかを判定し、新規のリポジトリにも既存のリポジトリにも同じ質問を適用できるようにする。

| 項目 | 内容 |
| --- | --- |
| 判定軸 | Issue の一案の 3 つ（Windows 側のプロセスがリポジトリのファイルを実行・読み書きするか / Windows 専用の依存を Windows の上で動かすか / Windows のアプリで日常的に開くか）を元に、ドキュメント修正で確定する |
| 結果 | Linux 側に配置する・`/mnt/c` に配置する・Windows の上で動かすものを持つリポジトリの扱い（下の `未確定`） |
| ※n の定義 | 質問の単語（Windows 側のプロセス・Windows 専用の依存・日常的に開く）を判定できる粒度で定義する |
| 関連 | 判定フローチャート [テストの実行場所](https://github.com/shuhei1101/knowledge/blob/f55409b/docs/flowchart/flowchart-test-location.yaml) へ、新規作成する側からだけ関連を張る |

判定フローチャートは、作業 PR を始めた時点の develop の記法（`※n` の定義）で記載する。
[#173](https://github.com/shuhei1101/knowledge/issues/173)（作業 PR [#396](https://github.com/shuhei1101/knowledge/pull/396)）が後に入る場合は、#396 へ新規作成した 1 件も書き換えの範囲に含めるよう連絡する。

knowledge の判定フローチャートは全てのプロジェクトが参照するため、AI Monitor の仕組みの名前（監視対象・配信元の設定のキー）を判定と結果に記載しない。

`未確定`: Windows の上で動かすもの（`pywinauto`・`pywin32`・`pycaw` を使用するもの）を持つリポジトリの扱い（決める工程: ドキュメント修正）

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | リポジトリを `/mnt/c` に配置する | クローンが 1 つで、Windows 側から直に実行できる | WSL 側の venv・git・テストが 9P の通信を待つ |
| B | 開発は Linux 側のクローンで行い、Windows の上で動かすときだけ `/mnt/c` のクローンを使用する | 開発の読み書きが速い | クローンが 2 つになり、`/mnt/c` のクローンを最新にする操作が要る |
| C | Windows の上で動かすときの頻度で A と B を分ける（常駐させるなら A、開発中だけ動かすなら B） | 両方の負担を用途で選べる | 質問が 1 つ増える |

推奨: B

Issue の現状で挙がった遅れは全て WSL 側の開発の操作で起きており、Windows 側で動かす操作は開発の操作より少ないため。
