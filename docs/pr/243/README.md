# AI slop の対応表に 4 種の単語とボタンの文言を登録し、シンプルだけど凡庸でない見た目の決まりを ui の規約とデザイン方針に追加する

## 概要

エージェントが「閲覧者」「アクセシブルネーム」「〜の枠」とボタンの「〜を表示」「〜を追加」を記載したとき、slop-check から置き換え先を通知されるようになる。
画面を作る人が、どのシステムにも適用する見た目の決まりを規約で参照し、システムごとのワンポイント・形状・色の候補をデザイン方針で選べるようになる。

## 背景

束の親 [Issue #242](https://github.com/shuhei1101/knowledge/issues/242) の要望で、`scope:dev/コーディング規約/ui` を触る 2 件を 1 つの作業 PR で対応する。

- [#228](https://github.com/shuhei1101/knowledge/issues/228): [shuhei1101/mdmark#394](https://github.com/shuhei1101/mdmark/pull/394) で AI が選んだ置き換え先のうち 4 種がユーザーに不自然と判断され、AI slop として登録する依頼を受けた。規約『入力と文言』のボタンの書式は「権限を追加」を例に持ち、ボタンに「を」を付けないユーザーの判断と食い違う
- [#233](https://github.com/shuhei1101/knowledge/issues/233): [shuhei1101/ai-monitor#2351](https://github.com/shuhei1101/ai-monitor/issues/2351) から移した要望。画面の見た目が、機能は整っていてもシンプルすぎて印象に残らない。文字の大きさの対比・色を絞ったうえでの 1 色・製品固有の題材を 1 か所だけ主役にする決まりが規約に無い
