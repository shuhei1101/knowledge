# 要件

## 要望

- `docs/flowchart/` に、狭い幅でヘッダーの文字（アプリ名・ボタンの文言）と画面の短い文言（通知・ボタン・ラベル・見出し）が折り返す・省略されるときに、どの対処を選ぶかを判定する判定フローチャートを、テンプレート『判定フローチャート』（`template-flowchart`）の書式で作る
- 本文・説明文の折り返しは対象外にする（折り返してよいもの）
- 結果の対処には、Issue の本文の候補を全て含める
  - アプリのアイコンだけにする
  - アプリ名を短い名前にする
  - ヘッダーのボタンを優先度の低い順に減らす
  - ヘッダーの左のメニューの中にボタンの操作をしまう
  - ヘッダーのボタンをアイコンだけにする（読み上げ名は残す）
  - 文字量を減らす（「1 件のコメントをコピーしました」→「コピーしました」）
  - 前後の文脈で分かる語を落とす
  - 件数などの変わる値を別の場所（一覧の見出しなど）へ移す
  - 文言を 2 つの要素に分けて片方を補足の小さな字にする
  - 要素の幅（通知の最大幅など）を広げる
  - 狭い幅だけ短い別の文言にする
- 主要な Web アプリ・デザインシステムの扱いを調べ、候補に無い対処があれば結果に追加する。参照した資料は判定フローチャートの `sources` に記載する
- 規約『レイアウト』（`ui-layout`）と『入力と文言』（`ui-input-wording`）から、この判定フローチャートを参照する
- develop へマージした後に、release の手順でバージョンのタグを打つ
