## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 生成のシナリオ | Markdown のテンプレートを生成する正常・異常のシナリオを新しい単一 UC にする | SC-201-1 は変えない |
| 生成のスクリプト | スキーマの `$ref` を解決し、種類ごとに雛形と記載例の文書を組み立てて dev-docs の `schema_to_markdown` へ渡し、`<!-- dev-docs-table: … -->` を除いて `docs/template/markdown/` へ書き出す | 新しいスクリプトにする |
| プレースホルダ | キーは `{title}`、`enum` は選択肢を ` / ` でつなぐ。真偽の値と `title` の無い配列の要素の表記を整える | - |
| 管理用の YAML | 生成のスクリプトが、YAML のテンプレートの `name`・`description`・`tags` から行を書き出す | `aliases` はコピーしない |
| dev-docs の取り込み | `uv run --with "dev-docs @ git+https://github.com/shuhei1101/dev-docs@{コミット}"` でコミットを固定して入れる | 外部ライブラリの設計書を新設する |
| 全ての文書の検査 | Markdown のテンプレートと管理用の YAML がスキーマから生成した内容と一致するかを確認し、ずれを違反にする | - |
| エラー | スキーマを読み込めない・dev-docs の変換が失敗したときは、スキーマのパスと理由を出して 0 以外で終わり、生成物を書き換えない | - |
