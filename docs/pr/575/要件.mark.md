# 要件

## 要望

- 設計書の種類（`schemas/design/` の `common`・`index` を除く全ての種類）ごとに、次の 2 つの Markdown をスキーマから機械で生成する
  - 雛形: 全てのキーにプレースホルダを入れたもの。`enum` のあるキーは選択肢を ` / ` でつなぎ、配列は要素を 1 件にする
  - 記載例: スキーマのトップの `examples` から作ったもの
- Markdown への変換は dev-docs の `schema_to_markdown` を import して使用し、knowledge 側に `x-heading`・`x-shape` などの変換の規則を実装しない。knowledge 側は `$ref` の解決・雛形の組み立て・dev-docs の画面専用のマーカー `<!-- dev-docs-table: … -->` の除去・プレースホルダの表記の整形だけを持つ
- 取り込む dev-docs のコミットを固定し、CI と手元で同じコマンドで生成できるようにする
- 生成物は `docs/template/markdown/` の下に、種類ごとにコピーしてそのまま使用できるファイルで置く
- `check_all.py` が、Markdown のテンプレートがスキーマから生成した内容と一致するかを確認し、ずれを違反にする
- 生成物を dev-docs の画面から参照できるようにする。メタデータは生成のスクリプトが管理用の YAML に、対応する YAML のテンプレートの `name`（`テンプレート（Markdown）: {種類の名前}`）・`description`・`tags` から書き出す。`aliases` はコピーしない

Markdown のテンプレートは、YAML のテンプレートの生成（`scripts/build_templates.py`）と別の新しい生成のコマンドで生成する。
YAML のテンプレートの生成は dev-docs に依存しないまま残す。
