## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 規約のキーの表の列 | `key-table-01` の列を、キー・型・必須・条件・説明・例にする。条件があるキーが 1 つも無い表には条件の列を出さない | - |
| 条件と必須の関係 | 条件があるキーの「必須」は、条件に該当するときの扱いにし、該当しないときはキーを持たない | スキーマの `condition` の `description` に書く |
| スキーマのキー | `required`（ER 図は `not_null`）を持つ要素に、任意のキー `condition`（`title`: 条件）を `required` の直後に追加する。必須のキーの並び（`required:`）には入れない | 値の型は `未確定`（要件.mark.md） |
| テンプレート | スキーマを変えた後に `uv run --frozen --script scripts/build_templates.py` で作り直し、スキーマと一緒に commit する | - |
| 設計書のスキーマのタグ | 任意のキーの追加で今の設計書がそのまま検査を通るため、マージの後に `design-schemas/v*` のマイナーを上げたタグを作る | 反映作業 |
