## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 規約のキーの表の列 | `key-table-01` の列を、キー・型・必須・条件・説明・例にし、条件の書き方を書く | 空の条件の列を出さないことは `table-03` が定め、dev-docs の変換も空の列を省く |
| 条件と必須の関係 | 条件があるキーの「必須」は、条件に該当するときの扱いにし、該当しないときはキーを持たない | スキーマの `condition` の `description` に書く |
| スキーマのキー | 共通の型 `common.schema.yaml#/$defs/key_condition`（文字列。`title`: 条件）を作り、`required`（ER 図は `not_null`）を持つ要素の直後に、任意のキー `condition` として `$ref` で追加する。`required` を持たない応答の表（インターフェース定義の `response[]`・外部 API の `endpoints[].response[]`・外部ライブラリの `returns[]`）は `type` の直後に追加し、外部 API・外部ライブラリの `name` の説明の「条件を補足に記載する」を「条件を `condition` に記載する」に修正する | - |
| テンプレート | スキーマを変えた後に `uv run --frozen --script scripts/build_templates.py` で作り直し、スキーマと一緒に commit する | - |
| 設計書のスキーマのタグ | 任意のキーの追加で今の設計書がそのまま検査を通るため、マージの後に `design-schemas/v*` のマイナーを上げたタグを作る | 反映作業 |
