# 要件

## 要望

キーの表を持つ設計書のスキーマ・テンプレートと、規約『表し方の優先順位』の「キーの表」で、「このキーは、ほかのキーがこの値のときに持つ（必須）」を「条件」の列（キー）として記載できるようにする。

- 規約『表し方の優先順位』の `key-table-01` に、条件の列（「必須」の後）と条件の書き方を書く。条件があるキーが 1 つも無い表に列を出さないことは、同じ規約の `table-03`（どの行も空の列は出さない）が既に定めている
- `required` を持つキーの表の要素（`config`・`data`・`interface`・`external_api`・`library`・`component`・`screen`・`module` の各スキーマ）の `required` の隣に、条件のキー `condition` を任意のキーとして追加する
- ER 図（`er`）の `not_null` の隣にも、同じ条件のキーを追加する
- テンプレート（`docs/template/template-*.yaml`）は `scripts/build_templates.py` でスキーマから作り直して追随させる
- 条件のキーを省いた今の設計書は、そのまま検査を通る

条件のキーの値は文字列にし、`{キー}: {値}`（例 `type: anime`）か、そのキーを省略したときの `{キー} なし` で記載する。
