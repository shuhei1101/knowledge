## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| 規約『入力と文言』 | `input-submit-01` の送信中の行を、書き込み（送信・保存・更新・削除）をするボタンの行に置き換える。応答を待つ間はもう一度押せなくし、押したボタンの上で待っていることを見せる。ボタンの幅と文言の位置を変えない | 待っている見せ方の切り替えは規約『表示の安定』の待ち時間の行を参照する |
| 規約『ミューテーション』 | `useMutation` のセクションに、mutation を呼ぶボタンを `isPending` の間は押せなくする行を追加する | 決定: 表 1 の A（楽観更新をする操作のボタンは除く） |
| 画面設計のスキーマ | `elements[]` の `initial_state` の後に、書き込みの応答を待つ間の要素の状態を記載する任意のキーを追加し、スキーマの `examples` に例を入れる | 決定: 表 2 の B（文字列のキー `pending_state`） |
| テンプレート『画面設計』 | `scripts/build_templates.py` で生成し直す | 手で編集しない |
| チェックシート『実装した画面のレビュー観点』 | 書き込みをするボタンを応答を待つ間に続けて押し、反映が 1 回だけで、待っていることがボタンの上で分かるかを確認する行を追加する | 補足の列に規約『入力と文言』へのリンクを配置する |
| チェックシート『モック HTML のレビュー観点』 | Disabled・Hover などの場面を撮る行に、書き込みのボタンの応答を待つ間の場面を加える | - |
| 設計書のスキーマのタグ | 任意のキーの追加で今の設計書がそのまま検査を通るため、マージの後に `design-schemas/v*` のマイナーを上げたタグを作る | 反映作業 |

表 1: 楽観更新の許可リストの操作（いいね・トグルなど）のボタンの扱い

| 案 | 内容 |
| --- | --- |
| A | 楽観更新をする操作は押せなくする対象から除外し、楽観更新をしない mutation のボタンだけを `isPending` の間押せなくする |
| B | 楽観更新をする操作も含め、全ての mutation のボタンを `isPending` の間押せなくする |

決定: A

楽観更新は押した直後に画面を変えて待たせない方式で、押せなくすると連続のトグルの操作を妨げるため。

表 2: 画面設計のキーの構造

| 案 | 内容 |
| --- | --- |
| A | 列挙のキー（例: `pending_state`。値は `非活性 + 読み込み中の表示` / `変えない`）を追加する |
| B | 文字列のキー（例: `pending_state`。応答を待つ間の状態と見た目を文で記載する）を追加する |

決定: B

`initial_state` と同じ列挙にすると見た目（回る表示・文言の差し替え）を記載できず、ボタン以外の要素（入力欄を読み取り専用にする 等）の状態も文で記載できるため。
