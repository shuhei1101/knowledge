# 要件

## 要望

書き込み（送信・保存・更新・削除）をするボタンの、応答を待つ間の状態の決まりを knowledge の文書に持ち、画面を設計・実装・レビューする人が参照できるようにする。

- 規約『入力と文言』に、書き込みをするボタンは応答を待つ間にもう一度押せず、押したボタンの上で待っていることが分かる決まりがある（送信に限らない）
- 規約『ミューテーション』（React）に、mutation を呼ぶボタンを `isPending` の間は押せなくする決まりがある（編集・新規画面の保存ボタンだけでなく、削除・送信などのボタンにも適用する）
- 画面設計のスキーマ（`schemas/design/screen.schema.yaml`）の要素に、書き込みの応答を待つ間の要素の状態を記載するキーがあり、テンプレート『画面設計』（`docs/template/template-screen-design.yaml`）を生成し直してその行が出る
- キーは任意で、キーを省いた今の画面設計の設計書はそのまま検査を通る
- チェックシート『実装した画面のレビュー観点』に、書き込みをするボタンを応答を待つ間に続けて押しても 1 回だけ反映され、待っていることが分かるかを確認する行がある
- チェックシート『モック HTML のレビュー観点』の撮る場面に、書き込みのボタンの応答を待つ間の場面がある
- マージの後に `design-schemas/v*` のマイナーを上げたタグを作る

読み込み中の見た目と、画面設計のキーの構造は [文書](./文書.mark.md) の変更方針の `未確定` でドキュメント修正の工程で決める。
