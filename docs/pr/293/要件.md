### #258

- ※3 の例は、MCP を持たないプラグインの実在する決まりがあれば差し替え、無ければ例を削除する

### #250

- 判定の対象: 新しく作る関数・クラス・定数・型・設定のキー・部品の候補
- 判定の結果: 「既存を使用する（同じ役割）」「既存を広げる」「別に新しく作る（理由を記録する）」の 3 つ
- 共通化しすぎの歯止めに、規約『設計原則』の `dedup-02`（コードの見た目の重複は 3 回目で共通化する。共通化した関数に分岐用の引数が増えたら、インラインに戻す）を使用する
- 部品を作る前に既存を探す既存の手順と食い違わないようにする
  - 規約『コンポーネントカタログ』の `before-new-component-01`〜`04`（カタログ → shadcn → Base UI → 3 回目で共通化）
  - `docs/rule/html-components-prefetch-catalog.yaml` の `common-layer-prefetch-05`（既にあれば使用し、無ければ共通層に追加する）
- 規約『設計原則』の `dedup-02` から、新しい判定フローチャートを参照する
