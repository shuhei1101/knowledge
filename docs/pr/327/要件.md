# 要件

## 要望

プラグイン knowledge を `plugins/knowledge/` に移し、2 つのプラグインを `plugins/{プラグイン名}/` に配置する。
直下の `.claude-plugin/` には `marketplace.json` だけを残す。

- `.claude-plugin/plugin.json` を `plugins/knowledge/.claude-plugin/plugin.json` へ移す
- `skills/`（`files.yaml`・`text-review/SKILL.md`）を `plugins/knowledge/skills/` へ移す
- `marketplace.json` のプラグイン knowledge の `source` を `./plugins/knowledge` にする
- `dev-docs.yaml` の `skills` の行の `paths`、`docs/skill/text-review.yaml` の `skill.path`、フォルダ構成の設計書 LAY-72-1、SKILL.md のパスを記載したシナリオを、移した後のパスに合わせる
- プラグインの名前（`knowledge@knowledge`・`slop-check@knowledge`）と入れ方のコマンドは変えない

`未確定`: 移すかどうか（決める段: 単一ユースケース設計のレビューの合格後のユーザーへの確認）

スキル text-review は、dev-docs の無い端末では `${CLAUDE_PLUGIN_ROOT}/docs/rule/{ID}.yaml` の規約を参照する（`skills/text-review/SKILL.md`・`docs/skill/text-review.yaml`）。
マーケットプレイスから入れたプラグインは `source` のフォルダだけがキャッシュへコピーされるため、`source` を `./plugins/knowledge` にすると `docs/rule/` がキャッシュに入らない（[#98](https://github.com/shuhei1101/knowledge/pull/98) で直下をプラグインにした理由）。

| 案 | 内容 | メリット | デメリット |
| --- | --- | --- | --- |
| A | `plugins/knowledge/` へ移し、規約の参照先を無くす（SKILL.md・`docs/skill/text-review.yaml` から `${CLAUDE_PLUGIN_ROOT}/docs/rule/` の行を削除し、dev-docs の無い端末での振る舞いを要件に記載する） | 配置が統一され、仕組みは増えない | dev-docs の無い端末でスキルが規約を参照できなくなる |
| B | `plugins/knowledge/` へ移し、スキルが参照する規約をプラグインの中へ入れる（入れ方と更新のされ方を要件に記載する） | 配置が統一され、機能も変わらない | 規約をプラグインへ入れる生成かコピーの仕組みが増える |
| C | 移さず、knowledge だけを直下に配置する理由（キャッシュに `docs/rule/` を含めるため）を LAY-72-1 に記載する | 機能と仕組みが今のまま変わらない | 配置は統一されない |

推奨: C

#98 で決めた理由は今も成り立ち、A は機能が減り、B は仕組みが増えるため。

C に決まった場合、上の箇条書きの移動・パスの書き換えと、単一 UC SC-327-1・SC-72-3・SC-72-4 の変更を取り消し、LAY-72-1 の `lead` とエントリに理由を記載する変更だけにする。
A か B に決まった場合、SC-327-1 に dev-docs の無い端末でスキルが規約を参照するシナリオ（A なら参照できないときの振る舞い）を追加し、更新ドキュメントに `docs/skill/text-review.yaml` の手順の変更を追加する。
