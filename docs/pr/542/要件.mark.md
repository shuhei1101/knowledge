### #540: ヒューマンエスカレーションの表・確認観点の表のスキーマとテンプレート

`schemas/design/` に、次の 2 つの設計書のスキーマを追加する。
どちらも 1 ファイル = 制作の種類 1 つで、エージェントフローの `human_escalation.ref` とレビュアーのエージェントフローが指す。

| 表 | 原本 | キー | 決まり |
| --- | --- | --- | --- |
| ヒューマンエスカレーションの表 | A-207 | `items[]`（`id`・`name`・`condition`・`examples.match`・`examples.not_match`・`ask`・`steps`・`executor_context`・`record.target`）・`notes[]`（`item`・`rule`） | 判定する人・該当の決め方・判断が済んだ項目・項目の追加と削除・識別子 |
| 確認観点の表 | A-214 | `items[]`（`id`・`check`・`targets`・`steps`・`when`・`note`）・`knowhow[]`（`steps`・`refs`）・`notes[]`（`item`・`rule`） | 項目にするもの（テンプレート『チェックシート』の項目の決まりを引き継ぐ）・`targets` の省略・判定の方法 |

設計書のスキーマを追加するので、次も合わせて変える。

- `scripts/build_templates.py` のテンプレートの対応表に 2 行を追加し、`docs/template/` に 2 つのテンプレートを生成する
- テンプレートの対応表を持つ設計書（インターフェース定義 [IF-201-1](https://github.com/shuhei1101/knowledge/blob/7893c91/docs/interface/IF-201-1.py.yaml)・モジュール構成 [MOD-201-1](https://github.com/shuhei1101/knowledge/blob/7893c91/docs/module/MOD-201-1.py.yaml)）に行を追加する
- エージェントフローのスキーマ（`agent_flow.schema.yaml`）に、ヒューマンエスカレーションの表を指す `human_escalation.ref` を追加し、テンプレートを再生成する。レビュアーのエージェントフローは、確認観点の表を既存の `refs` で指す
- `rules.yaml` に、2 つの表の設計書を記載するときに参照するスキーマの行を追加する
- `schemas/files.yaml` に、追加するスキーマの行を追加する

種類・フォルダ・ID の接頭辞・テンプレートの ID・キーの名前は、A-207・A-214 では仮のため、knowledge の命名の決まりに合わせて見直し、テンプレートを新規作成するので設計の工程（インターフェース定義設計）でユーザーへ確認する。

### #537: 精度評価の観点の決め方

| 対象 | 変更 |
| --- | --- |
| チェックシート『精度評価の観点の抜け』 | A-266 を原稿に、テンプレート『チェックシート』の書式で `docs/checksheet/` に追加する |
| 判定フローチャート『精度評価の観点の確認の方法』 | A-267 を原稿に、テンプレート『判定フローチャート』の書式で `docs/flowchart/` に追加する |
| 観点のスキーマ（`eval_criterion.schema.yaml`）とテンプレート | 最上位の `x-rules` の `aspect:` の語彙の決まりに、語彙の表の列（タグ・確認すること・設ける場合）を追加する。`human` の決まりと `method` の `description` に、採点のモデルが受け取れない形式の出力（画像・音声・動画）のときだけ LLM の採点を省き、人だけが採点の基準で点を付ける例外（D-818）を追加し、テンプレートを再生成する |
| 判定フローチャート『精度評価をするか』 | 追加する 2 件への関連を付ける |

原稿の中の話し合いの ID の参照（A-91・TH-532 など）は、knowledge の文書の ID に置き換える。
`aspect:` の語彙そのものはプロジェクトの精度評価の仕組みの設計書が持ち、knowledge には登録しない。
`difficulty:high` のタグは、今のまま観点にだけ付ける（D-817）。
