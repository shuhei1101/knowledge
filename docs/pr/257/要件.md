# 要件

## 要望

knowledge の既存の文書を、次の 4 つで今の規約に統一する（[#145](https://github.com/shuhei1101/knowledge/issues/145)、2026-11-09 のユーザーの依頼で範囲を絞り直した）。

| 作業 | 内容 | 適用する規約 |
| --- | --- | --- |
| 表への書き換え | 同じ属性を持つ項目が 2 件以上ある文・箇条書きを表にする。`**キー**: 値` が 3 つ以上並ぶものは「項目 / 値」の表にする | 『表し方の優先順位』・判定フローチャート『表し方の選び方』 |
| 不要な文の削除と AI slop の修正 | 見出し・表で分かることの繰り返し・既出の言い直し・理由の説明・当たり前の注意を削除し、この PR で書き換える文を確認表と対応表で点検する | 『文章の書き方』・対応表『AI slop の単語の対応表』・判定フローチャート『用語の選び方』 |
| メタデータの付け直し | タグ（`action:`・`topic:`・`tool:` と `main` 1 つ）・用語・`description`（何を定め、どんなときに参照するかの 1 文）・関連を付け直す | 『タグと用語の登録』・判定フローチャート『タグの付与』『用語の登録』『関連の張り方』 |
| lint の違反の修正と設定の切り替え | 警告にしたルールの違反を修正し、`scripts/lint/` の設定で全てのルールを error へ切り替える | 『Markdown 編集規約』・`scripts/lint/` の設定 |

対象は `dev-docs.yaml` が配信する文書のうち、PR ドキュメントを除く全て（規約・手書きのテンプレート・判定フローチャート・判定表・チェックシート・使い方・対応表・スキル・変更履歴・設計書）。
設計書は、メタデータの付け直し（`description` は設計書のスキーマの書き方のまま）だけをし、本文の表への書き換えはしない。
AI slop は、lint の違反の修正・表への書き換え・メタデータの付け直しで書き換える文だけを修正し、残りはフォルダごとの Issue に分ける（確認ログ）。
`description` の末尾の「ときに読む」は「ときに参照する」へ統一し、規約『文書のタグと description の記載』の `description-01` と例も書き換える（確認ログ）。
スキーマから生成する設計書のテンプレート（`scripts/build_templates.py` の `TEMPLATE_IDS`）は手で修正せず、違反の元の `schemas/design/` を修正して生成し直す。

終わりの条件は次の 2 つ。

- `uv run --frozen --script scripts/check_all.py` が、警告 0 件・違反 0 件で終了コード 0 を返却する
- `scripts/lint/.markdownlint-cli2.jsonc`・`.textlintrc.json` に `warning` の指定が残っていない
