# 要件

## 要望

フォルダ構成の設計書の種類（layout）を `schemas/design/` に追加し、`docs/template/` にテンプレートを生成する。
フォルダを切る観点とレビューの観点は規約に記載し、ディレクトリ構成を持つ既存のキーをフォルダ構成の設計書に合わせる。

<!-- table: data -->

| 項目 | 要件 |
| --- | --- |
| スキーマ | `schemas/design/layout.schema.yaml` を追加する。`x-kind` は `layout`、`id` の接頭辞は `LAY`、リポジトリに 1 枚 |
| キー | 案 A-74 の最新版のキーの一覧に従う（`id`・`title`（表示名）・`repository`・`lead`・`content_types[]`・`entries[]`・`gitignore[]`・`refs`） |
| エントリ | `entries[]` の要素を `type`（`folder`・`file`）で分け、`folder` だけが `children[]`・`naming`・`used_by`・`id_root`・`convention` を持つ入れ子にする。どの要素も `name`・`contents` を必須にし、`content_types`・`generated_from`（`path`・`command`）・`placeholders[]`（`name`・`from`）を任意で持つ |
| 中身の種類の語彙 | キー名は `content_types`（`kinds`・`categories` から改名した）。`content_types[].group` は `role`・`feature` |
| テンプレート | `scripts/build_templates.py` の `TEMPLATE_IDS` に `layout` を登録し、生成のコマンドで `docs/template/` にフォルダ構成のテンプレートを生成する。CI の全ての文書の検査で、スキーマとテンプレートが一致する |
| 切る観点・レビューの観点 | テンプレートには書式だけを記載し、案 A-74 の「フォルダを切る観点」「レビューの観点」の 2 つの表は規約に記載して、スキーマから規約を ID で指す |
| `python -m` の入口 | 規約『トップレベルレイアウト + feature 内構造』（`python-architecture-layout`）に、`python -m` の入口（`{pkg}/{command}/__main__.py`）の配置先を追加する |
| 既存のキー | フォルダ構成の設計書を原本にし、アーキテクチャ図の `repository.layout` と、モジュール構成の `directory`（分類をまとめる設計書の `x-rules` を含む）を廃止する。設定の `files[]` と目次の `summary` は、リポジトリの外のファイルや `docs/` の目次の行を持ち、フォルダ構成の設計書と別の事柄を記載するので残す |
| スキーマのタグ | 既存のキーを廃止すると既存の設計書が検査を通らなくなるため、`design-schemas` のメジャーを上げたタグを作成する（反映作業） |
