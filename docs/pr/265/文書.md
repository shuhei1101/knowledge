## 変更方針

| 対象 | 方針 | 補足 |
| --- | --- | --- |
| フォルダ構成のスキーマ | `schemas/design/layout.schema.yaml` を、案 A-74 の最新版のキーの一覧と見本の YAML で作る。`entries[]` の要素は `type` の `if`/`then` で `folder` だけのキーを許す。`children[]` は同じエントリの定義を `$ref` で再帰させる | キーごとに `examples` を記載する |
| フォルダ構成のテンプレート | `TEMPLATE_IDS` に `layout` を登録し、生成のコマンドで `docs/template/template-layout.yaml` を作る。メタデータ（`id`・`name`・`description`・`tags`）は手で記載する | 本文（`items`）は生成物 |
| 切る観点・レビューの観点 | `docs/rule/` にフォルダ構成の規約を 1 件追加し、案 A-74 の 2 つの表を記載する。フォルダ構成のスキーマの `description` からこの規約を ID で指す | rules.yaml に、フォルダ構成の設計書に該当する行を追加する |
| 既存のキー | `repository.layout` と `directory`・分類をまとめる設計書の `x-rules` を削除し、`template-architecture`・`template-module` を生成し直す | 生成し直すのは実装の工程 |
| `python -m` の入口 | `python-architecture-layout` のトップレベルの構成に、`{pkg}/{command}/__main__.py` の配置先の行を追加する | - |

## テスト結果

ドキュメント修正はスキーマ・規約・索引だけを変え、関係する単体・結合テストは無い。
スキーマの記載例が `layout.schema.yaml` 自身に合うこと、`type: file` のエントリに `children` を記載すると検査で違反になること、`layout.schema.yaml` がメタスキーマに合うことを確かめた。
全ての文書の検査（`scripts/check_all.py`）の違反は、`template-architecture`・`template-module` がスキーマと一致しない 2 件だけで、実装の工程で生成し直して解消する。
