# 要件

## 要望

ネットミームの登録のスキル・リサーチャーのエージェントフロー・知名度の判定表を knowledge に配置し、最初の作品と用語をネットミームの配信元 `knowledge-memes` に登録する。
終了の条件は次のとおり。

<!-- table: {"kind": "data"} -->

| 項目 | 終了の条件 |
| --- | --- |
| 登録のスキル | `docs/skill/` に `type: skill` のエージェントフローがあり、生成した SKILL.md を knowledge のプラグインが `/knowledge:meme-register` として配る。工程・引数・候補の選別・利用者への確認の方法は A-241 のとおり |
| リサーチャー | `docs/skill/` に `type: flow` のエージェントフローがあり、登録のスキルの調査の工程がサブエージェントとして指す。集める言葉・依頼に指定する情報・返却する情報は A-238 のとおり |
| 知名度の判定表 | `docs/decision-table/` に判定表があり、段階の基準・判定の手順・判定の例は A-242 のとおり。リサーチャーと登録のスキルが推奨の値の根拠として指す |

| 出典 | 用語の `refs` に、調査 R-25〜R-28 の出典の URL を移す |
| 放送 | 作品の `airings` に、A-244 の最新のシーズンに加えて、2026-11-20 までに始まった前のシーズンを Web で確認して記載する |
| 後続への連絡 | マージの後に [shuhei1101/aituber#163](https://github.com/shuhei1101/aituber/issues/163) へ着手できる旨をコメントし、`確認:task-planner` を付ける |

キー・タグの語彙・作品の説明の書き方は、MindStella の資料 [データ: ネットミーム](/home/shuhei2441/repo/tmp/nandemo-kaiwa/.mindstella/docs/A-237.mark.md) と、#530 で入ったスキーマ（`memes/schemas/`）に従う。

最初の登録は、作業 PR の commit で入れる（`write_docs` を `commit` なしで作業 PR の worktree へ書き込む）。
直コミットは手元のセッションが使用する方式で、AI Monitor のエージェントの作業では使用しない（A-243 の「使用しない場面」）。

知名度の判定表の境界の値（A-242 の「この資料で決定しないこと」）は調整しない。
A-244 で利用者の値と推奨の値が食い違った作品は、利用者が作品ごとに値を決めており、境界の値を変える指示は無い。

登録のスキルが `search_docs`・`write_docs` などの MCP のツールを呼ぶ工程は、`type: tool` にしてツールの完全な名前（`mcp__plugin_project-index_project-index__write_docs` など）で記載する。
SKILL.md の生成（IF-312-1）は `type: mcp` の `calls[].server` を ID のまま出力し、ツールの名前に解決しないため、『MCP サーバーの定義』を指しても SKILL.md を読むエージェントがツールを特定できない。
既存のスキル text-review も、MCP のツールを完全な名前で記載している。

## 話し合いの資料との食い違い

Issue の決まりのとおり、話し合いの資料を正にし、食い違う箇所を挙げる。
リポジトリの約束に合わせる箇所は、資料で「仮」とされている値と、今の仕組みで成り立たない箇所（理由を「このリポジトリ」の列に記載）だけにする。

<!-- table: {"kind": "data"} -->

| 箇所 | 話し合いの資料 | このリポジトリ | 扱い |
| --- | --- | --- | --- |
| スキルの配置先 | `plugins/knowledge/skills/meme-register/SKILL.md`（A-241。仮） | knowledge のプラグインは直下が `source` で、スキルは `skills/{名前}/SKILL.md`（フォルダ構成の設計書） | `skills/meme-register/SKILL.md` に配置する |
| エージェントフローの ID | `meme/register`・`research/meme`（A-238・A-241。仮） | `docs/skill/` の ID は `/` を持たないスラッグ（`text-review`） | `meme-register`・`meme-research` にする |
| 最初の登録の方法 | 直コミット方式で登録する（A-244・計画の行の概要） | AI Monitor のエージェントの作業では直コミットを使用しない（A-243） | 作業 PR の commit で入れる |
| 呼ぶ MCP サーバーの参照 | `MCP-2#`（A-241。knowledge の ID に置き換える） | knowledge に『MCP サーバーの定義』が無く、SKILL.md の生成は `calls[].server` をツールの名前に解決しない | `type: tool` でツールの完全な名前を記載する |
| 登録のコミットの単位 | 1 つの作品・話題を 1 回のコミットにする（A-241 の「登録する」） | ネットミームの検査は `memes/works/` をディスクから参照するため、同じ `write_docs` の呼び出しで作る作品を見つけられない（`dry_run` で `作品 … が works/ にありません` を確認） | 1 つの作品ごとに、作品のコミットと、その作品の用語をまとめたコミットの 2 回にする |
