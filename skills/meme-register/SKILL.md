# ネットミームの登録

## 引数

| 引数 | 説明 |
| --- | --- |
| `$season` | アニメを登録するときの放送のシーズン。省くと今期 |
| `$sources` | 登録する作品・話題・言葉。省くと、そのシーズンのアニメの候補を集めて利用者に確認する |

## 手順

### 登録済みの作品とネットミームを取得する

ネットミームの配信元（`source` は `knowledge-memes`）から、登録済みの作品（タイトル・種別・放送のシーズン・知名度）と、その用語を取得する。
続編の作品を登録済みと判定するため、シーズンでは絞らない。
作品とネットミームのキー・タグの決まりは `describe`（`source` は `knowledge-memes`）で参照する。

呼ぶもの:

- ツール `mcp__plugin_project-index_project-index__describe`
- ツール `mcp__plugin_project-index_project-index__search_docs`

### そのシーズンの作品を集めて、調べる作品を確認する

利用者が作品・話題・言葉を指定していないときだけ行う。

そのシーズンのアニメの一覧と、人気のランキングを 2〜3 件検索して、登録済みでない作品の名前を順位と一緒に示し、調べる作品を利用者に確認する。

呼ぶもの:

- ツール `WebSearch`
- ツール `WebFetch`

### 作品・話題ごとに、調査を依頼する

調べる作品・話題ごとに、リサーチャーのサブエージェントを 1 件ずつ並行で起動し、作品の情報と用語の候補を集める。
依頼には、作品・話題の名前と種別、利用者が示した知名度と言葉、登録済みの言葉、調べる日を指定する。
作品を持たない言葉（ネットの用語・構文）だけを調べるときは、作品を省略して言葉を指定する。

リサーチャーが正式なタイトルを特定できなかった作品（`work.title` が空）は、書き込まず、特定できなかった名前を利用者に示して言い直しを依頼する。

呼ぶもの:

- サブエージェント `general-purpose`: project-index の search_docs（source は knowledge、filter は id の eq で meme-research、view は full）でエージェントフロー『ネットミームの調査』を参照し、その工程のとおりに、指定した依頼の作品・話題を調べて、返却する情報の JSON だけを返却する

### 候補を選別する

リサーチャーが返却した候補を次の表の基準で分け、確認に示す候補へ登録の推奨を付ける。
確認に示さない候補は、理由と一緒に確認の資料の末尾（通常のセッションでは確認の表の後）へ記載する。
利用者は、その候補を確認の対象へ戻せる。
聞き飽きたか・古いかは利用者が判断するので、選別の基準にしない。

<!-- table: {"kind": "data"} -->

| 区分 | 基準 |
| --- | --- |
| 確認に示さない | 一般的な言葉すぎて、言っても作品だと気づかれない（題材の単語として使用できるものは示す）。楽曲・画像が無いと成立しない |
| 推奨しないで示す | 通じる人が少ないキャラクターの名前 |
| 推奨して示す | 上の 2 つに該当しない言葉。主人公のほかのキャラクターの名前も、有名なら推奨する。アニメで放送された程度の下ネタ・不衛生・過激さは、推奨を下げる理由にしない |
| 気になる点に記載して示す | 成人向けの作品が出所・実在の人が元・人種や性別の差別に当たる言葉（リサーチャーの `concerns`） |

<!-- /table -->

### 作品と、登録する用語を確認する

作品・話題ごとに、作品の情報と用語の候補を次の 2 つの表で示して、知名度と登録する用語を確認する。

- 利用者が知名度を示した作品は、その値にする
- 知名度を示していない作品は、推奨の値と根拠（判定表『ネットミームの知名度』（`decision-table-meme-popularity`） の該当した行）を添える
- 登録済みのアニメに放送のシーズンを追加するとき（続編・再放送）も、ここで確認する
- 利用者が候補に無い用語を示したら、リサーチャーにその言葉を指定して調べさせてから候補に追加する
- 確認の前の候補は登録しない

| 実行する場所 | 確認の方法 |
| --- | --- |
| MindStella のセッション（MindStella の MCP のスレッドの書き込みを使用できるセッション） | 作品・話題ごとの候補の表と候補の全文（リサーチャーの返却）を 1 件の資料にまとめ、案が「推奨のとおりに登録する」「修正する（No をコメントで指定）」「登録しない」の検討事項を 1 件作成する |
| 通常の Claude Code のセッション | 会話の中で表で示して、回答を待つ |

作品の確認に示す表。

| 列 | 内容 |
| --- | --- |
| 作品・話題 | 正式な名前と種別 |
| 状態 | 登録済み・登録できる |
| 放送 | 最新の放送のシーズン（アニメ）。登録済みの作品は追加するシーズン |
| 説明 | 作品の説明の案 |
| 知名度 | 利用者の値。示していないものは推奨の値 |
| 根拠 | 推奨の値の根拠 |

登録する用語の確認に示す表。

<!-- table: {"kind": "data"} -->

| 列 | 内容 |
| --- | --- |
| No | 回答で指定する番号 |
| 表記 | 用語か、構文の型 |
| 文脈と、使う場面 | どういう文脈で使われている言葉か・どこが面白いか・どんな話の流れで使用するか |
| 使い方の案 | 使い方の種類（そのまま言う・型を残して入れ替える・題材に触れる・口癖をまねる）と、型（`〇〇` で示す）。例文は記載しない |
| タグ | 作品・内容・場面のタグの案 |
| 気になる点 | 成人向けの作品が出所・実在の人が元・差別（人種・性別）に当たる言葉 など、利用者が判断する材料 |
| 出典 | 出典の数と、セリフの言い回しを照合したか |
| 知名度 | 作品を持たない言葉だけ。推奨の値 |
| 登録 | 推奨するか |

<!-- /table -->

呼ぶもの:

- サブエージェント `general-purpose`: project-index の search_docs（source は knowledge、filter は id の eq で meme-research、view は full）でエージェントフロー『ネットミームの調査』を参照し、利用者が示した言葉だけを調べて、返却する情報の JSON だけを返却する

### 登録する

利用者が登録すると回答した作品（説明・放送・知名度）と用語を、ネットミームの配信元のキーで状態 `active` にして、`write_docs` の `commit` で直コミットする。
登録しないと回答したものは書き込まない。

- 1 つの作品ごとに、作品を先に 1 回の呼び出しで書き込み、続けてその作品の用語をまとめて 1 回の呼び出しで書き込む（ネットミームの検査は、同じ呼び出しで作る作品を見つけられない）
- 用語の `work` は作品の ID を指し、作品のタグを用語にも付ける
- 作品のネタでない用語（リサーチャーの `in_work` が `false`）は、作品を指さずに、種別と知名度を用語に持たせる
- 登録する用語が 1 つだけの話題（種別が `general`・`tech`）は、作品を登録せずに、確認した種別と知名度を用語に持たせる
- 続編の放送と知名度の修正は、作品の 1 件だけを修正する
- 検査で断られたら、断られた作品・用語と違反の内容を利用者に示す（断られた呼び出しは何も書き込まれない）

呼ぶもの:

- ツール `mcp__plugin_project-index_project-index__write_docs` `{"required": ["source", "operations", "commit"], "properties": {"source": {"const": "knowledge-memes"}}}`

### 旬が過ぎた用語の状態を変える

利用者が、用語か作品・話題を、旬が過ぎた・使用しないと指示したときだけ行う。

指示された用語（作品・話題のときは作品の 1 件だけ）の状態を `inactive` にして、`write_docs` の `commit` で直コミットする。
作品を `inactive` にしたときは、その作品の用語のファイルは変えない。

呼ぶもの:

- ツール `mcp__plugin_project-index_project-index__write_docs` `{"required": ["source", "operations", "commit"], "properties": {"source": {"const": "knowledge-memes"}}}`

### 結果を伝える

登録した作品と用語の数と、コミットと、登録しなかった候補を伝える。
コミットしたときは、その登録で最後にプッシュしたコミットで動いた develop のワークフローの結果だけを確認する。
途中のコミットの run は、同じ concurrency のグループの後の run に取り消される（`cancelled`）ことがあるので、結果を確認しない。

1. `gh run list` を、そのコミットの run が一覧に出るまで 30 秒ごとに繰り返す
2. 出たら、`gh run watch` に run の ID と `--exit-status` を指定し、Bash の `run_in_background` で終了まで待つ
3. 終了コードが 0 なら成功と伝える
4. 0 以外なら、失敗したワークフローと、この登録のコミットを打ち消すコミットを提案する
5. 打ち消しのコミットは、利用者が回答するまで作らない

待つ時間の上限は、1 から 2 の終了までを合わせて 30 分にする。
上限を超えたら待つのをやめ、結果が出ていない旨と run の URL を伝える。

| 導出の元の値 | 値 |
| --- | --- |
| 同じグループで先に動いている run の待ち（`pages.yml` は `cancel-in-progress: false`） | `build`・`deploy` の `timeout-minutes` の合計 10 分 |
| 自分の run | `build`・`deploy` の `timeout-minutes` の合計 10 分 |
| 余裕 | 内側の待ちの合計の 50% で 10 分 |
| `gh run list` を繰り返す間隔 | 30 秒（上限 30 分の間で最大 60 回で、認証済みの GitHub の REST API の上限の 1 時間 5,000 回に収まる） |

呼ぶもの:

- コマンド `gh run list --repo shuhei1101/knowledge --branch develop --commit {コミット} --json databaseId,status,conclusion,url,workflowName`
- コマンド `gh run watch {run の ID} --repo shuhei1101/knowledge --exit-status`
